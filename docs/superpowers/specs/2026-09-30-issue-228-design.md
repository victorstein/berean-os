# Issue #228 design — no whole-Bible progress in the reader status bar

Research: `docs/superpowers/research/2026-09-30-issue-228-research.md`.
Line numbers were read on `feature/228-status-bar-no-bible-progress` at `e3e5c94e`. The
research note's `BaseTheme.cpp` ranges (`594-610`, `614-630`) were a few lines early; the
numbers here were re-read and supersede them.

## Problem

The reader status bar is the last place a Bible shows progress through the whole
publication. `EpubReaderActivity::renderStatusBar` computes
`bookProgress = epub->calculateProgress(...) * 100` (`src/activities/reader/EpubReaderActivity.cpp:1800`)
and hands it to `GUI.drawStatusBar` (`:1824-1825`). `BaseTheme::drawStatusBar` prints it as
`"n/m  47%"` or `"47%"` (`src/components/themes/BaseTheme.cpp:595-610`), and draws it as the bar
when `progressBarMode == BOOK_PROGRESS` (`:625-626`). The percentage is on by default
(`statusBarBookProgressPercentage = 1`, `src/CrossPointSettings.h:266`).

The owner decided (2026-09-30, option A of the whole-branch review's MINOR 1) that a Bible has
no progress UI anywhere. #197 (`3591e3fe`) removed the Home line and the reader-menu band, and
`ReaderMenuModel.h:93-94` hides Go to % in a Bible. This removes what remains.

## Goal

In a Bible:

1. The book percentage is never drawn, whatever `statusBarBookProgressPercentage` says. The
   chapter page count (`n/m`) still follows `statusBarChapterPageCount`.
2. A `BOOK_PROGRESS` bar draws chapter progress, identically to `CHAPTER_PROGRESS`.
   `CHAPTER_PROGRESS` and `HIDE_PROGRESS` are unchanged.

Outside a Bible, and in the Settings preview, output is byte-for-byte what it is today.

## Non-goals

- No setting changes: no new setting, no changed default, no settings-format bump. The two
  settings still govern non-Bible books.
- No change to the Settings → status bar screen or its preview
  (`src/activities/settings/StatusBarSettingsActivity.cpp:279`).
- No change to the reserved status-bar height (`src/components/UITheme.cpp:132-147`) — see A4.
- Not the initial-percent jump at `EpubReaderActivity.cpp:768-773`.
- Not the `calculateProgress` use at `EpubReaderActivity.cpp:1944`. It feeds the screenshot
  filename's `%dpct` field (`src/util/ScreenshotUtil.cpp:32-41`), which is file metadata, not
  on-screen UI. A whole-Bible percentage therefore survives there; removing it is a follow-up if
  the owner wants it.
- No change to `readerMenuTitle()` or the title slot.

## Assumptions (each is a decision the review should attack)

- **A1 — "Bible" means `epub->getBibleBookNavSpineIndex() >= 0`.** The same test
  `readerMenuTitle()` uses (`EpubReaderActivity.cpp:1788`) and the activity uses at `:274`,
  `:857`, `:938`. Nothing new is introduced to detect a Bible.
- **A2 — The theme learns nothing about Bibles.** `drawStatusBar` gains one trailing
  parameter, `const bool showWholeBookProgress = true`. `renderStatusBar` is the only place that
  maps "is a Bible" onto it. The default keeps the preview call at
  `StatusBarSettingsActivity.cpp:279` and any future caller unchanged. The issue allows "a flag
  or an adjusted status-bar spec"; a flag is chosen because the theme re-reads
  `SETTINGS.statusBarSpec()` itself (`BaseTheme.cpp:583`), so an adjusted spec would mean either a
  second, overriding spec parameter or threading the spec through every caller.
- **A3 — The rule is one pure function, `StatusBarProgress::resolve`, in a new header
  `src/components/StatusBarProgress.h`.** Modelled on `src/components/ListRowHeight.h` (from
  #197): header-only, `constexpr`, free of Arduino, FreeInkUI, GfxRenderer and
  `CrossPointSettings`, tested in `test/ui_layout`. It cannot take `CrossPointSettings::StatusBarSpec`,
  because no host test can include `CrossPointSettings.h` (it pulls in `ArduinoJson.h`,
  `PersistableStore.h` and `SdPaths.h`, `CrossPointSettings.h:2-5`).
- **A4 — The reserved height does not follow the Bible rule.** When the book percentage is the
  *only* text item enabled, a Bible gets an empty text lane: `UITheme::getStatusBarHeight`
  still reserves it from the unadjusted settings spec (`UITheme.cpp:132-139`). That is accepted.
  Making the reservation Bible-aware would change the page margins read at
  `EpubReaderActivity.cpp:1136-1140`, hence the viewport, and invalidate every Bible section
  cache whenever the setting combination hits it. With the defaults (chapter page count on,
  chapter title on, battery on — `CrossPointSettings.h:265-270`) the lane is never empty.
- **A5 — The bar mode is reduced to one bool before it reaches the rule.** The caller passes
  `barTracksBook = sb.progressBarMode == BOOK_PROGRESS`. `CHAPTER_PROGRESS` and `HIDE_PROGRESS`
  both map to `false`, and the rule never sets it `true`, so their behaviour cannot change;
  whether a bar is drawn at all still comes from `sb.showsProgressBar()` (`BaseTheme.cpp:618`),
  untouched. This keeps the enum values out of the firmware-free header rather than restating
  them.
- **A6 — `bookProgress` is still computed in a Bible.** `renderStatusBar` keeps calling
  `calculateProgress` unconditionally; the rule decides whether it is shown. Skipping the call
  in a Bible is a micro-optimisation this change does not need, and keeping one code path keeps
  non-Bible output provably identical.
- **A7 — The `~` estimate prefix is unaffected.** It belongs to the page count
  (`BaseTheme.cpp:599-600`), which the rule never hides.

## Architecture

### New: `src/components/StatusBarProgress.h`

```cpp
#pragma once

// Which whole-book progress the reader status bar may draw. Plain bools and free of
// CrossPointSettings, Arduino and GfxRenderer so the host suite can exercise it
// (test/ui_layout).
namespace StatusBarProgress {

struct Inputs {
  bool showWholeBookProgress = true;  // false in a Bible: a reference, not a book to finish
  bool showBookPercent = false;       // StatusBarSpec::showBookProgressPercent
  bool barTracksBook = false;         // StatusBarSpec::progressBarMode == BOOK_PROGRESS
};

struct View {
  bool showBookPercent = false;
  bool barTracksBook = false;  // false: the bar, if shown, tracks the chapter
};

constexpr View resolve(const Inputs& in) {
  return View{in.showBookPercent && in.showWholeBookProgress, in.barTracksBook && in.showWholeBookProgress};
}

}  // namespace StatusBarProgress
```

### Changed: `BaseTheme::drawStatusBar` (`BaseTheme.h:239-242`; defined at `BaseTheme.cpp:576`, edits within `:583-630`)

- New trailing parameter `const bool showWholeBookProgress = true`.
- After `const auto sb = SETTINGS.statusBarSpec();` (`:583`), compute the view with designated
  initialisers, so the three adjacent bools cannot be transposed silently (C++20,
  `-std=gnu++2a`, `platformio.ini:40`):
  `const auto progressView = StatusBarProgress::resolve({.showWholeBookProgress = showWholeBookProgress, .showBookPercent = sb.showBookProgressPercent, .barTracksBook = sb.progressBarMode == CrossPointSettings::STATUS_BAR_PROGRESS_BAR::BOOK_PROGRESS});`
- Replace every read of `sb.showBookProgressPercent` in the text block (`:595`, `:602`, `:605`)
  with `progressView.showBookPercent`.
- Replace the `BOOK_PROGRESS` test in the bar block (`:625`) with `progressView.barTracksBook`.
  The `else` branch (chapter progress, `:627-630`) is unchanged.
- `showStatusBarTextLane` (`:584`) keeps reading `sb` — per A4 — and the right-cluster width
  still comes from the drawn string, so an empty text block adds zero width.

### Changed: `EpubReaderActivity::renderStatusBar` (`EpubReaderActivity.cpp:1796-1826`)

- `const bool isBible = epub && epub->getBibleBookNavSpineIndex() >= 0;`
- Pass `!isBible` as the new final argument of the `GUI.drawStatusBar` call at `:1824-1825`.

### Changed: `USER_GUIDE.md:379-381`

Append to the "Customise status bar" bullet: in a Bible the status bar shows chapter position
only — the book percentage is not shown, and a book progress bar tracks the chapter.

## Data and control flow

```
renderStatusBar                         (EpubReaderActivity.cpp:1796)
  isBible = getBibleBookNavSpineIndex() >= 0
  bookProgress = calculateProgress(...) * 100          (unchanged, A6)
  GUI.drawStatusBar(..., showWholeBookProgress = !isBible)
    sb   = SETTINGS.statusBarSpec()                    (BaseTheme.cpp:583, unchanged)
    view = StatusBarProgress::resolve({flag, sb.showBookProgressPercent, mode == BOOK_PROGRESS})
    text: view.showBookPercent / sb.showChapterPageCount choose the format string
    bar:  if sb.showsProgressBar(): view.barTracksBook ? bookProgress : chapter %
```

Resulting behaviour (page count and bar visibility follow settings as today):

| Book | Percent setting | Bar mode | Text shows % | Bar tracks |
|---|---|---|---|---|
| non-Bible | on / off | BOOK | as setting | book |
| non-Bible | on / off | CHAPTER | as setting | chapter |
| non-Bible | on / off | HIDE | as setting | — |
| Bible | on / off | BOOK | never | chapter |
| Bible | on / off | CHAPTER | never | chapter |
| Bible | on / off | HIDE | never | — |

No new state, no allocation: the rule is `constexpr` over three bools, and `View` is two bools
on the stack. No SD, no mutex, no task.

## Error handling

Nothing new can fail. The existing guards stand: `pageCount > 0` before the chapter division
(`BaseTheme.cpp:629`, `EpubReaderActivity.cpp:1799`) and `epub ?` before `calculateProgress`
(`:1800`). `isBible` is computed behind the same `epub` null check.

## Testing strategy

- **Host test (TDD, written first):** `test/ui_layout/StatusBarProgressTest.cpp`, registered in
  `test/ui_layout/CMakeLists.txt` exactly like `ListRowHeightTest` (`test/ui_layout/CMakeLists.txt:1-14`):
  `${REPO_ROOT}/src` include, `crosspoint_test_common`, `GTest::gtest_main`. `ui_layout` is already
  added by `test/CMakeLists.txt:102`, so the shared top-level file is not touched.
  Cases:
  - non-Bible: all four combinations of `showBookPercent` × `barTracksBook` come back unchanged
    (the identity guarantee behind "non-Bible output is unchanged").
  - Bible: all four combinations give `showBookPercent == false` and `barTracksBook == false`.
  - A `static_assert` on one `resolve` call, since the function is `constexpr`.
- **Build:** `pio run` (x4pro) clean, no new warnings.
- **Format:** `./bin/clang-format-fix` over the whole tree after `git add`.
- **Static analysis:** `pio check` — no new findings in the touched files.
- **Device (human):** in a Bible with the defaults, the bar reads `n/m` with no `%`; with Progress
  bar = Book, the bar resets at each chapter. In another EPUB, `n/m  47%` and the book bar are as
  before. The Settings preview still shows `8/32  75%`.

## Changes after spec review pass 0

`docs/superpowers/reviews/issue-228-spec-review-0.md` returned CLEAR with four MINORs. All four
are applied:

1. Dropped the "default-constructed `Inputs`" test. Firmware always builds `Inputs` explicitly,
   so the test never guarded the preview default. That default is covered by the device check.
2. `drawStatusBar` builds `Inputs` with designated initialisers, so a transposed bool cannot
   compile silently into a Bible-only bug.
3. The `:1944` non-goal now says what that code does: the screenshot filename's `%dpct` field
   survives as a follow-up.
4. The `drawStatusBar` range is cited as its definition (`:576`) plus the edited region
   (`:583-630`).
