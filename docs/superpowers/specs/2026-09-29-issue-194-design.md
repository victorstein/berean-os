# Issue #194 — compact metrics and no Bible progress indicators

Branch `feature/194-compact-metrics-no-progress`, base `a8461e94` (release 1.20.1). Research:
`docs/superpowers/research/2026-09-29-issue-194-research.md` (cited below as **R**). Every
`file:line` was re-read on this branch on 2026-09-29.

## Problem

On the X4 Pro (touch, Lyra theme, 480×800 portrait) every list screen spends 145 px above its first
row: `topPadding 5 + headerHeight 84` (`src/components/themes/lyra/LyraTheme.h:11,13`), then a 40 px
tab or progress band and a 16 px spacer (`verticalSpacing`, `LyraTheme.h:14`). One-line rows are
66 px because touch lists use FreeInkUI's `rowHeight = lineHeight * 2 + 8`
(`freeink-sdk/libs/ui/FreeInkUI/src/FreeInkUI.cpp:114`, body line height 29), which is sized for a
label plus a subtitle. Settings and the reader menu each show **9** rows (R, "Measured baseline").

Three screens also show Bible reading progress: the Home tile's "N of 1189 chapters read"
(`src/activities/launcher/LauncherActivity.cpp:84-98`), the reader menu's page/percent band
(`src/activities/reader/EpubReaderMenuActivity.cpp:182-191`) and the sleep screen's per-book strip
(`src/activities/boot_sleep/StudySleepScreen.cpp:255-289`, drawn at `:361-364`). The owner's rule is
that the Bible is a reference, not a book to finish, so these go.

## Goal

1. Lyra header band ≤ 49 px including top padding, with the battery on the title line.
2. Lyra `verticalSpacing` 16 → 8.
3. Touch one-line lists get their own row height (50 px, never below `minTouchSize`); subtitle lists
   keep today's 66 px.
4. Settings and the reader menu show ≥ 12 rows per page (today 9; +30% is 11.7).
5. No chapters-read line on Home, no progress band in the reader menu, no strip on the sleep screen.
6. The reader menu's title is the current reference ("Isaiah 40") in a Bible; other books keep
   their title.
7. Translation keys left unused are deleted; `USER_GUIDE.md` matches the screens.

## Non-goals

- The chapter-completion store, its file, its writers and its tests
  (`src/study/ChapterCompletionFile.*`, `src/study/StudyStore.*`,
  `lib/StudyStore/StudyStore/ChapterCompletion.*`, `test/chapter_completion/`,
  `test/storage_io/ChapterCompletionFileTest.cpp`). A follow-up issue retires it.
- Meetings progress (`src/activities/network/MeetingsActivity.cpp:248-251, 356-358`). Kept.
- The Classic theme's metrics (`src/components/themes/BaseTheme.h:124-148`) and every non-touch
  path. Nothing changes on a board without touch.
- freeink-sdk. No edit there; everything is set from our side.
- `WifiSelectionActivity`'s own row-height code (`src/activities/network/WifiSelectionActivity.cpp:1065`)
  and `EndOfBookOptions`'s fixed `listRowHeight` (`src/activities/reader/EndOfBookOptions.cpp:184`).
  Neither routes through the two sync functions; they keep their current heights.
- The reading status bar. It already shows the page; it keeps its current behaviour.

## Decisions

### D1 — the header goes shared-line, modelled on Classic

Lyra takes Classic's shape (`BaseTheme.h:127-128, 147`): `headerHeight 44`,
`headerBatteryDetached false`. `BaseTheme::drawHeader` already implements the shared line: the title
gets a `rightReserve` of `batteryReserve + spaceMd` (`src/components/themes/BaseTheme.cpp:352-359`)
and the FreeInkUI header vertically centres it (`freeink-sdk/libs/ui/FreeInkUI/include/components/controls/header.h:136-144`).
`batteryBarHeight` becomes 44 so the battery, which is centred inside
`Rect{batteryX, band.y, batteryReserve, batteryBarHeight}` (`BaseTheme.cpp:384-385`;
`components/bars/battery-indicator.h:77-78`), sits on the title's centre line.

### D2 — a header subtitle goes next to the battery when the battery fills the band

Settings passes `BEREAN_VERSION` (`src/activities/settings/SettingsActivity.cpp:483`) and Wi-Fi passes
a count (`src/activities/network/WifiSelectionActivity.cpp:960`) as the header's secondary text.
Today a shared-line header with the battery on the right draws that text manually in the band's
**lower-right corner** (`BaseTheme.cpp:333-336, 387-394`), which is free only because Classic's
battery sits in a 20 px top strip. With the battery centred on a 44 px band the two would overlap.

The rule becomes: draw the manual corner label only when the battery strip is shorter than the band
(`metrics.batteryBarHeight < rect.height`). Otherwise hand the text to the header component as
`props.rightLabel`, which already right-aligns it inside the reserved content width (left of the
battery) and bottom-aligns it to the title line (`header.h:72-78, 137-157`). The comment at
`BaseTheme.cpp:327-332` describes that component behaviour; nothing new is invented. Classic
(20 < 45) is unchanged.

### D3 — touch one-line row height is a new `ThemeMetrics` field, applied per list

The theme's `rowHeight` token also sizes buttons and sliders (`src/components/UiSliderDialog.h:50`,
`src/components/UiAppHelpers.h:140`, `BibleSearchActivity.cpp:757, 803`,
`BibleDownloadActivity.cpp:317, 352`, `FrontlightPanelActivity.cpp:184-226`; R), so it is **not**
lowered. Instead a new field `int touchListRowHeight = 0;` joins `ThemeMetrics`
(`src/components/themes/BaseTheme.h:25-...`), with a default member initializer exactly like
`tabPillFullSlot = false` (`BaseTheme.h:66`), which neither metrics table names (`grep -rn tabPillFullSlot src/components/themes` finds only the declaration). Lyra sets it to 50;
Classic omits it (0 = "use the token", today's behaviour).

The two sync functions — `UiListActivity::syncListViewport` (`src/activities/UiListActivity.cpp:123-138`)
and `UiTabListActivity::syncTabListViewport` (`src/activities/UiTabListActivity.cpp:73-90`) — already
pick a per-list height and write `props.rowHeight` on non-touch. They now call one pure helper for
both branches and **always** write `props.rowHeight`. Modelled on that non-touch branch.

### D4 — the reader menu title is computed by the reader, not the menu

`EpubReaderActivity::openReaderMenu` (`src/activities/reader/EpubReaderActivity.cpp:257-289`) already
passes the title (`:278`) and knows `isBible` (`:276`). It passes the reference instead of
`epub->getTitle()` for a Bible, built by the same rule the status bar uses
(`EpubReaderActivity.cpp:1628-1641`): the TOC entry covering `currentSpineIndex`, plus the chapter
number when it is known for this spine. The rule moves into a pure header shared by both call sites
so the two can never disagree.

### D5 — pure helpers live in headers free of Arduino, FreeInkUI and GfxRenderer

Modelled on `src/activities/reader/NumberGridLayout.h:1-10` ("Deliberately free of FreeInkUI,
Arduino and GfxRenderer so the host suite can exercise it").

## Architecture

### 1. `src/components/themes/BaseTheme.h` — `ThemeMetrics`

Add after `listWithSubtitleRowHeight` (`:39`):

```cpp
  // Touch-screen height for one-line list rows; 0 keeps FreeInkUI's
  // label-plus-subtitle rowHeight token.
  int touchListRowHeight = 0;
```

Designated initializers must follow declaration order; `BaseMetrics::values` omits it (0).

### 2. `src/components/themes/lyra/LyraTheme.h` — `LyraMetrics::values`

`batteryBarHeight = 44`, `headerHeight = 44`, `verticalSpacing = 8`, `touchListRowHeight = 50`
(after `.listWithSubtitleRowHeight`), `headerBatteryDetached = false`. Nothing else.

### 3. `src/components/ListRowHeight.h` (new, pure)

```cpp
namespace ListRowHeight {
struct Inputs {
  bool touch;
  bool hasSubtitle;
  int tokenRowHeight;     // FreeInkUI theme().rowHeight
  int minTouchSize;       // FreeInkUI theme().minTouchSize
  int denseRow;           // ThemeMetrics::listRowHeight
  int denseSubtitleRow;   // ThemeMetrics::listWithSubtitleRowHeight
  int touchSingleRow;     // ThemeMetrics::touchListRowHeight
};
constexpr int16_t resolve(const Inputs& in);  // rule A-7
}
```

Plain ints, so the host test needs neither `BaseTheme.h` nor FreeInkUI.

### 4. `UiListActivity::syncListViewport` / `UiTabListActivity::syncTabListViewport`

Both compute `rowHeight = ListRowHeight::resolve({mappedInput.hasTouch(), hasSubtitle,
screen.theme().rowHeight, screen.theme().minTouchSize, metrics.listRowHeight,
metrics.listWithSubtitleRowHeight, metrics.touchListRowHeight})` and set `props.rowHeight =
rowHeight` unconditionally, then carry on as today (`UiListActivity.cpp:137`,
`UiTabListActivity.cpp:87-...`). The non-touch comments are rewritten for the merged state.

### 5. `BaseTheme::drawHeader`

`manualRightLabel` (`BaseTheme.cpp:333`) gains `&& metrics.batteryBarHeight < rect.height`, and its
comment (`:327-332`) says the corner is only free when the battery sits in a shorter top strip.
Nothing else in the function changes.

### 6. `src/activities/reader/BibleReference.h` (new, pure)

```cpp
// "Isaiah" + 40 -> "Isaiah 40"; chapter <= 0 leaves the book name alone.
inline std::string bibleReference(const std::string& tocTitle, int chapter);
```

`EpubReaderActivity::renderStatusBar` (`:1634-1639`) calls it in place of its inline append, with
the same `bibleChapterNumberSpine == currentSpineIndex` guard (passing 0 when the guard fails). A new
private `std::string readerMenuTitle() const` in `EpubReaderActivity` applies A-11 and is what
`openReaderMenu` passes. `std::string` matches the menu's existing `const std::string& title`
parameter (`EpubReaderMenuActivity.h:33`); this runs once per menu open, not in a render loop.

### 7. `EpubReaderMenuActivity`

Constructor loses `currentPage`, `totalPages`, `bookProgressPercent` (`.h:33-34`, `.cpp:18-29`) and
the members (`.h:85-87`). `buildScreen` loses `:181-190`; the spacer (`:191`) stays (A-14).

### 8. `LauncherActivity`, `StudySleepScreen` — deletions per A-15, A-16.

### 9. Translations, per A-17. `USER_GUIDE.md` per "Documentation" below.

## Data and control flow

- **List screen render:** `UiListActivity::render` → `drawChrome` → `GUI.drawHeader(Rect{0, 5, W, 44})`
  (`UiListActivity.cpp:140-145`) → shared-line header, battery centred at the right →
  `renderUi` → activity `buildScreen` sets `contentMargin.top = topPadding + headerHeight = 49`
  (e.g. `SettingsActivity.cpp:438`) → `sync*Viewport` resolves 50 (touch, one-line) and writes it to
  `props.rowHeight` → `ListNav::syncToProps` computes visible rows from the same height
  (`components/lists/list.h:244-258`) → `list()` lays out 50 px rows, growing only wrapped rows.
- **Rows per page (A-6):** Settings `800 − (5 + 44 + 40 + 8) = 703`, `703 / 50 = 14`. Reader menu
  `800 − (5 + 44 + 8) = 743`, `743 / 50 = 14`. `listRowGap` is 0 (`LyraTheme.h:20`), X4 Pro viewable
  insets are 0 and touch `buttonHintsHeight` is 0 (R).
- **Reader menu open:** centre tap → `openReaderMenu` → `readerMenuTitle()` reads
  `epub->getTocIndexForSpineIndex(currentSpineIndex)`, `getTocItem`, and the cached
  `bibleChapterNumber` (no SD read beyond what the TOC lookup already does in the status bar) →
  `EpubReaderMenuActivity(title, orientation, ...)` → header shows "Isaiah 40".
- **Home enter:** `resolveTargets` sets `bibleSubtitle = bibleTitleFor(...)` and no longer opens the
  completion file.
- **Sleep:** `render` → pick passage → `drawScreen` with no progress chrome → the passage fit gets the
  freed height.

## Resources

- No new heap allocation. The sleep path loses one `makeUniqueNoThrow<study::ChapterCompletion>()`
  and one JSON read (`StudySleepScreen.cpp:396-401`); Home loses one completion-file load per
  `resolveTargets` (`LauncherActivity.cpp:85-86`). Both are fewer heap operations and fewer SD reads
  under `storageMutex`.
- `readerMenuTitle()` builds one short `std::string` per menu open (the menu already copies a
  `std::string` title, `EpubReaderMenuActivity.h:79`). Not a hot path.
- `ThemeMetrics` grows by one `int` (two `constexpr` instances in flash plus the `adjustedMetrics`
  copy in `UITheme`, `UITheme.cpp:53`): 4 bytes of DRAM.
- Flash: five translation keys × 32 languages leave the string tables.

## Error handling

- `ListRowHeight::resolve` never returns less than 1: a zero or negative token falls back to the
  dense row, and a positive `touchSingleRow` is clamped up to `minTouchSize`.
- `readerMenuTitle()`: no TOC entry → `epub->getTitle()`; unknown chapter → book name alone (A-12).
  No error return; nothing to log.
- Header: no new failure mode; a long title is clipped by the component as today.
- Removing the completion reads removes their error logs (`StudySleepScreen.cpp:243, 246, 398`) with
  their callers.

## Testing strategy

TDD per the pipeline: each test is written and run red before the code.

### `test/ui_layout/ListRowHeightTest.cpp` (new)

- touch, subtitle → `tokenRowHeight` (66)
