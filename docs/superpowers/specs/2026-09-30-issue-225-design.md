# Issue #225 design: one Bible reference formatter

Research: `docs/superpowers/research/2026-09-30-issue-225-research.md` (called "R" below).
Line numbers refer to `e3e5c94e`.

**Modelled on.** The formatter mirrors `src/util/PlacesDoc.{h,cpp}`, a namespace of pure
functions kept free of `<Arduino.h>` so the host can test it (`PlacesDoc.h:14-17`). Its tests
extend the existing `BibleReferenceTest` target (`test/ui_layout/CMakeLists.txt:17-29`) and
`PlacesDocTest` (`test/places_doc/`). The unification follows the shape of #127 (`c46f87a2`):
several diverged copies are replaced by one helper, and one suite pins the shared behaviour.

---

## 1. Problem

Seven places build a `"Book C:V"` string (R §1). The issue lists five. The status-bar chapter
title and the tagged-passage reference are the other two. Each has its own number formatting,
its own handling of an empty book name and its own truncation:

| Site | Today | Empty book | Cut |
|---|---|---|---|
| Reader-menu title | `bibleReference` → `std::string` (`BibleReference.h:8-11`) | caller returns early (`EpubReaderActivity.cpp:1792`) | none |
| Status bar | `bibleReference` (`EpubReaderActivity.cpp:1817`) | **`" 5"`**: no guard | none |
| Stored place | `PlacesDoc::formatReference` (`PlacesDoc.cpp:51-60`) | no space (#226) | `utf8SafeSummary` 48 B |
| Recent chip | `PlacesDoc::formatChipLabel` (`PlacesDoc.cpp:62-77`) | falls back to stored reference | `snprintf` 49 B |
| Search "Go to" | `formatTypedReference` (`TypedReference.cpp:254-271`) | explicit branch | `snprintf` 64 B, may split UTF-8 |
| Search hit row | inline `snprintf` (`BibleSearchActivity.cpp:597-604`) | explicit branch | `snprintf` 64 B, may split UTF-8 |
| Tagged passage | `toc.title + " " + VerseAnchors::format` (`PassageSelectActivity.cpp:230-238`) | caller branch (`:238`) | `PassageDoc.cpp:150` 48 B |

The issue's concern is that one place could be labelled two ways, once as the menu title and
once as a Recent chip, because the book names reach these sites by two different joins (R §2)
and the chapter by two different paths (R §3).

## 2. Goal

- One formatting core, `BibleReference::format`. Every site above calls it, directly or through
  an adapter that adds only a site-specific policy (a byte cap, or a fallback).
- One documented source for full book names and one for abbreviations (§4.2).
- One chapter derivation, documented and pinned by a test (§4.3).
- A host test showing that one place formats the same way in the reader title, Recent chips,
  stored places and search (§7).
- The labels the owner sees on the NWT stay the same. Every change is listed in §6.

## 3. Non-goals

- **Loading `BibleBookNameTable` in the reader title or status bar.** The table is ~4.2 KB and
  loading it streams the nav spine item, which can inflate it (`BibleBookNameTable.cpp:28-53`).
  The status bar renders on every page turn, so it cannot pay that cost (§4.2, A3).
- **Rewriting stored `places.json` or passage references.** These are display strings written
  once and read back verbatim (`PlacesDoc.cpp:152`, `LauncherActivity.cpp:148,309`,
  `HighlightsActivity.cpp:113`). Old entries keep the label they were saved with. The format
  version does not change (A8).
- **Changing what a surface shows.** The reader title stays at chapter granularity
  (`"Isaías 40"`) and a place stays at verse granularity (`"Isaías 40:31"`). Search keeps full
  names and the chips keep abbreviations. The issue unifies how labels are built, not which
  label each surface uses.
- **Changing the chapter pipeline** (`resolveBibleChapterNumber`, the unit index, `bible.idx`).

## 4. Architecture

### 4.1 The formatter: `src/util/BibleReference.{h,cpp}`

It replaces `src/activities/reader/BibleReference.h`. It moves to `src/util/` because
`PlacesDoc` (`src/util/`) must include it, and nothing in `src/util/` reaches into
`src/activities/`. `PlacesDoc.h:12` includes `"../Place.h"`, not an activity header. Like
`PlacesDoc`, it is free of Arduino, the Epub library and HAL.

```cpp
namespace BibleReference {

// chapter 0: the book name alone. verse 0: the whole chapter. verseEnd 0: a single verse.
struct Verses {
  uint16_t chapter = 0;
  uint16_t verse = 0;
  uint16_t verseEnd = 0;
};

// "65535:65535-65535" plus NUL.
inline constexpr size_t MAX_NUMBERS_BYTES = 18;

// "Isaías 40:31", "Génesis 1", "Juan 3:16-18"; "40:31" when `book` is empty; `book` alone when
// verses.chapter is 0. Cut on a UTF-8 boundary to fit `outBytes`. No-op when outBytes is 0.
void format(char* out, size_t outBytes, std::string_view book, const Verses& verses);

// The same, uncapped, for the reader title and status bar, which draw arbitrary TOC titles and
// truncate by width themselves.
std::string format(std::string_view book, const Verses& verses);

}  // namespace BibleReference
```

The `.cpp` has one private helper, `formatNumbers(char (&)[MAX_NUMBERS_BYTES], const Verses&)`.
It writes `""`, `"C"`, `"C:V"` or `"C:V-E"` with the three `snprintf` shapes in
`TypedReference.cpp:257-264`. Both overloads join `book`, one space and those numbers. The space
appears only when both parts are non-empty. That single rule replaces the four separate
empty-book branches.

The fixed-buffer overload writes with `snprintf("%.*s", …)` and then trims the length with
`utf8SafeTruncateBuffer` (`Utf8.h:24`). This follows `copyUtf8Truncated` in
`BibleBookNameTable.cpp:21-26`. It must not pass that function a length longer than the buffer
(project memory `utf8-safe-truncate-buffer-trusts-len`), so it clamps first.

**"Full-name and abbreviated variants"** (acceptance criterion 1). The variant is which name the
caller passes, the full name or the abbreviation. The numbers and the join are identical by
construction, since both go through `format`. A `Style` enum would carry no logic, so there is
none.

### 4.2 Book-name sources (acceptance criterion 2)

- **Full names come from the publication's TOC title for the book.** It is documented in the
  `BibleReference.h` header comment. Two existing access paths reach it:
  - by spine item: `epub->getTocItem(epub->getTocIndexForSpineIndex(spine)).title`, used by the
    reader title, status bar, stored places and passages. The spine-to-TOC map is built in
    `BookMetadataCache.cpp:236-316`.
  - by canonical book number: `BibleBookNameTable::forBook`, which holds the TOC title of the
    entry each `biblebooknav.xhtml` link targets (`BibleBookNameTable.cpp:56-67`). Search uses
    this path.
- **Abbreviations come only from the nav link text,** `BibleBookNameTable::abbreviationFor`
  (`BibleBookNameTable.cpp:51-52,74-77`). This follows the #206 / PR #90 decision: the
  publication's own abbreviations, never truncated names or a hardcoded table.

**Measured agreement of the two full-name paths.** R §2 left this open. I have now measured it.
The script in Appendix A replays `BookMetadataCache`'s spine-to-TOC rule, "the first TOC entry
targeting a spine item, else inherit the previous one" (`BookMetadataCache.cpp:239-245,311-316`).
It also replays `BibleNav::findTargetByHref`'s filename-tail join (`BibleNavScanner.cpp:193-206`),
and then compares, for every chapter file each `biblechapternav<N>.xhtml` lists (or the nav
target itself, for the five single-chapter books), the inherited TOC title with the nav-joined
name:

```
$ python3 join.py ~/Downloads/nwt_S.epub       → books 66 differ 0
$ python3 join.py ~/Downloads/nwt_S_slim.epub  → books 66 differ 0
```

On the Spanish NWT, whose TOC is doubled (every book listed twice, project memory
`jw-nwt-epub-toc-doubling`), all 1,189 chapter files inherit the book entry, never the
"Contenido de …" outline entry. Their title equals the nav-joined name for all 66 books. No
English NWT EPUB was available locally. `test/bible_book_join/BibleBookJoinTest.cpp:17-33`
models the English TOC with the same outline-then-book interleave.

### 4.3 Chapter derivation (acceptance: "the chapter comes from one derivation")

The derivation is the `chapter<N>_verse<M>` marker, parsed once by `VerseAnchors::Scanner`
(`VerseAnchors.cpp:30-41`). It is documented in the `BibleReference.h` header comment. Every
chapter number in the firmware is already read from it:

- `currentBibleChapter()` reads the first marker (`BibleChapterNumber.h:14-29`,
  `EpubReaderActivity.cpp:1763-1785`).
- `unit.major` comes from `study::scanUnits` over the same markers (`Unit.h:17-20`,
  `UnitAnchors.h:34`).
- `VerseEntry.chapter` in `bible.idx` comes from `VerseTextScanner`, which uses `VerseAnchors`.
- The passage reference uses `VerseAnchors::format` of the anchor itself
  (`PassageSelectActivity.cpp:230`).

This change keeps those runtime paths (A4). It adds a host test that feeds one document to
`BibleChapterNumber::scan` and `study::scanUnits` + `PlacesDoc::placeUnit` and asserts the same
chapter (§7, T3). That makes "one derivation" a checked property rather than a comment.

## 5. Data and control flow, per site

| Site | Book argument | `Verses` | Overload | Wrapper kept? |
|---|---|---|---|---|
| Reader-menu title `readerMenuTitle()` `EpubReaderActivity.cpp:1787-1794` | covering TOC title (unchanged) | `{max(currentBibleChapter(), 0)}` | `std::string` | no: `bibleReference` deleted |
| Status bar `EpubReaderActivity.cpp:1812-1819` | covering TOC title (unchanged) | `{max(currentBibleChapter(), 0)}` | `std::string` | — |
| Stored place `EpubReaderActivity.cpp:1489-1492` | covering TOC title (unchanged) | `{unit.major, chapterOnly ? 0 : unit.minor}` | fixed buffer inside `PlacesDoc::formatReference` | **yes**: `formatReference` keeps its signature and the 48-byte cap policy, and delegates |
| Recent chip `EpubReaderActivity.cpp:903-906` | `names->abbreviationFor(book)` | same as stored place | fixed buffer inside `PlacesDoc::formatChipLabel` | **yes**: keeps its "no abbreviation → stored reference" fallback, and delegates |
| Search "Go to" `BibleSearchActivity.cpp:526-530` | `bookNames.forBook(book)` | `{ref.chapter, ref.verse, ref.verseEnd}` | fixed buffer, `char place[REFERENCE_BYTES]` | no: `formatTypedReference` deleted |
| Search hit row `BibleSearchActivity.cpp:597-604` | `bookNames.forBook(entry.book)` | `{entry.chapter, entry.verse}` | fixed buffer, `row.reference` | — |
| Tagged passage `PassageSelectActivity.cpp:230-238` | covering TOC title (unchanged) | the anchor's `{chapter, verse}`, via `VerseAnchors::find` | `std::string` | — |

For the passage site, `verseReference` keeps its early returns: no HTML cache, scan failure, and
no anchor, which returns `{}` (`:200-231`). It replaces the `VerseAnchors::format` +
concatenation tail with `BibleReference::format(title, {anchor->chapter, anchor->verse})`, where
`title` is empty when `spine.tocIndex < 0`. `VerseAnchors::format` then has no firmware caller but stays: `test/verse_anchors/VerseAnchorsTest.cpp:100-101`
covers it, and removing it is outside #225.

**Memory.** No new heap allocation and no new buffers. The fixed-buffer sites reuse their
existing arrays (`row.reference[64]`, `place[64]`, `labels.text[i][49]`). The `std::string`
overload allocates exactly as `bibleReference` and the passage concatenation already do. The
numbers scratch is an 18-byte stack array, well under the 256-byte local rule. The search-row
loop (`ROW_CACHE` rows per `ensureRows`) makes one `snprintf` per row today. After the change it
makes two: numbers, then join. That is one extra `snprintf`, with no allocation, per row fill.

## 6. What the owner sees: changes on the NWT

With NWT names (at most 25 B, `BibleBookNameTable.h:28-30`) and abbreviations (at most 15 B),
no cap is ever reached. Every surface prints the same bytes as today, **except**:

1. **Status bar with an empty TOC title and a known chapter.** It shows `"5"` where it showed
   `" 5"`. This cannot happen on the NWT, where every chapter file inherits a named book entry
   (§4.2). It is a consistency fix and is listed in the PR.
2. **Search rows or "Go to" with a name that overflows 64 B.** These are cut on a UTF-8
   boundary instead of mid-sequence. They are unreachable on the NWT (a 48-B name plus 17 B of
   numbers is the worst case) and listed in the PR.

The passage reference and the stored place are byte-identical for every input, including an
empty title (A6).

## 7. Testing strategy

TDD. The failing tests land first, in the targets that already exist.

**T1: formatter unit tests.** These rewrite `test/ui_layout/BibleReferenceTest.cpp`. The target
gains `${REPO_ROOT}/src/util/BibleReference.cpp` and `${REPO_ROOT}/lib/Utf8/Utf8.cpp`, plus the
`lib/Utf8` include. Cases:
- the four shapes: book only, `"Isaías 40"`, `"Isaías 40:31"`, `"Juan 3:16-18"`
- an empty book (`"40:31"`, `"40"`, `""`)
- chapter 0 returning the book unchanged, which is the status bar on a non-Bible EPUB
- UTF-8 names
- a buffer cut that would split `"É"` lands before it
- `outBytes == 0` and `outBytes == 1`
- the two overloads agree
- 65535 in every field fits `MAX_NUMBERS_BYTES`

The five `formatTypedReference` tests (`TypedReferenceTest.cpp:205-246`) move here, rewritten
against `format`, with their expected strings unchanged.

**T2: adapters.** The existing `PlacesDocTest` display tests (`PlacesDocTest.cpp:286-312`) stay
unchanged and must still pass. They pin that the adapters' output did not move. The
`PlacesDocTest` target gains `BibleReference.cpp`.

**T3: cross-surface consistency (acceptance criterion 3).** This is a new test in
`test/places_doc/`: a `ReferenceConsistencyTest` executable added to
`test/places_doc/CMakeLists.txt`. It is not the shared `test/CMakeLists.txt`, so no hand-off
line is needed. Its sources are those of `PlacesDocTest` plus
`lib/Epub/Epub/BibleChapterNumber.cpp` and `src/util/BibleReference.cpp`. It uses one short
synthetic chapter document, Isaiah 40 with verses 30 and 31, built with the marker helper from
`BibleChapterNumberTest.cpp:11-19`. That is markup only, not publisher text (project memory
`public-repo-test-fixtures-no-full-publisher-text`). It asserts:
- `BibleChapterNumber::scan(doc)` equals `PlacesDoc::placeUnit(study::scanUnits(doc), offsetOfVerse31)->unit.major`,
  which is the one chapter derivation.
- The reader title, built from `(name, {scan(doc)})`, is `"Isaías 40"`, a prefix of the stored place.
- The stored place `PlacesDoc::formatReference(name, unit, false)` is `"Isaías 40:31"`.
- The chip `formatChipLabel("Is.", place)` is `"Is. 40:31"`. With `""` it equals the stored
  place.
- The search hit row, built from `VerseEntry{23, 40, 31}` fields, and the "Go to" row, built
  from `TypedReference{23, 40, 31, 0}` fields, both equal the stored place.
- The chapter-only place `"Isaías 40"` equals the reader title.
- The same holds for `"El Cantar de los Cantares"`/`"Cant."` and for an empty name.

The search-row and "Go to" call sites map struct fields to `Verses` inline. T3 replicates those
two one-line mappings. It cannot link `BibleSearchActivity.cpp`, which pulls Arduino and HAL
(R §4).

**Build and format.** Run `pio run` (x4pro) once after the last edit, `./bin/clang-format-fix`
over the whole tree, and `ctest` for `BibleReferenceTest`, `PlacesDocTest`,
`ReferenceConsistencyTest` and `TypedReferenceTest`.

**Device (the owner).** On the Spanish NWT, open Isaías 40:
- The menu title reads "Isaías 40", the Recent chip after moving away reads "Is. 40:…", and Home's
  Recent reads "Isaías 40:…".
- Search for `Is 40:31`: the Go-to row reads "Ir a Isaías 40:31" and the hit rows are unchanged.
- Highlight a verse: the Highlights row reads "Isaías 40:N".

## 8. Error handling

`format` has no failure mode. `outBytes == 0` writes nothing (as `formatTypedReference` does
today, `TypedReference.cpp:255`). An empty book or chapter 0 degrades to the shapes in §4.1.
Callers keep their existing failure handling unchanged:
- The chip keeps its table-load failure fallback (`EpubReaderActivity.cpp:897-906`).
- The reader title falls back to the publication title (`:1788-1792`).
- `verseReference` returns `{}` on a scan failure (`PassageSelectActivity.cpp:200-231`).

Nothing logs, because nothing new can fail.

## 9. Assumptions (each open to review)

- **A1 (scope).** The status bar and the tagged-passage reference are in scope, although the
  issue lists five sites. Both build `"Book C[:V]"` from the TOC title and are the same class of
  duplication. Leaving them out would contradict "one formatting function".
- **A2 (full-name source).** The single source of truth for a full book name is the
  publication's TOC title for the book. The two access paths (§4.2) stay, because each site
  already holds the key its path needs: a spine index in the reader, a book number in search.
  Unifying the path would cost either a table load per status-bar render or an SD read of
  `book.bin` per search row. Their agreement is measured on the Spanish NWT (Appendix A), not
  assumed. On a publication where they disagreed, the issue's divergence would persist. That is
  accepted, since this firmware's scope is the NWT.
- **A3 (no table in the reader title).** The title and status bar keep the covering TOC title
  and do not load `BibleBookNameTable` (§3).
- **A4 (chapter).** The runtime chapter paths are unchanged. "One derivation" is satisfied by
  the shared `VerseAnchors` marker parse and pinned by T3. The title keeps its existing gap: it
  shows the bare book name when `currentBibleChapter()` is −1 (`EpubReaderActivity.cpp:1771-1776`),
  even when a place is known.
- **A5 (variants).** "Full-name and abbreviated variants" means the same function called with a
  full name or an abbreviation. There is no style enum.
- **A6 (policy adapters survive).** `PlacesDoc::formatReference` (the 48-B cap through
  `utf8SafeSummary`, which also collapses whitespace runs) and `PlacesDoc::formatChipLabel`
  (the stored-reference fallback) remain as adapters over `format`. `bibleReference` and
  `formatTypedReference`, which carry no policy, are deleted.
- **A7 (no whitespace normalisation in the core).** `format` does not collapse whitespace in a
  book name. The stored place still does, through `utf8SafeSummary`, as today. Measured with the Appendix A
  script: no TOC title in `nwt_S.epub` has a leading, trailing or doubled whitespace run (two
  non-book appendix titles carry U+00A0, which neither rule touches), so the surfaces agree.
- **A8 (no migration).** Stored labels are left as they are, and the format version is
  unchanged (§3).
- **A9 (cut rule).** The fixed-buffer overload cuts on a UTF-8 boundary with no ellipsis,
  matching `copyUtf8Truncated` and `utf8SafeSummary`'s cut.

## Appendix A: the join measurement

This is a scratch script and is not committed. It reads the local EPUB:

```python
import zipfile,re,sys
z=zipfile.ZipFile(sys.argv[1])
opf=z.read('OEBPS/content.opf').decode()
items={m.group(1):m.group(2) for m in re.finditer(r'<item[^>]*?id="([^"]+)"[^>]*?href="([^"]+)"',opf)}
navhref=re.search(r'href="([^"]+)"',re.search(r'<item[^>]*properties="[^"]*nav[^"]*"[^>]*>',opf).group(0)).group(1)
spine=[items[i] for i in re.findall(r'<itemref[^>]*idref="([^"]+)"',opf)]
sidx={h:i for i,h in enumerate(spine)}
tocnav=re.search(r'<nav[^>]*epub:type="toc".*?</nav>',z.read('OEBPS/'+navhref).decode(),re.S).group(0)
toc=[(a.split('#')[0],re.sub('<[^>]+>','',t).strip()) for a,t in re.findall(r'<a[^>]*href="([^"]+)"[^>]*>(.*?)</a>',tocnav,re.S)]
cover=[-1]*len(spine)                                   # BookMetadataCache.cpp:239-245
for j,(h,_) in enumerate(toc):
  i=sidx.get(h,-1)
  if i>=0 and cover[i]==-1: cover[i]=j
last=-1                                                 # BookMetadataCache.cpp:311-316
for i in range(len(spine)):
  if cover[i]==-1: cover[i]=last
  last=cover[i]
links=re.findall(r'<a[^>]*href="([^"]+)"[^>]*>(.*?)</a>',z.read('OEBPS/biblebooknav.xhtml').decode(),re.S)
diff=0
for b,(target,_) in enumerate(links,1):
  target=target.split('#')[0]
  name=next((t for h,t in toc if h.split('/')[-1]==target.split('/')[-1]),'')  # findTargetByHref
  p='OEBPS/biblechapternav%d.xhtml'%b
  cn=z.read(p).decode() if p in z.namelist() else ''
  chs=[h.split('#')[0] for h in re.findall(r'<a[^>]*href="([^"]+)"',cn) if 'nav' not in h] or [target]
  if {toc[cover[sidx[h]]][1] for h in chs} != {name}: diff+=1; print(b,name)
print('books',len(links),'differ',diff)
```
