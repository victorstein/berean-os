# Issue #235 — tag actions outside the Bible open the Bible's tags

Research: `docs/superpowers/research/2026-09-30-issue-235-research.md`. Base `58546aaf`.
Surface: `ui`. Tier: `standard`.

## Problem

Tags are Bible-only, but the reader treats every book as taggable:

- `ReaderMenuModel::build` adds the **Tag** quick action (`HIGHLIGHT_PASSAGE`) and the
  **Highlights** row for any book when `hasHighlights` is set
  (`src/activities/reader/ReaderMenuModel.h:82`, `:86`). Only `TAGS_HERE` checks `isBible` (`:85`).
- **Highlights** → `openHighlights()` (`src/activities/reader/EpubReaderActivity.cpp:793-795`)
  lists `STUDY`'s passages, and `STUDY` is opened on the *current* book in `loadBook`
  (`:226`, `src/study/StudyStore.cpp:44-60`). From a Watchtower that list is empty.
- **Tag** → `openHighlightPassage()` (`EpubReaderActivity.cpp:789-791`, `:326-351`) pushes
  `PassageSelectActivity`, whose save calls `STUDY.addPassage`
  (`src/activities/reader/PassageSelectActivity.cpp:355`) and writes
  `/.berean/passages/<current pubkey>.json` (`src/study/StudyStore.cpp:110-117`).
- `openHighlightPassage` has three more callers, none gated on the Bible: touch long-press
  (`EpubReaderActivity.cpp:461-469`, the call at `:466`), Confirm long-press with
  `LP_MENU_HIGHLIGHT` (`:514-518`) and Home-key hold with `LP_MENU_HIGHLIGHT` (`:539-540`).

## Goal

1. In a non-Bible publication, **Tag** and **Highlights** stay visible and each opens the Bible
   at its tag list — the same handoff Home → Tags makes (`HomeTargets.h:67-68`,
   `LauncherActivity.cpp:444`).
2. No path in a non-Bible reader creates a passage. No `/.berean/passages/<non-bible>.json` is
   written.
3. If no Bible can be resolved, both entries are hidden outside the Bible, and that is logged.
4. Inside the Bible, nothing changes.
5. The visibility-and-target rule lives in one pure function in `ReaderMenuModel.h`, host-tested.

## Non-goals

- No change to Home, `HighlightsActivity`, `PassageSelectActivity`, `StudyStore` or any on-disk
  format. Existing `/.berean/passages/*.json` are not read, migrated, hidden or deleted.
- No new label or translation key (A7). The pre-existing missing Spanish `STR_HIGHLIGHTS`
  (research, "Labels") is out of scope.
- No change to `TAGS_HERE`, which is already Bible-only (`ReaderMenuModel.h:85`).
- No change to the input layer (`MappedInputManager`).

## Assumptions (each is a decision the review should attack)

- **A1 — One rule, three outcomes.** A new pure function in `ReaderMenuModel.h`:
  `TagTarget tagTarget(bool hasHighlights, bool isBible, bool bibleReachable)` returning
  `Hidden` (no highlights support, or non-Bible with no Bible), `ThisBook` (in the Bible) or
  `BibleTags` (non-Bible with a Bible). `build()` shows `HIGHLIGHT_PASSAGE` and `HIGHLIGHTS` iff
  the target is not `Hidden`; the activity dispatches both actions and the Tag hold on the same
  function. This is the issue's "keep the rule in one place in `ReaderMenuModel`".
- **A2 — `Inputs::bibleReachable` defaults to `false`.** Fail closed: a caller that forgets to set
  it hides the entries in a non-Bible rather than offering a tag action that has nowhere to go.
  It is ignored inside a Bible (the Bible is always its own target).
- **A3 — The configured Tag hold behaves like the Tag tile.** Confirm long-press and Home-key hold
  with `LP_MENU_HIGHLIGHT` (`EpubReaderActivity.cpp:514-518`, `:539-540`) are an explicit "Tag"
  command, so outside the Bible they open the Bible's tags; with no Bible they do nothing and log.
- **A4 — A touch long-press on a word does nothing outside the Bible.** It is a word-selection
  gesture (`:461-469`), not a Tag command; there is nothing to select for the Bible from another
  book's page, and an accidental long contact must not throw the owner out of their Watchtower.
  The long-press is still consumed (read by `wasScreenLongPress`) and `loop()` returns, exactly
  as today; only the `openHighlightPassageAt` call is replaced by a `LOG_DBG`. Consuming it keeps
  the contact from reaching anything below, as the block's own comment requires (`:458-460`).
- **A5 — `openHighlightPassage` refuses outside the Bible.** A guard at its top
  (`if (!isBible()) { LOG_ERR(...); return; }`) is the single choke point in front of every
  `PassageSelectActivity` construction (`EpubReaderActivity.cpp:346-351` is the only one in
  `src/`, per `grep -rn "PassageSelectActivity>" src`). A1/A3/A4 route around it; A5 guarantees
  acceptance criterion "no non-Bible passage is written" even if a future caller forgets.
- **A6 — `ReaderEntryIntent::route(Kind::Tags, false)` becomes `Route::None`.** Today it is
  `Highlights` everywhere (`src/activities/reader/ReaderEntryIntent.h:44-45`), pinned by
  `TagsOpenTheHighlightsEverywhere` (`test/ui_layout/ReaderEntryIntentTest.cpp:28-31`). The
  Recents step of the Bible lookup is a title/path guess that "can take a non-Bible titled 'New
  World'" (`src/activities/launcher/LauncherBible.h:75-81`); if it guesses wrong, the Tags intent
  would open that book's own tag list, which is exactly the bug this issue removes. `None` opens
  the book normally and logs (`EpubReaderActivity.cpp:943-948`), matching `OpenAt` and `Search`
  (`ReaderEntryIntent.h:38-43`). This also applies to Home → Tags, for the same reason. The test
  is renamed and flipped; it is a reversal of #221's choice and is called out in the PR.
- **A7 — Labels stay** `STR_TAG` / `STR_HIGHLIGHTS` (`EpubReaderMenuActivity.cpp:44-45`, `:68-69`).
  The issue allows this ("The menu label may stay the same"). No shared YAML hand-off.
- **A8 — The Bible is resolved lazily, once per reader instance, only in a non-Bible.** First
  asked for in `openReaderMenu` or a Tag hold; the result (path or "none") is cached in the
  activity. A Bible reader never resolves. The card cannot gain a Bible while the reader is open:
  the only card writers that run concurrently with a screen are the web server and downloads, and
  both have their own screens (research, CLAUDE.md "Storage discipline" point 5).
- **A9 — The resolver is the launcher's, lifted, not a new one.** The three-step lookup
  (`LauncherActivity.cpp:109-123`, `findBibleOnCard` `:201-207`, `findBibleInRecents` `:211-218`)
  moves into `src/activities/launcher/BibleFinder.{h,cpp}`; the launcher calls it and keeps its
  log line, cover thumbnail and `APP_STATE` write (`:124-135`). Modelled on
  `src/util/CardBooks.{h,cpp}` — a namespace of free functions doing card I/O next to a pure
  header — and placed beside `LauncherBible.h`, which the reader already includes
  (`EpubReaderActivity.cpp:48`).
- **A10 — A resolved path equal to the open book is "no Bible".** Only the Recents guess can
  return a non-Bible (A6); if it returns the book the owner is reading, offering "open the Bible"
  would reopen the same book. Treated as unreachable and logged.
- **A11 — The handoff mirrors `GO_HOME`.** `activityManager.goToReader(path, false,
  ReaderEntryIntent::of(Kind::Tags))`, then `return` from `onReaderMenuConfirm`, as the `GO_HOME`
  case does with `onGoHome()` (`EpubReaderActivity.cpp:801-804`, `src/activities/Activity.cpp:13`).
  `allowFastInitialRefresh = false` is `goToReader`'s default, which the end-of-book handoff uses
  (`src/activities/reader/ReaderActivity.cpp:100`).
- **A12 — Reading position needs no new code.** The page is saved on every render that changed it
  (`EpubReaderActivity.cpp:1395-1402`); `replaceActivity` defers the swap and `exitActivity` calls
  `onExit` (`src/activities/ActivityManager.cpp:176-196`), which records the place and saves
  `APP_STATE` (`EpubReaderActivity.cpp:1507-1512`, `ReaderActivity.cpp:67-76`).

## Architecture

```
ReaderMenuModel.h (pure)            BibleFinder.{h,cpp} (card I/O)
  TagTarget tagTarget(...)  <──┐       std::optional<Found> find()
  Inputs::bibleReachable       │          ├── PubKeyRegistry::findBySymbol({BIBLE_SYMBOL})
  build() uses tagTarget       │          ├── CardBooks::list() + isCdnNamedCopyOf
                               │          └── RECENT_BOOKS.getBooks() + looksLikeBibleInRecents
EpubReaderActivity             │                     ▲                    ▲
  bibleForTags()  ─────────────┼─────────────────────┘                    │
  tagTarget()     ─────────────┘                          LauncherActivity::resolveTargets
  openBibleTags() → activityManager.goToReader(bible, false, of(Kind::Tags))
  openHighlightPassage(): refuses outside the Bible (A5)
ReaderEntryIntent.h: route(Tags, false) → None (A6)
```

### `ReaderMenuModel.h`

```cpp
enum class TagTarget : uint8_t { Hidden, ThisBook, BibleTags };

constexpr TagTarget tagTarget(const bool hasHighlights, const bool isBible, const bool bibleReachable) {
  if (!hasHighlights) return TagTarget::Hidden;
  if (isBible) return TagTarget::ThisBook;
  return bibleReachable ? TagTarget::BibleTags : TagTarget::Hidden;
}
```

`Inputs` gains `bool bibleReachable = false;` after `hasHighlights`. In `build`, `:82` and `:86`
test `tagTarget(in.hasHighlights, in.isBible, in.bibleReachable) != TagTarget::Hidden`. Order of
items is unchanged, so `NonBibleRowOrder` and the quick-action order tests keep their meaning.
`ReaderMenuAction` is not changed (its values are appended-only, `ReaderMenuModel.h:5-6`).

### `BibleFinder.{h,cpp}`

```cpp
namespace BibleFinder {
struct Found { std::string path; BibleLookup by; };
// Registry, then a card scan for the CDN's name, then a guess over recents
// (LauncherBible.h's order). Reads recents as already loaded.
std::optional<Found> find();
}
```

Body: `resolveBible` (`LauncherBible.h:66-73`) with the lambda now at
`LauncherActivity.cpp:112-123`, and `findBibleOnCard` / `findBibleInRecents` moved verbatim from
`LauncherActivity.cpp:201-218` into the `.cpp` as file-static functions. `LauncherActivity.h:60-65`
loses the two static declarations. `resolveTargets` keeps `RECENT_BOOKS.loadFromFile()` (`:101`)
before calling `BibleFinder::find()`. The reader does not reload recents: `RECENT_BOOKS` is loaded
at boot (`src/main.cpp:420`) and kept current by `addBook` (`EpubReaderActivity.cpp:445`,
`ReaderActivity.cpp:62`).

### `EpubReaderActivity`

New private members: `std::string bibleForTagsPath;` and `bool bibleForTagsResolved = false;`
(one short heap string, allocated once per non-Bible reader; a fixed `char[]` was rejected
because `goToReader` takes a `std::string` anyway and paths have no fixed bound here).

- `bool bibleReachableForTags()` — returns `false` in a Bible without resolving (A8). Otherwise
  resolves once via `BibleFinder::find()`, applies A10, logs the outcome once
  (`LOG_INF("ERS", "Bible for tags: %s (%s)", …)` / `LOG_INF("ERS", "No Bible for tags; tag
  actions hidden")`), and returns `!bibleForTagsPath.empty()`.
- `TagTarget tagTarget()` — `ReaderMenuModel::tagTarget(hasHighlights, isBible(),
  hasHighlights && !isBible() && bibleReachableForTags())`, so resolution only ever runs for a
  non-Bible on a board with highlights, with `hasHighlights` the same `BOARD_HAS_PSRAM` constant now local to
  `openReaderMenu` (`EpubReaderActivity.cpp:274-278`), hoisted to a file-scope `constexpr`.
- `void openBibleTags()` — logs and calls `activityManager.goToReader(bibleForTagsPath, false,
  ReaderEntryIntent::of(ReaderEntryIntent::Kind::Tags))`.
- `void runTagCommand()` — `switch (tagTarget())`: `ThisBook` → `openHighlightPassage()`,
  `BibleTags` → `openBibleTags()`, `Hidden` → `LOG_DBG` and nothing.

`EpubReaderMenuActivity`'s constructor gains a `bibleReachable` parameter after `hasHighlights`
(`EpubReaderMenuActivity.h:26-27`, `.cpp:105-114`), forwarded into `Inputs`.

## Control flow

| Trigger | In the Bible | Non-Bible, Bible found | Non-Bible, no Bible |
|---|---|---|---|
| Menu **Tag** tile | `openHighlightPassage()` (unchanged) | `openBibleTags()`, `return` (A11) | not shown |
| Menu **Highlights** row | `openHighlights()` (unchanged) | `openBibleTags()`, `return` | not shown |
| Menu **Tags here** | unchanged | not shown (unchanged) | not shown |
| Confirm long-press / Home hold, `LP_MENU_HIGHLIGHT` | `openHighlightPassage()` | `openBibleTags()` (A3) | nothing, logged |
| Touch long-press on a word | `openHighlightPassageAt(x, y)` | nothing (A4) | nothing (A4) |
| Reader entered with `Kind::Tags` | `openHighlights()` | n/a | `Route::None`, opens normally (A6) |

The menu-confirm cases replace `EpubReaderActivity.cpp:789-796`:

```cpp
case MenuAction::HIGHLIGHT_PASSAGE:
case MenuAction::HIGHLIGHTS:
  if (tagTarget() == TagTarget::BibleTags) { openBibleTags(); return; }
  menu.action == HIGHLIGHT_PASSAGE ? openHighlightPassage() : openHighlights();
  break;
```

(shape only; the plan fixes the exact code). `Hidden` cannot reach here: the entries were not
built. If it does, `openHighlightPassage` still refuses (A5) and `openHighlights` lists the
current book's empty document, which is today's behaviour — never a write.

In the touch long-press block (`:461-469`), after `wasScreenLongPress` has consumed the contact,
`openHighlightPassageAt` runs only when `isBible()`; otherwise `LOG_DBG` and the same `return`
(A4). `detectTouchPageTurn` has already run above it (`:456`), so nothing else changes.

On the Bible side the handoff is the existing Home → Tags path: `onBookLoaded` →
`Route::Highlights` → `openHighlights()` (`:967-968`) → a pick `navigateTo`s in the Bible
(`:366-375`).

## Error handling

- **No Bible found:** entries hidden; one `LOG_INF` per reader instance. Tag hold does nothing
  and logs at `LOG_DBG`.
- **Bible file deleted between resolve and use:** `ReaderActivity::create` in `goToReader`
  (`ActivityManager.cpp:225-228`) fails as for any missing book; this is the same exposure Home
  has with its own `biblePath`. Not handled specially.
- **Registry unreadable:** `findBySymbol` returns `nullopt` (`src/study/PubKeyRegistry.cpp:55-57`)
  and the card scan and recents still run, as on Home.
- **Non-PSRAM board:** `hasHighlights` is `false`, so `tagTarget` is `Hidden` everywhere. The
  activity's `tagTarget()` checks `hasHighlights` and `isBible()` before calling
  `bibleReachableForTags()`, so no resolution happens there either. The X4 Pro has PSRAM
  (`platformio.ini:166,171`); this only keeps the `#else` path honest.
- **`openHighlightPassage` outside the Bible:** `LOG_ERR` and return (A5). No UI message — no
  shipped route reaches it.

## Memory and cost

- One `std::string` member per reader (A8). No allocation in a Bible reader.
- Resolution cost, once per non-Bible reader, on the loop task: one registry JSON read plus
  `Storage.exists` (`PubKeyRegistry.cpp:53-76`); on a miss a directory listing
  (`CardBooks.h:6-11`) and an in-RAM scan of recents. The same work Home does on every entry.
- No new flash tables; `tagTarget` is `constexpr`.

## Testing strategy

TDD, host suites only; red first.

`test/ui_layout/ReaderMenuModelTest.cpp` (no CMake change):

- `TagTargetRule` — all eight combinations of `tagTarget(hasHighlights, isBible, bibleReachable)`.
- `NonBibleWithABibleKeepsBothTagEntries` — `BOOK_ALL` + `bibleReachable = true`: quick actions
  and rows equal today's `NonBibleGetsThreeQuickActionsWithoutSearch` / `NonBibleRowOrder`.

  `{SELECT_CHAPTER, TOGGLE_BOOKMARK}`, rows without `HIGHLIGHTS`.

- Existing tests: `Flags` gains `bibleReachable`; `BOOK_ALL` and `BIBLE_ALL` set it `true`, so the
  existing expectations hold unchanged. `EveryLegacyItemSurvivesForEveryFlagCombination` walks
  128 masks and removes `HIGHLIGHTS` and `HIGHLIGHT_PASSAGE` from the expectation exactly when

`test/ui_layout/ReaderEntryIntentTest.cpp`:

- `TagsOpenTheHighlightsEverywhere` → `TagsAreBibleOnly`: `route(Tags, true) == Highlights`,
