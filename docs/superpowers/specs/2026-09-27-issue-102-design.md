# Remove unreachable fork activities and themes

**Date:** 2026-09-27
**Status:** Design v1
**Target:** bereanOS, `x4pro` build target (ESP32-S3, 8 MB PSRAM, 800x480 e-ink)
**Delivery:** `origin` (victorstein/berean-os), branch `refactor/102-remove-unreachable-fork-code`
**Closes:** #102
**Review tier:** heavy (raised from standard during research)
**Builds on:** `docs/superpowers/research/2026-09-27-issue-102-research.md`
**Modelled on:** `docs/superpowers/specs/2026-09-16-issue-38-design.md` (PR #41,
removing `QrDisplayActivity`) — the nearest existing deletion: activity files
out, one dispatch site edited, completeness greps as the guard, and the flash
delta measured against a local pre-change build. The i18n half follows PR #57
(`70041d90`, issue #31), which removed keys from all 32 YAMLs directly.

## Problem

Code inherited from CrossPoint is still compiled and linked although no path on
this device reaches it. Each item below was re-verified against the tree at
`e41880e3`; the research note carries the full evidence.

- **`HomeActivity`.** `ActivityManager::goHome` always constructs
  `LauncherActivity` (`src/activities/ActivityManager.cpp:247-255`). Nothing
  constructs `HomeActivity`; `ActivityManager.cpp:16` only includes it.
- **`RecentBooksActivity`.** Constructed only in `goToRecentBooks`
  (`ActivityManager.cpp:210-212`, declared `ActivityManager.h:87`), whose only
  caller is `HomeActivity::onRecentsOpen` (`HomeActivity.cpp:322`).
- **`ButtonRemapActivity`.** Constructed only at `SettingsActivity.cpp:311-312`
  on `SettingAction::RemapFrontButtons`, whose row is inserted only under
  `!BoardConfig::hasTouch()` (`SettingsActivity.cpp:77-80`). On this build
  `BoardConfig::ACTIVE` is `XTEINK_X4_PRO`
  (`freeink-sdk/libs/hardware/BoardConfig/include/BoardConfig.h:1519-1520,1532`;
  `platformio.ini:169,187`) with a `TouchController::Gt911`
  (`BoardConfig.h:1411`), so `hasTouch()` (`BoardConfig.h:1622`) is true and the
  row never appears.
- **Theme methods with dead-only callers.** Outside `src/components/themes/`,
  `drawButtonMenu` (`HomeActivity.cpp:293`), `drawRecentBookCover`
  (`HomeActivity.cpp:278`), `getMenuRowHeight` (`HomeActivity.cpp:233`) and
  `drawList` (`ButtonRemapActivity.cpp:135`) have no other callers. Three take
  `std::function` parameters (`src/components/themes/BaseTheme.h:235-240,249-254`),
  which the root `CLAUDE.md` asks to keep out of library and render code.
- **Theme variants.** Four are selectable (`src/SettingsList.h:273-276`). The
  issue calls Lyra, Lyra3Covers and RoundedRaff "extra"; research found that
  only Lyra3Covers is dead (see A1).
- **`STR_CALIBRE_*`.** Eleven keys in `english.yaml`, no code reference.
- **`#include "../../util/HighlightFile.h"`** at
  `src/activities/reader/EpubReaderActivity.cpp:26`, with no other
  `HighlightFile` token in that file.

## Goal

1. Delete `HomeActivity`, `RecentBooksActivity` and `ButtonRemapActivity`, and
   every declaration, dispatch site, action enumerator and string key that only
   they used.
2. Delete the `Lyra3Covers` and `RoundedRaff` themes; remove the four dead theme
   methods from `BaseTheme` and `LyraTheme`, and the metrics fields only those
   methods and `HomeActivity` read.
3. Remove the 11 `STR_CALIBRE_*` keys (plus Hebrew's stray
   `STR_CALIBRE_WEB_URL`) and every key orphaned by 1–2, from all 32 YAMLs.
4. Remove the dead `HighlightFile.h` include.
5. Keep `settings.json` from older builds loading: every stored `uiTheme` value
   0–3 resolves to a theme that exists, with no migration code.
6. `pio run` succeeds; the PR states the flash delta against a pre-change build
   on this branch.

## Non-goals

- **`FileBrowserActivity`, `EndOfBookOptions`** — kept, per the issue.
- **`HomeMenuItem`** (`ActivityManager.h:20`). After this change only `NONE` is
  ever used, but removing it means editing `src/main.cpp:578`, which
  `.claude/agents/ui-dev.md` ("Shared files") reserves to the orchestrator. See A6.
- **`HighlightFile::save`** and its host-tested decision logic
  (`src/util/HighlightFileAction.h`, `test/highlight_file/`). The issue asks
  for the include only. See A7.
- **`RecentBooksStore`** — live: the launcher (`LauncherActivity.cpp:24,149`),
  `ReaderActivity.cpp:13` and `PublicationsActivity.cpp:16` use it.
- **`GfxRenderer` region copy** (`GfxRenderer.h:379-386`) — live in
  `SleepActivity.cpp:460-473`. Only its comment, which names `HomeActivity`,
  changes.
- **The `frontButton*` settings fields** — still loaded
  (`src/CrossPointSettings.cpp:188-194`) and consumed by `MappedInputManager`.
  The input layer is not touched (ui-dev.md, "Do not touch the input layer").
- **`ThemeMetrics` knobs that live code still reads**, such as
  `tabPillFullSlot` (`BaseTheme.h:69`, read at `UiTabListActivity.cpp:134,164,183`).
  Only RoundedRaff set it true, but it stays as theme data. See A4.

## Assumptions

Each is a decision the review can attack.

**A1 — Delete Lyra3Covers and RoundedRaff; keep Classic and Lyra. Lyra stays
the default.** *Settled by the orchestrator (decision d1, 2026-09-27): listing
Lyra in the issue was an error, not a product request; retiring Lyra is out of
scope. The PR body must state this correction to the issue.*

- `uiTheme` defaults to `LYRA` (`src/CrossPointSettings.h:315`). Every device
  that never changed the setting renders all live screens through `LyraTheme`
  and `LyraMetrics`: `UITheme::setTheme` installs both
  (`src/components/UITheme.cpp:30-52`); `uiThemeTokens` feeds `LyraMetrics`
  into every FreeInkUI list (`src/components/UIThemeTokens.h:12-43`);
  `LyraTheme` overrides live methods such as `drawHeader`, `drawTabBar`,
  `fillBatteryIcon` and `drawButtonHints` (`lyra/LyraTheme.h:91-115`).
  Deleting Lyra redesigns the default UI; that is a product change, not a
  dead-code removal.
- `Lyra3CoversTheme` is `LyraTheme` plus two home-cover metrics and one
  `drawRecentBookCover` override (`lyra/Lyra3CoversTheme.h:7-22`), all read only
  by `HomeActivity`. On every live screen it is pixel-identical to Lyra, so it
  is dead.
- RoundedRaff is a live alternative look (`roundedraff/RoundedRaffTheme.h:96-119`),
  but it carries ~500 lines and its own `drawList`/`drawButtonMenu`
  implementations, and the issue asks for it to go. Users who picked it fall
  back to Lyra (A2).

**A2 — Shortening the options list to `{Classic, Lyra}` is the whole
compatibility mechanism; no migration code.**

- Load: `v = clamp(v, info.enumValues.size(), fieldDefault)` where
  `clamp` returns `fieldDefault` unless `val < maxVal`
  (`src/CrossPointSettings.cpp:119,165-169`). Stored `2` (Lyra3Covers) or `3`
  (RoundedRaff) load as `LYRA`. Stored `0`/`1` are unchanged. A missing key
  takes the default, `LYRA`.
- Web POST: `CrossPointWebServer.cpp:1268-1272` accepts only
  `0 <= val < enumValues.size()`, so 2 and 3 are rejected. The GET lists options
  from `enumValues` (`:1187`), so the web UI shows two.
- The on-device option popup draws from the same list (`SettingsList.h:273-276`).
- The enum `UI_THEME { CLASSIC = 0, LYRA = 1, LYRA_3_COVERS = 2, ROUNDEDRAFF = 3 }`
  (`CrossPointSettings.h:218`) keeps all four constants so the numbers keep
  their meaning and are never reused. `UITheme::setTheme` maps the two retired
  values to Lyra explicitly (see Architecture), so the switch covers every
  enumerator and no path leaves `currentTheme` null.
- The stored file is not rewritten on load (no `needsResave` is set for an enum
  clamp, `CrossPointSettings.cpp:165-178`); it is normalised on the next save.
  Harmless: every read goes through the same clamp.

**A3 — Delete the four theme methods from the base class, not just their
overrides.** `drawList`, `drawButtonMenu`, `drawRecentBookCover`,
`getMenuRowHeight` are removed from `BaseTheme.h/.cpp` and `LyraTheme.h/.cpp`.
With no callers left they are pure flash, and three carry `std::function`
signatures. `UITheme::getCoverThumbPath` (`UITheme.h:36`, `UITheme.cpp:124-130`)
goes too: its only callers are the removed `drawRecentBookCover`
implementations (`BaseTheme.cpp:584,633`, `LyraTheme.cpp:418`). The
`struct RecentBook;` forward declaration (`BaseTheme.h:10`) and
`#include "RecentBooksStore.h"` (`BaseTheme.cpp:16`) go if nothing else in those
files needs them — the build decides.

**A4 — Trim `ThemeMetrics` only of fields whose every reader is deleted.**
`menuRowHeight`, `menuSpacing`, `homeTopPadding`, `homeCoverHeight`,
`homeCoverTileHeight`, `homeRecentBooksCount`, `homeContinueReadingInMenu`,
`homeMenuTopOffset` (`BaseTheme.h:62-63,74-79`). `rg` over `src lib` finds
readers only in `HomeActivity.cpp:225-299`, `BaseTheme.cpp:584-820` (the
removed methods), `LyraTheme.cpp:403-518` (the removed overrides), and the
metrics initialisers (`BaseTheme.h:158-169`, `LyraTheme.h:33-44`). Fields read
by live code (`tabPillFullSlot`, the list/header knobs) stay even where only a
deleted theme set a non-default value: `UIThemeTokens.h:9-10` describes these as
the data an SD-card theme file will supply.

**A5 — Remove every string key the deletion orphans, not only the Calibre set.**
Each key below has zero references under the repo (excluding YAML, generated
i18n files, `docs/`, `.pio/`) outside the files being deleted or the lines being
removed from `SettingsActivity.cpp` and `SettingsList.h` (research, command in

**A6 — `HomeMenuItem` stays.** Its removal touches `src/main.cpp:578`, a shared
file ui-dev.md says to report rather than edit, and it saves no flash worth the
cross-surface edit (an `enum class` plus a discarded argument,
`ActivityManager.cpp:247-253`). A follow-up can take it with the next `main.cpp`
change.

**A7 — Only the `HighlightFile.h` include goes.** `HighlightFile::save` has no
call site, but its logic is host-tested (`test/highlight_file/`) and the save
path is the documented storage discipline the tags work may reuse. Deleting it
is a separate decision. The stale comments that describe `save` as live
(`HighlightsActivity.h:48`, `TagPickerActivity.h:29`) are left, out of scope.

**A8 — The YAMLs are edited in this branch.** ui-dev.md lists
`lib/I18n/translations/*.yaml` as a report-only shared file, but the issue
requires the keys removed and regenerated, and PR #57 edited all 32 directly.
The edit is pure line deletion, so it merges cleanly against a sibling that
adds keys elsewhere in the same files.

**A9 — No new host test.** No suite in `test/` references any file being
deleted (`rg -n 'themes/|HomeActivity|RecentBooksActivity|ButtonRemap' test` →
nothing), settings loading has no host harness (`rg -ln
'CrossPointSettings|SettingsList' test` → nothing), and the behaviour under test
is absence, which the compiler and the completeness greps assert. This mirrors
the issue-38 spec ("Testing strategy"). The one behavioural claim, A2's clamp,
is checked on device (Testing strategy, step 5).

**A10 — `USER_GUIDE.md:263` is updated** to list "Classic or Lyra", since it

### Theme dispatch after the change

`UITheme::setTheme` keeps its `switch` over all four enumerators. `CLASSIC`
installs `BaseTheme`; `LYRA`, `LYRA_3_COVERS` and `ROUNDEDRAFF` install
`LyraTheme` with `LyraMetrics`. After A2's clamp the last two cannot arrive from
a loaded file, but `setTheme` takes a raw cast of `SETTINGS.uiTheme`
(`UITheme.cpp:21,26`) and a `switch` with a missing case would leave
`currentTheme` null — so the mapping is defensive, not dead.

`src/MappedInputManager.cpp:390-391` (names ButtonRemapActivity — a comment
only; the input layer's code is untouched), `src/CrossPointSettings.cpp:87,188`

## Data and control flow

**Navigation.** Unchanged for every reachable path: `goHome` → `LauncherActivity`
(`ActivityManager.cpp:254`); Settings rows are built from the same list minus a
row that was never inserted on this board.

**Settings load** (`CrossPointSettings.cpp:165-178`):

```
settings.json uiTheme = n
  n absent            → fieldDefault = LYRA (1)
  n ∈ {0, 1}          → n
  n ∈ {2, 3}          → clamp fails (n ≥ size() = 2) → LYRA
  n ≥ 4 (corrupt)     → LYRA                              (as today)
UITheme() / reload() → setTheme(static_cast<UI_THEME>(n))  → BaseTheme or LyraTheme
```

**Settings change** (`SettingsActivity.cpp:190-199`): the option popup offers
two entries; picking one reloads the theme exactly as today.

**Web settings**: GET lists two options; POST rejects 2 and 3
(`CrossPointWebServer.cpp:1269-1272`) instead of storing them.

## Error handling

No new failure paths. The removed code had none that other code relied on. The
two error-adjacent points:

- A retired stored theme value loads as Lyra silently. That is a fallback
  per the `LOG_ERR + fallback` pattern's intent, but no log line is added: the
  generic clamp does not log for any enum, and adding one only for `uiTheme`
  would be a new pattern.
- A half-deletion (a dangling include, a key still referenced) fails the build,
  not the device. The completeness greps below catch the silent cases the
  compiler cannot: leftover comments and YAML keys.

## Testing strategy

**TDD note.** For a deletion the "failing test" is the completeness gate: run
the greps in step 2 before the change, record the non-zero counts, and see them
reach zero after. No host test is added (A9).

Gates, in this order, after the last code edit (pio through the batch lock
wrapper):

```sh
# 0. Baseline, before any code change, on this branch:
pio run -e x4pro   # record "Flash:" and ls -l .pio/build/x4pro/firmware.bin

# 1. Build — regenerates lib/I18n/I18nKeys.h.
pio run -e x4pro   # record "Flash:" and firmware.bin; the delta goes in the PR

# 2. Completeness — each expect 0 lines.
rg -n 'HomeActivity\b|RecentBooksActivity|ButtonRemapActivity|goToRecentBooks|RemapFrontButtons' src lib
rg -n 'Lyra3Covers|RoundedRaff|drawButtonMenu|drawRecentBookCover|getMenuRowHeight|getCoverThumbPath' src lib
rg -n '\bdrawList\(' src lib
rg -n 'menuRowHeight|menuSpacing|home(TopPadding|CoverHeight|CoverTileHeight|RecentBooksCount|ContinueReadingInMenu|MenuTopOffset)' src lib
rg -n 'HighlightFile' src/activities/reader/EpubReaderActivity.cpp
rg -n '^(STR_CALIBRE_|STR_ALREADY_ASSIGNED|STR_BROWSE_FILES|STR_HW_(BACK|CONFIRM|LEFT|RIGHT)_LABEL|STR_MENU_RECENT_BOOKS|STR_NO_RECENT_BOOKS|STR_REMAP_|STR_REMOVE_FROM_RECENTS|STR_RESUME|STR_UNASSIGNED|STR_THEME_LYRA_EXTENDED|STR_THEME_ROUNDEDRAFF)' lib/I18n/translations
# gen_i18n.py's "Unused keys (N)" must not grow (trust it, not i18n_orphans.sh)
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/

# 3. The other CI jobs.
pio check --fail-on-defect low --fail-on-defect medium --fail-on-defect high
cmake -S test -B build/test -DCMAKE_BUILD_TYPE=Release && cmake --build build/test && ctest --test-dir build/test --output-on-failure -j

# 4. Format, whole tree.
./bin/clang-format-fix
```

`isHomeActivity` (`Activity.h:53`, `LauncherActivity.h:32`) is a live virtual;
the `HomeActivity\b` pattern does not match it.

**5. Device, for the human tester:**
- Settings → Display → UI theme shows two options; switching repaints live.
- With `uiTheme` set to `3` in `/.crosspoint/settings.json` (a RoundedRaff user
  from an older build), the device boots into Lyra and Settings shows Lyra.
- Settings → Controls has no remap row (unchanged — it never appeared).
- Free heap after one launcher → settings → launcher cycle is unchanged.

## Risks

- **RoundedRaff users see their look change** on update, to Lyra. Accepted in
  A1; the release note (PR title) says so.
- **A sibling branch adding keys to the same YAMLs** — pure deletions of distinct
  lines rebase cleanly; re-run step 2 after any rebase.
- **The flash figure varies with `BEREAN_VERSION`** (branch name baked in, per
  PR #41); both measurements are taken on this branch.
