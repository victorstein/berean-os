# Issue #188 — tagged passages keep the full verse

Research: `docs/superpowers/research/2026-09-29-issue-188-research.md` (cited below as R§n).
Base: `a4e2288d`. Every `file:line` was read at that commit.
Modelled on: `docs/superpowers/specs/2026-09-27-issue-182-design.md` (#183, the same files and the
same kind of format bump) for shape, and on `lib/StudyStore/StudyStore/MigrationPlanner.{h,cpp}` +
`src/study/MigrationRunner.cpp` for the repair (a pure per-record planner with an injected text
function, driven by a firmware loop that yields and saves once).

**One decision is open: D1, where the uncapped text lives in memory.** It is written below as the
recommended option and raised with `hpipe decide`. Nothing else in this spec depends on its answer
except the Resources table and the `PassageText` type.

## Problem

A tagged passage's text is cut in three places (R§2):

1. **At capture.** `passage_label::Builder` is capped at `MAX_DISPLAY_TEXT_BYTES` = 384 and ends a
   cut text with `…` (`src/activities/reader/PassageLabel.h:26-41`,
   `PassageSelectActivity.h:154`). It holds only the words the user selected, so a mid-verse
   selection stores a mid-verse text. `StudyStore::addPassage` stores that string as both `"x"` and
   `"w"` (`src/study/StudyStore.cpp:286-287`).
2. **In old records.** Rows saved before #183 have only the 120-byte `"x"`; some start at the wrong
   word. `PassageDoc::fromJson` refuses any `"w"` over 384 bytes (`PassageDoc.cpp:87-96`).
3. **On the sleep screen.** `offerRow` falls back to `"x"` (`StudySleepScreen.cpp:109-117`),
   `Sampler::copyInto` clips at 384 bytes (`StudySleepPick.h:119-123`), and `fitPassage` cuts at
   12pt with `…` (`StudySleepFit.h:119-136`).

## Goal

- A tagged passage's stored text is the **complete verse(s)** its selection touches, never capped.
- Every existing passage is **repaired** to that text from the publication, or left untouched and
  logged if it cannot be resolved. Nothing stored is ever downgraded.
- The sleep screen shows a passage **whole or not at all**: it frees room and goes below 12pt, and a
  passage that still cannot fit is left out of the rotation. No `…`, ever.
- The file stays under an explicit byte budget; a save over it is refused and reported.

## Non-goals

- Changing what a passage **highlights** in the reader. `start`/`end` stay the user's selection;
  only the stored text snaps (A3).
- Changing the reference string (`"r"`). A multi-verse passage keeps its start-verse reference.
- The Highlights list's one-line row. It keeps showing the 120-byte `"x"`, elided (issue, "List rows").
- Snapping non-Bible passages to whole paragraphs (A4).
- A new font (A13).

## Labelled assumptions

Each is a behavioural decision for review to attack.

### Text: what "the full verse" is

- **A1 — The one producer of passage text is `UnitTextScanner`, not the laid-out words.**
  - Capture and repair both extract `[from, to)` from the spine XHTML through
    `UnitIndexCache` + `UnitTextScanner::setRange` (`src/study/UnitIndexCache.cpp:388-398`,
    `lib/StudyStore/StudyStore/UnitText.h:43-46`). So a new passage and a repaired one are built the
    same way and cannot drift.
  - `passage_label::Builder` and `PassageSelectActivity`'s word accumulation (`label`,
    `appendWords`, `PassageSelectActivity.cpp:149,245-260,372-374`) are removed with
    `PassageLabel.h` and `test/passage_label/`. They exist only to build the stored text.
  - `UnitText.h:9-14` already names the laid-out words as the wrong source: they lose the U+202F.
- **A2 — Verse snapping.** For a passage whose start is a `Verse` unit, the text span is
  `[anchor(start).offset, unitEndOffset(anchorIndexOf(lastVerse)))`, where `lastVerse` is the unit
  containing the **last selected codepoint**, `documentOffsetOf(end) - 1`.
  - `end` is stored half-open, one past the last word's start (`PassageSelectActivity.cpp:376-381`),
    so resolving `end` itself could land on the next verse if a one-codepoint word ended a verse
    with no space before the next anchor. The `- 1` removes that case.
  - Built from `resolve`, `anchorIndexOf`, `unitEndOffset`, `documentOffsetOf`
    (`lib/StudyStore/StudyStore/UnitAnchors.cpp:88-120`). No new parsing.
  - Selections never cross a spine document (`PassageSelectActivity.cpp:131-145`: only
    `section.loadPage` on the same section), so start and end share one `DocumentUnits`.
- **A3 — `start`/`end`/fingerprints are not changed by snapping.** The highlight still paints what
  the user selected; the fingerprints still cover the start/end units (`StudyStore.cpp:290-293`).
  Only `"w"` and `"x"` change.
- **A4 — Paragraph and DocumentOffset passages keep the selected range, extended to whole words.**
  "Whole verse" means nothing there (R§3). The span is `[documentOffsetOf(start),
  documentOffsetOf(end))`, and the extracted text is extended to the end of the word the range
  stops in (the next U+0020, or the end of the unit). The meeting publications address by
  `data-pid` (`lib/StudyStore/StudyStore/Unit.h:17-20`), so this is what they get. The alternative,
  snapping to whole paragraphs, is rejected: a Watchtower paragraph often exceeds what the sleep
  screen can hold, and the issue decided snapping only for verses.
- **A5 — The captured text leaves out what is not the verse.** Verified in the real Spanish NWT
  (`nwt_S.epub`, pub-media, 14,945,282 B, `1001061152-split5.xhtml`, Gálatas 5):
  - The last verse of a chapter runs to the end of `<body>` (`UnitAnchors.cpp:108-111`), and that
    tail is the chapter's footnotes: `<div class="groupFootnote"><aside epub:type="footnote">…`.
    `VisibleOffsetCounter` counts `<aside>` as visible (`lib/Epub/Epub/VisibleTextUtils.h:17-20`), so
    today's extraction of Gál 5:26 would include every footnote of the chapter.
  - Verses carry footnote markers: `obstáculo<a epub:type="noteref" href="#footnote29">*</a> del`.
  - Every verse starts with its number: `<strong><sup>4</sup></strong>` then U+202F
    (bytes `e2 80 af`); verse 1 carries the chapter number instead:
    `<span class="w_ch"><strong>5</strong> </span>`.
  - So `UnitTextScanner` gains an opt-in **capture filter**. It does not capture text inside
    `<aside>`, inside `<a epub:type="noteref">`, and — in a Verse document only — inside `<sup>` or
    `<span class="w_ch">`. A U+202F or U+00A0 immediately after a skipped number is also not captured.
  - **Counting is untouched**: `VisibleOffsetCounter` still counts every codepoint, so offsets and
    the fingerprints built by `extractUnitText` do not change (`UnitText.cpp:26-43`,
    `UnitTextTest.cpp:34-46`). The filter only decides what is appended to `captured`.
  - The filter is off by default; `extractUnitText`, `extractRangeText` and fingerprinting keep
    today's output byte for byte.
- **A6 — Verse numbers are dropped from the stored text.** The reference already names the start
  verse, and a sleep-screen quote reads as prose. The alternative — keep interior numbers as
  separators — needs a "first number" rule and puts `12 ` into the middle of a quote. Rejected for
  simplicity; easy to revisit because the filter is one flag.
- **A7 — Block boundaries become one space.** A selection can span `</p><p>`. The filter appends one
  U+0020 into `captured` (never counted) when a block element (`p`, `div`, `li`, `h1`–`h6`) closes,
  so words in adjacent paragraphs do not glue together. `utf8SafeSummary` then collapses runs of
  ASCII whitespace and trims (`lib/Utf8/Utf8.cpp:185-197`).
- **A8 — `"x"` is derived from the whole text.** `"x" = utf8SafeSummary(wholeText, 120)`, at capture
  and at repair. A repaired pre-#183 row's list label therefore starts at the verse's first word, not
  at the wrong word it was saved with.

### Format

- **A9 — `PassageDoc` v4.** Rows gain `"h": true`, meaning "`"w"` is this passage's whole text". A
  row with `"h"` always has a non-empty `"w"`, of **any length** — including ≤ 120 bytes, which v3
  never wrote. There is no per-text cap: the only bound is `SAVE_BYTE_BUDGET` (A11).
  - A file is v4 when any row has `"h"`, otherwise it keeps the lowest version that holds it
    (`formatVersionFor`, `PassageDoc.cpp:106-110`). A v4 file is refused by version on every 1.19.x
    build (`FormatVersion.h:13-15`), which is what `PassageDoc.h:36-50` requires.
  - `fromJson` for a **v4** file: `"h"` must be a boolean when present; a row with `"h": true` and an
    empty or non-string `"w"` refuses the load. A row without `"h"` may carry a v3-shaped `"w"`
    (121..384 bytes, validated as today) — that is an unrepaired row carried forward.
  - `fromJson` for a **v1–v3** file: unchanged validation; every row loads with `whole = false`.
  - `MAX_DISPLAY_TEXT_BYTES` is deleted. The v3 range check keeps its own named constant,
    `V3_MAX_DISPLAY_TEXT_BYTES = 384`, used only for rows without `"h"`.
- **A10 — A row without `"h"` is "not yet whole".** It is repaired (A14), never shown on the sleep
  screen (A19), and its stored `"x"`/`"w"` are written back unchanged until the repair succeeds.
  That is the "never downgrade" rule: nothing is dropped to reach v4.
- **A11 — The file budget stays `SAVE_BYTE_BUDGET = 200000`** (`PassageDoc.h:34`). `add` and the
  repair's `setWholeText` refuse any change that would exceed it (`PassageDoc.cpp:129-132` is the
  pattern). At #183's median of ~705 B per 5–7-verse passage plus ~250 B of other row fields, the
  budget holds roughly 200 such passages; the owner has 63 (`PassageDoc.h:43-45`). This is an
  estimate from #183's figures, not a measurement.
- **A12 — `docs/file-formats.md:487-518` is updated**: the version table gains v4 / `"h"`, the `w`
  paragraph states "uncapped; whole verses; bounded only by the file budget", and the example row
  becomes a whole Gál 5:4.

### Sleep screen

- **A13 — The size ladder, largest first, then skip.** Each rung is tried in order; the first at
  which every line fits the width and all lines fit the height wins:

  | Rung | Passage font | Chrome kept |
  |---|---|---|
  | 1–4 | Noto Serif 18 / 16 / 14 / 12 italic (today's `PASSAGE_FONT_IDS`, `StudySleepScreen.cpp:64-66`) | all: date, quote mark, reference, tag pill, progress strip, mark + footer |
  | 5 | Noto Serif 12 italic | drops the progress strip |
  | 6 | Noto Serif 12 italic | also drops the date line and the tag pill |
  | 7 | Ubuntu 10 regular (`UI_10_FONT_ID`, `src/fontIds.h:12`) | as rung 6 |

  - The floor is `UI_10_FONT_ID`: the smallest face already on the device that the UI uses for body
    text. There is no serif below 12pt (R§2d); Noto Sans 8 (`SMALL_FONT_ID`) is regular-only and is
    judged too small for a quote. Adding a Noto Serif 10 italic is rejected: a new built-in font
    costs flash (the 12pt italic's source alone is 334,032 B, R§2d) and touches shared files
    (`src/main.cpp`, `src/fontIds.h`).
  - The reference, the opening quote mark and the Berean mark + footer are always kept: without the
    reference a quote has no address.
  - `fitPassage` loses its truncating tail (`StudySleepFit.h:119-136`) and `FIT_ELLIPSIS`. It returns
    `fits = false` when no rung fits. `FitResult::ellipsized` is replaced by `fits`.
- **A14 — "Fits at all" is decided before sampling, not after.** A pick that then fails to fit would
  leave the screen with nothing. So `offerRow` asks whether the text fits at rung 7 and offers only
  rows that do; the reservoir stays uniform over fitting passages.
  - Cost bound: one greedy wrap at one size per `"h"` row. A text over `FIT_PREFILTER_BYTES = 4096`
    is rejected without measuring: at rung 7 on this 480-wide portrait panel roughly 70 codepoints
    per line × ~40 lines is under 3,000 codepoints. Both figures are estimates to confirm on device
    (device check 6); the prefilter only has to be conservative, never tight.
- **A15 — The chosen rung is recomputed at draw time** with the real chrome (a missing tag or date
  frees room), so a passage may render larger than rung 7.
- **A16 — `Candidate::text` becomes a `std::string`** and `TEXT_CAPACITY` and its `static_assert`
  (`StudySleepPick.h:19-23`, `StudySleepScreen.cpp:68`) are deleted. The pick copies the text once
  per replacement; it is freed with the `Sampler` after the draw.

### Repair

- **A17 — The repair runs when a publication is opened, for that publication only.**
  - `StudyStore::openPublication` already holds the `Epub` and a ready `UnitIndexCache`
    (`StudyStore.cpp:29-67`). There is no pubkey → EPUB lookup outside `findBySymbol` (R§5), so a
    boot- or sleep-time repair across every file would need a new resolver. The Bible — which holds
    almost all passages — is opened constantly, so it is repaired first in practice.
  - It runs from `EpubReaderActivity` straight after `openPublication` returns
    (`EpubReaderActivity.cpp:214`), on the main task. The plan must confirm the render lock is not
    held there, because `SpineHtmlStream::stream(..., WhenMissing::Inflate)` takes it to draw its
    popup (`src/activities/reader/SpineHtmlStream.h:25-33`).
  - If the passages failed to load (`saveDisabled_`, `StudyStore.cpp:49-53`), no repair runs.
- **A18 — Bounded, resumable, idempotent.**
  - Rows are visited in stored order; a row with `whole == true` is skipped (idempotent).
  - The pass stops after `REPAIR_TIME_BUDGET_MS = 3000` of wall time; the rest wait for the next open.
    `vTaskDelay(1)` after each row keeps the 5 s task watchdog fed, as `MigrationRunner` does
    (`src/study/MigrationRunner.cpp:359-364`).
  - One save at the end of the pass, through `StudyStore::save` → `PassageFile::save`
    (atomic, budgeted, `PassageFile.cpp:26-37`). If the save fails, every row repaired in this pass is
    restored from its backup so memory matches the card, and the failure is logged.
  - A document that has to be inflated shows the existing "Indexing" popup
    (`SpineHtmlStream.h:22-24`). No new UI string.
- **A19 — Per-row outcome, from a pure planner** (`study::planTextRepair`, in `lib/StudyStore`,
  modelled on `planMigration`'s injected `unitText` function, `MigrationPlanner.h:33-45`):
  - **Rebuilt** — the span resolves (A2/A4) and extraction returns non-empty text: `"w"` = that
    text, `"x"` = its summary (A8), `whole = true`.
  - **Unresolvable** — the start or end unit is not in the stored spine, or the Verse search in
    `locateUnit` finds nothing (`StudyStore.cpp:177-197`), or extraction returns empty (a stream
    failure): the row is **left exactly as it was**, logged with its compact start unit, and retried
    on the next open.
  - **Over budget** — `setWholeText` refuses: left as it was, logged.
  - **Suspect start (the known limit)** — a pre-#183 row whose `"x"` does not occur in the rebuilt
    text (compared after `utf8SafeSummary` on both, first 32 bytes of `"x"`): it is still rebuilt
    from its stored range, verse-snapped, and logged as `suspect start` with its reference. This is
    the issue's "verse-snapped rebuild of the stored range, flagged in a log".
  - The stored `documentSpine` hint is updated when the unit was found in another spine
    (`PassageDoc::repairDocumentSpine`, `PassageDoc.cpp:196-198`), and persisted by the same save.
- **A20 — Repair storage discipline.** The owning task is the main task; every read and write goes
  through `HalStorage`, which takes the recursive `storageMutex` per operation
  (`lib/hal/HalStorage.cpp:20,34-35`), and `writeDocToFileAtomic` streams to `.tmp` and renames
  (`lib/Serialization/PersistableStore.cpp:104-122`). No new writer is introduced.

### Capture

- **A21 — `StudyStore::addPassage` builds the text itself.** Its signature drops `snippet`
  (`StudyStore.h:119-120`); it resolves the span (A2/A4), extracts it (A1/A5), sets `"w"`, `"x"`
  (A8) and `whole = true`, then `add` + `save` as today (`StudyStore.cpp:295-299`).
- **A22 — Capture fails closed.** If extraction returns empty, the passage is **not saved** and the
  existing `STR_HIGHLIGHTS_SAVE_FAILED` message is shown (`PassageSelectActivity.cpp:382-386`).
  Saving a row without whole text would put a passage on the card that the sleep screen cannot show
  and that repair would have to fix later. The section's HTML cache exists while the reader is on
  that section (`verseReference` relies on it, `PassageSelectActivity.cpp:200-204`), so extraction
  reads SD, not the zip.
- **A23 — Over budget at capture is refused and reported** by the existing path: `add` returns false,
  `addPassage` returns false, the activity shows `STR_HIGHLIGHTS_SAVE_FAILED`. No new string.

### Memory — pending decision D1

- **A24 (recommended; D1) — The whole text lives in PSRAM.**
  - Why not internal SRAM: every per-passage text is under 4,096 B, so a `std::string` lands in
    internal SRAM (`CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=4096`, R§4), and `ESP.getFreeHeap()` reports
    internal SRAM only (`framework-arduinoespressif32/cores/esp32/Esp.cpp:163-164`). At ~700 B per
    passage the owner's 63 would hold ~44 KB resident and about as much again during a save (R§4),
    against #183's accepted ~25 KB and the ~50 KB floor.
  - Why not "not resident": `PassageDoc::toJson` rewrites the whole file from memory
    (`PassageDoc.cpp:216-246`), so a text not in RAM is erased by the next save (#183 A16).
  - **Mechanism.** `TaggedPassage::displayText` becomes `study::PassageText`: a copyable, owning
    byte buffer from an injected allocator, mirroring `BibleSearch::BuildAllocator` /
    `AllocatedBuffer` (`lib/BibleSearch/BibleSearch/Allocator.h`). Host default is malloc/free; the
    firmware installs a `heap_caps_malloc(MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)` allocator, mirroring
    `BibleSearchStore::psramAllocator` (`src/study/BibleSearchStore.cpp:25-27,97`).
  - **Transient copies.** `PassageFile::load`/`save` and the sleep scan's `offerFile` build their
    `JsonDocument` with an `ArduinoJson::Allocator` that routes to PSRAM
    (`JsonDocument(Allocator*)`, ArduinoJson 7.4.2 `Document/JsonDocument.hpp:24`), so parsing and
    serialising the whole texts does not touch internal SRAM either.
  - **This is the part no repo pattern covers**: no JSON store or string field here uses PSRAM
    today; the precedents are raw buffers. Hence D1.
  - Rejected alternative (the D1 fallback): keep `std::string` in internal SRAM and verify on
    device. Simpler, no new pattern, but ~44 KB resident is an estimate that could breach the floor
    with the Bible open.

## Data and control flow

**Capture.** Tap → `finalizeSelection` (`PassageSelectActivity.cpp:368`) →
`STUDY.addPassage(spine, range.start, range.end, reference, tags)` → resolve units (as today) →
`snapSpan` → `units_->rangeText(spine, from, to)` (filter on) → `utf8SafeSummary` → `whole = true`,
`"x"` = summary(120) → `PassageDoc::add` (budget) → `save` (atomic) → on any failure roll back and
return false → activity shows `STR_HIGHLIGHTS_SAVE_FAILED`.

**Open + repair.** `EpubReaderActivity` → `STUDY.openPublication` (load v1–v4) →
`STUDY.repairTexts()`: for each `!whole` row until the time budget runs out, locate its
spine (spine hint, then the Verse book search), `snapSpan`, `rangeText`, `planTextRepair` →
apply or leave, `vTaskDelay(1)` → one `save`; restore on failure.

**Sleep.** `render` → scan files (unchanged bounds, `StudySleepScreen.cpp:43-47`) → per row:
skip unless `"h"`; prefilter bytes; `fitsAtFloor` (rung 7 wrap) → `Sampler::offer` → pick → draw
with the first rung that fits the real chrome.

## Error handling

| Case | Behaviour |
|---|---|
| Extraction fails at capture | Not saved; `STR_HIGHLIGHTS_SAVE_FAILED` (A22) |
| Capture over the file budget | Not saved; same message (A23) |
| Repair: unit not found / stream fails | Row unchanged; `LOG_ERR` with the start unit; retried next open (A19) |
| Repair: over budget | Row unchanged; `LOG_ERR` (A19) |
| Repair: save fails | All rows of the pass restored in memory; `LOG_ERR` (A18) |
| Passages failed to load | No repair, saves refused, as today (`StudyStore.cpp:49-53,84-88`) |
| v4 file on an old build | Refused by version; saving latches off there (`FormatVersion.h:13-15`) |
| Malformed v4 row (`"h"` without text) | Whole load refused, never repaired or cut (A9) |
| PSRAM allocation fails (D1) | `add`/`setWholeText`/load fail cleanly and log; nothing half-written |
| Sleep: row without `"h"`, or unfit | Not offered; if nothing is offered the existing non-study sleep path runs (`render` returns false, `StudySleepScreen.cpp:388`) |

## Testing strategy

TDD, each test failing first. New suites need lines in `test/CMakeLists.txt`, a shared file: the PR
body carries them for the orchestrator (`.claude/agents/data-dev.md`, "Shared files").

- **`test/unit_text/`** (extend): the filter drops `<aside>` footnotes, `noteref` markers, `<sup>`
  verse numbers and the `w_ch` chapter number, plus the following U+202F; the default (filter off)
  output is byte-identical to today's; the codepoint-count invariant test still holds. Fixture: a
  short hand-written excerpt in the NWT's shape, not a full chapter (public repo).
- **`test/passage_span/`** (new): a selection starting mid-verse 4 and ending mid-verse 5 snaps to
  `[anchor4, anchor6)` — **the issue's mid-verse test**; a selection ending on the last verse snaps
  to `UINT32_MAX` and, through the filter, excludes the footnotes; the `end - 1` edge; Paragraph and
  DocumentOffset spans extend to the end of the word.
- **`test/passage_doc/`** (extend): a passage longer than 384 B (seven verses) round-trips
  byte-for-byte — **the issue's round-trip test**; `"h"` makes the file v4; a short whole text
  (≤ 120 B) is kept with `"h"`; a v3 file loads with `whole = false` and saves back unchanged;
  `"h"` with empty `"w"` refuses the load; `add`/`setWholeText` over the budget return false and
  leave the document unchanged — **the issue's budget test**.
- **`test/text_repair/`** (new): a v1 snippet-only row and a v3 row with a capped `"w"` are rebuilt
  to whole verses — **the issue's repair test**; an unresolvable row and an over-budget row are left
  byte-identical; a wrong-start row is rebuilt and flagged suspect; a second run changes nothing.
- **`test/study_sleep_pick/`** (extend): `fitPassage` never returns an ellipsis; it steps through
  the rungs in order; a text that fits no rung returns `fits = false`; the sampler never picks a row
  offered as unfit — **the issue's fit-and-pick test**; `Candidate::text` holds more than 384 B.
- **Build:** `pio run` once after the last edit; `./bin/clang-format-fix` over the whole tree.

## Resources

| Where | Cost | Memory | Why acceptable |
|---|---|---|---|
| Resident whole texts (D1 recommended) | ~44 KB for 63 × ~700 B (estimate) | PSRAM | 8 MB PSRAM; internal SRAM untouched |
| Load / save `JsonDocument` (D1) | about the file size, briefly | PSRAM | freed when each call returns |
| Capture extraction | one streamed pass over the cached section HTML, 1 KB chunks | internal, transient | same pass shape as today's `unitText` (`StudyStore.cpp:290`) |
| Repair pass | ≤ 3 s per open, one inflate per unrepaired document at worst | as capture | bounded by A18; paid once per row |
