# Issue #157 — Buscar lists only what the device can open, says what each row is, and reports the real failure

Research: `docs/superpowers/research/2026-09-27-issue-157-research.md` (cited as
**R** below). Every line reference was checked on `6f47178e`.

## Problem

1. Buscar lists catalog entries that have no EPUB. Tapping one fails with "No
   está publicada en este idioma" (`PublicationDownloader.cpp:248-249`,
   `spanish.yaml:379`). The publication does exist in that language, so the
   message is wrong.
2. The index cannot tell EPUB-capable entries apart. The builder records
   nothing beyond `symbol, issue, year, kind, title`
   (`build_catalog_index.py:144`) and never contacts the pub-media API (R,
   "Building and publishing").
3. Every row carries a raw code: `describeHit` prints `"g  1980  19800422"`
   (`CatalogSearchActivity.cpp:46-53`). The title repeats the year, so
   consecutive issues all read "¡Despertad! 1980" (R, "Titles already end in
   the year"). The screen never says which language the list is in
   (`CatalogSearchActivity.cpp:552`).

## Goal

- Buscar never lists an entry the index knows has no EPUB.
- When a download does find no EPUB, the message says so. "Not published in
  this language" is shown only when the language really is absent.
- Each result reads as a publication and a date, "¡Despertad!" / "22 de abril
  de 1980", and the header names the list's language.
- The index learns EPUB availability by probing each `(symbol, issue,
  language)` at most once. Only negative results are re-probed, and only
  rarely.

## Non-goals

- Downloading JWPUB. `CLAUDE.md` keeps JW Library interop out of scope.
- A toggle to show hidden entries. The owner decided on 2026-09-27 that there
  is none.
- Telling a network failure apart from "not published in this language".
  Today both return `NoMediaLink` (`PublicationDownloader.cpp:156-158`). This
  change narrows the message only for the no-EPUB case, and a network failure
  keeps today's message (A-7).
- A detail screen per result.
- Changing the "Download \"<query>\"" symbol row
  (`CatalogSearchActivity.cpp:240-243`). It bypasses the index, so a filter
  cannot reach it. Its failures get the corrected message from part 1.
- Retiring the v1 asset (A-2).

## Data and control flow

### 1. Builder (`build_catalog_index.py`)

```
catalog.db ──► rows (symbol, issue, year, kind, title)          [unchanged :120-147]
previous sidecar ──► cache {(symbol, issue): (epub, probedOn)}
                     │
                     ├─ plan: unprobed rows, then 0-rows with probedOn < today-90d   (A-10, A-11)
                     ├─ probe up to --max-probes, ≥ --probe-interval s apart         (A-9, A-10)
                     └─ merge results into cache; drop keys not in rows              (A-12)
rows + cache ──► v2 index  (header version 2, epub field)                           (A-1)
rows        ──► v1 index  (byte-identical to today's output)                        (A-2)
cache       ──► sidecar
```

- New arguments: `--out-v1`, `--previous-v1`, `--probes-in`, `--probes-out`,
  `--seed-from-v2`, `--max-probes` (default 1000), `--probe-interval` (default
  1.0), `--probe-budget-seconds` (default 1500), `--throttle-marker`, and
  `--no-probe`. `--out` now writes v2, and `--previous` compares v2 records.
- v1 is compared against `--previous-v1` separately. The builder writes it only
  when its own records differ, so a flag-only change never republishes v1 with
  a new date, and older firmware never reports a false "update available"
  (review 0, MINOR 2).
- Probe URL: `https://b.jw-cdn.org/apis/pub-media/GETPUBMEDIALINKS?output=json&pub=<sym>&langwritten=<lang>&fileformat=EPUB`,
  with `&issue=<issue>` added only when the issue is non-empty. This mirrors
  the device's `pubMediaUrlForSymbol` (`WolWeekScan.cpp:71-84`), including the
  rule that a book omits the parameter (`WolWeekScan.h:32-34`). The request
  sends the existing `USER_AGENT`.
- The network call and the clock are injected, as `probe(url) -> (status, body)`
  and `sleep`/`now`, so tests run with no network.
- Exit codes: 0 when either index was written because its records differ, and
  3 when neither was written. The sidecar is written in both cases (A-14).
  Upload is per file: an index file that was not written this run is not
  uploaded.

### 2. Workflow (`catalog-index.yml`)

- **Fetch step:** list the release's assets first
  (`gh release view catalog --json assets -q '.assets[].name'`). Then also
  fetch `catalog-<lang>.v2.txt` and `catalog-<lang>.probes.tsv`. Put each
  listed-but-failed download into a step output, so the build step can choose
  the A-13 case.
- **Build steps:** pass `--out catalog-<lang>.v2.txt --out-v1 catalog-<lang>.txt
  --previous previous-<lang>.v2.txt --probes-in … --probes-out …`, plus
  `--previous-v1 previous-<lang>.txt`, and `--no-probe` or `--seed-from-v2` per
  A-13. English also gets `--no-probe` when Spanish was throttled (A-9). Add a
  job-level `timeout-minutes: 90`, sized for two languages at the 1,500 s
  probing budget each (50 minutes) plus the 57.6 MB download.
- **Publish:** the `if:` (`:71`) becomes "either language's status is 0 or 3".
  Each index file is uploaded only if it exists, which keeps the existing
  `[ -f "$f" ] || continue` guard at `:86`. Each sidecar is uploaded when its
  language's status is 0 or 3, unless A-13(a) held that language back.
- **Fail loudly** (`:93-97`) now checks `steps.english.outputs.status` as well
  as Spanish, since a malformed English sidecar is a new English-only failure
  (review 0, MINOR 8).
- The existing `concurrency: catalog-index` (`:20-22`) already stops two runs
  from probing at once.

### 3. Device: index load and fetch

- `CatalogIndexStore::assetUrl` points at `catalog-<lang>.v2.txt.gz`
  (`CatalogIndexStore.cpp:57-60`). The on-card path
  `/.berean/catalog-<lang>.idx` stays the same (`:51-53`).
- `catalog::indexAcceptable` accepts `1 <= version <= FORMAT_VERSION`, where
  `FORMAT_VERSION = 2`. Any higher version is refused (`CatalogStamp.cpp:61-63`).
  The language check is unchanged.
- `Stamp` gains `int version`. `stampOf` copies it, and `sameRelease` compares
  it (A-6).
- `nextEntry(index, version, cursor, out)` takes the version from the parsed
  header. A v1 record splits into 5 fields and sets `out.epub =
  EpubAvailability::Unknown`. A v2 record splits into 6 fields and maps
  `1`→`Available`, `0`→`Unavailable`, and anything else→`Unknown`. A v2 line
  with fewer than 6 fields is skipped, just as a short v1 line is today
  (`CatalogIndex.cpp:88-89`).
- `bool catalog::listable(const Entry&)` returns `entry.epub !=
  EpubAvailability::Unavailable` (A-4).
- The scan moves out of the activity into `lib/Catalog`:
  `size_t catalog::search(std::string_view index, std::string_view query,
  size_t maxResults, bool& truncated, void (*visit)(void* ctx, const Entry&),
  void* ctx)`. It calls `parseHeader(index)` **on every call**, so the version
  always belongs to the buffer being scanned. If the version is anything other
  than 1 or 2, it visits nothing. It then walks the records, applying
  `listable`, then `matches`, then the cap (A-5).
- `runSearch` calls `catalog::search`, and its visitor copies each entry into a
  `Hit` (`CatalogSearchActivity.cpp:182-207`). Nothing caches a version in the
  activity. This is why a first install or an in-session v1→v2 update
  (`:111-120`, `:163-171`) scans the new buffer correctly. *(Revised after
  review 0, MAJOR 3 and MINOR 9.)* A function pointer plus context is used
  rather than `std::function`, following `CLAUDE.md` ("Template and
  `std::function` bloat") and `publication::Hooks` (`PublicationDownloader.h:38-52`).

### 4. Device: labels and header

- `catalog::displayTitle(title, year, hasIssue) -> std::string_view` returns
  the title minus a trailing `" " + year` when `hasIssue` is true (A-20).
  It returns a sub-view, so nothing is allocated.
- `catalog::formatIssueDate(issue, monthsLong, dayFormat, monthFormat, out,
  outSize) -> bool`. It has the same contract as `formatIndexDate`: false only
  when `out` is too small, and the raw code written back on any parse failure
  (A-15 to A-17). The month name is a `string_view` into the twelve-word list,
  so it is first copied into a terminated `char[16]` before `snprintf`.
  `dayFormat` and `monthFormat` are `const char*`, because they come straight
  from `tr()` (review 0, MINOR 4).
- `wordAt` moves from `CatalogStamp.cpp:20-35` into `CatalogLabel.cpp` and is
  exposed as `catalog::wordAt`, so both formatters share it instead of
  duplicating it. `test/catalog_stamp/CMakeLists.txt:2-5` therefore also
  compiles `CatalogLabel.cpp`, or the stamp test fails to link. That file
  belongs to this change, so it is edited here rather than reported (review 0,
  MINOR 3).
- `runSearch` stores `Hit::title` already trimmed. `rebuildRowItems` builds the
  subtitle with `formatIssueDate` into a `char[48]` when the issue is
  non-empty, and uses the year otherwise, or the symbol when the year is empty
  (A-21). `describeHit` is deleted.
- `render` draws the header text from A-22 (`CatalogSearchActivity.cpp:552`).

### 5. Device: download failure (`PublicationDownloader::download`)

```
GET …&fileformat=EPUB  ──ok & found──► download (unchanged)
      │ fail or !found
      ▼
media->reset(); GET … (no fileformat)          [pubMediaUrlForSymbol(..., epubOnly=false)]
      ├─ fetched & found           ──► download with this link          (A-7)
      ├─ fetched & languagePresent ──► Result::NoEpubEdition            (A-7, A-8)
      └─ otherwise                 ──► Result::NoMediaLink (unchanged)
```

- `pubMediaUrlForSymbol` gains a defaulted `bool epubOnly = true`. Existing
  callers (`WolWeekScan.cpp:87`, `PublicationDownloader.cpp:151`) are
  unchanged.
- `PubMediaJsonParser` gains `bool languagePresent() const`. It is set when
  `push` creates a `Node::Language` frame (`PubMediaJson.cpp:57-58`) and
  cleared by `reset` (`:31-39`). No other parser behaviour changes: EPUB is
  still read only at `files.<lang>.EPUB[0]`.
- The unfiltered body is streamed through the same parser, so its 36 KB worst
  case never sits in RAM. The parser keeps only its fixed fields
  (`PubMediaJson.h:76-86`).
- `failureMessage(NoEpubEdition)` returns `tr(STR_NO_EPUB_EDITION)`.

## Error handling

| Situation | Behaviour |
|---|---|
| Probe gets a transport error, a 5xx, a 429, bad JSON, or 200 without EPUB | Nothing is recorded and the row stays unprobed (A-9). A 429 or 5xx also ends probing for the run. The build still succeeds and publishes. |
| An asset is listed but its download fails | The run uses `--no-probe`, and that language's v2 and sidecar are not published this run (A-13a). |
| The v2 is listed and the sidecar is not | The cache is rebuilt from the v2's flags and probing resumes (A-13b). |
| Spanish was throttled (429 or 5xx) | English runs with `--no-probe` (A-9). |
| Probing reaches its time budget | Probing stops and the output is written and published (A-10). |
| Sidecar is malformed (wrong magic, wrong version, wrong language) | The builder exits non-zero and publishes nothing, so a corrupted cache is never adopted. The failure step (`:93-97`), now extended to English, reports it. |
| Device fetches a v2 with version 3+ | `BadFormat`. The held index is left alone and the UI shows `STR_CATALOG_FETCH_FAILED`, as today (`CatalogIndexStore.cpp:235-239`, `CatalogSearchActivity.cpp:154-158`). |
| Older build fetches from the v1 URL | It receives v1, unchanged (A-2). |
| New build holds a v1 index | It reads it and lists everything (A-3). The next "check for update" stages v2, because the versions differ (A-6). |
| Download: EPUB request fails and the fallback also fails | `NoMediaLink`, with today's message (non-goal). |
| Malformed issue code | The raw code is shown (A-17). |

## Memory and flash

- Index size: the v2 field adds 2 B per row (`\t` plus one digit), about
  7.5 KB for 3,769 rows. That fits inside the existing `MAX_INFLATED_BYTES = 1
  MiB` PSRAM budget (`CatalogIndexStore.h:78`), and the budget is unchanged.
- `Entry` gains a one-byte enum, and `Hit` is unchanged. The label buffer is a
  48-byte stack `char[]` in `rebuildRowItems`, within the 256 B local limit.
- `PubMediaJsonParser` gains one `bool`, inside the existing
  `makeUniqueNoThrow` allocation (`PublicationDownloader.cpp:145`).
- The fallback request adds no allocation. It reuses the same parser after
  `reset()`.

## Testing strategy

TDD throughout: each test below is written and run failing before its code.

**Host (gtest, `test/`):**

- `test/pub_media_json`: a new trimmed fixture shaped like km 198001, with
  `files.S` holding only `JWPUB`. `languagePresent()` is true and `found()` is
  false. The existing w/mwb fixtures give `languagePresent()` true. A body
  whose `files` lacks the key gives false. `reset()` clears the flag. Fixtures
  follow `public-repo-test-fixtures-no-full-publisher-text`: structure and
  `pubName` only.
- `test/catalog_index`: a v2 record parses `epub` as all three states. A v2
  title containing a tab stays whole. A v1 record gives `Unknown`. A short v2
  line is skipped. `listable` drops `Unavailable` and keeps the other two.
  `catalog::search` over a mixed v2 index returns only listable rows, and hidden
  rows do not count against the cap. Running the same query against a v1 buffer
  and then a v2 buffer in turn reads each by its own header. An unknown version
  visits nothing. The existing `CatalogIndexTest.cpp:30`, which compares a v1

**Script (`scripts/tests/test_build_catalog_index.py`, A-23):**

- It probes only uncached rows, plus expired negatives. It never re-probes a
  positive row, or a negative row younger than 90 days.
- It honours `--probe-interval` (injected clock) and `--max-probes`, with
  unprobed rows first.
- It maps 200+EPUB→`1` and 404→`0`. 500/429/timeout record nothing, and
  429/5xx stops the run.
- It writes the `epub` field in v2. v1 output is byte-identical to today's
  builder for the same rows. The sidecar round-trips, and dropped catalog rows
  are pruned from it.
- `--no-probe` makes no calls and carries the previous v2 flags over.
  `--seed-from-v2` rebuilds a sidecar from a v2's flags.
  `--probe-budget-seconds` stops probing when the injected clock passes it. A
  throttle writes the marker.
- v1 is not rewritten when only flags changed (`--previous-v1`), and the exit
  code is 3 when neither index changed but the sidecar did.

`./bin/clang-format-fix` over the whole tree.

## Rollout

1. Merge. The first scheduled run after merge, on a Monday at 05:00 UTC (or an
   earlier `workflow_dispatch` by the owner, A-24), is also the first probing
   run. It builds v1 (unchanged, and not republished if its records did not
   move), builds v2 with up to 1,000 probed rows per language (A-13c), and
   uploads the first sidecar. The backlog clears in about four runs. Until a
   row is probed it stays listed, and the download-time message covers it.
2. Devices on the new firmware fetch v2 on their next "check for update" (A-6).
   Devices on older firmware keep receiving v1 (A-2).

## Decisions

- **d1 — A-2, asset naming: settled.** v2 is published as
  `catalog-<lang>.v2.txt{,.gz}` on the same `catalog` release. v1 is still built
  byte-identically at the old URL in the same run. Replacing v1 in place would
  leave every device not yet updated by OTA refusing the only index URL it
  knows (`CatalogStamp.cpp:61-63`). A device with no index could then never
  get one.
- **d2 — A-23, script-test harness: settled.** Tests use stdlib `unittest` in
  `scripts/tests/test_build_catalog_index.py`, with the network call and the
  clock injected, so no test touches jw.org. They run in a new, lightweight
  `script-tests` job in `ci.yml`: `setup-python` 3.12, then `python -m unittest
  discover -s scripts/tests`. The job uses no PlatformIO setup action and no
  PlatformIO cache, and it is added to `test-status`'s `needs`
  (`ci.yml:155-161`) so it gates PRs. The plan's file set includes
  `.github/workflows/ci.yml` and `scripts/tests/`.
