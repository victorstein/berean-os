# Stream store saves straight into the temp file (issue #100)

Research: `docs/superpowers/research/2026-09-27-issue-100-research.md`.
Modelled on: `HalFileReader` in `src/study/PassageFile.cpp:15-28` (the reader
this writer mirrors), `serialization::BufferedFileWriter` in
`lib/Serialization/BufferedFile.h:26-72` (the buffering it reuses), and the
atomic-write host tests in `test/storage_io/AtomicWriteTest.cpp`.

## Problem

1. **One large String per save.** `writeDocToFileAtomic` serialises the whole
   document into an Arduino `String` before writing it
   (`lib/Serialization/PersistableStore.cpp:28-29`). ArduinoJson 7.4.2's String
   writer appends every 31 bytes (`ArduinoStringWriter.hpp:25-45`) and the
   core's `String` reallocates to the exact new length rounded to 16
   (`framework-arduinoespressif32/cores/esp32/WString.cpp:205-212`, `:329-339`).
   A passage file may reach `PassageDoc::SAVE_BYTE_BUDGET` = 200,000 bytes
   (`lib/StudyStore/StudyStore/PassageDoc.h:31`): about 6,450 `realloc`s and a
   final contiguous block of ~200 KB. Past 4,096 bytes that block is PSRAM
   (`CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=4096`,
   `framework-arduinoespressif32-libs/esp32s3/sdkconfig:2154`).
2. **An OOM mid-serialise commits a truncated file.** When `String::concat`
   fails, the writer drops bytes and serialisation carries on; the byte count
   `serializeJson` returns is discarded (`PersistableStore.cpp:29`). `writeFile`
   then checks against the shortened String's own length
   (`freeink-sdk/libs/hardware/SDCardManager/src/SDCardManager.cpp:292-294`),
   reports success, and the truncated `.tmp` is renamed over the good file
   (`PersistableStore.cpp:39-40`). The issue does not name this; it is the
   integrity half of the same change.
3. **The wrong directory is created.** Both writers call
   `Storage.mkdir(sdpaths::CROSSPOINT_DIR)` unconditionally
   (`PersistableStore.cpp:13`, `:24`), including for `/.berean/...` paths.
4. **The streaming reader is private to one file.** `HalFileReader` and
   `readInto` live in an anonymous namespace in `src/study/PassageFile.cpp:13-50`,
   and are the only `deserializeJson` instantiation on the store path outside
   `PersistableStore.cpp` (research note, "How the writer adaptor must be shaped").

## Goal

- `writeDocToFileAtomic` serialises straight into the open `.tmp` `HalFile`
  through a small fixed buffer, then does the existing remove-then-rename.
- A save whose bytes did not all reach the card never replaces the destination.
- The directory created is the parent of the path being written.
- The streaming reader is a `PersistableStoreBase` function any store can pass
  to `loadAdopting`; `PassageFile` uses it.
- Host tests prove a >50,000-byte passage document round-trips byte-exact,
  and that a short write leaves the destination untouched.

## Non-goals

- **Changing any on-disk format.** The bytes written are the same
  `serializeJson` output; `AtomicWriteTest`'s byte-exact assertion
  (`test/storage_io/AtomicWriteTest.cpp:28-30`) guards this. No version bump.
- **Moving `readDocFromFileChecked` to streaming.** It still goes through
  `Storage.readFile` and its 50,000-byte cap
  (`PersistableStore.cpp:47-62`). The stores that use it are budgeted under
  that cap (`SaveBudget.h`); lifting it is a separate behaviour change.
- **Migrating other stores to the streaming reader.** Only `PassageFile`
  switches; others may opt in later.
- **Deleting the per-caller mkdirs** (`PassageFile.cpp:75`,
  `ChapterCompletionFile.cpp:36`, `TagPaletteFile.cpp:36`,
  `PubKeyRegistry.cpp:46`, `MigrationRunner.cpp:118,173`,
  `MeetingWeekCache.cpp:57`, `BookmarkFile.cpp:65`, `HighlightFile.cpp:42`).
  They become redundant, not wrong; removing them touches three surfaces for no
  behavioural gain. The two comments that describe the old behaviour
  (`BookmarkFile.cpp:64`, `HighlightFile.cpp:40-41`, "writeDocToFileAtomic
  ensures /.crosspoint") are corrected, since they would become false.
- **Changing any public signature.** `writeDocToFile`, `writeDocToFileAtomic`,
  `DocReader`, `loadAdopting` keep their declarations
  (`PersistableStore.h:60,66,88,108`).

## Assumptions, for the review to attack

- **A-1 — Reuse `BufferedFileWriter`, do not write a new buffer.** The JSON
  sink is a thin adaptor exposing ArduinoJson's writer shape
  (`write(uint8_t)`, `write(const uint8_t*, size_t)`,
  `ArduinoJson/Serialization/Writer.hpp:11-27`) over a
  `serialization::BufferedFileWriter`. Reason: ArduinoJson writes strings one
  character at a time (`Json/TextFormatter.hpp:38-62,169-171`), and every
  unbuffered `HalFile::write` takes `storageMutex` and calls SdFat
  (`lib/hal/HalStorage.cpp:138-141,160`). `BufferedFileWriter` already batches,
  degrades to passthrough on OOM, and reports short writes through `flush()`
  (`BufferedFile.h:19-21,53-57`).
- **A-2 — Buffer is 512 bytes, heap-allocated once per save.** One SdFat
  sector. ≤ 4,096, so it is internal SRAM (A-1's sdkconfig line); 200,000 / 512
  ≈ 391 `HalFile::write` calls for the largest passage file. Not on the stack:
  the resource protocol caps locals at 256 bytes (`CLAUDE.md`, "The resource
  protocol" 1). Not static: saves come from more than one task (web server and
  main, `PersistableStore.h:29-32`), so a shared static buffer would need its
  own lock. One `makeUniqueNoThrow` per save replaces ~6,450 `realloc`s.
- **A-3 — The adaptor lives in `PersistableStore.cpp`, not a header.**
  `PersistableStore.h:15-23` keeps `serializeJson`/`deserializeJson`
  instantiated in one TU; a header adaptor would re-instantiate them per store.
  Both the reader and writer adaptors go in that file's anonymous namespace.
  This is how the issue's "move them into `lib/Serialization`" is honoured.
- **A-4 — A save succeeds only if all four hold:** the `.tmp` opened; the
  count `serializeJson` returned equals `measureJson(doc)`; `BufferedFileWriter::flush()`
  returned true; `HalFile::close()` returned true. Anything else logs
  `LOG_ERR("PERSIST", ...)`, returns false, and does **not** remove or rename.
  The measure costs a second CPU pass over the document, no I/O and no
  allocation; callers that already measured (`PersistableStore.h:205`,
  `PassageFile.cpp:70`) pay it twice. Accepted: the check is what makes a
  short write detectable even if a future sink stops reporting through `flush()`.
- **A-5 — The failed `.tmp` is left on the card**, not removed. This matches
  today (a failed `writeFile` leaves whatever it left) and the adopting read's
  handling: a `.tmp` that does not parse is kept and reported as nothing there
  when the primary is missing (`PersistableStore.cpp:66-97`, #127), and is
  ignored entirely when the primary is present (`lib/Serialization/TempAdoption.h:17-23`). The next successful save truncates it
  (`SDCardManager.cpp:337`, `O_TRUNC`).
- **A-6 — Close explicitly before rename.** The `.tmp` `HalFile` is a local, but
  it is renamed by path while still in scope, so `close()` is called and checked
  before `Storage.remove`/`Storage.rename`. This is `CLAUDE.md`'s "close before
  delete" case applied to rename, and it surfaces the flush-on-close error that
  `writeFile` ignores today (`SDCardManager.cpp:293`).
- **A-7 — The buffer is flushed before close.** The `BufferedFileWriter` is
  scoped inside a helper that returns before the file closes, so its destructor
  never flushes into a closed file; `flush()` is called explicitly and its
  result used (A-4).
- **A-8 — `storageMutex` is taken per chunk, not across the save.** Each
  `HalFile::write` holds it for one chunk (`HalStorage.cpp:138-141`), exactly as
  `BookMetadataCache` does today through the same `BufferedFileWriter`
  (`lib/Epub/Epub/BookMetadataCache.cpp:190`). Other tasks may interleave SD
  calls between chunks; they cannot touch this `.tmp` because every adopting
  file is single-task (`PersistableStore.h:99-107`). `storeMutex` still
  serialises CRTP saves end to end (`PersistableStore.h:199-200`).
- **A-9 — Parent directory is derived from the path.** Everything before the
  last `/`; nothing is created when that is empty or `/`. Uses
  `Storage.mkdir(parent)` with the default `pFlag = true`
  (`lib/hal/HalStorage.h:34`), which creates intermediate directories. Its result
  is ignored, as today (`PersistableStore.cpp:13,24`): SdFat's mkdir fails on an
  existing directory (fake models this, `test/stubs/HalStorageFake.cpp:105-114`),
  and a real failure surfaces as the `.tmp` open failing. Every CRTP store path
  is under `/.crosspoint` (`SdPaths.h:14-17`, asserted `:38-41`), so their
  behaviour is unchanged. The derivation needs a `std::string` copy of the
  parent; it is one short allocation per save, the same kind the existing
  `tmpPath` already makes (`PersistableStore.cpp:25-26`).
- **A-10 — `writeDocToFile` streams too, through the same helper.** It has no
  callers (`saveToFile()` is its only user and has none,
  `PersistableStore.h:179-180`), but leaving it on a String keeps the String
  serializer instantiated in this TU for dead code. It writes straight to
  `path` (open with `O_TRUNC` via `openFileForWrite`, `SDCardManager.cpp:337`)
  instead of `writeFile`'s remove-then-create (`:282-287`) — observably the same
  for a successful write. Same A-4 checks, minus the rename.
- **A-11 — The reader becomes `PersistableStoreBase::readDocFromFileStreamed`**,
  a public static matching `DocReader` (`PersistableStore.h:88`), with
  `PassageFile`'s `readInto` body moved verbatim
  (`src/study/PassageFile.cpp:30-50`). Its log module changes from `"PASSAGE"`
  to `"PERSIST"`, the module every other function in that file logs under.
  `PassageFile::load` passes it to `loadAdopting`.
- **A-12 — The Storage fake gains one failure hook,** `failWritesAfter(path,
  bytes)`: `HalFile::write` on that path accepts bytes until the file holds
  `bytes`, then returns short. It mirrors `failWritesTo`
  (`HalStorageFake.h:33-37`) and is the only way to prove A-4 on the host. It is
  cleared by `clearFailures()`/`reset()` like the others, and gets its own test
  in `HalStorageFakeTest.cpp`.
- **A-13 — Flash is not claimed to improve.** The String writer's
  instantiation leaves this TU and a custom writer's arrives; the plan records
  `pio run` section sizes before and after and reports them rather than
  asserting a direction.

### Shape inside `PersistableStore.cpp`

```cpp
namespace {

constexpr size_t WRITE_BUFFER_BYTES = 512;

class HalFileReader { /* moved verbatim from PassageFile.cpp:15-28 */ };

// ArduinoJson writer over a BufferedFileWriter. Reports every byte as taken;
// short writes surface through BufferedFileWriter::flush().
class JsonFileWriter {
 public:
  explicit JsonFileWriter(serialization::BufferedFileWriter& out) : out(out) {}
  size_t write(uint8_t c) { out.write(&c, 1); return 1; }
  size_t write(const uint8_t* s, size_t n) { out.write(s, n); return n; }
 private:
  serialization::BufferedFileWriter& out;
};

void ensureParentDirectory(const char* path);             // A-9
bool serializeInto(HalFile& file, const JsonDocument& doc); // A-4 count + flush, A-7
bool writeDocStreamed(const char* path, const JsonDocument& doc); // open, serializeInto, close (A-6)

}  // namespace
```

Names are the plan's to refine; the split — one function that owns the
buffer's lifetime, one that owns the file's — is what A-6/A-7 depend on.

## Data and control flow

### `writeDocToFileAtomic(path, doc)`

1. `ensureParentDirectory(path)` (A-9).
2. `writeDocStreamed(tmpPath, doc)`:
   - `Storage.openFileForWrite("PERSIST", tmpPath, file)` — false → log, return false.
   - `serializeInto(file, doc)`: allocate `BufferedFileWriter(file, 512)`;
     `written = serializeJson(doc, JsonFileWriter(buffered))`; `ok = written == measureJson(doc)`;
     `ok &= buffered.flush()`; buffer freed on return.
   - `file.close()`; `ok &= closed`. Any false → log with path and the two
     counts where relevant, return false.
3. On false: return false. Destination untouched; `.tmp` left (A-5).
4. Unchanged from `PersistableStore.cpp:36-44`: `Storage.remove(final)`,
   `Storage.rename(tmp, final)`, log and false on rename failure.

### `writeDocToFile(path, doc)`

`ensureParentDirectory(path)`; `writeDocStreamed(path, doc)`; log on failure.

### `PassageFile::save`

Unchanged in control flow (`PassageFile.cpp:66-78`): budget refusal before any
I/O, its own `mkdir(PASSAGES_DIR)`, then `writeDocToFileAtomic`. Peak heap for
the write drops from a String of up to 200 KB (PSRAM) to 512 bytes (internal).

### `PassageFile::load`

`loadAdopting(path, PersistableStoreBase::readDocFromFileStreamed, accept, &doc)`
— the same reader body, now reachable by name.

## Error handling

| Failure | Result | Destination file | `.tmp` |
|---|---|---|---|
| Parent mkdir fails | open fails → `LOG_ERR`, false | untouched | not created |
| `.tmp` open fails | `LOG_ERR`, false | untouched | not created / as before |
| Buffer OOM (512 B) | passthrough, slower, still correct (`BufferedFile.h:19-21`) | replaced on success | renamed |
| Short write on any chunk | `flush()` false → `LOG_ERR`, false | untouched | partial, left (A-5) |
| `serializeJson` count ≠ `measureJson` | `LOG_ERR` with both counts, false | untouched | left |
| `close()` fails | `LOG_ERR`, false | untouched | left |
| remove/rename | unchanged (`PersistableStore.cpp:36-44`) | as today | as today |

Every failing return is preceded by a `LOG_ERR("PERSIST", ...)` with exact
format specifiers (`%zu` for `size_t`), per the `-Wformat` LOG macros on main.
`PassageFile::save` already maps false to `SaveResult::WriteFailed`
(`PassageFile.cpp:77`), which its caller reports.

## Testing strategy

### TDD order

Each step: write the test, run `StorageIoTest`, see it fail for the stated
reason, implement, see it pass.

1. `HalStorageFakeTest`: `failWritesAfter` truncates at the limit and returns
   short. Fails: symbol does not exist.
2. `AtomicWriteTest`: **writing under `/.berean/x/` on an empty card succeeds
   and creates no `/.crosspoint`** (`storage_fake::isDir`). Fails today: the
   hardcoded mkdir creates `/.crosspoint`, and `/.berean/x` does not exist so
   `writeFile` fails (`HalStorageFake.cpp:130`).
3. `AtomicWriteTest`: **a short write leaves the existing destination
   byte-identical and returns false.** Seed `PATH` with v1,
   `failWritesAfter(TMP_PATH, 3)`, write v2 → expect false and
   `fileBytes(PATH) == v1`. Fails today: `writeFile` never goes through
   `HalFile::write`, so the hook does not bite and v2 replaces v1. After the
   switch, the implementer also confirms it fails when `serializeInto` ignores
   `flush()`'s result, so the test proves the check rather than the plumbing.
4. `PassageFileTest`: **save-then-load of `pastTheReadCap()`
   (`PassageFileTest.cpp:43-52`, > 50,000 bytes) round-trips**: `save` → `Ok`,
   `fileBytes(PATH) == serialised(saved)`, no `.tmp`, `load` → `Loaded` with the
   same passage count. This is the round-trip the issue asks for.
5. Existing `AtomicWriteTest` byte-exact and failure-hook cases, and every
   existing `PassageFileTest` case, pass unchanged — the regression guard for
   A-10/A-11 and the format non-goal.

### Gates

- Host: `StorageIoTest` and the full host suite via CMake/ctest.
- Device build: `pio run -e x4pro` through the batch's `pio-locked.sh`, with
  section sizes recorded before and after (A-13).
- `./bin/clang-format-fix` over the whole tree after `git add`.

### What only the human tester can verify

The issue proposes watching `getMaxAllocHeap`. That reads
`heap_caps_get_largest_free_block(MALLOC_CAP_INTERNAL)`
(`framework-arduinoespressif32/cores/esp32/Esp.cpp:171-173`), and the String
this removes lives in PSRAM past 4 KB — so that number would barely move. The
meaningful measurement is `ESP.getMinFreePsram()` / `ESP.getMaxAllocPsram()`
(`Esp.cpp:189`, `:196-199`) logged with `LOG_DBG("MEM", ...)` immediately before and
after a passage save on a card holding a large passages file (> 50 KB). Before
this change the PSRAM low-water mark should dip by roughly the file size; after
it, not measurably. Then reboot and confirm the passages list is intact.
