# Issue #201 design — recent places store and reader entry intents

Research: `docs/superpowers/research/2026-09-30-issue-201-research.md`. All `file:line`
citations are at `a22af1d1` (current `main`).

**Modelled on:** `src/util/RecentBooksDoc.{h,cpp}` + `src/RecentBooksStore.{h,cpp}` +
`test/recent_books_doc/` for the store; `test/persistable_store/` (with
`test/stubs/HalStorageFake.*`) for the refused-file-is-never-overwritten test; the tile band in
`ReaderMenuSheetLayout::compute` (`src/activities/reader/ReaderMenuSheetLayout.h:97-103`) for the
chip band; `HighlightsActivity`'s chip hit/`event.value` routing
(`src/activities/reader/HighlightsActivity.cpp:41,171-172`) for chip taps.

## Problem

A returning reader cannot get back to where they were a few jumps ago. The only record of past
positions is `ReturnStack`, a 16-slot RAM ring that covers citation jumps only
(`src/activities/reader/ReturnStack.h:13-19`; pushed only by `ReturnPolicy::Push`,
`EpubReaderActivity.cpp:1670-1675`) and dies with the activity. `progress.bin` holds one position
per book (`EpubReaderActivity.cpp:1322-1330`). `RecentBooksStore` records books, not places
(`src/util/RecentBooksDoc.h:25`). And `goToReader(path, allowFast)`
(`src/activities/ActivityManager.h:85`) has no way to say "open the Bible *at* X" or "open the
Bible's grid / search / tags", which Home (#203) needs.

## Goal

1. A persisted list of the last 12 Bible places, newest first, one per (book, chapter).
2. A one-shot, RAM-only entry intent on `goToReader`: open at a place, or open straight into the
   book grid, verse search or the tags list.
3. A Recent row of place chips in the reader menu sheet (#200/#217); tapping one jumps there.

## Non-goals

- **Home UI.** Continue, Recent rows, Go to and the icon row are #203, which consumes this
  store and these intents. #201 adds no launcher UI.
- **Non-Bible places.** See A1.
- **Changing `ReturnStack`** or the Return swipe. Places are a separate, coarser history.
- **Progress UI of any kind** (overhaul rule: no Bible reading-progress UI).
- **Cross-language display.** A place's `reference` stays in the language it was recorded in (A9).

## Assumptions (each is a decision the review should attack)

- **A1 — Bible only.** A place is recorded only while the open publication's pubkey is
  `study::BIBLE_PUB_KEY` (`lib/StudyStore/StudyStore/PubKey.h:37`, the same gate
  `StudyStore::spineIndicesForBook` uses, `src/study/StudyStore.cpp:83-86`), and only for a
  document whose units are `Verse` kind. Only a `Verse` unit carries `book`/`major`
  (`lib/StudyStore/StudyStore/Unit.h:27-29`), so (book, chapter) dedupe is only defined there. Book
  intros, the book grid's nav pages and appendices are not places.
- **A2 — The verse is the unit at the top of the page.** `study::resolve(units, pageOffset)`
  (`lib/StudyStore/StudyStore/UnitAnchors.h:58-61`, body `UnitAnchors.cpp:88-99`) of the page's
  first visible-text offset. A page that starts before the chapter's first verse anchor (resolve
  falls back to `DocumentOffset`, `UnitAnchors.cpp:94`) records the chapter's first anchor with
  `offset = 0`. That is the issue's "record the chapter only", expressed as verse 1 so that
  `documentOffsetOf` can still resolve it (`UnitAnchors.cpp:113-120`).
- **A3 — No units, no place.** If the unit index is not ready or the document failed to index
  (`UnitIndexCache::ready()`, `indexFailed()`, `src/study/UnitIndexCache.h:62,68`), there is no
  book number (`book` is stamped from the index's book map, `UnitIndexCache.cpp:186`), so no
  (book, chapter) key exists and nothing is recorded; a `LOG_DBG` says so. The issue's
  "chapter only" fallback is A2, which needs the anchors but not a verse.
- **A4 — Write triggers.** A place is written (i) when the reader leaves a chapter by a page turn
  or chapter skip (`pageTurn`/`skipPages`, `EpubReaderActivity.cpp:907-970`); (ii) in
  `navigateTo`, for the place being left, only when the target spine differs from the current one
  — a same-chapter jump (highlights `ReuseIfSameSpine`, `:360-362`) leaves no chapter; (iii) on
  reader exit (Home, sleep, opening another book), via a new `EpubReaderActivity::onExit`
  override. Never per page.
- **A5 — Nothing is recorded before the first page render of the session.** A `bool
  pageShown` set after the first successful `renderContents` (`EpubReaderActivity.cpp:1256-1261`)
  gates every write. Otherwise an intent-driven `navigateTo` in `onEnter` would record the
  `progress.bin` position the user never saw this session.
- **A6 — Redundant writes are skipped.** If the new place equals the list's head (same `Unit`,
  same hints) the store neither reorders nor saves.
- **A7 — `reference` is chapter-level.** `bibleReference(tocBookTitle, unit.major)`
  (`src/activities/reader/BibleReference.h:8-11`), the book title from the spine's TOC entry
  exactly as `readerMenuTitle()` does (`EpubReaderActivity.cpp:1615-1622`), capped with
  `utf8SafeSummary(…, study::PassageDoc::MAX_REFERENCE_BYTES)` (48 B,
  `lib/StudyStore/StudyStore/PassageDoc.h:44`; same call as `PassageDoc.cpp:150`). The chips show
  "Genesis 1", not "Genesis 1:5"; the verse is kept in the unit for the jump.
- **A8 — `OpenAt` carries the unit as well as the hints.** The issue writes `OpenAt(spine,
  offset)`. This design's `OpenAt` carries `{unit, spineHint, offsetHint}`: the reader resolves the
  unit through the existing `StudyStore::locateUnit` (`src/study/StudyStore.cpp:162-183`), which
  tries the hint and then searches the unit's book, so a place survives a Bible edition whose
  spine layout differs. Home (#203) has no unit index open, so it cannot resolve a place itself.
  12 extra bytes, RAM only.
- **A9 — Places are edition-independent, references are not.** A `Unit` is language-free
  (`Unit.h:9-15`); the stored `reference` is the recording edition's text and is not rewritten.
- **A10 — Jumping to a place uses `ReturnPolicy::Clear`** (the `navigateTo` default,
  `EpubReaderActivity.h:126-128,145`), like every menu jump. The Recent row itself is the way back.
- **A11 — An unresolvable place is reported, not removed.** `locateUnit` returning `nullopt` posts
  the existing `STR_LINK_TARGET_NOT_FOUND` ("Not found in this publication",
  `lib/I18n/translations/english.yaml:404`) through `PostedMessage::post` (as
  `ReaderUtils::showMessage` does, `ReaderUtils.h:233`) and leaves the list untouched — it may
  resolve in another edition. No new translation keys.
- **A12 — Intent-opened sub-screens cancel to the page, not the menu.** Menu-opened grid/search
  cancel back into the menu (`openReaderMenu(false)`, `EpubReaderActivity.cpp:737,754`). An
  intent-opened one cancels to the reading page at the restored position: `ActivityManager` already
  re-renders the popped activity (`ActivityManager.cpp:130-133`), so the intent path's cancel
  handler does nothing.
- **A13 — Intents that do not apply are ignored with a log.** `Search` needs a Bible
  (`BibleSearchActivity`); on a non-Bible book it is dropped. `BookGrid` on a non-Bible book opens
  the TOC chapter list, exactly as SELECT_CHAPTER does (`EpubReaderActivity.cpp:728-734`). `OpenAt`
  on a non-Bible book is dropped.
- **A14 — The Recent row shows at most 3 chips, excluding the chapter on screen,** only for a
  Bible, only when the store has at least one other place. Chips are equal-width like the tiles
  (`ReaderMenuSheetLayout.h:97-103`), labels clipped to fit. Touch-only, like the close control
  (`EpubReaderMenuActivity.cpp:406`): physical-button navigation keeps walking the model items
  (`navigateButtons`, `:364-369`), so `ReaderMenuModel` is unchanged.
- **A15 — The store is resident from boot**, loaded beside `RECENT_BOOKS` (`src/main.cpp:419`),
  because both the reader and #203's Home read it.
- **A16 — `SAVE_BUDGET` is derived, ≈ 2 KB,** from the field caps (below), not the issue's
  round 4 KB: it satisfies "cap 4 KB" and follows the `RecentBooksDoc` rule that a bounded store
  claims its real worst case (`src/util/RecentBooksDoc.h:59-69`).

### Data model

```cpp
// src/Place.h
struct Place {
  study::Unit unit;             // Verse kind, book 1-66, major = chapter, minor = verse
  std::string reference;        // display, <= 48 B
  uint16_t spineIndex = 0;      // hint: the edition it was recorded in
  uint32_t visibleTextOffset = 0;  // hint: the page's first visible codepoint
};
```

`/.berean/places.json`:

```json
{"v":1,"places":[{"u":"v:1:1:1:0","r":"Genesis 1","s":12,"o":0},
                 {"u":"v:66:21:3:17","r":"Revelation 21","s":1201,"o":2310}]}
```

`u` is `study::unitToCompact` / `unitFromCompact` (`Unit.h:43-47`) — reused, not a new encoding.

### `PlacesDoc` (mirrors `RecentBooksDoc`)

- `FORMAT_VERSION = 1`; `fromJson` reads `doc["v"] | 0`, so an absent version is refused
  (`lib/Serialization/FormatVersion.h:10-16`: "`doc["v"] | 0` refuses it"). There is no pre-version
  file to accept.
- `MAX_PLACES = 12`.
- `record(std::vector<Place>& places, Place place) -> bool changed`: erase any entry with the same
  `(unit.book, unit.major)`, insert at front, trim to `MAX_PLACES`. Returns false and changes
  nothing when the head already equals `place` (A6). Pure; this is what the dedupe/eviction tests
  hit. (`RecentBooksStore::addBook` keeps this logic in the untestable shell,
  `RecentBooksStore.cpp:27-51`; moving it into the Doc is the one deliberate departure.)
- `normalise(Place&)`: erase NULs and `utf8SafeSummary` the reference to 48 B, as
  `RecentBooksDoc::normalise` (`RecentBooksDoc.cpp:33-41`).
- `fromJson(doc, places, needsResave)`: refuses an unknown version before touching `places`
  (`RecentBooksDoc.cpp:54-58`); caps the count at 12; **drops** an entry whose `u` does not parse,
  is not `Verse`, or has `book` outside 1–66 or `major == 0`, setting `needsResave`; `s`/`o` read
  with `| 0`, range-clamped to their types; duplicates of an earlier (book, chapter) are dropped
  (newest wins, `needsResave`).
- `placeUnit(const study::DocumentUnits&, uint32_t pageOffset) -> std::optional<study::Unit>`: A2
  and A3 as a pure function — `nullopt` unless `units.kind == Verse && units.book != 0 &&
  !units.anchors.empty()`.
- Budget, derived like `RecentBooksDoc::worstCaseBytes` (`RecentBooksDoc.h:45-69`):

  | term | bytes |
  |---|---|
  | wrapper `{"v":1,"places":[]}` | 19 |
  | per entry `{"u":"","r":"","s":,"o":}` | 25 |
  | `u` max `v:255:65535:65535:4294967295` | 28 |
  | `r` 48 × escape factor 2 (`RecentBooksDoc.h:49-57`) | 96 |
  | `s` max `65535` | 5 |
  | `o` max `4294967295` | 10 |
  | total `19 + 11 + 12 × 164` | **1,998** |

  The test measures a worst-case document against it exactly, as `RecentBooksDocBudget` does
  (`test/recent_books_doc/RecentBooksDocTest.cpp:30-50,367-…`), so a serialiser change fails loudly.

### `PlacesStore` (mirrors `RecentBooksStore`)

`PersistableStore<PlacesStore>`, `SAVE_BUDGET = PlacesDoc::SAVE_BUDGET`, `getFilePath()` →
`sdpaths::PLACES_FILE`, `toJson`/`fromJson` delegating to the Doc with `requestResave()` on
`needsResave` (`RecentBooksStore.cpp:11-25`), `static_assert`s tying the budget to the Doc
(`:86-90`). Public API:

- `void record(Place place)` — `PlacesDoc::normalise`, `PlacesDoc::record`; on change,
  `saveToFileAtomic()`, `LOG_ERR` on failure (as `RecentBooksStore.cpp:48-50`).
- `const std::vector<Place>& places() const`.

Every rule in CLAUDE.md "Storage discipline" is met by the base class, not re-implemented: atomic
write and budget check in `saveToFileAtomic` (`PersistableStore.h:212-225`); the `loadRefused`
save-block (`:165-170`, `:236`); `.tmp` adoption on load (`:234`). Owning task: the Arduino loop
task — every caller below runs on it (`navigateTo`, `pageTurn`, `onExit`, boot). `storageMutex` is
taken by `HalStorage` under `writeDocToFileAtomic`; `storeMutex` by the base class. The web server
cannot write it: dot-paths are protected on its routes (`CrossPointWebServer.cpp:588`,
`WebRouteUtils.cpp:9-10`).

### `StudyStore` additions

`locateUnit` and `units_` are private (`src/study/StudyStore.h:158,165`). Two public methods:

- `std::optional<study::Unit> placeAt(uint16_t spineIndex, uint32_t pageOffset)`: `nullopt` unless
  `pubKey_ == study::BIBLE_PUB_KEY`, `units_ && units_->ready()`, and
  `!units_->indexFailed(spineIndex)`; else `PlacesDoc::placeUnit(units_->unitsFor(spineIndex),
  pageOffset)`. The spine being left is the one the render path last looked up
  (`EpubReaderActivity.cpp:1401` → `StudyStore.cpp:215`), so this is the one-entry cache hit
  (`UnitIndexCache.cpp:227`). If a sub-screen displaced the cache, it is one index-entry read;
  a build only happens for a document never indexed, which cannot be a document just rendered.
- `std::optional<Location> locatePlace(const study::Unit&, uint16_t spineHint)`: `nullopt` unless
  Bible; else `locateUnit(unit, spineHint)`.

## Control flow

### Recording

One private helper, `void EpubReaderActivity::recordLeftPlace()`, called on the loop task:

1. Return if `!pageShown` (A5), `!highlightsLoaded` (the study store is not open,
   `EpubReaderActivity.cpp:211-219`), or `currentSpineIndex` is out of range (end of book,
   `:972`).
2. Page offset: with a live `section`, `currentPageVisibleOffset` (set per render, `:1256`) —
   falling back to `section->getVisibleTextOffsetForPage(section->currentPage)` as `saveProgress`
   does (`:1323-1328`). Without one (a sub-screen released it, `:249-258`), `cachedVisibleTextOffset`
   when `cachedSpineIndex == currentSpineIndex`; else offset 0 (chapter start).
3. `STUDY.placeAt(spine, offset)`; `nullopt` → return (A1, A3).
4. Build the reference (A7) and `PLACES.record(place)`.

Call sites:

| Trigger | Where | Order constraint |
|---|---|---|
| Page turn / chapter skip crosses a spine | `pageTurn` (`:918-944`), `skipPages` (`:951-968`) | before `currentSpineIndex` changes and `section.reset()` |
| Explicit jump | `navigateTo` (`:1656`), when `target.spineIndex != currentSpineIndex` | before `clearDeferredReposition()` (`:1679`), which erases `cachedVisibleTextOffset` (`:1317-1320`); outside `RenderLock` (the SD write must not stall the render task any longer than today's saves do) |
| Exit | new `EpubReaderActivity::onExit()` → `recordLeftPlace()` → `ReaderActivity::onExit()` | `section`/`epub` still alive (reset in the destructor, `:133-140`). Covers Home (`Activity.cpp:13`), sleep (`main.cpp:259` → `ActivityManager.cpp:175-181`) and a stacked reader torn down under a sub-screen (`ActivityManager.cpp:145-150`, section released → step 2's cached branch) |

`recordLeftPlace` must not take `RenderLock` itself: `navigateTo`'s own lock scope starts after it,
`pageTurn` takes the lock only around the spine change, and `onExit` runs with the caller's lock
already held (`ActivityManager.cpp:175-177`). `ReaderActivity::onExit` already saves
`APP_STATE` there (`ReaderActivity.cpp:68-69`), so an SD write under that lock has precedent.

### Consuming an intent

At the end of `EpubReaderActivity::loadBook()` success is not enough — `onEnter` must have set
`APP_STATE`/recents (`ReaderActivity.cpp:58-60`). So a new protected virtual
`ReaderActivity::onBookLoaded()` hook, called in `onEnter` after `RECENT_BOOKS.addBook` and before
`requestUpdate()` (`:60-61`), default no-op; `EpubReaderActivity` overrides it to consume the
intent once (reset to `None` first):

- `OpenAt` → `STUDY.locatePlace(unit, spineHint)`; found → `navigateTo({.spineIndex, .offsetJump})`;
  not found → A11 message, stay at the `progress.bin` position.
- `BookGrid` / `Search` → the same sub-activity the menu opens, through two extracted helpers
  `openChapterPicker(CancelTo)` / `openBibleSearch(CancelTo)` with `CancelTo::Menu` from
  `onReaderMenuConfirm` (unchanged behaviour) and `CancelTo::Page` from the intent (A12).
- `Tags` → `openHighlights()` (`:342-364`), whose cancel already just returns (`:354`).

`navigateTo` from `onEnter` is safe: `onEnter` runs after `ActivityManager` releases its lock
(`ActivityManager.cpp:159-160`), and `navigateTo` takes `RenderLock` itself (`EpubReaderActivity.h:143-145`).
A sub-activity started from `onEnter` is handled on the next manager loop (`:162`).

### Recent row

- `openReaderMenu` (`EpubReaderActivity.cpp:260-290`), for a Bible, copies up to 3 places from
  `PLACES.places()` whose (book, chapter) differs from the chapter on screen (A14) into a member
  `recentShown` (≤ 3 `Place`s), and passes their references to the menu constructor.
- `ReaderMenuSheetLayout::Inputs` gains `chipCount`, `chipHeight` (= `minTouchSize`); `Layout`
  gains `chips[MAX_CHIPS = 3]`, laid out as an equal-width band between the tiles and the columns,
  same arithmetic as the tiles (`ReaderMenuSheetLayout.h:97-103`), and counted into `sheetHeight`
  (`:75-76`), so `fitsOverPage`/`fitsAlone` stay truthful.
- `EpubReaderMenuActivity` registers each chip as a hit with a new `ACTION_RECENT = ACTION_USER + 2`
  carrying the chip index (as `ACTION_CHIP`, `HighlightsActivity.cpp:41,171-172`), and finishes with
  `MenuResult{OPEN_RECENT_PLACE, …, recentIndex}`. `ReaderMenuAction::OPEN_RECENT_PLACE` is appended
  (`ReaderMenuModel.h:5-6` requires appending); `MenuResult` gains `int8_t recentIndex = -1`
  (`src/activities/ActivityResult.h:24-28`).
- `onReaderMenuConfirm(OPEN_RECENT_PLACE)` → `recentShown[recentIndex]` → `STUDY.locatePlace` →
  `navigateTo` (A10), which records the chapter being left — Genesis ↔ Revelation ping-pong
  works because each jump records its origin.

## Error handling

| Failure | Behaviour |
|---|---|
| `places.json` missing | empty list; first save creates it (`writeDocToFileAtomic` creates the parent, `PersistableStore.h:62-66`) |
| unknown `v` (e.g. 2) or absent `v` | `fromJson` refuses; `loadRefused` blocks every save (`PersistableStore.h:165-170`); list stays empty in RAM; Recent row empty; file untouched |
| parse error / unreadable | base-class behaviour (`FormatVersion.h:28-31`): keeps the previous refusal state |
| over budget on save | `saveToFileAtomic` refuses with `LOG_ERR` (`PersistableStore.h:218-222`); unreachable by construction (the budget is the worst case) |
| save fails | `LOG_ERR`, in-memory list keeps the place (`RecentBooksStore.cpp:48-50` precedent). No on-screen report: a lost place is not user data loss, and page turns must not pop messages |
| bad entry on the card | dropped on load, `requestResave` |
| unit index not ready / document not Verse | no record (A1, A3) |
| place does not resolve | A11 message, list unchanged |
| intent not applicable | A13, `LOG_INF`, normal open |
| OOM | the vector is `reserve(12)`d once at load (`RecentBooksDoc.cpp:63` pattern); no per-record allocation beyond the reference string |

## Memory

- Resident: `std::vector<Place>` reserved to 12. `sizeof(Place)` ≈ 12 (`Unit`) + 24 (32-bit
  libstdc++ `std::string`) + 2 + 4 + padding ≈ 44 B → ~530 B, plus heap for references over the
  15-byte SSO (e.g. "1 Corinthians 13") — about 1 KB worst case. Internal SRAM: each allocation is
  far under the 4,096-byte PSRAM auto-routing threshold (project memory
  "ESP32-S3 PSRAM auto-routing threshold"). No PSRAM, per the issue.
- Transient per save: one `JsonDocument` of ~2 KB inside `saveToFileAtomic`, freed on return —
  the same cost every store pays.
- Reader: `recentShown` ≤ 3 `Place`s (~130 B + strings) while the menu is open; the intent is
  ~24 B for the reader's lifetime.
