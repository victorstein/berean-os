## Problem

A returning reader cannot get back to where they were a few jumps ago. The only record of past
positions is `ReturnStack`, a 16-slot RAM ring that covers citation jumps only
(`src/activities/reader/ReturnStack.h:13-19`; pushed only by `ReturnPolicy::Push`,
`EpubReaderActivity.cpp:1670-1675`) and dies with the activity. `progress.bin` holds one position
per book (`EpubReaderActivity.cpp:1322-1330`). `RecentBooksStore` records books, not places
(`src/util/RecentBooksDoc.h:25`). And `goToReader(path, allowFast)`
(`src/activities/ActivityManager.h:85`) has no way to say "open the Bible *at* X" or "open the
Bible's grid / search / tags", which Home (#203) needs.

## Goal

1. A persisted list of the last 12 Bible places, newest first, one per (book, chapter).
2. A one-shot, RAM-only entry intent on `goToReader`: open at a place, or open straight into the
   book grid, verse search or the tags list.
3. A `RECENT` chip row in the reader menu sheet (#200/#217), as drawn in the mockup; tapping a chip
   jumps there.

## Non-goals

- **Home UI.** Continue, Recent rows, Go to and the icon row are #203, which consumes this store
  (its `r` is the mockup's "Continue · Isaiah 40:31" / "Revelation 21:4" text) and these intents.
  #201 adds no launcher UI.
- **Non-Bible places** (A1).
- **Changing `ReturnStack`** or the Return swipe.
- **Progress UI of any kind** (overhaul rule).
- **Cross-language display.** A place's `r` stays in the language it was recorded in (A9).

## Assumptions (each is a decision the review should attack)

- **A1 — Bible only.** A place is captured only while the open publication's pubkey is
  `study::BIBLE_PUB_KEY` (`lib/StudyStore/StudyStore/PubKey.h:37`, the same gate
  `StudyStore::spineIndicesForBook` uses, `src/study/StudyStore.cpp:83-86`), and only for a
  document whose units are `Verse` kind. Only a `Verse` unit carries `book`/`major`
  (`lib/StudyStore/StudyStore/Unit.h:27-29`), so (book, chapter) dedupe is only defined there.
- **A2 — The verse is the unit at the top of the page.** `study::resolve(units, pageOffset)`
  (`UnitAnchors.h:58-61`, body `UnitAnchors.cpp:88-99`) of the page's first visible-text offset. A
  page that starts before the chapter's first verse anchor (resolve falls back to `DocumentOffset`,
  `UnitAnchors.cpp:94`) is the issue's "chapter only" case: the unit is the first anchor at
  `offset = 0`, so `documentOffsetOf` still resolves the jump (`UnitAnchors.cpp:113-120`), and the
  place is flagged chapter-only for display (A7).
- **A3 — No units, no place.** If the unit index is not ready or the document's anchors are not in
  the index (`UnitIndexCache::ready()`, `src/study/UnitIndexCache.h:62`; entry not `indexed()`),
  there is no book number (`book` is stamped from the index's book map, `UnitIndexCache.cpp:186`,
  and loaded back from the entry, `:150`), so nothing is captured; a `LOG_DBG` says so. `ready()`
  is false only when `begin()` failed (`StudyStore.cpp:66-68`).
- **A4 — Capture triggers.** (i) A page turn or chapter skip leaves the spine: `pageTurn` forward to
  the next spine (`EpubReaderActivity.cpp:919`), forward off the last page of the book (`:925-929`),
  back to the previous spine (`:936-944`); `skipPages` both directions (`:951-956`, `:961-966`).
  (ii) `navigateTo` for the place being left, only when `target.spineIndex != currentSpineIndex` — a
  same-chapter jump (highlights `ReuseIfSameSpine`, `:360-362`) leaves no chapter. (iii) Reader exit
  (Home, sleep, another book), via a new `EpubReaderActivity::onExit` override. Never per page.
- **A5 — Nothing is captured before the first page render of the session.** A `bool pageShown`,
  set on the render task after the first successful `renderContents` (`:1256-1261`, which runs under
  the render lock) and read only inside `RenderLock` scopes (A19). Otherwise an intent-driven
  `navigateTo` from `onEnter` would record the `progress.bin` position the user never saw.
- **A6 — Redundant writes are skipped.** If the new place equals the list's head (same `Unit`,
  same hints, same `r`) the store neither reorders nor saves.
- **A7 — `r` is the full, verse-level reference, as the mockup draws it.** Home's rows read
  "Revelation 21:4", "Genesis 1", "Psalm 83:18", and the plate "Continue · Isaiah 40:31" (mockup
  `homeProposed`). `r = "<book> <chapter>:<verse>"` — `"%s %u:%u"` as `BibleSearchActivity.cpp:599`
  — or `bibleReference(book, chapter)` ("Genesis 1", `BibleReference.h:8-11`) for a chapter-only
  place (A2). `<book>` is the spine's TOC book title, exactly as `readerMenuTitle()` gets it
  (`EpubReaderActivity.cpp:1615-1622`). Capped with `utf8SafeSummary(…,
  study::PassageDoc::MAX_REFERENCE_BYTES)` (48 B, `PassageDoc.h:44`; as `PassageDoc.cpp:150`).
  Chapter-only is persisted as its own boolean `c` so the chip label (A17) can drop the verse too.
- **A8 — `OpenAt` carries the unit as well as the hints.** The issue writes `OpenAt(spine, offset)`.
  This design's `OpenAt` carries `{unit, spineHint, offsetHint}` so the reader resolves through the
  existing `StudyStore::locateUnit` (`src/study/StudyStore.cpp:162-183`): the hint first, then the
  unit's own book. Home has no unit index open, so it cannot resolve a place itself; the mockup
  promises places "survive re-downloading the Bible or switching language" ("The one new file").
  12 extra bytes, RAM only.
- **A9 — Places are edition-independent, references are not.** A `Unit` is language-free
  (`Unit.h:9-15`); `r` is the recording edition's text and is not rewritten.
- **A10 — Jumping to a place uses `ReturnPolicy::Clear`** (the `navigateTo` default,
  `EpubReaderActivity.h:126-128,145`), like every menu jump. The Recent row itself is the way back.
- **A11 — An unresolvable place is reported, not removed.** `locatePlace` returning `nullopt` posts
  the existing `STR_LINK_TARGET_NOT_FOUND` ("Not found in this publication", `english.yaml:404`)
  through `PostedMessage::post` (as `ReaderUtils::showMessage`, `ReaderUtils.h:233`) and leaves the
  list untouched.
- **A12 — Intent-opened sub-screens cancel to the page, not the menu.** Menu-opened grid/search
  cancel back into the menu (`openReaderMenu(false)`, `EpubReaderActivity.cpp:737,754`). An
  intent-opened one cancels to the reading page at the restored position: `ActivityManager`
  re-renders the popped activity (`ActivityManager.cpp:130-133`), so the cancel handler does nothing.
- **A13 — Intents that do not apply are ignored with a log.** `Search` on a non-Bible book is
  dropped; `BookGrid` on a non-Bible book opens the TOC list, exactly as SELECT_CHAPTER does
  (`EpubReaderActivity.cpp:728-734`); `OpenAt` on a non-Bible book is dropped.
- **A14 — The Recent row, as the mockup draws it.** A bold `RECENT` caption at the left of the
  band, then pill chips sized to their label, one line, newest first, from the store's places whose
  (book, chapter) differs from the chapter on screen. As many as fit the line, at most
  `MAX_RECENT_CHIPS = 3` (the mockup shows three); a chip that does not fit is dropped, never
  clipped. Shown only for a Bible with at least one such place. Touch-only, like the close control
  (`EpubReaderMenuActivity.cpp:406`): physical-button navigation keeps walking the model items
  (`navigateButtons`, `:364-369`), so `ReaderMenuModel::build` is unchanged. Band height is
  `minTouchSize`, as the tiles' floor (`ReaderMenuSheetLayout.h:58-61`).
- **A15 — The store is resident from boot**, loaded beside `RECENT_BOOKS` (`src/main.cpp:419`) —
  both the reader and #203's Home read it — and **self-loads** if that hand-off line is missing:
  `record()` and `places()` run `load()` first when no load has been attempted (review finding 6;
  `main.cpp:420-422` documents the same hazard for `WIFI_STORE`).
- **A16 — `SAVE_BUDGET` is derived** from the field caps (table below), not the issue's round 4 KB:
  it satisfies "cap 4 KB" and follows `RecentBooksDoc` (`src/util/RecentBooksDoc.h:59-69`).
- **A17 — Chip labels use the publication's own book abbreviations.** The mockup's chips read
  "Rev 21:4", "Gen 1", "Ps 83:18". The project already decided abbreviations come from
  `biblebooknav.xhtml`'s link text, not truncation or a table (`BibleNavScanner.h:34`,
  `BibleBookNameTable.h:19-21`). `openReaderMenu` loads a `BibleBookNameTable` transiently, through a new
  `SpineHtmlStream::WhenMissing` parameter on `load` set to **`Fail`** — an inflate would borrow the
  framebuffer (`SpineHtmlStream.cpp:34-40`, `GfxRenderer.h:342-348`) and return it blank just before
  the menu snapshots the page (`EpubReaderMenuActivity.cpp:199-201`), so a stream from
  `openReaderMenu` must never borrow it. Otherwise it is the
  same per-open load `BibleSearchActivity` does (`BibleSearchActivity.cpp:189`) — only when there is
  at least one chip to show, builds the labels into fixed buffers, and frees the table before the
  menu is constructed. It needs one new accessor, `abbreviationFor(uint8_t book)`, beside `forBook`
  (`BibleBookNameTable.h:44`). Cost: one stream of the book-nav page (≤ ~14 KB,
  `SpineHtmlStream.h:21-24`), already cached on SD once the grid or search has opened it; ~4.2 KB
  table (`66 × (48 + 16)`, `BibleBookNameTable.h:26,30,49-50`), which routes to PSRAM (> 4,096 B)
  and lives only for the call. If the load fails — including a book-nav page not in the HTML cache
  (`Section.cpp:477-478`; wiped by Delete cache) — the chip shows `r` instead, never a blank chip.
  **Departure:** the issue's "No PSRAM use" is read as the store's resident cost; the only PSRAM
  this adds is this transient table at menu open, for the mockup's abbreviated chips. The PR body
  says so.
- **A18 — One new translation key, `STR_RECENT` ("Recent"),** drawn upper-case as the mockup's
  caption. Hand-off lines for `english.yaml` and `spanish.yaml`; the other YAMLs fall back to
  English (CLAUDE.md "Generated files").
- **A19 — Capture under the render lock, persist after it.** The unit cache is also used by the
  render task under `RenderLock` (`EpubReaderActivity.cpp:1401` → `StudyStore.cpp:215` →
  `UnitIndexCache.cpp:225-247`), so every capture runs inside a `RenderLock` scope the caller
  already opens, and `placeAt` never builds (`buildDocument` streams through
  `SpineHtmlStream::stream` with `WhenMissing::Inflate`, which takes the render lock —
  `SpineHtmlStream.h:28-34` — a deadlock for a caller holding it). The captured `Place` is handed to
  `PLACES.record` only once the lock is released, so no SD write is added under the lock except on
  exit, where `ReaderActivity::onExit` already saves `APP_STATE` under it
  (`ReaderActivity.cpp:68-69`; the caller holds the lock, `ActivityManager.cpp:175-177`).
- **A20 — Intent device checks belong to #203; the routing is host-tested here.** #201 ships no
  launcher entry point that sets an intent. The dispatch rules (A13) are a pure
  `ReaderEntryIntent::route(Kind, bool isBible) -> Route {None, Locate, ChapterGrid, TocList, Search,
  Highlights}` in `ReaderEntryIntent.h`, host-tested in `test/ui_layout`. #203's acceptance
  ("Continue, Go to, Recent … each land on the right screen") exercises them on device; the PR body
  says so.
- **A21 — A chip resolves its hint under the lock first.** The chip handler runs in the menu's
  result handler, off-lock, with the reader current (`ActivityManager.cpp:115-127`). It first takes
  `RenderLock` and calls `STUDY.locatePlaceAtHint(unit, spineHint)` — `documentOffsetOf(peekUnits(hint),
  unit)`, which cannot build. Only on a miss (a stale edition) does it call the unlocked, possibly
  building `locatePlace`, which is safe because no render is requested before the handler returns
  (`requestUpdate()` notifies only at the end of `ActivityManager::loop`, `:167-172`) — the same
  off-lock condition `STUDY.repairTexts()` relies on in `loadBook` (`EpubReaderActivity.cpp:220-224`).
  The intent consumer calls `locatePlace` directly under that same condition.

### Data model

```cpp
// src/Place.h
struct Place {
  study::Unit unit;                // Verse kind, book 1-66, major = chapter, minor = verse
  std::string reference;           // display, <= 48 B: "Revelation 21:4" or "Genesis 1"
  bool chapterOnly = false;        // A2: the page began before the first verse
  uint16_t spineIndex = 0;         // hint: the edition it was recorded in
  uint32_t visibleTextOffset = 0;  // hint: the page's first visible codepoint
};
```

`/.berean/places.json`:

```json
{"v":1,"places":[{"u":"v:1:1:1:0","r":"Genesis 1","c":true,"s":12,"o":0},
                 {"u":"v:66:21:4:17","r":"Revelation 21:4","c":false,"s":1201,"o":2310}]}
```

`u` is `study::unitToCompact` / `unitFromCompact` (`Unit.h:43-47`) — reused, not a new encoding.

### `PlacesDoc` (mirrors `RecentBooksDoc`)

- `FORMAT_VERSION = 1`; `fromJson` reads `doc["v"] | 0`, so an absent version is refused
  (`FormatVersion.h:10-16`). There is no pre-version file to accept.
- `MAX_PLACES = 12`.
- `record(std::vector<Place>&, Place) -> bool changed`: erase any entry with the same
  `(unit.book, unit.major)`, insert at front, trim to 12; false and no change when the head already
  equals the place (A6). Pure. (`RecentBooksStore::addBook` keeps this in the shell,
  `RecentBooksStore.cpp:27-51`; moving it into the Doc for testability is the one deliberate
  departure.)
- `normalise(Place&)`: erase NULs and cap `reference` at 48 B with `utf8SafeSummary`, as
  `RecentBooksDoc::normalise` (`RecentBooksDoc.cpp:33-41`).
- `fromJson(doc, places, needsResave)`: refuses an unknown version before touching `places`
  (`RecentBooksDoc.cpp:54-58`); caps the count at 12; drops (with `needsResave`) an entry whose `u`
  does not parse, is not `Verse`, has `book` outside 1–66 or `major == 0`, or repeats an earlier
  (book, chapter); `s`/`o` read with `| 0` and clamped to their types; `c` with `| false`.
- `placeUnit(const study::DocumentUnits&, uint32_t pageOffset) -> std::optional<PlaceUnit>`
  (`{Unit unit; bool chapterOnly;}`): A2/A3 as a pure function — `nullopt` unless
  `units.kind == Verse && units.book != 0 && !units.anchors.empty()`.
- `formatReference(std::string_view book, const Place&)` and
  `formatChipLabel(std::string_view abbreviation, const Place&)`: A7/A17 as pure functions, into a
  caller buffer, capped at 48 B.
- Budget, derived like `RecentBooksDoc::worstCaseBytes` (`RecentBooksDoc.h:45-69`):

  | term | bytes |
  |---|---|
  | wrapper `{"v":1,"places":[]}` | 19 |
  | per entry `{"u":"","r":"","c":,"s":,"o":}` | 30 |
  | `u` max `v:255:65535:65535:4294967295` | 28 |
  | `r` 48 × escape factor 2 (`RecentBooksDoc.h:49-57`) | 96 |
  | `c` max `false` | 5 |
  | `s` max `65535` | 5 |
  | `o` max `4294967295` | 10 |
  | total `19 + 11 + 12 × 174` | **2,118** |

  The longest realistic verse reference is ~25 B in Latin script ("1 Corinthians 13:13" is 19 B;
  "El Cantar de los Cantares 8:14" is 30 B), inside the 48 B cap; a 42 B Cyrillic book name plus
  ":150:176" is cut on a codepoint boundary, which the display can afford. The test measures a
  worst-case document against the budget exactly, as `RecentBooksDocBudget` does
  (`RecentBooksDocTest.cpp:30-50,367-…`).

### `PlacesStore` (mirrors `RecentBooksStore`)

`PersistableStore<PlacesStore>`, `SAVE_BUDGET = PlacesDoc::SAVE_BUDGET`, `getFilePath()` →
`sdpaths::PLACES_FILE`, `toJson`/`fromJson` delegating to the Doc with `requestResave()` on
`needsResave` (`RecentBooksStore.cpp:11-25`), `static_assert`s tying the budget to the Doc
(`:86-90`). Public API:

- `bool load()` — sets `loadAttempted`, then `loadFromFile()`.
- `void record(Place place)` — `load()` first if `!loadAttempted` (A15); **returns immediately while
  `loadRefused`** (`PersistableStore.h:52`, protected, visible to the derived store), logging
  `LOG_ERR` once per session; else `PlacesDoc::normalise`, `PlacesDoc::record`, and on change
  `saveToFileAtomic()`. Success logs one `LOG_DBG("PLC", "saved: <r1> | <r2> | …")` line; failure
  `LOG_ERR` (as `RecentBooksStore.cpp:48-50`).
- `const std::vector<Place>& places()` — `load()` first if `!loadAttempted`.

Every rule in CLAUDE.md "Storage discipline" is met by the base class, not re-implemented: atomic
write and budget check (`PersistableStore.h:212-225`); the `loadRefused` save-block (`:165-170`,
`:236`), now also a record-block; `.tmp` adoption on load (`:234`). Owning task: the Arduino loop
task — every caller runs on it (`pageTurn`, `skipPages`, `navigateTo`, `onExit`, boot). `storageMutex`
is taken by `HalStorage` under `writeDocToFileAtomic`; `storeMutex` by the base class. The web
server cannot write it: dot-paths are protected on its routes (`CrossPointWebServer.cpp:588`,
`WebRouteUtils.cpp:9-10`).

### Unit-index additions

- `const study::DocumentUnits& UnitIndexCache::peekUnits(uint16_t spineIndex)`: the cache hit
  (`UnitIndexCache.cpp:227`), else `readEntry` + `loadAnchors` into the one-entry cache when the
  entry is `indexed()` (`:230-238`), else a static empty `DocumentUnits` — **never**
  `buildDocument` (`:240`) and never `bookFor`. `loadAnchors` takes the book from the entry
  (`:150`) and only reads SD. Caller holds `RenderLock`, like the render task's `unitsFor`.
- `StudyStore::placeAt(uint16_t spine, uint32_t pageOffset) -> std::optional<PlaceUnit>`: `nullopt`
  unless `pubKey_ == study::BIBLE_PUB_KEY` and `units_ && units_->ready()`; else
  `PlacesDoc::placeUnit(units_->peekUnits(spine), pageOffset)`. Caller holds `RenderLock`.
- `StudyStore::locatePlace(const study::Unit&, uint16_t spineHint) -> std::optional<Location>`:
  `nullopt` unless Bible; else the private `locateUnit` (`StudyStore.h:158`). It may build, so it is
  called only from loop-task code that holds no lock and before any render is requested (A21).
- `StudyStore::locatePlaceAtHint(const study::Unit&, uint16_t spineHint) -> std::optional<Location>`:
  `nullopt` unless Bible and ready; else `documentOffsetOf(units_->peekUnits(spineHint), unit)`.
  Caller holds `RenderLock`; never builds.

## Control flow

### Capturing and recording a place

`std::optional<Place> EpubReaderActivity::captureLeftPlace()` — **caller holds `RenderLock`** (A19):

1. `nullopt` if `!pageShown` (A5), `!highlightsLoaded` (study store not open,
   `EpubReaderActivity.cpp:211-219`), or `currentSpineIndex` outside `[0, spineCount)`.
2. Page offset: with a live `section`, `currentPageVisibleOffset` (`:1256`), else
   `section->getVisibleTextOffsetForPage(section->currentPage)` as `saveProgress` does
   (`:1323-1328`). Without a section (a sub-screen released it, `:249-258`),
   `cachedVisibleTextOffset` when `cachedSpineIndex == currentSpineIndex`, else 0.
3. `STUDY.placeAt(spine, offset)`; `nullopt` → `nullopt` (A1, A3).
4. Build `reference` with `PlacesDoc::formatReference` from the TOC book title (A7).

Call sites — each captures **before** the state change, inside the lock the site already takes,
and calls `PLACES.record(*place)` after that lock's scope ends:

| Trigger | Where the capture goes | Record |
|---|---|---|
| forward turn to next spine | `pageTurn`, inside the lock at `:919`, before `currentSpineIndex++` | after the scope |
| forward off the last page | `pageTurn`, inside the lock at `:926`, before `currentSpineIndex = getSpineItemsCount()` (`:927`) | after the scope |
| back turn to previous spine | `pageTurn`, inside the lock at `:937`, before `currentSpineIndex--` | after the scope |
| chapter skip | `skipPages`, inside the locks at `:952` and `:962` | after the scope |
| explicit jump | `navigateTo`, inside the lock at `:1665`, when `target.spineIndex != currentSpineIndex`, before `clearDeferredReposition()` (`:1681`), which erases `cachedVisibleTextOffset` (`:1317-1320`) | after the scope, before `requestUpdate()` (`:1701`, after the lock scope closes at `:1700`) |
| exit | new `EpubReaderActivity::onExit()`: the caller already holds the lock (`ActivityManager.cpp:175-177`, and `:141-150` for a reader stacked under a sub-screen), so capture and record directly, then `ReaderActivity::onExit()` | directly (A19) |

The exit site covers Home (`Activity.cpp:13`), sleep (`main.cpp:259` → `ActivityManager.cpp:175-181`)
and opening another book (`ReaderActivity.cpp:97`). `section`/`epub` are still alive there (reset in
the destructor, `EpubReaderActivity.cpp:133-140`).

### Consuming an intent

A new protected virtual `ReaderActivity::onBookLoaded()`, called in `onEnter` after
`RECENT_BOOKS.addBook` and before `requestUpdate()` (`ReaderActivity.cpp:60-61`), default no-op.
`EpubReaderActivity` overrides it to consume the intent once (reset to `None` first):

- `OpenAt` → `STUDY.locatePlace(unit, spineHint)`; found → `navigateTo({.spineIndex, .offsetJump})`
  (no capture: `pageShown` is false, A5); not found → A11 message, stay at the `progress.bin`
  position.
- `BookGrid` / `Search` → the sub-activity the menu opens, through two helpers extracted from
  `onReaderMenuConfirm`: `openChapterPicker(CancelTo)` / `openBibleSearch(CancelTo)`, with
  `CancelTo::Menu` from the menu (today's behaviour, `:737`, `:754`) and `CancelTo::Page` from the
  intent (A12).
- `Tags` → `openHighlights()` (`:342-364`), whose cancel already just returns (`:354`).

`onEnter` runs after `ActivityManager` releases its lock (`ActivityManager.cpp:159-160`) and
`navigateTo` takes `RenderLock` itself (`EpubReaderActivity.h:143-145`); a sub-activity started from
`onEnter` is handled on the next manager loop (`ActivityManager.cpp:162`).

### Recent row

- `openReaderMenu` (`EpubReaderActivity.cpp:260-290`), for a Bible, in the lock it already takes for
  `tagsHereCount` (`:272-275`), captures the chapter on screen (`captureLeftPlace`, ignoring
  `pageShown`'s record semantics — only book and chapter are compared). Outside the lock it picks up
  to `MAX_RECENT_CHIPS` places from `PLACES.places()` with a different (book, chapter) into a member
  `recentShown`, and — if any — loads a transient `BibleBookNameTable` (A17), formats each chip label
  with `PlacesDoc::formatChipLabel` into `char[MAX_RECENT_CHIPS][PassageDoc::MAX_REFERENCE_BYTES + 1]`,
  and frees the table. The labels go to the menu constructor.
- `ReaderMenuSheetLayout`: `Inputs` gains `recentCount` and `recentHeight` (= `minTouchSize`);
  `Layout` gains a `recent` band box, placed between the tiles and the columns and counted into
  `sheetHeight` (`:75-76`), so `fitsOverPage`/`fitsAlone` stay truthful. A pure
  `fitChips(captionWidth, const int* chipWidths, int count, int bandWidth, int gap) -> int` returns
  how many chips fit one line after the caption; the activity measures text widths and passes them.
  The pass-0 review measured the worst Bible sheet with a 52 px band still over the page
  (451 + 52 = 503, and (800 − 503) × 3 ≥ 800).
- `EpubReaderMenuActivity` draws the `tr(STR_RECENT)` caption bold and upper-case, then each fitting
  chip as a rounded outline (`drawRoundedRect`, as `drawTile`, `EpubReaderMenuActivity.cpp:375`),
  registering each with `ACTION_RECENT = ACTION_USER + 2` carrying the chip index (as `ACTION_CHIP`,
  `HighlightsActivity.cpp:41,171-172`). A tap finishes with
  `MenuResult{OPEN_RECENT_PLACE, …, recentIndex}`.
- `ReaderMenuAction::OPEN_RECENT_PLACE` is appended (`ReaderMenuModel.h:5-6`); `labelFor`
  (`EpubReaderMenuActivity.cpp:35-73`, a switch with no `default`) gains a case returning
  `StrId::STR_RECENT`, so `-Wswitch` stays quiet. `MenuResult` gains `int8_t recentIndex = -1`
  (`ActivityResult.h:24-28`). `onReaderMenuConfirm` changes from `(MenuAction)` to
  `(const MenuResult&)` (`EpubReaderActivity.h:113`, call at `:287`, which today casts `menu.action`).
- `onReaderMenuConfirm(OPEN_RECENT_PLACE)` → `recentShown[recentIndex]` → A21 (hint under the lock, then `STUDY.locatePlace`) →
  `navigateTo` (A10), which captures the chapter being left — Genesis ↔ Revelation works because
  each jump records its origin.

## Error handling

| Failure | Behaviour |
|---|---|
| `places.json` missing | empty list; first save creates it (`writeDocToFileAtomic` creates the parent, `PersistableStore.h:62-66`) |
| unknown `v` (e.g. 2) or absent `v` | `fromJson` refuses; `loadRefused`; `record()` is a no-op (one `LOG_ERR`); list stays empty in RAM; Recent row empty; file untouched |
| parse error / unreadable | base-class behaviour (`FormatVersion.h:28-31`) |
| `main.cpp` load line missing | first `record()`/`places()` loads (A15), so the guard above still applies |
| over budget on save | `saveToFileAtomic` refuses with `LOG_ERR` (`PersistableStore.h:218-222`); unreachable by construction |
| save fails | `LOG_ERR`, in-memory list keeps the place (`RecentBooksStore.cpp:48-50`). No on-screen report: a lost place is not user data, and chapter turns must not pop messages |
| bad entry on the card | dropped on load, `requestResave` |
| document not in the unit index / not Verse | no capture (A1, A3) — never a build under the lock (A19) |
| place does not resolve | A11 message, list unchanged |
| abbreviation table fails to load | chips show `r` (A17) |
| intent not applicable | A13, `LOG_INF`, normal open |
| OOM | vector `reserve(12)` once at load (`RecentBooksDoc.cpp:63` pattern); the table is `makeUniqueNoThrow`, null → A17 fallback |

## Memory

- Resident: `std::vector<Place>` reserved to 12. `sizeof(Place)` ≈ 12 (`Unit`) + 24 (32-bit
  libstdc++ `std::string`) + 1 + 2 + 4 + padding ≈ 48 B → ~580 B, plus heap for references past
  the 15-byte SSO ("Revelation 21:4" is exactly 15; "1 Corinthians 13:13" spills) — ~1–1.3 KB worst
  case, internal SRAM (each allocation far under the 4,096-byte PSRAM auto-routing threshold). No
  PSRAM, per the issue.
- Transient per save: one `JsonDocument` of ~2 KB inside `saveToFileAtomic`.
- Menu open with chips: a ~4.2 KB `BibleBookNameTable` (PSRAM by size — the labelled departure from
  "No PSRAM use", A17) for the duration of
  `openReaderMenu` only, plus `recentShown` (≤ 3 `Place`s) and 3 × 49 B labels while the menu is up.
- Reader: the intent, ~24 B.
