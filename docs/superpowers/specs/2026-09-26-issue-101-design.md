# Format versions for the four inherited stores

Design for issue #101, on `fix/101-inherited-store-format-version`. Built on
`docs/superpowers/research/2026-09-26-issue-101-research.md`. Modelled on
`src/util/BookmarkDoc.{h,cpp}` (PR #47, `d043fd84`), which retrofitted a version onto a
file that had none.

## Problem

Storage rule 4 (`CLAUDE.md`, "Storage discipline") requires a format version that a future
build refuses rather than reinterprets. Four stores inherited from CrossPoint write none:

| Store | File | `toJson` / `fromJson` |
|---|---|---|
| `CrossPointSettings` | `/.crosspoint/settings.json` (`src/CrossPointSettings.h:431`) | `src/CrossPointSettings.cpp:63-105` / `:107-236` |
| `CrossPointState` | `/.crosspoint/state.json` (`src/CrossPointState.h:36`) | `src/CrossPointState.cpp:43-57` / `:59-96` |
| `WifiCredentialStore` | `/.crosspoint/wifi.json` (`src/WifiCredentialStore.h:47`) | `src/WifiCredentialStore.cpp:11-26` / `:28-112` |
| `RecentBooksStore` | `/.crosspoint/recent.json` (`src/RecentBooksStore.h:27`) | `src/util/RecentBooksDoc.cpp:42-51` / `:53-74` |

Each `fromJson` returns `true` unconditionally (`CrossPointSettings.cpp:235`,
`CrossPointState.cpp:95`, `WifiCredentialStore.cpp:111`, `RecentBooksDoc.cpp:73`). An OTA
rollback, or a partition switch after a failed boot, puts an older build in front of a file
a newer build wrote, and today the older build reads it as if it were its own format.

Refusing at load time is only half the job. `PersistableStore<T>::saveToFileAtomic()`
(`lib/Serialization/PersistableStore.h:165-177`) writes from memory with no knowledge of what
the last load saw, and the stores are saved from about thirty call sites. `enterDeepSleep`
saves `APP_STATE` on every sleep (`src/main.cpp:263`). A load-only refusal would replace a
newer `state.json` with defaults the first time the device sleeps.

## Goal

1. Each of the four files carries `"v": 1`.
2. A file with no `"v"` loads exactly as it does today, so every card in the field keeps
   working.
3. A file whose `"v"` this build does not know is refused. The store keeps its defaults
   (the in-memory values it had before the load), and **this build does not overwrite that
   file** for as long as the refusal stands.
4. `docs/file-formats.md` documents all four files.

## Non-goals

- **Parse errors and unreadable files.** Today a `ParseError`/`Unreadable` read leaves the
  store at defaults and a later save overwrites the file (`PersistableStore.h:186-188`, then
  any save site). That is the existing behaviour for corrupt files. It is not what #101 asks
  about, and changing it would change every corrupt-card recovery path. Out of scope.
- **Migrating the file shapes.** Every key stays as it is. `"v"` is added and nothing else
  changes.
- **Surfacing the refusal on screen at boot.** A refused save already reaches the user
  wherever a save the user asked for can fail (see Error handling). No new boot-time message.
- **The other `PersistableStore` users.** `grep -rn 'public PersistableStore<' src lib` finds only
  these four. Any later store opts in through the same `fromJson` contract.

## Assumptions (each is a behavioural decision the review should attack)

**A1 — version semantics are BookmarkDoc's.** `const int version = doc["v"] | FORMAT_VERSION;`
and refuse when `version <= 0 || version > FORMAT_VERSION` (`BookmarkDoc.cpp:28-32`). An absent
`"v"` reads as 1. A written `0` or a negative is refused, because no build ever wrote it. A
non-integer `"v"` (say `"2"`) is unconvertible, so it reads as 1 (`operator|` semantics, pinned
by `test/bookmark_doc/BookmarkDocTest.cpp:81-115`). That is accepted: no build writes a string
there. The born-versioned stores' `doc["v"] | 0` (`TagPalette.cpp:78`,
`ChapterCompletion.cpp:111`) is deliberately **not** used, because it would refuse every card
in the field.

**A2 — the version check is the first statement of each `fromJson`**, before any member is
assigned. `loadFromFile` only returns `false` after `fromJson` returns `false`
(`PersistableStore.h:189,198`), so the members keep their pre-load values. For the boot loads
(`src/main.cpp:411-413`) those values are the struct-initialiser defaults. For the mid-session
reloads (`LauncherActivity.cpp:97`, `PublicationsActivity.cpp:45`,
`WifiSelectionActivity.cpp:106`) they are whatever was in memory. On a rolled-back build
that is the defaults as well, because the boot load was refused first. `WifiCredentialStore`
takes `credentialMutex` at `:29`; the check goes after the lock and before `:30`, so the lock
discipline is unchanged.

**A3 — a refused load blocks this store's saves until a later load is accepted.**
`PersistableStore<T>` gains a private `bool loadRefused = false;` next to `resaveRequested`
(`PersistableStore.h:44-46`), guarded by the same `storeMutex`:

- `loadFromFile()` sets it `true` when the read is `Ok` and `fromJson` returns `false`.
- It sets it `false` when the read is `Ok` and `fromJson` returns `true`, or when the read is
  `Missing`, because there is then no file left to protect.
- On `Unreadable`/`ParseError` it is left alone (non-goal above).
- `saveToFileAtomic()` checks it under the lock, before `toJson`. If it is set, it logs
  `LOG_ERR("PERSIST", "Refusing to save %s: its format is newer than this build", ...)` and
  returns `false`.

`saveToFile()` (`:148-153`) has no store callers (`:146-147`). It gets the same check so that
nothing can bypass the guard.

This is new behaviour in `lib/Serialization` that reaches every CRTP store, so it is raised
as a decision (see Open decision). There is precedent for the *rule* but not for its
*placement*. `EpubReaderActivity.cpp:1770-1775` keeps `bookmarksSaveDisabled` after a `Failed`
bookmark load, `PubKeyRegistry.cpp:28-32` refuses to rewrite a newer registry, and
`docs/file-formats.md:363-364` says completion "refuses the file and records nothing for the
session rather than overwriting it". Every existing guard lives beside a single load/save
pair. Here there are about thirty save sites across four singletons (research §2), and a
per-caller flag would have to be repeated at every one of them.

**A4 — a flag that lasts until reboot is intended, not a trap.** On a rolled-back device the
user cannot change settings, save a WiFi password or add a recent book until they reinstall a
build that knows the format. That is what "refuse" means. The alternative, silently writing
defaults over the newer build's settings and saved passwords, is the loss the rule exists to
prevent. OTA still works: it needs a WiFi connection, not a saved credential.

**A5 — a legacy (absent-`"v"`) file is not rewritten just to stamp it.** `fromJson` does not
call `requestResave()` for a missing version. The file gains `"v":1` on its next ordinary save.
Settings, state and recents are saved during normal use (research §2 call sites), and WiFi on
the next connect (`setLastConnectedSsid`, `WifiCredentialStore.cpp:234-240`, called from `WifiSelectionActivity.cpp:576`). Reasons: `CLAUDE.md` asks for redundant
writes to be guarded, and an absent `"v"` already reads as version 1, so stamping it earlier
changes nothing a reader could observe.

**A6 — one shared, host-testable predicate.** `lib/Serialization/FormatVersion.h`, in
`namespace persist`:

```cpp
constexpr bool isKnownFormatVersion(const int version, const int newestKnown) {
  return version > 0 && version <= newestKnown;
}
```

It is shaped like `persist::fitsBudget` (`SaveBudget.h:26`) and `classifyDocRead`
(`DocReadStatus.h:17-22`): `constexpr`, Arduino-free and ints only. Keeping ArduinoJson out of
the header also keeps the `operator|` read in each store's `.cpp`, which matches
`BookmarkDoc.cpp:31`. Its purpose is to put the version rule for Settings, State and WiFi
under host test, since none of their `.cpp` files compiles on the host (research §1).

**A7 — where `FORMAT_VERSION` lives.** Settings, State and WiFi each declare
`static constexpr int FORMAT_VERSION = 1;` in the class (`CLAUDE.md`: "`static constexpr` for
class-level constants"). `RecentBooksDoc` declares `inline constexpr int FORMAT_VERSION = 1;`
in its namespace, as `BookmarkDoc.h:23` does. Each file's version moves independently, so there
is no shared constant.

**A8 — the key is `"v"`, written first.** It matches every versioned JSON file in the repo
(research §4). No settings key is `"v"`: `grep -rnE '"v"' src/SettingsList.h src/*.cpp
src/util/*.cpp` matches only `BookmarkDoc.cpp`. An older build ignores an unknown top-level
key, because every `fromJson` looks keys up by name (for example
`CrossPointSettings.cpp:113-172`). So a file written by this build still loads on a
pre-#101 build.

## Architecture

```

lib/Serialization/PersistableStore.h   edit  loadRefused flag; set in loadFromFile, checked in both saves
src/CrossPointSettings.{h,cpp}         edit  FORMAT_VERSION; stamp in toJson; check first in fromJson
src/CrossPointState.{h,cpp}            edit  same; SAVE_BUDGET comment "11 keys" -> "12 keys"

src/RecentBooksStore.cpp               edit  none beyond what the static_asserts at :125-129 re-derive
```

`test/CMakeLists.txt` is a shared append point (`.claude/agents/data-dev.md`, "Shared
files"). The line `add_subdirectory(format_version)` goes in the PR description for the
orchestrator to apply.

### Budget arithmetic

`{"v":1,"books":[]}` is 18 bytes and `{"books":[]}` is 12 (`python3 -c 'print(len(...))'`).
`DOC_WRAPPER_BYTES` (`RecentBooksDoc.h:46-47`) becomes 18. `SAVE_BUDGET` stays
`worstCaseBytes()` and moves from 11421 to 11427. It is still under `DEFAULT_SAVE_BUDGET`, so
`RecentBooksStore.cpp:128` holds. The other three have headroom of more than 800 B
(`CrossPointState.h:32-34`, `CrossPointSettings.h:427-429`, `WifiCredentialStore.h:41-45`)
and their budgets do not move.

## Data and control flow

### Save

```
toJson(doc):  doc["v"] = FORMAT_VERSION;  …existing keys unchanged…
saveToFileAtomic():  lock -> if loadRefused: LOG_ERR, return false -> toJson -> measure -> write
```

### Load

```
loadFromFile():
  lock
  status = readDocFromFileAdopting(path)
  Missing                 -> loadRefused = false; return false        (first boot; unchanged)
  Unreadable / ParseError -> return false                             (unchanged)
  Ok -> ok = fromJson(doc)
        fromJson:  version = doc["v"] | FORMAT_VERSION
                   if !persist::isKnownFormatVersion(version, FORMAT_VERSION):
                       LOG_ERR(<store tag>, "Refusing %s: format v%d is newer than v%d", …)
                       return false                                   (no member touched)
                   …existing body unchanged…
        loadRefused = !ok
  unlock
  if ok && resaveRequested: saveToFileAtomic()                        (unchanged)
```

The existing `DeleteTempReportEmpty` arm reports `Missing` (`TempAdoption.h:53-55`), so it
clears the flag too, which is correct: the primary file is absent there as well.

## Error handling

| Situation | Behaviour | Where the user sees it |
|---|---|---|
| Absent `"v"` | Loads as v1; unchanged behaviour | — |
| `"v"` ≤ 0 or > known | Load refused, defaults kept, `LOG_ERR` naming file and version | Serial |
| A settings change the user made on a refused store | Save refused | `saveSettingsOrReport` posts `STR_SETTINGS_SAVE_FAILED` (`src/activities/SettingsSave.h:15-19`) |
| Web `POST` settings on a refused store | Save refused | HTTP 500 "Settings could not be saved" (`CrossPointWebServer.cpp:1292-1295`) |
| Save a WiFi password on a refused store | Save refused | `STR_WIFI_SAVE_FAILED` popup (existing, per `docs/superpowers/specs/2026-09-23-store-refusal-surfacing-design.md` Decision 2) |
| Background saves: state at sleep (`main.cpp:263`), recents, last-SSID | Save refused, `LOG_ERR` | Serial only, the same "bookkeeping" classification #39 made |

No new strings, no new popups. `PostedMessage` and the HTTP status already carry every
user-initiated save failure (issue #39's design), and the new refusal comes back through the
same `false` return.

## Testing strategy

TDD order: each test is written and seen to fail before the code it covers.

1. **`test/format_version/FormatVersionTest.cpp`** (new), modelled on
   `test/save_budget/` (`CMakeLists.txt` links only `crosspoint_test_common` and gtest).
   Cases: `1` of `1` is known; `0` is refused; `-1` is refused; `2` of `1` is refused; `2` of
   `2` is known; plus a `static_assert` so the predicate stays `constexpr`.
2. **`test/recent_books_doc/RecentBooksDocTest.cpp`** (extend), mirroring
   `BookmarkDocTest.cpp:75-115`:
   `ToJsonStampsTheCurrentVersion`, `AnAbsentVersionIsReadAsOneWithEveryEntry`,
   `APresentZeroIsRefused`, `AFutureVersionIsRefusedRatherThanReinterpreted`,
   and `ARefusedDocumentLeavesTheListUntouched`. The last one checks that `fromJson` returns
   false before `books.clear()` (`RecentBooksDoc.cpp:54`), which is A2. The existing
   `AWorstCaseDocumentFitsTheDerivedBudget` (`:267-285`) goes red on its own the moment
   `toJson` stamps `"v"`, and green again once `DOC_WRAPPER_BYTES` is 18. The pinned
   `11421u` (`:50`) moves to `11427u`.
3. **Settings, State, WiFi `fromJson` and the `PersistableStore` guard** have no host
   coverage, because their translation units need Arduino and `HalStorage`. The host
   `HalStorage` stub is a no-op (see issue #99), so an I/O test would prove nothing. Their
   version rule is covered through the predicate (1). The guard is covered by `pio run` plus
   the device check below. This is stated as a limit, not hidden.
4. **Build:** `pio run` (x4pro) once after the last edit; `./bin/clang-format-fix` over the
   whole tree after `git add` of the new files.
5. **Device (human tester):** with a card reader, set `"v":2` in `/.crosspoint/state.json`
   and `settings.json`, then boot a dev build. Expect `Refusing … format v2` on serial and
   default settings on screen. Change a setting and expect the "save failed" popup. Sleep and
   wake. Both files must still contain `"v":2` and the original values. Then delete
   `"v"` from both, boot, and expect the old values back. After a settings change,
   `settings.json` starts with `{"v":1,`.

## Documentation

`docs/file-formats.md` gains one section per file after the completion section
(`:350-375`), following its layout: owner files, `### Version 1`, a one-line example, the
`v` rule, and the save budget. The `v` bullet, in each: *absent reads as 1; any other value
this build does not know is refused, the store runs on defaults, and it is not written until
a build that knows the format loads it.* Keys are summarised, not listed exhaustively for
settings, because `SettingsList.h` is the source of truth for those.

Comments that become false are rewritten: `RecentBooksDoc.h:84-86` ("no format version to
police") and `CrossPointState.h:32` ("11 keys").

## Open decision

A3 puts a save-blocking flag in `PersistableStore<T>`. That is a cross-cutting mechanism
in the shared base class, and `.claude/agents/data-dev.md` says to escalate a mechanism like
that rather than invent it. It is raised through `hpipe decide` with A3 as the
recommendation. If it is rejected, the fallback is a per-store `loadRefused` member checked
in each store's mutators. That fallback leaves the direct `APP_STATE.saveToFileAtomic()`
calls (research §2) unguarded unless every one of them is wrapped, which is why it is not
the recommendation.
