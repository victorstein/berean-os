# One spelling for the store format-version check

Design note for issue #132, on `refactor/version-check-single-helper`.
Research: `docs/superpowers/research/2026-09-26-issue-132-research.md`.
Modelled on: #123 (`2674c3c2`), which routed the four inherited stores through
the same helper. The code shape copied is `src/CrossPointSettings.cpp:110-116`
(read the version with a `|` default, then `persist::isKnownFormatVersion`). The
test shape copied is the `RecentBooksDocVersion` cases in
`test/recent_books_doc/RecentBooksDocTest.cpp:264-337`. The layout of this
document follows `docs/superpowers/specs/2026-09-26-issue-113-design.md`.

## Problem

CLAUDE.md storage rule 4 says a build must **refuse** a format version it does not
know. `persist::isKnownFormatVersion` (`lib/Serialization/FormatVersion.h:13-15`)
is the single spelling of that rule: `version > 0 && version <= newestKnown`. Only
the four inherited stores call it (`CrossPointSettings.cpp:111`,
`CrossPointState.cpp:65`, `WifiCredentialStore.cpp:33`, `RecentBooksDoc.cpp:58`).

Eleven checks in eight files spell the rule by hand, in three different shapes
(research note, table "The hand-rolled sites"):

- **`> newest` only**, which accepts a written `0` or a negative value:
  `PubKeyRegistry.cpp:28-29, 57, 83`, `MigrationRunner.cpp:68, 95`,
  `MeetingWeekCache.cpp:24` and `HighlightDoc.cpp:121-122`.
- **`<= 0 || > newest` after `| 0`**, which refuses an absent `"v"`:
  `TagPalette.cpp:78-79`, `ChapterCompletion.cpp:111-112` and `PassageDoc.cpp:221-222`.
- **`<= 0 || > newest` after `| FORMAT_VERSION`**, which accepts an absent `"v"`:
  `BookmarkDoc.cpp:31-32`.

The issue's table lists ten of the eleven. `PubKeyRegistry.cpp:28-29`, in
`record`, is the write-path twin of the two read paths the issue does list.

This does no harm today, because no build has ever written `v <= 0`. But the rule
has four spellings, and seven of the checks accept a value the helper refuses.

## Goal

- Every check above calls `persist::isKnownFormatVersion`, so a written `v <= 0`
  is refused at every one of them.
- Whether an absent `"v"` is accepted or refused stays exactly as it is at each site.
- The refusal path stays exactly as it is at each site: same return value, same
  `LOG_ERR` text, and the file is not overwritten.
- No format-version constant changes, and nothing written to the card changes.

## Non-goals

- **Unifying the absent-`"v"` column.** The issue forbids it. `TagPalette`,
  `ChapterCompletion` and `PassageDoc` refuse an absent `"v"`. The other five
  stores accept it. Both answers stay.
- **The binary-header version checks.** `CatalogStamp.cpp:62` and
  `IndexReader.cpp:30-31` compare a field in a binary header, not a JSON `"v"`.
  `IndexReader` also refuses older versions, a different rule from the helper's.
- **`MigrationRunner.cpp:135` `writeReport`.** It stamps `"v":1` on a report that
  nothing reads back, so there is no check to route.
- **`MeetingWeekCache::save`** (`MeetingWeekCache.cpp:38-`). It builds a new
  document and never reads the old one, so it has no version check.
- **`test/passage_doc/PassageDocTest.cpp:410-412`.** It restates the guard of an
  already-released v1 build, to prove that shipped reader refuses a file with
  links. It models released code, so it stays as written.
- **Adding host harnesses for `PubKeyRegistry`, `MigrationRunner` or
  `MeetingWeekCache`.** None of them has a suite (research note, "Host-test
  coverage today"). The issue says to say so in the PR rather than add one.
- **Rewording any `LOG_ERR`.** See A5.

## Assumptions (each one is a decision the review should attack)

**A1: Each site keeps its absent-`"v"` answer through its `|` default. The helper
does not change.**
The helper judges only an `int` (`FormatVersion.h:13-15`). Whether an absent
`"v"` passes is decided by the default after `|`:
- `doc["v"] | FORMAT_VERSION` turns an absent `"v"` into the current version, so
  the file is accepted. This is how the four #123 stores and `BookmarkDoc.cpp:31`
  already read it. Every constant involved is at least 1 (research note).
- `doc["v"] | 0` turns an absent `"v"` into `0`, and the helper refuses `0`.

The rejected alternatives are a second helper, or a flag argument such as
`requireExplicit`. Either would add a new shape to a header that exists so the
rule has one shape. It would also fork the tested `constexpr` contract that
`FormatVersionTest.cpp:5` pins.

**A2: An absent `"v"` reads as the store's `FORMAT_VERSION` in every store that
accepts it. No store gets a separate "pre-versioning" constant.**
The issue says to read an absent `"v"` "as the version the pre-versioning files
correspond to". In all five accepting stores that version is 1, and the current
constant is also 1:
- `HighlightDoc.h:22`
- `PubKeyRegistry.cpp:13`
- `MigrationRunner.cpp:31`
- `MeetingWeekCache.cpp:13`
- `BookmarkDoc.h:23`

For four of them, `HighlightDoc`, `PubKeyRegistry`, `MigrationRunner` and
`MeetingWeekCache`, no build ever wrote a file without `"v"`. The commit that
created each file already stamped it (research note, "Where an absent `"v"` could
come from"). `| FORMAT_VERSION` matches the four #123 sites exactly. A future bump
of any of these constants would have to revisit the default. That is also true of
the #123 stores, and it is the reason `FormatVersion.h:10-12` spells out the idiom.

**A3: A non-integer `"v"` keeps today's answer at every site.**
ArduinoJson's `operator|` returns the default for a value it cannot convert, not
only for a missing key. `RecentBooksDocTest.cpp:309-321` pins `"v":"2"` reading as
the default. With the defaults chosen in A1:
- A string `"v"` is still accepted at the five accepting stores. Today
  `0 > 1` is false, and after the change `1` is a known version.
- A string `"v"` is still refused at the three `lib/StudyStore` stores, because
  `0` is refused both before and after.

No test is added for this. `RecentBooksDocTest` already pins the ArduinoJson
behaviour it rests on, and the issue's case list does not include it.

**A4: `lib/StudyStore` and `lib/Epub` may include `<FormatVersion.h>`.**
Neither library includes anything from `lib/Serialization` today (research note,
"Build / dependency facts"). The issue asks for these exact sites to use the
helper, and the helper is the only shared spelling. The header states it is kept
free of Arduino and ArduinoJson so that host-testable code can use it
(`FormatVersion.h:5-7`). Its only include is `DocReadStatus.h` (`:3`). It is also
header-only `constexpr`, so it adds no link dependency and no new source file to
any test.

The include is spelled `#include <FormatVersion.h>`, as in
`src/CrossPointSettings.cpp:3`. `platformio.ini` sets no `lib_ldf_mode`, so
PlatformIO's default chain mode finds it the same way it does for `src/`. Each of
the four affected host suites adds `${REPO_ROOT}/lib/Serialization` to its own
`target_include_directories`, the way `test/bookmark_doc/CMakeLists.txt` already
does. The shared `test/CMakeLists.txt` is not touched (A7).

**A5: Every `LOG_ERR` string stays byte-identical, even where it now also covers `0`.**
`MigrationRunner.cpp:69, 96`, `MeetingWeekCache.cpp:25` and `PubKeyRegistry.cpp:30`
all say "newer … format". After the change, the same branch also runs for `v <= 0`,
which is not "newer". The issue says to keep each site's existing refusal behaviour,
including its `LOG_ERR`, unchanged. No build writes `v <= 0`, so the imprecise
wording can only appear for a hand-edited or corrupted file.

The alternative was to switch to the #123 wording, `"Refusing %s: unknown format
v%d (this build knows v1..v%d)"` (`CrossPointSettings.cpp:113`). It was rejected
because it changes behaviour the issue pins. It remains a cheap follow-up if the
reviewer disagrees.

**A6: `HighlightDoc` is changed on this branch although it lives in `lib/Epub`.**
It is a persisted-store parser (`HighlightDoc::toJson` / `fromJson`,
`HighlightDoc.cpp:98-122`). The issue lists it, and the change is two lines, the
same as at every other site. No sibling task in this batch is recorded as holding
it. The pipeline's re-read rule at `implement` covers the risk of a concurrent edit.

**A7: No shared-file lines.**
`test/CMakeLists.txt:68, 110-112, 122, 124` already registers every suite this
change touches. Only the per-suite `CMakeLists.txt` files change. The PR body will
say "none" under the "Shared-file lines for the orchestrator" heading.

**A8: The helper's comment is updated to describe both idioms.**
`FormatVersion.h:10-12` currently says callers read `doc["v"] | FORMAT_VERSION`.
After this change three callers deliberately read `| 0`, so the comment becomes
wrong. It is rewritten to state both defaults and what each one means for an
absent `"v"`. The code in the header does not change.

**A9: The three `| 0` sites carry no per-site comment.**
The `| 0` default makes an absent `"v"` refused, and the helper's comment (A8) is
the one place that explains why that works. `BookmarkDoc.cpp:28-30` explains its
`| FORMAT_VERSION` in place. That comment stays, because it explains a subtle
ArduinoJson behaviour. No new comment is added at the other sites.

## Architecture

There is no new component. `persist::isKnownFormatVersion` in
`lib/Serialization/FormatVersion.h` stays the only place the rule is written. Each
store owns only its `|` default.

| Site | Reads version as | Check becomes | Include added |
|---|---|---|---|
| `PubKeyRegistry.cpp:28-29` | `doc["v"] \| FORMAT_VERSION` | `!persist::isKnownFormatVersion(version, FORMAT_VERSION)` | `<FormatVersion.h>` |
| `PubKeyRegistry.cpp:57, 83` | same | same | (same file) |
| `MigrationRunner.cpp:68, 95` | `doc["v"] \| LEDGER_FORMAT_VERSION` | `!…(version, LEDGER_FORMAT_VERSION)` | `<FormatVersion.h>` |
| `MeetingWeekCache.cpp:24` | `doc["v"] \| FORMAT_VERSION` | `!…(version, FORMAT_VERSION)` | `<FormatVersion.h>` |
| `HighlightDoc.cpp:121-122` | `doc["v"] \| FORMAT_VERSION` | same | `<FormatVersion.h>` |
| `TagPalette.cpp:78-79` | `doc["v"] \| 0` (unchanged) | same | `<FormatVersion.h>` |
| `ChapterCompletion.cpp:111-112` | `doc["v"] \| 0` (unchanged) | same | `<FormatVersion.h>` |
| `PassageDoc.cpp:221-222` | `doc["v"] \| 0` (unchanged) | same | `<FormatVersion.h>` |
| `BookmarkDoc.cpp:31-32` | `doc["v"] \| FORMAT_VERSION` (unchanged) | same | `<FormatVersion.h>` |

`PubKeyRegistry`, `MigrationRunner` and `MeetingWeekCache` already include
`<PersistableStore.h>`, which includes `FormatVersion.h`
(`PersistableStore.h:11`). They still get the direct include, because they now use
the header themselves and `CrossPointSettings.cpp:3` sets that precedent.

Where the check is an inline expression (`PubKeyRegistry.cpp:57, 83`,
`MigrationRunner.cpp:68, 95`, `MeetingWeekCache.cpp:24`), the change introduces a
`const int version = …;` local, matching `CrossPointSettings.cpp:110`. The value
is not reused afterwards.

## Data and control flow

Nothing moves. Each store reads its document exactly as it does today. The version
check sits at the same point in each function, and so does the return that follows
a refusal:

- **Parser stores** (`HighlightDoc`, `TagPalette`, `ChapterCompletion`,
  `PassageDoc`, `BookmarkDoc`). The check is the first test after the
  `is<JsonObjectConst>()` guard (`HighlightDoc` has none, see `:120-121`). A
  refusal returns `false` before any member is touched. `BookmarkDoc` alone clears
  its output before the check (`BookmarkDoc.cpp:25`), and that order is kept.
- **Write paths** (`PubKeyRegistry::record` `:28-33` and
  `MigrationRunner::appendLedger` `:95-99`). The check runs before `doc["v"] =` is
  stamped and before the atomic rewrite, so a refused file is never overwritten.
  Before this change a written `v:0` would have been re-stamped `v:1` and
  rewritten. After it, the file is refused and left alone. That is the one
  behaviour this change adds to a write path.
- **Read paths** (`findBySymbol` `:57`, `lookup` `:83`, `readLedger` `:68`,
  `MeetingWeekCache::load` `:24`). A refusal returns `std::nullopt` / `false`, as
  it does for a newer version today.

The `readLedger` refusal is the case the comment at `MigrationRunner.cpp:55-60`
protects. It returns `nullopt`, not an empty ledger, so the migration does not run
again. A `v:0` ledger now takes that same `nullopt` path. Before the change it
read as a valid ledger.

## Error handling

This change adds no new error path. The existing refusal branch at each site now
also covers `v <= 0`:

| Site | Refusal, before and after |
|---|---|
| `PubKeyRegistry::record` | `LOG_ERR(MODULE, "Refusing to rewrite a newer registry format")`, `return false` |
| `PubKeyRegistry::findBySymbol`, `lookup` | `return std::nullopt`, no log |
| `readLedger` | `LOG_ERR(MODULE, "Refusing to read a newer ledger format")`, `return std::nullopt` |
| `appendLedger` | `LOG_ERR(MODULE, "Refusing to rewrite a newer ledger format")`, `return false` |
| `MeetingWeekCache::load` | `LOG_ERR(MODULE, "Refusing to read a newer week cache format")`, `return false` |
| The five parsers | `return false`, no log. Each caller's handling is unchanged. |

Nothing is written on any refusal path.

## Testing strategy

TDD order: the new cases are written first and the suites run before any production
line changes. Each case is named in the `…Version` style of
`RecentBooksDocTest.cpp:264-337` and `BookmarkDocTest.cpp:75-116`.

Every store with a host suite gets the five cases the issue lists: absent `"v"`,
`"v": 0`, `"v": -1`, current, and current + 1. Cases that already exist are
reused, not duplicated.

| Store (suite) | Absent | `0` | `-1` | Current | Current + 1 | New cases that fail before the change |
|---|---|---|---|---|---|---|
| `HighlightDoc` (`test/highlight_doc`) | new: accepted | new: refused | new: refused | exists `:60-63` | exists `:65-70` | **`0`, `-1`** |
| `TagPalette` (`test/tag_palette`) | new: refused | new: refused | new: refused | exists `:96-104` | exists `:88-94` | none (pins existing behaviour) |
| `ChapterCompletion` (`test/chapter_completion`) | exists `:271-274` | new: refused | new: refused | exists `:301` | exists `:266-269` | none |
| `PassageDoc` (`test/passage_doc`) | new: refused | new: refused | new: refused | exists `:53-55` (v2) | exists `:46-51` (v3) | none |
| `BookmarkDoc` (`test/bookmark_doc`) | exists `:81` | exists `:101` | new: refused | exists (round trip) | exists `:110` | none |

Only `HighlightDoc`'s `0` and `-1` cases can fail first. The other stores already
refuse those values, so their new cases pin behaviour rather than drive it. The
real proof that the refactor preserves behaviour is that these tests pass both
before and after the change. The PR says so plainly and does not present them as
red-then-green.

`PubKeyRegistry`, `MigrationRunner` and `MeetingWeekCache` have no host suite
(`grep -rln 'PubKeyRegistry\|MigrationRunner\|MeetingWeekCache' test` finds
nothing). Their change is covered by review and by the firmware build. The PR
names this gap.
