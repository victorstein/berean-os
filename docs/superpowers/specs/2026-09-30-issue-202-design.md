# Issue #202 design: reusable CoverBand component

Research: `docs/superpowers/research/2026-09-30-issue-202-research.md`. All `file:line` below are at `67eaaf1e`.

## Problem

The launcher's cover tile is the one place the firmware draws a publication cover honestly on a 1-bit
panel: at 1:1, cropped and never scaled, aimed at a focus band, masked to the tile's rounded corners, and
finished with an opaque caption plate. All of it is private to `LauncherActivity`
(`LauncherActivity.h:57-63`; `drawCoverFilling` `LauncherActivity.cpp:329-372`, `drawCoverTile` `:379-401`,
`coverFillHeight` `:259-261`). The Direction B overhaul wants the same art on Home and on the screen
mastheads, and the only way to reuse it today is to copy it. It has already been copied once:
`SleepActivity::drawBibleCover` (`SleepActivity.cpp:602-639`) repeats the buffers, the row walk and the
2-bit threshold line for line.

The crop arithmetic is the part most likely to be broken by a later caller, and none of it is tested: it
lives inside a function that also opens files and draws pixels.

## Goal

1. A `CoverBand` component in `src/components/` that blits a cached 1-bit cover into any rectangle,
   cropped at 1:1, aimed at a focus band, with an optional opaque label plate.
2. The crop geometry and the thumbnail-size rule in a renderer-free header with a host test.
3. The launcher moved onto it with **no visible change**.

## Non-goals

- **No new visual design.** Direction B's new Home and mastheads are later issues; this one only makes
  them possible.
- **No change to `SleepActivity`.** See A7.
- **No FreeInkUI painter adapter.** See A6.
- **No change to thumbnail generation or its cache naming.** `Epub::generateThumbBmp` (`Epub.cpp:670-764`)
  and `thumb_<h>.bmp` (`Epub.cpp:668`) are untouched; no cache is invalidated.
- **No SDK edit, no renderer clip region.**
- **No change to `CoverThumb::drawNative`, `sizeOf` or `pathFor`.** Meetings (`MeetingsActivity.cpp:227,231,374`),
  Publications (`PublicationsActivity.cpp:80`) and the launcher's stacked-tile fallback (`LauncherActivity.cpp:316`)
  keep calling them as today.

## Modelled on

- **Geometry header + host test:** `src/components/ToastLayout.h` and `test/posted_message/ToastLayoutTest.cpp`
  — `constexpr`, no firmware includes, its own plain `Bounds` struct, tested with named device-shaped inputs.
  CMake shape from `test/launcher_refresh/CMakeLists.txt`.
- **Draw functions:** `src/util/CoverThumb.{h,cpp}` — a namespace of free functions taking
  `const GfxRenderer&` and a cover path, opening the BMP through `HalStorage`, returning a success value the
  caller falls back on.
- **Rect type at the draw API:** the theme's `Rect` (`src/components/themes/BaseTheme.h:11-18`), which is what
  `GUI` draw calls already take (`LauncherActivity.cpp:459`).

## Architecture

Two new files in `src/components/`, one new test suite, and a launcher edit.

### `src/components/CoverBandGeometry.h` (new, header-only, no firmware includes)

```cpp
namespace CoverBandGeometry {

// Covers run roughly 0.6-0.75 wide-to-tall; see thumbHeightFor.
constexpr float NARROWEST_COVER_ASPECT = 0.6f;

struct Crop {
  bool fits;     // false: the cover is smaller than the band on some axis and must not be drawn
  int xOffset;   // first source column shown
  int yOffset;   // first source row shown
};

// Where a band of bandWidth x bandHeight shows a coverWidth x coverHeight cover.
// visibleHeight is the part of the band not hidden by a plate; focusBand is the
// fraction of the cover's height to centre in it.
constexpr Crop crop(int coverWidth, int coverHeight, int bandWidth, int bandHeight, int visibleHeight,
                    float focusBand);

// Thumbnail height that covers the band on both axes without upscaling.
constexpr int thumbHeightFor(int bandWidth, int bandHeight);

}  // namespace CoverBandGeometry
```

`crop` is the exact arithmetic of `LauncherActivity.cpp:339,348,354-355` (see A1):

- `fits = coverWidth >= bandWidth && coverHeight >= bandHeight`; when false, offsets are 0.
- `xOffset = (coverWidth - bandWidth) / 2`
- `focusRow = static_cast<int>(static_cast<float>(coverHeight) * focusBand)`
- `yOffset = std::clamp(focusRow - visibleHeight / 2, 0, coverHeight - bandHeight)`

`thumbHeightFor` is `LauncherActivity.cpp:260`:
`std::max(bandHeight, static_cast<int>(static_cast<float>(bandWidth) / NARROWEST_COVER_ASPECT))`.

`CoverBandGeometry` also carries `constexpr int plateTop(int bandY, int bandHeight, int plateHeight)`
= `bandY + bandHeight - plateHeight` (today `LauncherActivity.cpp:395`). `CoverBand::draw` and
`CoverBand::plateRect` both use it, so the plate's position has one source (review 0, MINOR 3).

The launcher's `BOOK_TITLE_BAND` and `MAGAZINE_MASTHEAD_BAND` (`:63-64`) move here too, as
`CoverBandGeometry::BOOK_TITLE_BAND` / `MAGAZINE_MASTHEAD_BAND`, because every future caller aiming at a book
or a magazine needs the same two values (A8).

### `src/components/CoverBand.{h,cpp}` (new)

```cpp
namespace CoverBand {

struct Style {
  float focusBand = CoverBandGeometry::BOOK_TITLE_BAND;
  int cornerRadius = 0;   // 0: square corners, no mask
  int plateHeight = 0;    // 0: no plate; the whole band is artwork
};

// Draws the cover into band at 1:1, cropped and aimed per style, masks the
// corners, and lays the opaque plate across the band's foot. False, with the band
// showing nothing of the cover, when it is missing, unreadable, or smaller than
// the band: a read that fails mid-stream clears the band to white first.
bool draw(const GfxRenderer& renderer, const std::string& coverPath, const Rect& band, const Style& style);

// The band's plate, for the caller to draw its label into. Zero height when style has no plate.
Rect plateRect(const Rect& band, const Style& style);

// The cached thumbnail sized for this band, generating it when missing (CoverThumb::pathFor
// at CoverBandGeometry::thumbHeightFor).
std::string thumbPathFor(const std::string& bookPath, int bandWidth, int bandHeight, bool& generatedAny);

}  // namespace CoverBand
```

`draw` performs, in this order — the current z-order of `drawCoverTile` (`LauncherActivity.cpp:385-398`):

1. The streamed blit: the body of `drawCoverFilling` (`:331-371`) with its inline arithmetic replaced by
   `CoverBandGeometry::crop(width, height, band.width, band.height, band.height - plateHeight, focusBand)`.
2. If `cornerRadius > 0`: `renderer.maskRoundedRectOutsideCorners(band..., cornerRadius)` (`:393`).
3. If `plateHeight > 0`: the white plate with rounded bottom corners only (`:395-397`) and the 1 px black
   rule along its top (`:398`).

The caption text and the tile border stay with the caller (A3, A4), drawn after `draw` returns, so the
launcher's draw order is unchanged.

### Launcher edit

- `LauncherActivity.h`: delete `drawCoverFilling` (`:60`) and `coverFillHeight` (`:63`).
- `LauncherActivity.cpp`:
  - delete `NARROWEST_COVER_ASPECT`, `BOOK_TITLE_BAND`, `MAGAZINE_MASTHEAD_BAND` (`:54-64`), `coverFillHeight`
    (`:253-261`) and `drawCoverFilling` (`:323-372`);
  - `resolveTargets` (`:118-119`, `:143-144`) calls `CoverBand::thumbPathFor(path, rect.w, rect.h, generatedAny)`;
  - `drawCoverTile` (`:379-401`) becomes: compute `plateHeight` as today (`:383`); call
    `CoverBand::draw(renderer, coverPath, Rect{rect.x, rect.y, rect.w, rect.h}, {focusBand, TILE_RADIUS, plateHeight})`;
    on `false` fall back to `drawTile` exactly as `:385-388`; otherwise
    `drawCenteredIn(rect.x, rect.w, CoverBand::plateRect(band, style).y + TILE_PADDING, ...)` and the border
    (`:399-400`) as today. The launcher no longer computes `plateTop` itself;
  - `render` (`:461-465`) passes `CoverBandGeometry::BOOK_TITLE_BAND` / `MAGAZINE_MASTHEAD_BAND`.

`TileRect` stays; converting to `Rect` at the one call site is cheaper than changing the launcher's layout type.

## Data and control flow

```
onEnter → computeLayout → resolveTargets
            └─ CoverBand::thumbPathFor(path, tile.w, tile.h)
                 └─ CoverThumb::pathFor(path, CoverBandGeometry::thumbHeightFor(w, h))   // same height as today
render → drawCoverTile
            ├─ CoverBand::draw(renderer, coverPath, band, style)
            │    ├─ open BMP (HalStorage), parseHeaders
            │    ├─ CoverBandGeometry::crop(...)  → !fits ⇒ return false (nothing drawn)
            │    ├─ allocate packedRow, rowScratch (per call, freed on return)
            │    ├─ stream rows; draw black where value < 3 inside [xOffset, +w) × [yOffset, +h)
            │    ├─ mask corners
            │    └─ plate + rule
            ├─ false ⇒ drawTile(..., emphasised, icon)              // unchanged fallback
            └─ true  ⇒ caption in plateRect, border                  // unchanged
```

Memory: the same two per-call buffers as today (`LauncherActivity.cpp:341-342`) — `(coverWidth+3)/4` and
`getRowBytes()` bytes via `makeUniqueNoThrow`, freed when `draw` returns. For the launcher's tiles (at most the
viewable column width, under 480 px) both are a few hundred bytes, below the 4096 B PSRAM auto-routing
threshold, so they come from internal SRAM transiently, exactly as now. No member, static or resident buffer
is added. `CoverBandGeometry` allocates nothing.

## Error handling

| Case | Today | After |
|---|---|---|
| empty path, open fails, bad header | `drawCoverFilling` returns false before drawing (`:331-336`) | `draw` returns false before drawing |
| cover smaller than band | returns false (`:339`) | `crop().fits == false` ⇒ false before drawing |
| row buffer OOM | `LOG_ERR`, false (`:343-346`) | same, module tag `COVER_BAND` |
| `readNextRow` fails mid-stream | false after a partial blit (`:358`); the fallback `drawTile` only outlines the tile (`:422`), so the partial cover stays visible under its icon and label | `renderer.fillRect(band, false)` (`GfxRenderer.h:243`, const) clears the band, then false (A5) |

Every false return leaves the fallback decision with the caller.

## Assumptions (each is a decision the review should attack)

- **A1 — Arithmetic is copied, not improved.** `crop` reproduces the current integer and float operations
  exactly, including truncation of `height * focusBand` and `/ 2` rounding toward zero. Any "cleaner" formula
  can move a crop by one pixel and breaks the no-visible-change criterion.
- **A2 — Same thumbnail height.** `thumbHeightFor(w, h)` equals `coverFillHeight(tile)` for every input, so
  the launcher asks for the same `thumb_<h>.bmp` it already has on the card. No regeneration, no new dither.
- **A3 — The plate is geometry and fill; the label is the caller's.** The component draws the opaque plate and
  its rule and exposes `plateRect`; it does not draw text. The launcher's caption uses launcher fonts and its own
  `drawCenteredIn` (`:403-415`), and a masthead's label will differ. Taking title/subtitle would bake the
  launcher's typography into a shared component.
- **A4 — The border is the caller's.** Selection is a launcher concept (3 px vs 1 px, `:400`); the component
  never draws the outer border.
- **A5 — A mid-stream read error clears the band.** Today a failed `readNextRow` (`:358`) leaves dithered rows
  that the fallback does not cover, because `drawTile` draws an outline, an icon and text but never fills the tile
  (`:417-452`, outline at `:422`). A shared component's "false means nothing drawn" contract must hold for every
  caller, so `draw` fills the band white before returning false. Buffering the band to make the blit atomic was
  rejected: it would be a new band-sized buffer, which the acceptance criteria forbid. This changes only the error
  path; a successful draw is pixel-identical. *Changed after review 0, MAJOR 1: the earlier text kept the partial
  blit on the false premise that the fallback painted over it.*
- **A6 — No `coverPainter` adapter yet.** `bookCard`'s painter is `bool (*)(DrawTarget&, Rect, const BookCardProps&, void*)`
  (`book-card.h:41`); `CoverBand::draw` can be called from one exactly as `MeetingsActivity::paintCover` calls
  `drawNative` (`MeetingsActivity.cpp:369-376`). Writing the adapter before a caller exists is speculative.
- **A7 — `SleepActivity` is not migrated.** Its crop uses a different vertical rule (`clamp(height/8)`,
  `SleepActivity.cpp:624`), draws the full panel, and runs during shutdown. Moving it changes the sleep screen's
  crop unless `Style` grows a second aiming mode; the issue names only the launcher. Left for a follow-up.
- **A8 — The focus-band constants move with the component.** They describe covers, not the launcher.
- **A9 — "Clip-aware" means clipped to the band.** The blit never writes outside `band`, because it iterates only
  the band's columns and rows. There is no renderer clip region (`GfxRenderer.h:70,210,226` clip a grayscale
  render band, not a rect); off-panel coordinates are already dropped by `drawPixel`'s bounds check
  (`GfxRenderer.cpp:559-571`).
- **A10 — `Rect` from `BaseTheme.h` at the draw API; plain `int` parameters and its own `Crop` struct in the geometry header.**
  The geometry header stays includable on the host with nothing but `<algorithm>`, as `ToastLayout.h` is.
- **A11 — The HAL log module tag changes from `LAUNCH` to `COVER_BAND`** for the open and OOM logs. Not visible
  on the device; noted so a log grep is not surprised.

## Testing strategy

TDD order: write `test/cover_band/CoverBandGeometryTest.cpp` against a stub header, see it fail, then fill in
`CoverBandGeometry.h`.

**Host tests** (`test/cover_band/`, `CoverBandGeometryTest`, CMake copied from `test/launcher_refresh/CMakeLists.txt`):

- `crop` centres horizontally, and truncates an odd surplus toward the left (`(W - w) / 2`).
- `crop` with `MAGAZINE_MASTHEAD_BAND` (0.0) gives `yOffset == 0`.
- `crop` with `BOOK_TITLE_BAND` (0.25) centres row `int(H * 0.25)` in `visibleHeight`, not in the band height.
- `crop` clamps to 0 when the focus row is near the top, and to `H - h` when it is near the bottom.
- `crop` reports `fits == false` when the cover is narrower, or shorter, than the band; and `true` at exact size
  with zero offsets.
- `thumbHeightFor` is width-bound for a wide band (`w / 0.6 > h`) and height-bound for a tall one.
- `thumbHeightFor` pins the single-precision truncation with a width divisible by 3: `240 → 399`, not the 400
  that exact arithmetic gives, because `0.6f` is stored slightly above 0.6. Every literal is computed with float
  semantics, never by hand in decimal. A test that expects 400 would push someone to "fix" the formula, which
  changes the requested `thumb_<h>.bmp` and breaks A2 (review 0, MINOR 1).
- `plateTop` puts the plate's top at `bandY + bandHeight - plateHeight`, and at the band's bottom edge with a
  zero plate.
- A characterisation case per launcher tile. Its inputs are named, each with its source written next to the
  literal (review 0, MINOR 2): tile widths derived from the X4 Pro metrics (viewable insets `{9,3,3,3}`,
  `BoardConfig.h:625-630`; `topPadding = 5`, `BaseTheme.h:129`; `TILE_GAP = 10`), giving Bible `w = 464` and
  Meetings `w = 227` under `computeLayout` (`LauncherActivity.cpp:281-307`); tile heights and plate heights derived
  the same way from the font line heights of `UI_10_FONT_ID` / `SMALL_FONT_ID` as read from the built-in font data;
  and cover sizes that `generateThumbBmp` produces for a portrait source at the requested height. The plan
  derives the numbers and cites where each came from. The expected offsets are then worked out once, with float
  semantics, and written as literals, so a change to either formula fails loudly.

Shared-file hand-off (PR body, not edited here): `add_subdirectory(cover_band)` in `test/CMakeLists.txt`, next
to `launcher_refresh` (`:126`).

**Build:** `pio run` (x4pro) once after the last edit; `./bin/clang-format-fix` over the tree.

**Human, on device:** photograph Home before (current release) and after (dev build) with the same Bible and
meetings publication on the card, selection on the Bible tile and on the Meetings tile; the photos must match.
Also confirm no `thumb_<h>.bmp` was newly generated (the serial `Generated a missing cover thumbnail` line,
`LauncherActivity.cpp:153`, must not appear on a card that already had covers).

## Changes after spec review 0

`docs/superpowers/reviews/issue-202-spec-review-0.md`, verdict CLEAR, one MAJOR and three MINORs, all accepted:

- **MAJOR 1:** the `draw` contract and A5 contradicted each other, and A5 rested on a false premise. `draw` now
  clears the band white on a mid-stream read failure. See A5 and the error table.
- **MINOR 1:** the tests pin `thumbHeightFor`'s float truncation (`240 → 399`), and all literals are computed with
  float semantics.
- **MINOR 2:** the characterisation inputs are named with their sources, and the plan derives the remaining heights.
- **MINOR 3:** `plateTop` is in the geometry header and host-tested; `draw`, `plateRect` and the launcher's caption
  all take the plate position from it.
