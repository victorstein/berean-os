# Issue #106 part 2 — design: `-Wall` on repo code, warnings at zero

- **Issue:** #106. Part 1, the `format` attribute on `logPrintf` plus `-Wformat`, landed in PR #142.
- **Branch:** `fix/106-enable-wall`
- **Research:** `docs/superpowers/research/2026-09-27-issue-106-research.md`, abbreviated to "R" below.

## Problem

The firmware build enables no general warnings.
- `[base] build_flags` carries `-Wno-bidi-chars` and `-Wformat` (`platformio.ini:70-73`), and nothing else.
- The framework's own C++ flags add only `-Wno-*` entries and `-Wwrite-strings`
  (`framework-arduinoespressif32-libs/esp32s3/flags/cpp_flags`; R, "Who owns the behaviour").
- The host tests already build the same `lib/` code with `-Wall -Wextra -pedantic`
  (`test/CMakeLists.txt:42-46`).

A probe with `-Wall` finds about 57 diagnostics in repo code across both envs (R, "Repo-code
warnings"). The categories include:
- mem-initialiser order;
- unhandled enum values;
- a function compiled for a board it is never called on;
- 44 locals that only exist to feed a `LOG_*` call.

Those locals become unused in `x4pro-gh_release`, the build OTA installs, because that env
compiles every `LOG_*` to nothing (`lib/Logging/Logging.h:62-66`, `platformio.ini:190`).

Turning `-Wall` on naïvely also reports warnings from code this repo does not own. That code
is `freeink-sdk` (a submodule we may not edit, `.claude/agents/hal-dev.md` "freeink-sdk is a
submodule"), vendored `lib/expat`, and `.pio/libdeps` packages (R, "Third-party and
`freeink-sdk` warnings").
- Those warnings would bury ours.
- The only config-level way to hide them, global `-Wno-*`, would also switch the same checks
  off for our own code.

## Goal

1. `-Wall` is on for every translation unit this repo owns, in both envs (`x4pro` and
   `x4pro-gh_release`), and on for nothing else.
2. A clean build of each env reports **zero** warnings from repo-owned files, including
   headers of third-party code that repo files include.
3. Every fix is behaviour-preserving. Where a fix would change behaviour, one specific warning
   is silenced at one site, with the reason written next to it.
4. The PR lists exactly what was excluded or suppressed for third-party code, and how.

## Non-goals

- **Fixing `freeink-sdk`, `lib/expat`, `lib/miniz`, `lib/uzlib` or any `.pio/libdeps` package.**
- **The pre-existing `WebSocketsClient.cpp:573` `-Wdeprecated-declarations`.** It is present
  without `-Wall` (R, baseline), it sits in a libdep, and this change neither adds nor removes it.
- **`-Wextra`, `-Wformat=2`, `-Werror`.** None was measured in the census. The issue offers
  `-Wformat=2` only as "possibly". Each is a follow-up once `-Wall` is at zero.
- **A CI gate that fails on new warnings.** See assumption **A11**.
- **Building `x4pro-gh_release` in CI** (`ci.yml:88-90` builds `x4pro` only).

## Architecture

### Scoping mechanism: a PlatformIO build middleware (A1 — pending `hpipe decide`)

This is the one part of the design with **no precedent in this repo or in its parent**:
`git grep 'AddBuildMiddleware\|build_src_flags\|isystem'` finds nothing on `HEAD` or on
`crosspoint/main`. It is therefore raised as a decision (see "Open decision" below) rather than
adopted silently.

Why the established knobs do not work:

| Knob | Why it fails the goal | Evidence |
|---|---|---|
| `-Wall` in `[base] build_flags` | Reaches every lib, including `freeink-sdk` and `.pio/libdeps`. Silencing those needs global `-Wno-comment -Wno-unknown-pragmas -Wno-unused-function -Wno-unused-but-set-variable`, which disables the same checks for our code. | R, census; `platformio/project/options.py:395-397` |
| `build_src_flags = -Wall` | Reaches `src/` only. Our `lib/` code carries 17 of the 57 diagnostics and would stay unchecked. | `piolib.py:964-967` (only `ProjectAsLibBuilder` reads `SRC_BUILD_FLAGS`) |
| `library.json` `build.flags` per repo lib | Needs roughly 20 new manifests. A manifest also switches that lib's builder class from the framework-guessed one to `PlatformIOLibBuilder` (`piolib.py:48-58`), which changes how the lib is built, not just its flags. | `piolib.py:48-58`, `:623-625` |

The proposed mechanism is PlatformIO's documented `env.AddBuildMiddleware(callback)`
(`platformio/builder/tools/piobuild.py:339-340`).
- `CollectBuildFiles` runs every registered middleware over every source node of every builder:
  `src/`, each `lib/` library, each libdep and the framework (`piobuild.py:296-336`).
- It passes the builder's own env when the callback takes two arguments (`:328-329`).
- The callback adds `-Wall` to a node only when that node's source path is repo-owned.

**Where it lives.** A new `pre:` script, registered in `[base] extra_scripts`
(`platformio.ini:131-137`). It is modelled on `scripts/patch_jpegdec.py` (`Import("env")`,
module docstring giving the reason, `env["PROJECT_DIR"]`-relative paths) and sits beside the
other `pre:` scripts.

It is split into two files so the path rule can be unit-tested without SCons (A10):
- `scripts/repo_warnings.py`: pure Python, no SCons.
  `is_repo_source(rel_path: str) -> bool` and the `VENDORED_LIBS` tuple.
- `scripts/enable_repo_warnings.py`: the `pre:` glue. It adds `env["PROJECT_DIR"]/scripts` to
  `sys.path`, imports `repo_warnings`, registers the middleware, and appends the `-isystem`
  entry (A3).

**Spike evidence.** A throwaway version of exactly this glue was run as
`PLATFORMIO_EXTRA_SCRIPTS=pre:<scratch>/spike_wall.py pio run -e x4pro-gh_release` at `24e3e8db`.
- The middleware wrapped 203 repo nodes and passed 325 others through.
- The build succeeded. RAM was 65,148 B and flash 5,412,302 B, both **byte-identical** to the
  probe without the middleware (R).
- Unique warnings fell from 77 to 62:
  - all 61 repo-code lines (the same set as R's table);
  - plus the pre-existing WebSockets deprecation.
  - Nothing from `freeink-sdk`, `lib/expat`, QRCode or wolfSSL.

### Ownership rule (A2)

A source is repo-owned when its path, relative to `PROJECT_DIR` with `/` separators:
- starts with `src/`, **or**
- starts with `lib/` **and** does not start with `lib/expat/`, `lib/miniz/` or `lib/uzlib/`.

Everything else is not owned: `freeink-sdk/…` (the `symlink://` libdeps resolve there),
`.pio/libdeps/…`, the framework, and paths outside the project.

The three vendored names come from their manifests declaring upstream versions: `expat` 2.7.3,
`miniz` 11.3.2, `uzlib` 2.9.8 with `repository: pfalcon/uzlib` (R, "How PlatformIO scopes
flags").

### Third-party headers included by our code (A3)

`freeink-sdk/libs/ui/FreeInkUI/include/FreeInkUIIcon.h:8` is a `//` comment ending in `\`, which
triggers `-Wcomment`. It is included from repo code: `src/components/UiAppHelpers.h:4` and
`src/activities/util/FrontlightPanelActivity.cpp`. So node-level scoping alone still reports it
inside our own translation units.

The glue therefore appends `-isystem <PROJECT_DIR>/freeink-sdk/libs/ui/FreeInkUI/include` to
`CCFLAGS`.
- GCC suppresses warnings in system headers.
- When a directory is given both as `-I` and as `-isystem`, the `-I` is ignored, so the
  directory is searched as a system directory.
- In the spike this removed the warning and left the binary byte-identical, so the header
  resolution did not change.

Only this directory is listed. It is the only third-party header the census saw reporting
inside repo TUs. The wolfSSL `user_settings.h:355` warning did not appear once `-Wall` was
scoped (spike), so no repo TU reaches it with `-Wall` on.

### Flag set (A4)

- The middleware adds exactly `-Wall`.
- `-Wformat` stays in `[base] build_flags` (`platformio.ini:71-73`), unchanged.
  `-Wall` implies it for owned code, but third-party `LOG_*`-style checks still need it for
  everything else.
- `-Wnonnull` is already live today through `-Wformat` (R, baseline), which is why the
  `CrossPointWebServerActivity.cpp:204` fix is in scope regardless.

## Data and control flow

The build proceeds in this order.
1. `pio run -e <env>`.
2. SCons runs the `pre:` scripts in `extra_scripts` order.
3. `enable_repo_warnings.py` does two things:
   - `env.Append(CCFLAGS=["-isystem", FreeInkUI/include])`. This reaches every builder, since
     lib envs are cloned from `env` afterwards.
   - `env.AddBuildMiddleware(add_wall)`.
4. Each builder (`src/`, each lib, the framework) calls `CollectBuildFiles`.
5. For each source node, `add_wall(builder_env, node)`:
   - computes `rel = relpath(node.srcnode().get_abspath(), PROJECT_DIR)`;
   - if `is_repo_source(rel)`, returns `builder_env.Object(node, CCFLAGS=builder_env["CCFLAGS"] + ["-Wall"])`;
   - otherwise returns `node` unchanged.
6. The compiler emits warnings for owned TUs only, and system-header warnings stay suppressed.

No firmware runtime data flow changes. Every source fix below is compile-time-neutral or
restructures an expression without changing its value.

## Source fixes (one assumption each)

These are the 57 diagnostics from R. Each fix names the idiom it mirrors.

- **A5 — log-only locals get `[[maybe_unused]]`.** This covers 42 `-Wunused-variable` and 2
  `-Wunused-but-set-variable`, all release-only except `contentTop` (A6).
  - The idiom is already used for exactly this:
    - `src/study/BibleSearchIndexer.cpp:152,228,256`;
    - `src/activities/reader/BibleSearchActivity.cpp:512`
      (`[[maybe_unused]] const unsigned long started = millis();`).
  - Rejected alternatives:
    - `#if LOG_LEVEL`/`ENABLE_SERIAL_LOG` guards: new pattern, and noisier.
    - Folding the expression into the `LOG_*` call: it changes when `millis()` is read for the
      timing locals in `EpubReaderActivity.cpp:1338-1579`, which measure intervals between
      statements.
  - Behaviour: none. The initialisers still run, exactly as today.
  - Sites (R): `EpubReaderActivity.cpp` (23), `CrossPointWebServer.cpp:744,761,762,1625`,
    `MeetingWeekPrefetch.cpp:70-72`, `main.cpp:758`, `CrossPointWebServerActivity.cpp:133`,
    `lib/Epub/Epub.cpp:421,430,448,486`, `BookMetadataCache.cpp:292`,
    `JpegToFramebufferConverter.cpp:502`, `PngToFramebufferConverter.cpp:472`,
    `FontDecompressor.cpp:525`, `SdCardFont.cpp:726`, `GfxRenderer.cpp:1725`, `Section.cpp:279`.
- **A6 — `FontDownloadActivity.cpp:638` `contentTop` is deleted.** It is unused in both envs
  (`grep -n contentTop` → only `:638`). Its initialiser reads three `metrics` fields and has no
  side effects.
- **A7 — `-Wswitch`: add explicit `case` labels, never a `default:`.** A `default:` would
  silence the warning for enum values added in future, which is what the warning is for.
  - `BibleDownloadActivity.cpp:252`: `NoEpubEdition` joins the
    `NoMediaLink`/`DownloadFailed`/`OutOfMemory` group (`:272-276`). Today it falls out of the
    switch to `fail(tr(STR_BIBLE_DOWNLOAD_FAILED_HINT))` at `:278`, which is the same call. The
    trailing `fail` at `:278` stays as the guard for out-of-range values.
  - `WifiSelectionActivity.cpp:967`: `PASSWORD_ENTRY` joins the `HIDDEN_SSID_ENTRY` no-draw case
    (`:978-980`). It is unreachable there, because `render()` returns early for both states
    (`:945-947`).
  - `EpubReaderActivity.cpp:714`: `AUTO_PAGE_TURN` and `ROTATE_SCREEN` get an empty case with a
    one-line "why".
    - The menu consumes both actions itself and returns before `setResult`
      (`EpubReaderMenuActivity.cpp:109-121`, `:124-131`). Its only `setResult` for a selected
      action is `:150`, and cancel sends `-1` (`:88-94`).
    - Their values reach the reader through `MenuResult`'s `pendingOrientation` and
      `selectedPageTurnOption` fields, not through `action` (`EpubReaderActivity.cpp:282-288`).
- **A8 — `-Wreorder`: reorder the mem-initialiser lists to declaration order.** The member
  declarations stay where they are.
  - Sites: `ChapterHtmlSlimParser.h` (init list at `:150`, members `:30` and `:57`) and
    `ProgressMapper.cpp` (init list at `:654`, members `:228` and `:234`).
  - C++ initialises members in declaration order whatever order the list is written in, so
    making the list match changes nothing at runtime.
  - Moving the declarations instead would change object layout and is rejected.
- **A9 — `-Wparentheses` at `ChapterHtmlSlimParser.cpp:925`: add parentheses that spell out
  the existing precedence**, `(a && b) || (c && d)`. The value is identical.
- **A12 — `-Wunused-function`: `lib/hal/HalGPIO.cpp:77` `detectDeviceTypeWithFingerprint()`
  moves under `#if FREEINK_MCU_C3`**, matching its only caller (`:116-117`).
  - Its private helpers in the same anonymous namespace are called only from it:
    - `readNvsDeviceValue` (`:51`, uses `:80,86`);
    - `writeNvsDeviceValue` (`:64`, uses `:100,105`);
    - `nvsToDeviceType` (`:73`, uses `:83,89`).
  - Guarding the function alone would make those three the next `-Wunused-function`, so the
    guard covers the NVS helper block and the function together.
  - The `constexpr` NVS key arrays (`:45-47`) go under the same guard. That is not for a
    warning (`-Wunused-const-variable` is not in `-Wall` for C++); it keeps the block coherent.
  - `X3GPIO::readI2CReg16LE`/`readBQ27220CurrentMA` (`:13-42`) are namespace-scope, externally
    linked and used at `:338`, and are untouched.
  - Behaviour on the S3: none. The guarded code is not called today.
- **A13 — `-Wdangling-reference` at `FontDownloadActivity.cpp:130,135`: hoist the range-init
  into a named local** (`const JsonArray styles = fObj["styles"].as<JsonArray>();`, and
  likewise `files`).
  - This is a GCC 13+ heuristic false positive.
  - `VariantRefBase::as<T>()` returns `T` by value
    (`.pio/libdeps/x4pro/ArduinoJson/src/ArduinoJson/Variant/VariantRefBase.hpp:49`, ArduinoJson
    7.4.2, `platformio.ini:154`).
  - `JsonArray` is a handle into the `JsonDocument`, not into the `MemberProxy` temporary GCC
    points at.
  - The named local keeps the same handle alive for the loop, so behaviour is identical.
- **A14 — `-Wmaybe-uninitialized` on `std::optional<uint32_t>`, in two places.**
  - The sites are:
    - `ReaderBookmarks.cpp:125-130`;
    - `EpubReaderActivity.cpp:1043`, reported at `Section.h:176` via the inline at
      `EpubReaderActivity.cpp:1112`.
  - Both reads are guarded by `has_value()`. This is GCC's known false positive on the payload
    of an `optional` built by a nested conditional.
  - **First choice:** restructure the nested `?:` into an `optional` default-constructed to
    `nullopt` and assigned in an `if`/`else if`, preserving every branch's value.
    - For `ReaderBookmarks.cpp:125`: `visibleOffset` if it has a value; else the page lookup
      when `currentPage` is in `[0, section.pageCount)`; else `nullopt`.
    - For `EpubReaderActivity.cpp:1043`: `pendingOffsetJump` if `explicitOffsetJump`; else
      `nullopt` if a page jump, an anchor or a spine change is pending; else
      `cachedVisibleTextOffset`.
  - **Fallback, only if the restructured form still warns:** a
    `#pragma GCC diagnostic push` / `ignored "-Wmaybe-uninitialized"` / `pop` around the single
    statement, with a one-line reason. The brief allows this ("silence one specific warning with
    a justified pragma/attribute").
    - It would be the first diagnostic pragma in the repo (R, "Existing idioms").
    - The inlined `Section.h:176` report is attributed to the header line. A pragma must
      therefore bracket `Section::buildReachedVisibleTextOffset` in `Section.h`, not its caller.
      The plan must confirm by build which location GCC honours.
- **A15 — `-Wnonnull` at `CrossPointWebServerActivity.cpp:204`: `if (AP_PASSWORD && …)` becomes
  `if constexpr (AP_PASSWORD != nullptr)` wrapping the `strlen` test.**
  - `AP_PASSWORD` is `constexpr const char* = nullptr` (`:28`).
  - The runtime behaviour, an open network through the `else` branch at `:207-208`, is
    unchanged because the condition is already a compile-time `false`.
  - If GCC still reports the discarded branch, the fallback is to drop the password branch
    entirely and keep the open-network call. That fallback is a larger edit, so the plan must
    record it as a deviation.

### Shared-file assumption (A16)

`src/main.cpp:758` (A5) is one of the append points `.claude/agents/hal-dev.md` says to report
rather than edit ("Shared files — report, do not edit").

The brief for this task overrides that: "You touch files everywhere, so you run last and alone."
The edit is a single `[[maybe_unused]]` and is made directly. `test/CMakeLists.txt` and the
translation YAMLs are not touched.

## Error handling

- **A middleware exception fails the build loudly.** The cases are a missing
  `scripts/repo_warnings.py`, a future PlatformIO dropping or renaming `AddBuildMiddleware`,
  or `node.srcnode()` raising. SCons aborts `pio run` with a Python traceback. That is the
  desired failure mode: there is no silent path where `-Wall` quietly stops applying and the
  build still looks clean.
- **A wrong ownership rule** is the silent failure. Two cases:
  - A new vendored library added under `lib/` would get `-Wall` and report its upstream
    warnings. That is loud, and the fix is to add its name to `VENDORED_LIBS`.
  - A repo library mis-listed as vendored would lose `-Wall` silently.

  The unit tests (A10) pin the rule. A docstring in `repo_warnings.py` states that
  `VENDORED_LIBS` is the only exclusion list and why each entry is on it.
- **A path outside `PROJECT_DIR`** (framework, toolchain) yields a `relpath` starting `..` and
  is classified not-owned. The unit tests cover this.
- **The `-isystem` path missing on disk** (submodule not checked out) is not a new failure. The
  build already fails on the missing `symlink://` libdeps (`platformio.ini:141-153`).

TDD order: a failing test first, then the minimum code that passes it, then run it again.

1. **Unit — path rule (A10).** Red first. `scripts/tests/test_repo_warnings.py` is modelled on
   `scripts/tests/test_build_catalog_index.py`: `sys.path.insert` of `scripts/`, `unittest`,
   and CI's `python -m unittest discover -s scripts/tests` (`ci.yml:163-164`).

   | Classification | Cases |
   |---|---|
   | Owned | `src/main.cpp`, `src/activities/reader/EpubReaderActivity.cpp`, `lib/hal/HalGPIO.cpp`, `lib/Epub/Epub/Section.cpp`, `lib/ProgressMapper/ProgressMapper.cpp` |
   | Not owned | `lib/expat/xmlparse.c`, `lib/miniz/src/miniz.c`, `lib/uzlib/src/tinflate.c`, `freeink-sdk/libs/display/FreeInkDisplay/src/driver/Ssd1677Driver.cpp`, `.pio/libdeps/x4pro/QRCode/src/qrcode.c`, `../packages/framework-arduinoespressif32/cores/esp32/main.cpp` |
   | Prefix traps, owned | `lib/expatfoo/x.cpp`, a hypothetical repo lib whose name starts with a vendored name |
   | Prefix traps, not owned | `srcx/a.cpp` |
   | Separators | Windows-style `lib\\hal\\HalGPIO.cpp`, owned after normalisation |

2. **Census — the acceptance test (red, then green).** The census command is
   `pio run -e x4pro` and `pio run -e x4pro-gh_release` through `pio-locked.sh`, then
   `grep -E 'warning: .*\[-W' | sort -u`.
   - **Red:** with only the scripts landed and no source fixes, it must reproduce R's 61 repo
     lines, and prove `-Wall` reaches owned TUs.
   - **Green:** after the fixes, zero lines whose path starts with `src/` or `lib/`, in both envs.
   - Whatever remains is listed verbatim in the PR, expected to be only the WebSockets
     deprecation.
   - The PR also shows one owned and one not-owned compile line from `pio run -v`, proving the
     scoping directly.
3. **Binary neutrality.** Record RAM/flash for both envs before and after.
   - `[[maybe_unused]]`, init-list order, parentheses and explicit empty cases should produce
     identical code.
   - A14/A15/A13 restructures may move a few bytes.
   - Any delta beyond ±64 B flash is explained in the PR, or the fix is revisited.
4. **Host tests.** `cmake -S test -B build/test && cmake --build build/test && ctest --test-dir build/test`.
   - The host build compiles `lib/` with `-Wall -Wextra -pedantic` (`test/CMakeLists.txt:42-46`).
   - The edits to `Section.h`, `ChapterHtmlSlimParser.*` and `ProgressMapper.cpp` must not add
     host warnings, and all tests must still pass.
5. **Format.** `./bin/clang-format-fix` over the whole tree after `git add`.
6. **Device — for the human tester.** These are the behaviour-sensitive paths touched:
   - reader menu → Auto page turn and Orientation popups (A7), with the reader applying both
     afterwards;
   - Bible download failure path (A7);
   - Wi-Fi password entry (A7);
   - font browser manifest listing families and styles (A13);
   - Network → Create Hotspot is still an open network (A15);
   - bookmark toggle on a page, and a jump by text offset (A14).

## Open decision

**A1** is surfaced with `hpipe decide` after this spec is committed. The recommendation is the
middleware, for the reasons in the Architecture table. The spike shows it isolates exactly the
repo diagnostics with byte-identical output.

If the answer is no, the fallback is global `-Wall` plus the four global `-Wno-*` flags listed
in the table. The goal would then be restated as "`-Wall` minus `-Wcomment`,
`-Wunknown-pragmas`, `-Wunused-function` and `-Wunused-but-set-variable` everywhere", and A12
plus the two `-Wunused-but-set-variable` sites of A5 would become unnecessary.
