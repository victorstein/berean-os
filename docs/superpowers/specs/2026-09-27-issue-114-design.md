# Issue #114 — study sleep screen: design

Research: `docs/superpowers/research/2026-09-27-issue-114-research.md` (the "research note", §n below).
All `file:line` references are on `af119732` (`origin/main`).

## Problem

An e-ink panel keeps its last frame with no power, so the sleep screen is what sits on the desk for
most of the day. Today every non-image mode ends in `renderDefaultSleepScreen`
(`src/activities/boot_sleep/SleepActivity.cpp:637-660`): the cached Bible cover, or the BereanMark,
plus "Berean" / "Sleeping". It never changes, and it shows nothing of the user's own study.

## Goal

A new, opt-in sleep-screen mode, `STUDY`. Each time the device sleeps it shows one of the user's
tagged passages, picked uniformly at random across every publication and not repeating a recently
shown one. The passage is framed by today's date, its reference, its first tag, and a 66-book Bible
progress strip. If anything is missing or unreadable, the mode falls back to the existing default
screen. It never writes to a study store.

## Non-goals

- Changing the default sleep mode. `sleepScreen = DARK` stays (`src/CrossPointSettings.h:242`).
- Resolving a passage's full text from the unit index. The stored snippet (≤ 120 B,
  `lib/StudyStore/StudyStore/PassageDoc.h:32`) is what shows.
- A new font. The largest built-in serif is used.
- Any change under `src/study/` or `lib/StudyStore/` (read-only for this task), `lib/hal/`, or
  `lib/Serialization/`.
- A grayscale render pass. The screen is 1-bit, like the default screen.

## Assumptions (each one is a decision the review can attack)

**A1 — Enum value.** `STUDY = 8` is appended after `TRANSPARENT_CUSTOM = 7` and before
`SLEEP_SCREEN_MODE_COUNT` (`CrossPointSettings.h:55-65`). It gets a label slot in
`SettingsList.h:233-241`. An older build reading `8` clamps it to its default `DARK` through
`CrossPointSettings.cpp:166-169`. That is acceptable, not a failure. The web settings page needs no
change (`SettingsPage.html:316-318` hardcodes only `QUICK_RESUME`).

**A2 — Where it hooks in.** A `case STUDY:` in the `switch` at `SleepActivity.cpp:534-549` calls the
single entry point `study_sleep_screen::render(renderer)` (a free function in `StudySleepScreen.h`,
see Architecture), which returns `bool`. On `false` the case calls
`renderDefaultSleepScreen()`. The "Entering sleep" popup (`:526-532`) is drawn first, as for every
other non-transparent mode, so the pick's I/O happens behind it.

**A3 — Read-only means no `loadAdopting`.** The sleep path never calls `PassageFile::load`,
`ChapterCompletionFile::load` or `TagPaletteFile::load`. All three can rename a `.tmp` into place
(`PersistableStore.h:84-115`; `PassageFile.cpp:18-24`, `ChapterCompletionFile.cpp:18-26`,
`TagPaletteFile.cpp:18-23`), and a rename is a write. The sleep path instead calls the public
non-adopting readers `PersistableStoreBase::readDocFromFileStreamed` (passages) and
`readDocFromFileChecked` (tags, completion) (`PersistableStore.h:77-81`) on the **primary path
only**. It hands the result to the pure `study::TagPalette::fromJson` / `study::ChapterCompletion::fromJson`.
A `.tmp` left by an interrupted save is ignored until the next ordinary load recovers it.

**A4 — Passage read: whole-file `JsonDocument`, one file at a time, no filter.** The issue asks for
an ArduinoJson filter on `x`/`r`/`t`. `readDocFromFileStreamed` takes no filter
(`PersistableStore.cpp:141-162`, bare `deserializeJson` at `:156`), and adding a filtered reader would
be a `lib/Serialization` API change. Each file is therefore parsed whole, **one document at a time**,
and freed before the next. The read is bounded by the file-size cap in A7. Rejected alternatives:
- `StreamingJsonParser` (`lib/JsonParser/StreamingJsonParser.h:6-30`) holds one row at a time. But it
  needs a depth-tracking callback state machine so that the link rows' own `u`/`r` keys
  (`PassageDoc.cpp:213-215`) are not mistaken for the passage's own keys. That is new, fiddly code
  for a store whose real size is 63 passages (`PassageDoc.h:37-38`).
- A filtered `readDocFromFileStreamed` overload is a shared-surface change for a memory saving of a
  few KB.

Memory cost (revised in pass 0, MAJOR 2): the parse costs **internal SRAM**, not PSRAM. ArduinoJson
7.4.2 builds a document from 1 KB variant pools plus one small allocation per distinct string, and
every block is under the 4096 B `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL` threshold. IDF therefore places
them in internal SRAM and spills to PSRAM only once internal SRAM is exhausted (the review cites
`Configuration.hpp:102-116`, `StringPool.hpp:44-62`, esp32s3 `sdkconfig:2153-2154`,
`heap_caps.c:117-124`). The peak is roughly the parsed size of the largest file, one file at a time.
That is the same cost `PassageFile::load` already pays when the reader opens that publication
(`src/study/StudyStore.cpp:49`). The sleep path has **more** internal heap than that reader load,
because `ActivityManager` exits the current activity and the whole stack before `SleepActivity::onEnter`
runs (`src/activities/ActivityManager.cpp:143-160`, reached via `goToSleep` → `replaceActivity`,
`:230-232`). So a file the device could load for the reader, it can parse here.

A PSRAM-backed `ArduinoJson::Allocator` was considered and rejected. No such allocator exists in this
repo (grep for `ArduinoJson::Allocator` in `src`/`lib`: none), and `BibleSearchStore.cpp:24-26`
has only raw `heap_caps_malloc` helpers. It would be a new cross-cutting pattern for a transient cost
the reader already pays. The device check logs `ESP.getFreeHeap()` **and** `ESP.getFreePsram()`
around the pick, so the real figure is measured, not asserted. The document is a local destroyed at
the end of each file's iteration.

**A5 — Per-file validation.** A file is used only when `readDocFromFileStreamed` returns
`DocReadStatus::Ok` and its `v` is in `1..study::PassageDoc::FORMAT_VERSION` (`PassageDoc.h:24`,
`PassageDoc.cpp:222`), and `p` is an array. A future-version file is skipped, never reinterpreted.
Rows are read field by field:
- `u` (string, required): the row is skipped unless `study::unitFromCompact(u)` succeeds
  (`Unit.h:47`), the same gate `PassageDoc::fromJson` applies (`PassageDoc.cpp:227-228`). That is a
  pure read of `lib/StudyStore`, not an edit.
- `e` (string, optional): it defaults to `u` when absent or when `unitFromCompact` rejects it, as
  `fromJson` does (`PassageDoc.cpp:232`).
  It is used only in the key (A10).
- `x` (string, required, non-empty).
- `r` (string, may be empty).
- `t` (array): the tag is the first element in `1..UINT16_MAX`, matching `fromJson`'s range filter
  (`PassageDoc.cpp:240-243`).

A row missing `u` or `x` is skipped, so no row the rest of the device ignores can appear on the sleep
screen. `x` and `r` are re-clamped with `utf8SafeSummary` to `MAX_SNIPPET_BYTES` /
`MAX_REFERENCE_BYTES`, as `PassageDoc::fromJson` does (`PassageDoc.cpp:237-238`), because the
renderer trusts its input. `PassageDoc::fromJson` itself is not used: it builds every row's full
`TaggedPassage` with links and fingerprints, and it rejects the whole file over one bad link.

**A6 — Enumeration: count, then a cyclic pass from a random start.** The directory is opened with
`Storage.open(sdpaths::PASSAGES_DIR)` and walked with `openNextFile()`, modelled on
`selectRandomSleepFile` (`SleepActivity.cpp:414-441`): a counting pass, then `rewindDirectory()`
and a second pass.
- An entry is eligible when it is a file, its name does not begin with `.`, and it ends in `.json`.
  That excludes `*.json.tmp`.
- **Pass 1** counts eligible entries by name only: no open-for-read, no parse. The count is bounded
  by `MAX_ENTRIES = 512` to guard a pathological directory.
- A start index `s = rng(count)` is drawn (revised in pass 0, MAJOR 3).
- **Pass 2** visits eligible entries in the order `s, s+1, …, count-1`, then rewinds and visits
  `0, …, s-1`.

So when the byte cap (A7) ends pass 2 early, the files it covered are a random contiguous window,
not the same leading entries on every sleep. Directory order depends on save history
(`writeDocToFileAtomic` removes and renames, `PersistableStore.cpp:111-117`), and the random start
removes that bias. The pubkey is the filename stem (`PassageFile.cpp:16`).

**A7 — Bounds.** There is no separate file-count cap (removed in pass 0, MAJOR 3), because bytes are
the real cost.
- `MAX_FILE_BYTES = PassageDoc::SAVE_BYTE_BUDGET + 4096` per file, checked with `file.size()` before
  parsing. An oversize file is skipped with `LOG_ERR`.
- `MAX_TOTAL_BYTES = 262144` summed over parsed files.

When the byte cap is reached, the scan **stops and uses the pick so far** if there is one.
Otherwise it returns `false` and the default screen draws. This refines the issue's "fall back if the
cap is hit". With the random start of A6, a partial scan is a uniform draw over a random window of
files. Throwing away a valid pick to show the Bible cover helps nobody.

The figures are not measured against the user's card. The file count and byte total of the real
store are unknown; research §4 gives only the passage count, 63. Because they are unmeasured, the
device check logs the count, the bytes read and whether the cap was hit.

**A8 — Sampling.** Reservoir sampling as the issue specifies: for the k-th eligible candidate, replace
the pick with probability 1/k. The RNG is Arduino `random(k)`, which is `esp_random() % k` on this
core (`WMath.cpp:52-62`, Arduino-ESP32 3.3.7). That is the same call the image picker uses
(`SleepActivity.cpp:433`). The sampler is pure and takes an injected `uint32_t (*)(void* ctx, uint32_t bound)`
so host tests can script it.

**A9 — No immediate repeats: two reservoirs.** Every candidate goes through one of two paths:
- *not recent*: into a uniform reservoir, as in A8;
- *recent*: kept only if it is the **oldest** recent one seen so far, by ring age (0 = newest).

After the scan the non-recent pick wins if one exists. Otherwise the oldest recent one is shown.

Rules added in pass 0 (MAJOR 1):
- **Age of a key** is its **newest** occurrence in the ring, the smallest age. The ring is walked
  newest-first, as `isRecentIndex` does (`CrossPointState.cpp:9-20`), and the walk stops at the first
  match. A key present twice therefore reports its most recent showing.
- **Tie-break** between recent candidates of equal age: the **first seen** in scan order is kept.
  Equal ages arise only from a genuine key clash (A10). Within one scan the order is the A6 cyclic
  order, whose start is random, so the survivor of a tie varies between sleeps.

With ≥ 2 passages whose keys differ, the just-shown passage (age 0) is never shown next, because
another candidate is either not recent or has age ≥ 1. With one passage, it is shown again. When
every passage is recent, the least recently shown one returns.

With 16 passages or fewer (`SLEEP_RECENT_COUNT`, `CrossPointState.h:15`), "oldest recent wins" settles
into a fixed cycle once every passage is in the ring. The image picker behaves the same way (window
`min(fill, fileCount-1)`, `SleepActivity.cpp:429-431`). It is listed under "Known limits" in the PR
body (pass 0, MINOR 5). This replaces the image picker's
20-reroll loop (`SleepActivity.cpp:430-436`), which needs the candidate count up front; a one-pass
stream does not have it.

**A10 — Ring key and storage.** The key is FNV-1a 32-bit over `pubkey + '/' + u + '/' + e`, with `e`
as resolved in A5. The end unit is included (pass 0, MAJOR 1) because two passages in one publication
may share a start unit: `PassageDoc::add` does not dedupe on start (`PassageDoc.cpp:91-107`). The
compact unit strings are `unitToCompact` output, `lib/StudyStore/StudyStore/Unit.h:46`, as stored.
The full filename stem is hashed, never a truncated copy. The hash is computed while the row is in
hand, so the slot does not store the pubkey (A19). The hash is written
inline in the pure header, modelled on `ZipFile::fnvHash64` (`lib/ZipFile/ZipFile.h:31-32`), which is
not reused because it would pull `ZipFile` into the sleep screen and its host test. `CrossPointState`
gains a third ring beside the two at `CrossPointState.h:23-28`:
`uint32_t recentStudySleep[SLEEP_RECENT_COUNT]`, `recentStudySleepPos`, `recentStudySleepFill`. It
serialises as JSON keys `recentStudySleep`, `recentStudySleepPos`, `recentStudySleepFill`, parsed and
clamped exactly as the existing rings are (`CrossPointState.cpp:71-94`).
- No `FORMAT_VERSION` bump. Older builds ignore unknown keys, as they already do for `bibleCoverPath`.
- `SAVE_BUDGET` (2048) holds: 16 × ≤ 10 digits + commas + keys ≈ 230 B on top of the ~1,190 B worst
  case (`CrossPointState.h:33-35`). The comment there is updated with the new figure.
- Key clashes still happen: a 32-bit hash collision, or two passages with an identical `u` and `e` in
  one publication, which `add` also permits. Either can only make two passages share recency for a
  few sleeps. The tie-break in A9 keeps that from starving one of them permanently.

There is **one** `ageOf`, in the pure header, over a `RingView { const uint32_t* ring; uint8_t pos;
uint8_t fill; }` (pass 0, MINOR 1). `CrossPointState` exposes only the raw ring fields and
`pushRecentStudySleep(uint32_t)`, reusing the existing push arithmetic (`CrossPointState.cpp:22-26`).
The screen code builds the view from `APP_STATE`. `CrossPointState` does not include anything under
`src/activities/`. The tested `ageOf` is the one the device calls.

**A11 — Persisting the ring.** After a successful pick, `APP_STATE.pushRecentStudySleep(key)` then
`APP_STATE.saveToFileAtomic()`. This mirrors `SleepActivity.cpp:447-448`, and it is the only write on
this path. It goes to `/.crosspoint/state.json`, not to a study store.

**A12 — Date line.** It shows only when `halClock.getDate(d)` returns true, which is the "never set"
signal (`HalClock.h:36-41`). The UTC hour and minute come from `halClock.getTime(h, m)` right after.
If `getTime` fails, the line is left out. A pure helper shifts the civil date by
`floor((h*60 + m + (q-48)*15) / 1440)` days (−1, 0 or +1), clamping `q` to 104 as `formatTime` does
(`HalClock.cpp:61-62`), and derives the weekday from days-since-epoch.
- The days↔civil conversion is written in the pure header, modelled on the file-local
  `daysFromCivil` in `src/network/WolWeekScan.cpp:22-29`, which the `ui` surface cannot export.
- The two RTC reads are not atomic, and `getTime` may serve a value up to 10 s old
  (`HalClock.cpp:18-23`). Across UTC midnight that can show the adjacent day for one sleep. That is
  accepted, because a single-read HAL API is a `hal` surface change for a one-sleep, once-a-day edge.

**A13 — Date format and strings.** The format is `"<Weekday> <day> <Mon>"`, e.g. "Sunday 27 Sep" /
"domingo 27 sep". Month names reuse `STR_MONTHS_SHORT` (`english.yaml:439`, `spanish.yaml:381`), read
with the same space-separated word-list pattern as `catalog::formatIndexDate`
(`lib/Catalog/Catalog/CatalogStamp.cpp:65-85`). A new `STR_WEEKDAYS` holds seven space-separated
names, Sunday first to match `Rtc::DateTime::weekday` (`Rtc.h:26`). The day-first order suits both
required languages. A per-language format string is not introduced.

**A14 — New strings**, appended at the end of `english.yaml` and `spanish.yaml`; other languages fall
back to English:
- `STR_STUDY_SLEEP`: "Study" / "Estudio" (the option label)
- `STR_WEEKDAYS`: "Sunday Monday … Saturday" / "domingo lunes … sábado"
- `STR_BOOKS_FINISHED`: "Books finished: %u" / "Libros terminados: %u" (count-neutral, pass 0 MINOR 6)

The chapter figure is formatted `"%u / %u"` with `CANONICAL_CHAPTER_TOTAL`
(`ChapterCompletion.h:26`). That is language-neutral, so it is not a string.

The worker edits the two YAMLs in-branch, as #161 did (`c6314b4f`), because a missing key fails
`pio run`. The `test/CMakeLists.txt` `add_subdirectory` line is added in-branch for local runs **and**
quoted in the PR body as the orchestrator hand-off (`.claude/agents/ui-dev.md`, "Shared files").

**A15 — Reference line and the title fallback.** It shows `r` in bold when it is non-empty. When `r`
is empty, the line is **left out**, which is the pattern `HighlightsActivity.cpp:100-107` already uses
for a passage with no reference. This deviates from the issue, which asks for the publication's
title. Research §1/§7: `PubKeyRegistry` holds no titles (`PubKeyRegistry.h:12-31`), and no store maps
pubkey → title. Non-Bible passages get an empty reference by construction:
`PassageSelectActivity::verseReference` returns `{}` without verse anchors
(`PassageSelectActivity.cpp:200-243`). **Settled by decision d1 (orchestrator, 2026-09-27):** omit the line; no follow-up issue — the PR body lists it under "Known limits" (non-Bible passages show no source line, same as the highlights screen).

**A16 — Tag pill.** The tag is the first non-`UNLABELLED` id in `t` (`TagPalette.h:31`). Its name
comes from `/.berean/tags.json` via `readDocFromFileChecked` + `TagPalette::fromJson`, then
`TagPalette::name(id)` (`TagPalette.h:53-54`), which also names retired tags. The pill is left out
when there is no tag, the palette read is not `Ok`, `fromJson` rejects it, or the name is empty. The
palette is read only after the pick, and only when the pick has a tag.

**A17 — Progress strip.** `/.berean/completion/bible.json` is read via `readDocFromFileChecked` +
`ChapterCompletion::fromJson`.
- `Ok` + accepted: draw the strip.
- `Missing`: draw the strip empty ("0 / 1189", no finished books). The user may simply not have
  read yet, and the strip is part of the screen's design.
- `Unreadable` / `ParseError` / rejected: `LOG_ERR` and leave the strip and its caption out. Never
  draw a wrong figure.

Book b's bar height is `max(MIN_BAR, maxBar × canonicalChapterCount(b) / 150)`. 150 is Psalms, the
largest, but the value is computed from the table rather than hardcoded. Each bar is an outline, with
the bottom `readCountInBook(b) / chapterCount(b)` filled. A finished book is solid. The caption is
`"N / 1189"` from `readCount()` (the same figure the launcher uses, `LauncherActivity.cpp:90-95`) plus
`STR_BOOKS_FINISHED`. All widths derive from `renderer.getScreenWidth()`.

**A18 — Layout and polarity.** The painter's first draw call is `renderer.clearScreen()`, which
removes the "Entering sleep" popup still in the framebuffer (`SleepActivity.cpp:526-532`), as
`renderDefaultSleepScreen` does (`:641`) (pass 0, MINOR 3). Then, top to bottom:
1. date, `UI_12`
2. a large opening quote `“` in `NOTOSERIF_18` bold, **black**
3. snippet in `NOTOSERIF_18` italic, centred, via `renderer.wrappedText(..., maxLines = 6)`
   (`GfxRenderer.h:299-303`)
4. reference in `UI_12` bold
5. the pill: `drawRoundedRect` around `SMALL_FONT` text
6. the strip and its caption
7. `berean_mark::draw` at 40 px plus `STR_BEREAN` in `SMALL_FONT` at the foot

It is a light background, and the screen is **not inverted**. This differs from
`renderDefaultSleepScreen`, which inverts for every mode but `LIGHT` (`SleepActivity.cpp:652-654`),
and it follows the issue's "light background". The issue's grey quote mark is drawn black, because
text drawing is `bool black` only (`GfxRenderer.h:283`) and the screen is 1-bit. Positions are
computed top-down from the measured line heights of each present element, and the whole content block
is centred vertically. It is drawn with the renderer directly, as `renderDefaultSleepScreen` and
`MigrationScreen` do (`SleepActivity.cpp:645-650`; `src/activities/boot_sleep/MigrationScreen.h:9-10`),
then `displayBuffer(HalDisplay::HALF_REFRESH)`.

**A19 — Candidate storage.** Each of the two reservoir slots (A9) is a fixed-size struct:
- `char snippet[SNIPPET_CAPACITY]`, `char reference[REFERENCE_CAPACITY]`
- `uint16_t tag`, `uint32_t key`, `uint8_t age`

There is no `pubKey` field (pass 0, MINOR 2), because the key is computed before the slot is filled.
`SNIPPET_CAPACITY = 121` and `REFERENCE_CAPACITY = 49` are the pure header's own `constexpr`s, so it
stays free of ArduinoJson. `StudySleepScreen.cpp`, which already includes `PassageDoc.h`,
`static_assert`s them against `PassageDoc::MAX_SNIPPET_BYTES + 1` and `MAX_REFERENCE_BYTES + 1`.

That is ≈ 180 B per slot. The pair is held in one `makeUniqueNoThrow<StudySleepPick>()` allocated at
the start of `study_sleep_screen::render` and freed on return. It is not on the stack, per the 256 B
local rule (CLAUDE.md, "Stack safety"). OOM → `LOG_ERR`, return `false`. Filling a slot copies with
`snprintf("%s")`; the source strings are already clamped (A5).

**A20 — No store writes, no mutex.** The sleep path runs on the Arduino loop task, and so does every
writer of these files (`PersistableStore.h:107-114`). Reads go through `HalStorage`, which holds
`storageMutex` per call.

## Architecture

```
src/activities/boot_sleep/
  StudySleepPick.h        pure, header-only, no ArduinoJson: FNV-1a key, RingView/ageOf, two-reservoir sampler,
                          civil-date shift + weekday, date-line formatter (word-list lookup)
  StudySleepScreen.h/.cpp  device side: study_sleep_screen::render(renderer) — scan, read palette/completion, draw
  SleepActivity.cpp        case STUDY -> study_sleep_screen::render(renderer) || renderDefaultSleepScreen()
src/CrossPointState.h/.cpp third ring (uint32_t), pushRecentStudySleep, JSON keys (no ageOf here)
src/CrossPointSettings.h   STUDY = 8
src/SettingsList.h         label slot
lib/I18n/translations/{english,spanish}.yaml  three keys
test/study_sleep_pick/     host tests for StudySleepPick.h
```

Modelled on:
- `src/activities/launcher/LauncherBible.h` + `test/launcher_bible/CMakeLists.txt`: a pure header
  beside an activity, tested with `${REPO_ROOT}/src` as the only include.
- `src/activities/boot_sleep/MigrationScreen.{h,cpp}`: a free-function painter in the same directory.
- `selectRandomSleepFile` (`SleepActivity.cpp:414-450`): directory scan, pick, ring push, save.

`StudySleepPick.h` includes nothing from Arduino, HAL or ArduinoJson. The scan code in
`StudySleepScreen.cpp` does the JSON field extraction and feeds `(pubKey, u, x, r, tag)` to the
sampler's `offer()`.

## Data and control flow

```
enterDeepSleep (main.cpp:253)
 └ SleepActivity::onEnter (SleepActivity.cpp:490)
    ├ popup "Entering sleep"                       (:526-532)
    └ case STUDY → study_sleep_screen::render(renderer)
        1 pick = makeUniqueNoThrow<StudySleepPick>()        OOM → false
        2 ring = APP_STATE study ring view
        3 pass 1: count eligible *.json (A6); s = rng(count)
          pass 2: for file in cyclic order from s, within byte caps (A7):
             JsonDocument doc; readDocFromFileStreamed(path, doc)   not Ok → LOG_ERR, next file
             version/array check (A5)                                  fail → LOG_ERR, next file
             for row in doc["p"]: extract (A5); key = fnv(pubkey/u/e); pick.offer(row, key, ageOf(ringView, key), rng)
        4 no candidate → return false                    (→ renderDefaultSleepScreen)
        5 chosen = pick.result()
        6 tag name (A16), completion (A17), date (A12/A13)
        7 draw (A18); displayBuffer(HALF_REFRESH)
        8 APP_STATE.pushRecentStudySleep(chosen.key); APP_STATE.saveToFileAtomic()
        9 return true
```

The ring is pushed after the draw. A failed draw path returns `false` before step 8, so a passage that
was never shown is not marked as shown.

## Error handling

| Condition | Behaviour |
|---|---|
| `PASSAGES_DIR` absent or not a directory | return `false` → default screen (no log; this is a fresh device) |
| No eligible row across all files | return `false` → default screen |
| A file not `Ok` (Unreadable/ParseError) | `LOG_ERR("SLP", …)`, skip the file, continue |
| Future `v`, or `p` not an array | `LOG_ERR`, skip the file |
| File over `MAX_FILE_BYTES` | `LOG_ERR`, skip the file |
| `MAX_TOTAL_BYTES` reached, or `MAX_ENTRIES` hit while counting | `LOG_INF`, stop the scan, use the pick if any (A7) |
| Candidate OOM | `LOG_ERR`, return `false` |
| Palette unreadable | no pill, `LOG_ERR` |
| Completion unreadable | no strip, `LOG_ERR`; `Missing` → empty strip |
| Clock unset / `getTime` fails | no date line |
| Ring save fails | `saveToFileAtomic` logs it; the screen is already drawn |

No path writes to `/.berean/`. Every `LOG_*` uses exact specifiers (`%u` with a `static_cast<unsigned>`,
`%s` with `.c_str()`, `PRIu32` for `ESP.getFreeHeap()`), because main builds with `-Wformat` and
format-attributed logging.

## Testing strategy

**Host (`test/study_sleep_pick/`, gtest, TDD — each test written and seen failing before the code):**
1. Uniform draw: with a scripted RNG over a fixed 4-candidate sequence, each candidate wins for the
   RNG value that selects it. The 1/k rule is exercised on every step.
2. Recent skip: a candidate at ring age 0 is never chosen while a non-recent one exists, for every
   RNG script.
3. Only one passage, and it is recent → it is chosen.
4. All recent → the oldest (largest age) is chosen, whatever the order of arrival.
4a. Two recent candidates with **equal** age → the first seen is kept (A9 tie-break).
5. `ageOf`: empty ring; wraparound at `pos`; `fill < 16` ignores stale slots; a key present **twice**
   in the ring reports its newest (smallest) age.
5a. Key: passages sharing `u` but differing in `e` get different keys; `e` absent → same key as `e == u`.
5b. Cyclic order: for `count = 5, s = 3` the visit order is `3,4,0,1,2`; `count = 1` → `0`;
    `count = 0` → nothing (the order helper is pure and in the header).
6. FNV key: known vectors (FNV-1a 32 of `""` = `0x811c9dc5`, of `"a"` = `0xe40c292c`), and pubkey/unit
   separation (`"ab"+"/"+"c" != "a"+"/"+"bc"`).
7. Date shift: `+0`; `q = 104` (UTC+14) at 23:00 UTC → next day; `q = 0` (UTC−12) at 05:00 → previous
