# Issue #182 — fit whole passages on the Study sleep screen

Research: `docs/superpowers/research/2026-09-27-issue-182-research.md`. Where this spec says "R§n",
it means section n of that note. Every claim about existing code cites a line that has been read.

## Problem

The Study sleep screen showed Galatians 5:4 starting at *"ley, …"*. There are three causes.

1. **A selection that crosses a page turn loses its start.**
   - `advancePage` sets `anchorIndex = -1` and discards the anchor's page
     (`src/activities/reader/PassageSelectActivity.cpp:153-161`).
   - `finalizeSelection` then builds the label from word 0 of the page where the user **ended**
     (`:377-378`).
   - The stored unit range is correct, because `selectionRange` falls back to `anchorOffset`
     (`:192-195`). Only the text is wrong.
2. **The stored text is capped at 120 bytes, and the tail is cut mid-word.** The cap is applied on
   save, on load and on the sleep path:
   - `PassageDoc::MAX_SNIPPET_BYTES = 120` (`lib/StudyStore/StudyStore/PassageDoc.h:32`);
   - on save (`PassageDoc.cpp:96`), on load (`:237`) and at sleep (`StudySleepScreen.cpp:102`);
   - the cut is `utf8SafeSummary`'s byte-wise tail cut (`lib/Utf8/Utf8.cpp:198-200`).

   Only 42.8% of Spanish NWT verses fit in 120 bytes (R§4).
3. **The sleep screen never adapts.**
   - It always wraps at 18pt italic with at most 6 lines (`StudySleepScreen.cpp:51,287-288`).
   - `wrappedText` ends the last line with `truncatedText`, which cuts **characters**
     (`GfxRenderer.cpp:1807-1812,1790-1792`).
   - Nothing checks the block against the available height (`StudySleepScreen.cpp:296-305`).

## Goal

A passage tagged from now on is stored with its text from the true start, up to a bounded length.
The sleep screen draws that text at the largest reader serif size that fits: 18, then 16, 14, 12pt,
italic. Only at 12pt does it end on a whole word followed by an ellipsis. The date, quote mark,
reference, tag pill, progress strip and footer keep their sizes and their order.

## Non-goals

- **Re-deriving text for passages saved before this fix.** They keep their stored `"x"` (≤ 120
  bytes), as the issue allows. See A7.
- **Resolving text from the unit index at sleep** (option A). It is rejected in R§4 and in D1 below.
- **Changing other readers of `"x"`:**
  - the highlights list (`HighlightsActivity.cpp:105,109`);
  - the link-label fallback (`PassageDoc.cpp:144`);
  - migration (`MigrationRunner.cpp:304`, `MigrationPlanner.cpp:37`).
- **Changing `SAVE_BYTE_BUDGET`** (`PassageDoc.h:30`). The batch context says to keep it.
- **`GfxRenderer::wrappedText` / `truncatedText`.** Other screens use them. The sleep screen stops
  calling `wrappedText`; neither function changes.
- **Selecting backwards across a page.** `advancePage` only moves forward (`:135-168`), and this fix
  keeps that.

## Decisions

### D1 — store the display text at save time (option B)

Option A would resolve the text from the unit range at sleep time. That needs:

- a pubkey→path lookup that does not exist (`PubKeyRegistry.h:23-29`);
- `Epub::load`, which can rebuild the CSS cache and remove the sections directory
  (`lib/Epub/Epub.cpp:374-398`);
- `UnitIndexCache::unitsFor`, which builds and persists index entries under `/.berean/units`
  (`UnitIndexCache.h:33-36`);
- `SpineHtmlStream::stream`, which may inflate the spine and draw a popup
  (`SpineHtmlStream.cpp:28-44`).

That is unbounded I/O with branches that write, on a path that must never write
(`StudySleepScreen.cpp:133-134`).

Option B has the text in hand at save time and costs a bounded ~400 B per long passage (R§4). This is
not a "both options costly" case, so no decision is raised.

### D2 — a new optional field `"w"`, format v3, written only when needed

This mirrors how #86 added `"k"`: `0bbcd47d`, `PassageDoc.h:20-25`, `PassageDoc.cpp:189-190`.

- `TaggedPassage` gains `std::string displayText`: the passage's text when it is longer than the
  snippet, and empty otherwise.
- `"x"` keeps its meaning and its 120-byte cap. `"w"` holds up to `MAX_DISPLAY_TEXT_BYTES`.
- The version written is the lowest one that holds everything in the file:

  | File contents | Version written |
  |---|---|
  | Any passage has `displayText` | 3 (`FORMAT_VERSION`) |
  | Otherwise, any passage has links | 2 |
  | Neither | 1 |

  A file with no long passage therefore stays readable by v1 and v2 builds.
- A v2 build refuses a v3 file (`isKnownFormatVersion`, `FormatVersion.h:13-15`) instead of loading
  it without `"w"` and erasing it on its next save.

### D3 — `MAX_DISPLAY_TEXT_BYTES = 512`

At 12pt, the full layout holds about 375 B. With no date, tag or strip it holds about 580 B (R§4:
11 lines hold 375 B; the extra 209 px are 6 more lines). 512 B covers the full layout completely and
nearly all of the bare layout. Anything past the cap would be cut by the ellipsis rule anyway.

### D4 — the worst-case budget test is relaxed from ≥ 100 to ≥ 70

`PassageDocTest.cpp:602-604` fills every field with `"`, which JSON escapes to 2 bytes, and asserts
that a worst-case passage is under 1,700 B and that at least 100 fit the budget. Adding a full `"w"`
of 512 `"` characters adds about 1,030 B, so the worst case is about 2,730 B and 73 fit. The
`MAX_LINKS_PER_PASSAGE` comment's "over a hundred of them" (`PassageDoc.h:36-38`) is updated to
match.

The realistic figure is unaffected: 63 passages with a full `"w"` each stay under about 64 KB, a
third of the budget. A new test asserts this, next to the existing
`HoldsTheUsersRealStoreWithRoomToSpare` (`PassageDocTest.cpp:271-275`).

## Labelled assumptions

Each of these is a behavioural decision the review should attack.

- **A1 — The acceptance example "5–7 verses shown whole" cannot be met, and the issue's own fallback
  governs.** The issue says: "Only if the smallest size still doesn't fit, truncate at a word
  boundary with an ellipsis."
  - In the full layout, 12pt holds about 375 B. Five verses run a median of 705 B and seven about
    993 B; 96–99% of such windows fit at no allowed size (R§4).
  - So a 5–7-verse passage shows at 12pt from its true start, ending "…word…".
  - The device check becomes two checks: a 2–3-verse passage shows whole at a smaller size, and a
    5–7-verse passage shows at 12pt, starting correctly and ending on a whole word plus `…`.
  - The 12pt floor, and the fixed sizes of everything around the text, come from the issue and are
    not changed.
- **A2 — `"w"` is written only when the text is longer than `MAX_SNIPPET_BYTES`.** At or under 120
  bytes, `"x"` already holds all of it, and writing `"w"` would force v3 on files older builds could
  otherwise read.
- **A3 — `"x"` stays 120 bytes, even when `"w"` exists.**
  - A long passage stores both, duplicating ≤ 120 B. In exchange no other `"x"` reader changes.
  - `"x"` is still derived from the same label exactly as today (`PassageDoc.cpp:96`).
- **A4 — A stored `"w"` is refused, not repaired, on load, as `"k"` is (`PassageDoc.cpp:55-83`).**
  `fromJson` fails the whole load when `"w"` is:
  - present but not a string;
  - longer than `MAX_DISPLAY_TEXT_BYTES`;
  - or no longer than `MAX_SNIPPET_BYTES`, which this build never writes.

  A failed load latches saving off (`FormatVersion.h:20-33`). Truncating on load would lose text
  silently. It would also let a future build widen the cap without a version bump, and older builds
  would then cut what it wrote.
- **A5 — The sleep path is lenient per row, as it is today.**
  - `offerRow` uses `"w"` when it is a string of 1..`MAX_DISPLAY_TEXT_BYTES` bytes. Otherwise it
    uses `"x"`, as today.
  - Today's sleep path already does not mirror `fromJson`'s whole-file refusals: it never inspects
    `"k"` (`StudySleepScreen.cpp:94-117`). A damaged row should still show something rather than
    blank the screen.
  - It never writes.
- **A6 — Capture ends on a word boundary, with ` …` appended when it had to stop early.**
  - The label builder stops before the word that would push the text, plus a reserved 4 bytes for
    `" …"`, past `MAX_DISPLAY_TEXT_BYTES`. It then appends `" …"` (U+2026).
  - So a stored text is never cut mid-word, and the sleep screen shows a capture-truncated passage
    as truncated even when it fits.
  - `PassageDoc::add` still runs `utf8SafeSummary(displayText, MAX_DISPLAY_TEXT_BYTES)` as a
    defensive bound. The builder guarantees it never cuts.
- **A7 — Passages saved before the fix show their stored `"x"` unchanged,** including a mid-word end
  from the old cap. Nothing marks them: a 120-byte `"x"` cannot be told apart from a natural
  120-byte text.
- **A8 — The fitter breaks only on ASCII space (U+0020), as `wrappedText` does**
  (`GfxRenderer.cpp:1816`). U+202F and U+00A0 in the NWT markup stay non-breaking.
- **A9 — A single word wider than the column is never cut.** It goes on its own line and is drawn
  centred, which may clip at both margins. At 12pt that takes a word of more than ~60 characters,
  which does not occur in the measured text.
- **A10 — At least one line is always shown.** If the space left for text is smaller than one 12pt
  line, the fitter still returns one line, and the block may push into the gap above the footer mark.
  With the chrome sizes fixed this cannot happen on 800 px (R§4: 392 px available).
- **A11 — The ellipsis attaches to the last kept word as `word…`,** with no space. When even
  `firstWord…` is too wide, it is kept anyway (A9).
- **A12 — The quote mark stays 18pt bold at its current position**, one 18pt line above the text
  (`StudySleepScreen.cpp:314-315`). Only the passage lines change size.
- **A13 — Cross-page capture covers every page the selection crosses.**
  - Before each forward turn, the words from the anchor (on the anchor's page) or from word 0 (on a
    later page) to the end of the page are appended to the builder.
  - At finalize, words 0..`endIndex` of the final page are appended.
  - When the anchor and the end are on the same page, the behaviour is exactly today's `lo..hi` walk
    (`:377-378`).
- **A14 — Word order is block-walk order, as `selectionLabel` uses today** (`:251-262`). An RTL line
  keeps today's behaviour, which is out of scope.

## Architecture

It is built from two pure headers, each modelled on
`src/activities/boot_sleep/StudySleepPick.h`: no Arduino, no HAL, no ArduinoJson, and host-tested.

### 1. `src/activities/reader/PassageLabel.h` (new)

`PassageLabelBuilder` holds a `std::string`, a byte cap and a `truncated` flag.

- `bool addWord(const char* text, size_t length)`:
  - joins words with one space;
  - returns false, and sets `truncated`, once the next word would break the A6 reservation;
  - is a no-op after that.
- `std::string take()` returns the text, with `" …"` appended when `truncated`.

It is modelled on `ReturnStack.h`, a pure header beside the reader and tested by
`test/return_stack/`.

### 2. `src/activities/boot_sleep/StudySleepFit.h` (new)

```cpp
struct FitSize { int lineHeight; };  // one per candidate size, largest first
using MeasureFn = int (*)(void* ctx, uint8_t sizeIndex, const char* text);
struct FitResult { uint8_t sizeIndex; std::vector<std::string> lines; bool ellipsized; };
FitResult fitPassage(std::string_view text, const FitSize* sizes, uint8_t sizeCount,
                     int maxWidth, int maxHeight, MeasureFn measure, void* ctx);
```

- It takes a function pointer plus a context, the same shape as `RandomFn`
  (`StudySleepPick.h:82,98`). There is no `std::function`, per `CLAUDE.md`.
- For each size, largest first, it wraps greedily on spaces. It returns the first size whose
  `lines × lineHeight ≤ maxHeight`.
- Otherwise it uses the last size:
  1. keep `max(1, maxHeight / lineHeight)` lines;
  2. drop words from the end of the last line until `line + "…"` measures ≤ `maxWidth`;
  3. set `ellipsized`.

### 3. `PassageDoc` / `TaggedPassage`

- Add `displayText` and `MAX_DISPLAY_TEXT_BYTES = 512`.
- Set `FORMAT_VERSION = 3` and add `LINKS_FORMAT_VERSION = 2`, keeping `LINKLESS_FORMAT_VERSION = 1`.
- `add()` normalises `displayText` (A2, A6), `toJson` writes `"w"` (D2), and `fromJson` validates it
  (A4).

### 4. `StudyStore::addPassage`

Sets both `passage.snippet` and `passage.displayText` from the one label (`StudyStore.cpp:286`). The
signature does not change.

### 5. `PassageSelectActivity`

- A `PassageLabelBuilder` member, reset in `commitAt` when the first anchor is set (`:308-315`).
- `advancePage` feeds the outgoing page's words, from `anchorIndex` or from 0, **before** the swap
  (`:150-163`).
- `finalizeSelection` feeds words 0..`endIndex`, or `lo..hi` when `anchorIndex >= 0`, and passes
  `take()` to `addPassage`.
- `selectionLabel`'s walk (`:245-268`) becomes `appendWords(lo, hi, builder)`. The
  `LABEL_SCAN_BYTES` constant and its stale 72-byte comment (`:246-250`) are removed.

### 6. `StudySleepPick.h` / `StudySleepScreen.cpp`

- `SNIPPET_CAPACITY` becomes `TEXT_CAPACITY = 513`, `Candidate::snippet` becomes `text`, and the
  `static_assert` points at `MAX_DISPLAY_TEXT_BYTES + 1` (`StudySleepScreen.cpp:63`).
- `offerRow` prefers `"w"` (A5).
- `drawScreen`:
  1. computes the chrome height first: date, the 18pt quote line, reference, pill and strip, as
     today (`:296-300`);
  2. calls `fitPassage` with `maxHeight = areaBottom - viewTop - chrome`;
  3. draws the returned lines at the chosen font id with `EpdFontFamily::ITALIC`.
- The measure callback calls `renderer.getTextWidth(fontId, text, EpdFontFamily::ITALIC)`
  (`GfxRenderer.h:278`). That is the same width `drawCenteredText` uses to centre
  (`GfxRenderer.cpp:632`), so wrapping and drawing agree.
- The candidate sizes are `NOTOSERIF_18/16/14/12_FONT_ID` (`src/fontIds.h:4-7`), all registered with
  italic faces (`src/main.cpp:68-92,306-311`).

## Data flow

```
select (page N: anchor … end of page) --advancePage--> builder += words[anchor..last]
select (page N+k: 0 … end)            --finalize-----> builder += words[0..end]
builder.take() -> StudyStore::addPassage(label)
  -> TaggedPassage{snippet=label, displayText=label}
  -> PassageDoc::add: snippet=summary(label,120); displayText=label if >120 else ""
  -> toJson: "x", and "w" when non-empty; v = 3 | 2 | 1
sleep: offerRow: text = valid "w" ? "w" : "x" -> Candidate.text[513]
  -> fitPassage(text, {51,45,40,34}, width, space) -> lines at chosen size -> draw
```

## Resources

| Where | What | Cost | Why this choice |
|---|---|---|---|
| Selection | `PassageLabelBuilder` string | ≤ 512 B of heap | Held only while `PassageSelectActivity` lives. A stack buffer would exceed the 256 B local limit (`CLAUDE.md`). |
| Sleep | `Sampler`'s two `Candidate`s grow by 2 × 392 B | ~784 B more of the existing heap allocation (`StudySleepScreen.cpp:348`) | Not on the stack. |
| Sleep | `fitPassage` builds at most one line set per size | `lines.reserve(maxLines)` | The line strings are short-lived. `wrappedText` uses the same pattern today (`GfxRenderer.cpp:1799-1858`). |
| Store | Per long passage | ≤ ~520 B of raw JSON | The user's store stays under 64 KB against 200 KB. |

## Error handling

- **Save.**
  - `PassageDoc::add` over budget returns false.
  - `StudyStore::addPassage` rolls back and reports `STR_HIGHLIGHTS_SAVE_FAILED`, as today
    (`StudyStore.cpp:294-298`, `PassageSelectActivity.cpp:386-390`).
  - The write stays `writeDocToFileAtomic` through `PassageFile`, unchanged.
- **Load.** A bad `"w"` fails `fromJson` (A4). The caller latches `loadRefused`, as it does for bad
  links.
- **Sleep.**
  - A bad `"w"` falls back to `"x"` (A5).
  - An unknown version still skips the file (`StudySleepScreen.cpp:141-145`), and v3 is known to
    this build.
  - Nothing is written under `/.berean/`. `APP_STATE.saveToFileAtomic()` (`:378`) writes
    `/.crosspoint/`, as today.
- **Fitter.** An empty text returns zero lines, and `offerRow` already drops empty snippets
  (`:103`). A non-positive width or height returns one line (A10). It never loops without progress:
  each drop removes a word.

## Testing strategy

All tests are written first and must fail before the code that passes them.

### `test/passage_doc/PassageDocTest.cpp` (existing suite)

- A text under 120 B: no `"w"`, and `v` stays 1.
- A text over 120 B: `"x"` is 120 B, `"w"` holds the whole text, and `v == 3`.
- The round trip preserves `displayText`.
- **Old files load:** a hand-built v1 and a v2 JSON without `"w"` both load, with an empty
  `displayText`.
- **Refused by an older reader:** a file with `"w"` writes `v > 2`. This mirrors
  `AVersionOneReaderRefusesAFileCarryingLinks` (`:431-444`).
- **Refused on load:**
  - a non-string `"w"`;
  - a `"w"` over the cap;
  - a `"w"` of ≤ 120 B (A4).
- Budget:
  - worst case ≥ 70 per budget (D4);
  - 63 passages with a full `"w"` stay under 64 KB.

### `test/passage_label/PassageLabelTest.cpp` (new suite)

- The words join with single spaces.
- **Across a page, the start is kept:**
  - feed the anchor page's words from the anchor, then the next page's words 0..end;
  - the text starts with the anchor word.
- The cap stops on a word boundary and ends with `" …"`. The result is always ≤ the cap.
- Words after truncation are ignored.

### `test/study_sleep_pick/StudySleepFitTest.cpp` (new file in the existing executable)

These tests use a fake measure function: fixed px per byte, per size.

- A short text picks size 0 (18pt).
- A text that overflows 18pt but fits 14pt picks 14pt, not 12pt.
- A text that overflows 12pt:
  - fills `maxHeight / 34` lines;
  - the last line ends with `…`;
  - every line is made of whole words from the input;
  - the first word is the input's first word.
- There is no ellipsis at a larger size, even when the text only just fits.
- An over-wide single word stays whole (A9), and a zero height still gives one line (A10).
- The existing capacity test (`StudySleepPickTest.cpp:174-180`) is renamed for `TEXT_CAPACITY`.

### Registration and checks

- `test/CMakeLists.txt` gains `add_subdirectory(passage_label)`, which the batch context allows.
- `pio run` must build with zero new warnings.
- `./bin/clang-format-fix` runs over the whole tree.

### Device checks (the human tester)

1. A one-verse passage shows at 18pt.
2. A 2–3-verse passage shows whole at a smaller size.
3. A 5–7-verse passage shows at 12pt, starting at its first word and ending `word…` (A1).
4. Highlight across a page turn, sleep, and confirm the text starts at the anchor word.
5. No text overlaps the reference, tag or strip.
6. A passage saved on v1.19.x still shows its old snippet.
