# Issue #206 design — typed Bible references in verse search

Issue: #206. Research: `docs/superpowers/research/2026-09-30-issue-206-research.md`. Branch
`feature/206-typed-references`, base `67eaaf1e`. Every `file:line` below was read on this branch.

## Problem

Verse search only finds words. `BibleSearchActivity` runs `BibleSearch::runQuery` over the typed
text (`BibleSearchActivity.cpp:506-540`), and nothing in the repo parses a Bible reference. A
reader who knows where they want to go (`Isa 40:31`, `Gén 1`, `Juan 3:16`) has to go through the
three-level book → chapter → verse grid instead. Typing a reference today returns word hits for
the tokens `isa`, `40`, `31` (`Fold.h:27-33`, `Query.h:25-30`), which is almost never useful.

## Goal

When the typed query reads as a reference, search shows a top row **"Go to Isaiah 40:31"** above
the word hits. Selecting it opens the reader at that verse, or at the top of the chapter for a
chapter-only reference. Book names and abbreviations come from the publication itself, matched
case- and accent-insensitively with the same fold search already uses.

## Non-goals

- **No reference jump before the search index exists.** The keyboard only opens once the index
  opens (`BibleSearchActivity.cpp:219-231`); this change keeps that gate (A1).
- No hardcoded per-language book table. Names and abbreviations come from the EPUB, as decided
  for the book grid (PR #90; `BibleNavigationActivity.cpp:89-96`).
- No reference parsing elsewhere (Home, reader menu, "Go to…" sheet). Those are other overhaul
  phases.
- No highlighting of a verse range in the reader. A range opens at its first verse (A7).
- No change to the index format, to `IndexReader`, or to any store. Nothing is written.
- No new UI component, font or icon. The row is an ordinary `ListItem`.

## Assumptions (each one is a decision the review should attack)

- **A1 — Index-gated.** References resolve through the search index's verse table, so they work
  exactly when word search works. Resolving before the index exists would need `UnitIndexCache`
  and `VerseAnchors` per chapter (the grid's path, `BibleNavigationActivity.cpp:246-281`), which
  this screen does not own. Out of scope.
- **A2 — Grammar.** A reference is `<book> <chapter>[:<verse>[-<verse>]]`, where `<book>` is one
  or more words that may start with a digit (`1 Juan`), and the numbers are ASCII decimal. The
  chapter/verse separator is `:` only — what NWT prints (`Isaiah 40:31`) and what the keyboard's
  symbol layer has (`FreeInkUI.cpp:169`). `.` and `,` are not separators, so `Juan 3.16` is not
  a reference. The range dash is ASCII `-` (en dash `–` also accepted, since the fold does not
  touch it and a pasted reference may carry it). Spaces around `:` and `-` are allowed.
- **A3 — A chapter is required.** `Genesis` alone, or any query not ending in a number, is never
  a reference. This is the main guard against false positives on ordinary words.
- **A4 — Normalisation.** Both the query's book part and every candidate name are reduced the same
  way: `BibleSearch::foldAppend` (lower-case, strip Latin diacritics, ñ→n, `Fold.h:18-23`), then
  every byte that is not an ASCII letter or digit and not part of a non-ASCII codepoint is
  dropped (spaces, `.`, `-`). So `Gén.` → `gen`, `1 Crón.` → `1cron`, `El Cantar de los Cantares`
  → `elcantardeloscantares`, and `1Juan`, `1 juan` and `1 Juan` all meet. Cyrillic and Greek pass
  through the fold unchanged (`Fold.h:21`), so they match case-sensitively; accepted.
- **A5 — Matching.** Candidates are, for each book, its full name (`BibleBookNameTable`) and its
  publication abbreviation (nav link text). In order:
  1. **Exact**: a candidate equal to the normalised book part. If exactly one book has an exact
     match, it wins even when the text also prefixes other books (English `Phil` → Philippians
     via `Phil.`, even though it prefixes `Philemon` / `Philem.`). More than one book exact → not
     a reference.
  2. **Unique prefix**: otherwise, the books with any candidate that starts with the normalised
     book part. Exactly one book → it wins (`Isa` → Isaiah, `Salmo` → `Salmos`, `Gene` →
     Genesis). Zero or several → not a reference (`Ju 3` → none).
  3. The book part must normalise to at least 2 bytes (`BibleSearch::MIN_TOKEN_BYTES`,
     `Fold.h:13`), so `a 3` or `1 3` are never references.
  4. A **prefix-only** match needs at least 3 normalised bytes. Two-letter function words
     otherwise prefix exactly one book on the real publications — `de 3` → Deuteronomy, `la 3` →
     Lamentations, `el 3` → El Cantar de los Cantares (spec review 0, MINOR 6) — which breaks the
     issue's "no false positives on ordinary words". Exact two-byte abbreviations (`Is.`, `Ps.`,
     `Os.`) still match under rule 1; the price is that informal two-letter forms that are not the
     publication's abbreviation (`Ro 12`, `Ez 1`) get no row.
- **A6 — Numbers.** Chapter and verse are 1..255: the index stores them as `u8`
  (`IndexFormat.h:53-59`; `BibleSearchIndexer.cpp:198-202` skips anything larger). 0, an empty
  number, more than three digits, or a range end below its start → not a reference.
- **A7 — Ranges.** `Juan 3:16-18` is parsed and kept (the label shows it) but opens at verse 16.
  The end verse is not checked against the index.
- **A8 — Single-chapter books.** For Obadiah, Philemon, 2 John, 3 John and Jude, a lone number is
  a verse: `Jude 3` → Jude 1:3. Implemented without a book list: if the parsed reference is
  chapter-only (`verse == 0`), `(book, N)` has no chapter entries, `N > 1`, and the book's only
  chapter is 1 (no entry for `(book, 2, *)`), the reference becomes `(book, 1, N)`. `Jude 3:1`
  is never rewritten; it is simply not found (A9). This mirrors how the grid treats those books as having no chapter
  level (`BibleNavigationActivity.cpp:263-268`).
- **A9 — Missing places show no row.** A chapter the index lacks (`Gen 51`) or a verse the index
  lacks (`Juan 3:99`) yields no Go-to row, rather than a jump to a nearest place the reader did
  not ask for. The word search still runs.
- **A10 — Chapter-only opens the chapter top.** `Gen 1` opens the chapter's spine with no offset,
  landing on the chapter heading, as the grid's fallback does
  (`BibleNavigationActivity.cpp:246-252`). Each chapter is its own spine document in these
  publications (1,189 verse documents, `BibleSearchStore.cpp:133-135`), so the first verse
  entry's spine is the chapter's.
- **A11 — Word search still runs.** A reference query is also a word query; its hits appear under
  the Go-to row as today. When there are no word hits but there is a Go-to row, the "No verse
  contains all of these words" line (`BibleSearchActivity.cpp:864-870`) is not drawn: the query
  was understood, and the line would contradict the row under it. For the same reason the
  header's `"Results: %d"` (`drawChrome`, `BibleSearchActivity.cpp:937-942`) counts the Go-to row:
  it shows `results.size() + (goTo.found ? 1 : 0)`, with the `+` form still driven by
  `resultsTruncated`. No new string.
- **A12 — Row order and selection.** Row 0 stays "Edit search"; the Go-to row is row 1; word hits
  follow. The initial selection is the Go-to row when present, otherwise the first hit as today
  (`BibleSearchActivity.cpp:532`).
- **A13 — Label.** `tr(STR_BIBLE_SEARCH_GO_TO)` = `"Go to %s"` / `"Ir a %s"`, where `%s` is the
  publication's **full** book name plus `c`, `c:v` or `c:v-w` — the same name the hit rows use
  (`BibleSearchActivity.cpp:572-578`), whatever the user typed. No subtitle.
- **A14 — Abbreviations are loaded by the name table.** `BibleBookNameTable::load` switches its
  scanner to `collectText=true` and keeps each book's nav label, as the grid does
  (`BibleNavigationActivity.cpp:60-96`). The grid keeps its own `bookAbbrev` copy untouched; it
  calls `joinToc` directly (`:82`), not `load`, so it is unaffected.

## Architecture

Two new pieces and a change to one activity. All in the ui surface
(`src/activities/reader/`), plus one test.

### 1. `src/activities/reader/TypedReference.{h,cpp}` — pure parser and resolver

Modelled on `BibleReference.h` ("Free of Arduino and the Epub library so test/ui_layout can
exercise it", `BibleReference.h:5-7`), and on `test/bookmark_doc/CMakeLists.txt:3`, which builds a
`src/*.cpp` into a host test. Depends only on `lib/BibleSearch` (`Fold.h`, `IndexReader.h`).

```cpp
struct TypedReference {
  uint8_t book = 0;        // canonical 1-66; 0 = not a reference
  uint8_t chapter = 0;
  uint8_t verse = 0;       // 0 = chapter only
  uint8_t verseEnd = 0;    // 0 = no range
};

// Per-book candidate names laid out as fixed-stride rows, as BibleBookNameTable
// stores them; row i is canonical book i + 1 and each row is NUL-terminated.
// Entries may be empty. A stride view needs no pointer array on the stack.
struct BookNameSource {
  const char* names = nullptr;
  size_t nameStride = 0;
  const char* abbreviations = nullptr;
  size_t abbreviationStride = 0;
  int count = 0;
};

// A2-A6: shape and book match only. Never touches the index.
TypedReference parseTypedReference(std::string_view query, const BookNameSource& books);

// A8-A10: looks the reference up in the verse table.
struct ResolvedReference {
  bool found = false;
  TypedReference reference;          // after the A8 rewrite
  uint16_t spine = 0;
  std::optional<uint32_t> offset;    // empty for chapter-only (A10)
};
bool resolveTypedReference(const BibleSearch::IndexReader& reader, const TypedReference& ref,
                           ResolvedReference& out);  // false only on an I/O failure or malformed table
```

**Parsing** works from the right: trim, split off the trailing number group
(`c`, `c:v`, `c:v-w`), then treat everything before it as the book part and match it (A5).
Normalised strings are built into fixed `char[]` buffers of `MAX_QUERY_BYTES + 1` (64 + 1,
`BibleSearchActivity.h:72`) and `NAME_BYTES` (48, `BibleBookNameTable.h:25`) — not `std::string`,
per the string policy. Normalising a candidate needs `foldAppend`, which appends to a
`std::string` (`Fold.h:23`); the parser uses one `std::string` reserved once to the larger buffer
size and cleared per candidate, so a parse costs one allocation. It runs once per entered query,
never per frame.

**Resolving** is a lower-bound binary search over the verse table by `(book, chapter, verse)`
through `IndexReader::verse(n, entry)` (`IndexReader.h:63`). The table is written in canonical
order (`IndexFormat.h:11`; spines fed book by book, `BibleSearchStore.cpp:146-156`). About 15
probes for ~31,100 verses. Each probe is a direct 9-byte `readAt` on the `ByteSource`
(`IndexReader.cpp:61-64,95-103`) — on the device a `seek` + `read` through `HalFile`
(`BibleSearchStore.cpp:29-38`); the reader's 4 KB page serves only postings (`IndexReader.cpp:77-92`)
and is not involved. No allocation. The resolve time is logged beside the existing query timing
(`BibleSearchActivity.cpp:524-525`). Chapter-only searches `(book, chapter, 0)` and takes the
first entry if its book and chapter match. A8 costs at most two more searches.

A lower bound that lands at `verseCount` (a reference past the last verse of the table, e.g.
`Apoc 23`) is **not found**, checked before any `verse()` call: `verse(n)` also returns false for
`n >= verseCount` (`IndexReader.cpp:96`), and that must not be reported as an I/O failure.

### 2. `BibleBookNameTable` gains abbreviations (A14)

`src/activities/reader/BibleBookNameTable.{h,cpp}`:

- `load()` constructs `BibleNav::Scanner scanner(/*collectText=*/true)` and uses `takeBookNav()`
  instead of `take()` (`BibleBookNameTable.cpp:33-43`; the scanner API is
  `BibleNavScanner.h:46,62`).
- New member `char abbreviations[MAX_BOOKS][ABBREV_BYTES]` with `ABBREV_BYTES = 16`, the size the
  grid already uses (`BibleNavigationActivity.h:43`), filled with `copyUtf8Truncated`
  (`BibleBookNameTable.cpp:20-25`). An abbreviation cut at 16 bytes still matches by prefix.
- New accessor `abbreviationForBook(uint8_t book)`, `""` out of range, like `forBook`
  (`BibleBookNameTable.h:36-38`).
- `joinToc` clears every abbreviation; `load()` copies `page.labels` into them **after**
  `joinToc` returns. A grid-side table (which calls `joinToc` only) therefore reports `""`.
- `BookNameSource` is filled from `&names[0][0]` / `NAME_BYTES` and `&abbreviations[0][0]` /
  `ABBREV_BYTES`, via a `nameSource()` accessor, so no per-query pointer arrays are built.

**Memory:** +1,056 B (66 × 16) in each `BibleBookNameTable`, inside the heap-allocated activity
object that owns it (`BibleSearchActivity.h:110`, `BibleNavigationActivity.h:58`). Internal SRAM
unless the activity exceeds the 4,096 B PSRAM routing threshold (project memory note
"ESP32-S3 PSRAM auto-routing threshold"); `BibleSearchActivity` already holds two `Row[16]` arrays
of ~240 B per row (`BibleSearchActivity.h:90-96,145,151`), so it is well over that and the object
lands in PSRAM. Rejected alternative: a separate abbreviation array only in the search activity —
the same bytes, but the load code would be duplicated beside the one already in `load()`. The
transient `BookNavPage` label strings (66 short `std::string`s) are freed when `load()` returns.

### 3. `BibleSearchActivity` shows and follows the row

`src/activities/reader/BibleSearchActivity.{h,cpp}`:

- New members, loop-task written, render-read under `RenderLock` like `results`
  (`BibleSearchActivity.h:142-143`): `ResolvedReference goTo;` and `char goToLabel[REFERENCE_BYTES + 16]`.
- `runSearch()` (`BibleSearchActivity.cpp:506-540`): before `runQuery`, parse with a
  `BookNameSource` built from `bookNames`, then resolve. Both are published in the same
  `RenderLock` block that publishes `results`, and `nav.reset` uses A12's row.
- One helper, `int firstResultRow() const` = `1 + (goTo.found ? 1 : 0)`. **Every** row↔result
  conversion goes through it: `listCount()` (`:542-544`), `ensureRows()` (`:546-551`: `first =
  max(listTop, firstResultRow()) - firstResultRow()`, `end = min({listTop + max(visibleRows, 1) -
  firstResultRow(), total, first + ROW_CACHE})`), `activateIndex()` (`:668-676`), `buildResults()`
  (`:885-899`) and `nav.reset` (`:532`). The plan includes a grep of the file for `- 1` and `, 1)`
  so no literal mapping survives (spec review 0, MAJOR 1: missing `ensureRows` leaves the top hit
  blank after any scroll).
- `activateIndex(1)` with a Go-to row → `finishWithReference()`, which mirrors `finishWithVerse`
  (`:678-696`): `leaving = true; app.clearTapFlash(); setResult(ChapterResult{spine, "", offset});
  finish();`. The reader already honours an empty `offsetJump` (`EpubReaderActivity.cpp:750-752`,
  `ActivityResult.h:30-37`).
- `buildResults()` gives the row `label = goToLabel`, no subtitle, and skips the empty-results
  line when `goTo.found` (A11).
- New i18n key `STR_BIBLE_SEARCH_GO_TO` (english `"Go to %s"`, spanish `"Ir a %s"`), handed off in
  the PR body (shared file, `.claude/agents/ui-dev.md` "Shared files").

## Data and control flow

```
keyboard OK → onQueryEntered (copy ≤ 64 B)                       BibleSearchActivity.cpp:494-504
  → enterState(Searching) → frame lands → runBusyWork → runSearch  :182-206
      parseTypedReference(query, names+abbreviations)   pure, no I/O
      if parsed: resolveTypedReference(*reader, ...)     ≤ ~45 verse-table reads
      runQuery(*reader, query)                           unchanged       :515
      RenderLock { results, goTo, goToLabel, nav.reset(firstResultRow or Go-to row) }
  → Results list: [Edit search] [Go to …]? [hit] [hit] ...
tap / confirm on Go to → finishWithReference → ChapterResult{spine, "", offset?}
  → EpubReaderActivity SEARCH_BIBLE callback → navigateTo       EpubReaderActivity.cpp:744-753
```

Everything new runs on the loop task, where every index read already happens
(`BibleSearchActivity.h:38-40`); `render()` only reads published members.

## Error handling

| Case | Behaviour |
|---|---|
| Book names failed to load (`BibleSearchActivity.cpp:189-191`) | `bookNames.count() == 0`, nothing matches, no row. Word search as today. |
| An abbreviation missing for a book | That book matches by full name only. |
| Query is not a reference (A2-A6) | No row; behaviour identical to today. |
| Reference not in the index (A9) | No row; `LOG_DBG` the parsed triple. |
| `IndexReader::verse` I/O failure during resolve | No row, `LOG_ERR`; the word query then runs and reports its own failure through the existing path (`:515-522`). |
| Ambiguous book (A5) | No row. |

The only new heap use is the parser's one fold `std::string` (≤ 65 B). Its failure mode is the one
the word search already accepts on every query: `runQuery` folds through `queryTokens`, which
returns `std::vector<std::string>` (`Query.cpp:57`, `Fold.h:33`). No new failure class is added.

## Testing strategy

TDD, host first. New executable `TypedReferenceTest` in `test/ui_layout/CMakeLists.txt` (a
subdirectory file, not the shared top-level one; `test/CMakeLists.txt:102` already adds the
directory). Sources: `src/activities/reader/TypedReference.cpp` plus `Fold.cpp`, `IndexFormat.cpp`,
`IndexBuilder.cpp`, `IndexReader.cpp` from `lib/BibleSearch/BibleSearch`, as
`test/bible_search_index/CMakeLists.txt:5-10` does. The in-memory index is built as
`test/bible_search_index/IndexTest.cpp:40,85` builds one (`sourceOf` over an `IndexBuilder`
output).

Fixtures are short name lists, not publisher text (project rule for this public repo): Spanish
names and the six abbreviations already in `BibleNavLabelsTest.cpp:20-27` (`Gén.`, `Éx.`,
`1 Crón.`, `Mat.`, `Jud.`, `Apoc.`) plus a handful more, and English names from
`BibleBookJoinTest.cpp:36-99` with abbreviations of the same shape (`Gen.`, `Isa.`, `John`).
Book numbers are placed at their canonical index.

Parser cases:
- Full names: `Juan 3:16`, `Isaiah 40:31`, `El Cantar de los Cantares 2:1`.
- Abbreviations: `Isa 40:31`, `Gén 1`, `Gen. 1`, `1 Crón 29:11`, `1Cron 29:11`.
- Case and accents: `gén 1` = `GEN 1` = `Gén 1`; `Exodo 3` = `Éxodo 3`.
- Chapter only, verse, range: `Gen 1`, `Gen 1:1`, `Juan 3:16-18`, `Juan 3:16 - 18`, `Juan 3:16–18`.
- Exact beats prefix: `Phil 4:13` → Philippians (English fixture with `Phil.`, `Philippians`,
  `Philem.`, `Philemon`); `Philem 1` → Philemon. `Jud 5` → Jude as a plain Spanish abbreviation.
- Unique prefix: `Isa 40` (Spanish, prefix of `Isaías`), `Salmo 23`, `Gene 1`; ambiguous prefix
  `Ju 3` → none.
- Two-letter prefixes (A5.4): `de 3`, `la 3`, `el 3` → none; exact two-byte abbreviation `Ps 23`
  (fixture `Ps.`) → Psalms.
- Malformed / no false positives: `amor`, `amor 3`, `dios es amor`, `Gen`, `Gen 0`, `Gen 1:0`,
  `Gen 256`, `Gen 1:3-2`, `Gen 1:`, `Gen :3`, `3:16`, `a 3`, `Juan 3.16`, `1234`, empty string.

Resolver cases (in-memory index with a few chapters of two books plus a single-chapter book):
chapter-only returns the chapter's spine and no offset; verse returns its spine and offset; a
missing chapter and a missing verse return not-found; `Jude 5` → Jude 1:5 (A8); a multi-chapter
book's missing chapter does not trigger A8; `Jude 3:1` → not found (A8 needs chapter-only); a
reference past the last verse of the last book → `true`, `found = false` (no `LOG_ERR`); a failing
`ByteSource` returns `false`.

The activity changes are not host-testable (Arduino, `GfxRenderer`); they are verified by `pio run`
and on device.

**Device (for the human tester):** Bible open, index prepared, Search verses:
1. `Isa 40:31` (English Bible) → top row "Go to Isaiah 40:31", selected; tap → reader at 40:31.
2. `Gén 1` (Spanish) → "Ir a Génesis 1"; opens at the chapter heading.
3. `Juan 3:16` → opens at 3:16; hits for the words follow below.
4. `amor` → no Go-to row, hits as before.
5. `Gen 51` → no row.
6. `Gen 1` (many word hits) → scroll one page → the top hit row shows its reference and snippet.
7. `Isa 40:31` with no word hits → header reads "Results: 1", no "No verse contains…" line.
8. Heap: `ESP.getFreeHeap()` before entering and after leaving search matches as before.

## Changes after spec review 0

`docs/superpowers/reviews/issue-206-spec-review-0.md` returned CLEAR with one MAJOR and eight
MINORs, all accepted:

- MAJOR 1 — `ensureRows` added to the `firstResultRow()` sites, with the exact arithmetic; a grep
  for leftover literals is part of the plan; device step 6 added.
- MINOR 1 — resolver cost restated: direct `readAt`s through `HalFile`, not the 4 KB page; resolve
  time logged.
- MINOR 2 — a lower bound at `verseCount` is not-found, checked before `verse()`; test added.
- MINOR 3 — the exact-beats-prefix example and test are now `Phil` (the only real case);
  `Jueces` claim removed.
- MINOR 4 — A8 requires a chapter-only reference; `Jude 3:1` test added.
- MINOR 5 — `BookNameSource` is a stride view over the table's fixed arrays; no stack pointer arrays.
- MINOR 6 — new A5.4: prefix-only matches need ≥ 3 bytes, trading `Ro 12` for no `de 3` false
  positive, in line with the issue's acceptance criterion.
- MINOR 7 — A11 extended: the header count includes the Go-to row; device step 7 added.
- MINOR 8 — A14's ordering stated: `joinToc` clears all abbreviations, `load()` fills them after.
