# Issue #200 — reader menu as a bottom sheet over the page

- **Branch:** `feature/200-reader-menu-sheet`, base `67eaaf1e` (release 1.21.0).
- **Research:** `docs/superpowers/research/2026-09-30-issue-200-research.md`, cited below as **R §n**.
- **Verification:** every `file:line` was re-read on this branch on 2026-09-29.

## Revision after spec review 0

Review: `docs/superpowers/reviews/issue-200-spec-review-0.md`. The verdict was BLOCKER, with 0 BLOCKERs and 2 MAJORs:
MAJOR 1 needed the owner's decision; MAJOR 2 and the 6 MINORs could be fixed inline. The owner answered MAJOR 1 as
decision **d1**. Everything is applied below.

- **MAJOR 1 → d1 (owner).** When no page snapshot is available, the menu draws the **same sheet layout on a cleared
  screen** with a HALF refresh. That covers:
  - reopening after a sub-screen;
  - an allocation failure;
  - night mode;
  - a rotation.

  Today's scrolling list is gone as a fallback. No path scrolls, and a host test asserts that a 15-item Bible menu
  fits (A-16, T-2). The path taken is logged at `LOG_DBG` (A-25). Non-Bible books follow the same rule. The rejected
  option, a reader-owned snapshot kept across sub-screens, is recorded under Follow-ups. This rewrites Goal 6, A-5,
  A-7, A-8, A-9 and A-22.
- **MAJOR 2.** `fui::button` puts the icon **beside** the label (`freeink-sdk/.../controls/button.h:63-73`). Tiles are
  now drawn by hand, stacked:
  - `frame().hit` for the tap target;
  - `renderer.drawRoundedRect` for the border;
  - `target().bitmap` for the icon;
  - `target().text` for the label.

  This is modelled on `src/activities/util/FrontlightPanelActivity.cpp:212-223` and
  `src/activities/launcher/LauncherActivity.cpp:399` (A-17).
- **Design change, same pass: the snapshot now uses the existing region API instead of a new `PageSnapshot` class.**
  While re-reading for MINOR 8, I found `GfxRenderer::readFramebufferRegion`/`writeFramebufferRegion`
  (`lib/GfxRenderer/GfxRenderer.h:268-275`), which `PassageSelectActivity` already uses for the same
  save-and-redraw-over pattern (`PassageSelectActivity.cpp:60,498,538`).
  - The sheet overwrites only its own plate. The page region above it is the only part that needs saving, and only
    because an `OptionPopup` (Auto turn) can draw over it.
  - Saving that region costs about 21 KB instead of 48 KB, needs no new class, and mirrors an existing pattern instead
    of inventing one (A-1 to A-3).
  - The old `PageSnapshotTest` goes away. The OOM fallback is now covered by a device check with a forced-failure
    flag (V-7).
- **MINOR 3.** `ReaderMenuModel::build` takes `hasFrontlight` and `hasRotation` explicitly and holds no `StrId`. The
  activity maps each action to its label (A-10).
- **MINOR 4.** Labels no longer depend on the mode. There is one layout and one label set, assigned once in the
  constructor (A-15).
- **MINOR 5.** The mode is a `std::atomic<SheetMode>`. The rotation callback changes it and drops the snapshot under
  `RenderLock lock(*this)`, as `moveSelectionTo` does (`UiListActivity.cpp:76`) (A-9).
- **MINOR 6.** The "Tags here" count no longer calls `passagesInDocument` at menu open.
  - The reader already walks the painted passages on every page render (`EpubReaderActivity.cpp:1398`), so it caches
    the count there, on the render task. `openReaderMenu` reads an `int` under the lock.
  - The chapter-filtered list queries outside any held `RenderLock`, then swaps its indices in under the lock. This
    matches `PassageSelectActivity::onEnter` (`:64`), which calls it unlocked (A-14).
  - `PaintedPassage` is 16 B on the target, as the review says (`StudyStore.h:107-113`).
- **MINOR 7.** `search24.h` and `search32.h` have no includers (`grep -rn "search24\|search32\|Search24Icon\|icon_search" src lib`
  finds only the files themselves). They are deleted, so the regenerated `icon_search_32` does not collide.
  Regeneration must leave the 13 existing icon arrays byte-identical. Formatting uses `./bin/clang-format-fix`, not
  `clang-format -i` (A-26).
- **MINOR 8.**
  - `ACTION_CLOSE` gets a handler, registered in a new `onEnter` override after `UiListActivity::onEnter()`.
  - Taps are routed in `handleCustomInput`, which consumes `ACTION_CHROME` without a render (A-19, A-23).
  - The layout is computed before any allocation (data flow).

## Problem

- **The menu scrolls.** A Bible can build 15 menu items (`buildMenuItems`,
  `src/activities/reader/EpubReaderMenuActivity.cpp:41-82`) on an X4 Pro, where rotation is compiled out
  (`src/CrossPointSettings.h:18-24`) and there is a frontlight. That is one more than the 14 rows a page holds after
  #197 (R §2).
- **The page is wiped.** `render()` calls `renderer.clearScreen()` (`EpubReaderMenuActivity.cpp:225`), although the
  page the user was reading is still in the single framebuffer (R §2).

## Goal

1. From the reading surface, the menu opens as a **sheet over the lower part of the page**, and the page stays visible
   above it.
2. **No path scrolls:** every item is reachable without scrolling, with or without a page underneath.
3. Sheet layout:
   - A title row with the reference (#197's `readerMenuTitle`, `EpubReaderActivity.cpp:1611-1618`) and a close (✕)
     control.
   - A row of large quick actions: **Go to**, **Search** (Bible only), **Mark** and **Tag**.
   - The remaining items in **two columns** of compact rows.
4. For a Bible, **Go to %** is hidden, and **"Tags here (n)"** appears when n > 0 tagged passages paint in the current
   chapter. Non-Bible books keep every item they have today.
5. Closing: a tap on the page area, the ✕, a left-edge swipe (Back) or Home.
6. When there is no valid page snapshot, the **same layout** is drawn on a cleared screen with a HALF refresh (d1). The
   triggers are:
   - a reopen after a sub-screen;
   - the snapshot allocation fails;
   - night mode;
   - no framebuffer;
   - a rotation.

   Each is logged. None may crash.
7. The page snapshot lives in PSRAM and is freed on exit. PSRAM and internal free heap are logged before the sheet opens,
   while it is open, and after it closes.

## Non-goals

- The mockup's "Recent" chip row. It is phase 4, `places.json` (R §7).
- Any new store, file or on-disk format.
- Changing what a menu action does once it is chosen. `onReaderMenuConfirm` keeps its cases
  (`EpubReaderActivity.cpp:672-859`), plus the new `TAGS_HERE`.
- Night-mode rendering of menus. Menus stay normal polarity (`ActivityManager.cpp:55-58`).
- `MappedInputManager`: it is used, not changed.
- Keeping the page visible when the menu reopens after a sub-screen. See Follow-ups.

## Assumptions (each one is a decision a reviewer can attack)

### Snapshot and mode

- **A-1: save only the page region, through the existing region API.**
  - What it saves: the rectangle from the safe area's top to `sheetTop`, full width, via
    `renderer.readFramebufferRegion(x, y, w, h, buf, cap)` (`GfxRenderer.cpp:1744-1760`).
  - How it restores: on every sheet render, via `writeFramebufferRegion` (`:1762-1775`). This mirrors
    `PassageSelectActivity`'s outline fast path (`:498,538`).
  - Why the rest needs no saving: the sheet repaints its plate opaquely on every render (A-17), so pixels under the
    sheet are never needed again. The saved region is restored only to undo anything drawn over the page region: the
    Auto turn `OptionPopup`, which draws over the current frame without clearing (`OptionPopup.h:15`), or a stray tap
    flash.
  - *Rejected, in this pass:*
    - The new chunked `PageSnapshot` class. It reinvents an API the renderer already has, and needs 48 KB.
    - `storeBwBuffer`/`restoreBwBuffer`. They are single-use, and they rewrite the controller baseline
      (`GfxRenderer.cpp:2352-2354`, `FreeInkDisplay.cpp:868-877`) (R §4).
- **A-2: one allocation, sized from the layout.**
  - Size: `cap = ((pageRect.width + 8 + 7) / 8) * pageRect.height`, allocated with
    `makeUniqueNoThrow<uint8_t[]>(cap)`. The `+8` covers `screenRectToAlignedMemRect`'s byte rounding, as
    `PassageSelectActivity.cpp:51` does.
  - On the X4 Pro that is `(480 + 15) / 8 = 61` bytes × about 355 rows ≈ **21.7 KB**.
  - `readFramebufferRegion` returns 0 if the region does not fit `cap` (`GfxRenderer.cpp:1752`). A return of 0 is
    treated like an OOM.
- **A-3: it lands in PSRAM.** One `operator new` of about 21 KB goes to `malloc`, which sends anything over
  `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL 4096` to PSRAM (R §4; the review re-found it at `sdkconfig.h:1040-1041`).
  Internal SRAM cost is 0 B. V-2 confirms this on the device.
  - The contiguous allocation is safe: PSRAM is 8 MB and the menu is a user action. `storeBwBuffer`'s 8 KB chunking
    (`GfxRenderer.h:42`) exists for internal-heap fragmentation, which this allocation never touches.
- **A-4: the capture happens in the menu's first `render()`, on the render task.** Renders are serialised under
  `RenderLock` (`ActivityManager.cpp:47-59`), so the framebuffer holds the last completed frame, and `onEnter` (loop
  task, `ActivityManager.cpp:159-160`) cannot race a reader render.
- **A-5: the reader says whether the framebuffer holds the page.**
  - `openReaderMenu(bool pageOnScreen)` passes `true` from the reading surface's own input: Confirm, the touch menu
    gesture, or a Home-key hold (`EpubReaderActivity.cpp:517-519,534-535`).
  - It passes `false` from every result handler that reopens the menu
    (`:675-677,728-731,745-748,757-760,771-774,798-801`), where the framebuffer holds the sub-screen (R §2).
  - `false` selects **cleared** mode (d1).
- **A-6: in snapshot mode, the first paint is FAST.** The framebuffer matches both the panel and the controller baseline
  after every reader render path. That covers the anti-aliasing cleanup (`EpubReaderActivity.cpp:1487,1507,1536,1570`),
  the toast and the popup, which each display what they draw (review §"What holds up"). So only the sheet region is
  driven.
- **A-7: two modes, decided once on the first render, degrade-only.**
  - `SheetMode::OverPage`: taken when `pageOnScreen`, `SETTINGS.screenInverted == 0`, `renderer.hasFrameBuffer()`,
    `layout.fitsOverPage`, the allocation succeeds and the read returns more than 0.
  - `SheetMode::Cleared`: everything else. It uses `clearScreen()` and the same layout. The first paint is a
    `HALF_REFRESH`, the issue's clean-entry case, as with `launcherNeedsCleanPaint`
    (`src/activities/launcher/LauncherRefresh.h:15`). Later paints are FAST.
  - Night mode goes to Cleared: the panel shows the page inverted while the framebuffer holds normal polarity
    (`ActivityManager.cpp:55-58`, `FreeInkDisplay.cpp:577-579`).
  - Toggling night mode **on** inside an OverPage sheet does not change the panel until the reader re-renders after
    close, exactly as today.
- **A-8: the mode is `std::atomic<SheetMode>`,** written on the render task and read on the loop task (routing, A-20),
  so there is no torn read.
- **A-9: a rotation degrades to Cleared.** The `ROTATE_SCREEN` callback (`EpubReaderMenuActivity.cpp:107-115`, loop
  task) sets Cleared, frees the snapshot and resets the first-paint flag, all under `RenderLock lock(*this)`. This is
  compiled out on the X4 Pro (`CrossPointSettings.h:18-24`), so it is not device-tested.

### Items

- **A-10: the model.** `ReaderMenuModel.h` holds `enum class ReaderMenuAction` (today's values, plus `TAGS_HERE`
  appended). `EpubReaderMenuActivity` aliases it as `using MenuAction = ReaderMenuAction;`, so every
  `EpubReaderMenuActivity::MenuAction::X` compiles unchanged (the review verified the uses at `EpubReaderActivity.h:114`
  and `EpubReaderActivity.cpp:283,710-851`).
  - Input: `build(Inputs{isBible, hasFootnotes, hasBookmarks, hasHighlights, hasFrontlight, hasRotation, tagsHereCount})`.
  - Output: a flat `ReaderMenuAction items[MAX_ITEMS]`, with `quickCount` and `rowCount`. There are no label ids.
  - The activity fills in `hasFrontlight = Frontlight.present()` and `hasRotation = BEREAN_CAP_ROTATION`.
  - `MenuResult.action` is an in-memory `int` (`ActivityResult.h:24-28`), so appending is safe.
- **A-11: quick actions, in this order**, each present only when its item exists today:

  | Tile | Action | Present when |
  |---|---|---|
  | Go to | `SELECT_CHAPTER` | always |
  | Search | `SEARCH_BIBLE` | Bible |
  | Mark | `TOGGLE_BOOKMARK` | always |
  | Tag | `HIGHLIGHT_PASSAGE` | `hasHighlights` |

  A non-Bible book gets three tiles, spread evenly.
- **A-12: row order**, each row present only under today's condition:

  | # | Row | Condition |
  |---|---|---|
  | 1 | Bookmarks | |
  | 2 | Tags here (n) | Bible, n > 0 |
  | 3 | Highlights | |
  | 4 | Footnotes | |
  | 5 | Text settings | |
  | 6 | Night mode | |
  | 7 | Frontlight | |
  | 8 | Rotate | rotation capability only |
  | 9 | Auto turn | |
  | 10 | Go to % | non-Bible only |
  | 11 | Screenshot | |
  | 12 | Go home | |
  | 13 | Delete cache | |

  - The rows fill **row-major**, as in the mockup.
  - Highlights stays, although the mockup drops it, because the issue requires every item to stay reachable.
- **A-13: capacity.**
  - The X4 Pro maximum is 4 tiles + 11 rows (Bible) or 3 + 11 (non-Bible); a rotation build adds a 12th row.
  - `MAX_QUICK = 4`, `MAX_ROWS = 14`.
  - `build` clamps and reports overflow, and the activity logs it as `EpubReaderMenuActivity.cpp:184-188` does today.
- **A-14: the "Tags here" count and its target.**
  - **Count.** `renderContents` already iterates `STUDY.passagesInDocument(currentSpineIndex)` on the render task
    (`EpubReaderActivity.cpp:1398-1405`). It stores the entry count in a new member `chapterPassageCount`, reset to 0
    whenever `highlightsLoaded` is false.
  - `openReaderMenu` reads that `int` under `RenderLock`, and only when `isBible`. This adds no StudyStore call at menu
    open and no inflate path, which removes MINOR 6's deadlock. The count equals what is painted.
  - **Target.** Tapping the row opens `HighlightsActivity(renderer, mappedInput, spineFilter, title)`.
  - With `spineFilter` set, the list's indices come from `STUDY.passagesInDocument(*spineFilter)`, most-recent-first,
    ANDed with the tag filter:
    - in `onEnter`, on the loop task with no lock held, as `PassageSelectActivity.cpp:64` calls it;
    - after a delete, the query runs **before** `RenderLock lock(*this)` (`HighlightsActivity.cpp:407`) and only the
      swap of `visibleIndices_` and `rowItems_` happens under it.

    No held lock is re-entered.
  - While `HighlightsActivity` is current, the reader does not render, so the render task does not contend for the
    `UnitIndexCache` the `StudyStore.h:137-138` comment protects.
  - The header shows the passed reference ("Isaiah 40").
  - The result handler is `openHighlights`'s (`EpubReaderActivity.cpp:338-358`).
- **A-15: labels, one set, assigned once in the constructor.**
  - Tiles use `STR_GO_TO` "Go to" (new), `STR_SEARCH` "Search", `STR_MARK` "Mark" (new) and `STR_TAG` "Tag".
  - Rows use their current keys, except:
    - Auto turn uses the new `STR_AUTO_TURN` "Auto turn";
    - Tags here uses the new `STR_TAGS_HERE` "Tags here (%d)", formatted with `snprintf` into a member `char[32]` when
      the menu is built.
  - The keys are handed off to the orchestrator.

### Layout and rendering

- **A-16: the geometry.** `ReaderMenuSheetLayout::compute(Inputs)` takes:

  | Input | Source |
  |---|---|
  | The safe rect | `getScreenSafeArea(renderer, true, false)`, which is the full screen on touch (`UITheme.cpp:52-54`) |
  | `titleHeight` | `metrics.headerHeight` (44, `LyraTheme.h:13`) |
  | `gap` | `metrics.verticalSpacing` (8, `:14`) |
  | `iconSize` | 32 |
  | `labelLineHeight` | the body font's line height |
  | `tileHeight` | `max(minTouchSize, iconSize + gap/2 + labelLineHeight + 2·gap)` (stacked, A-17) |
  | `rowHeight` | `ListRowHeight::resolve` (50 on touch, `LyraTheme.h:20`) |
  | `ruleWidth` | `metrics.popupFrameThickness` (2, `:53`) |
  | Counts | `quickCount`, `rowCount` |

  - **Placement.** The sheet is sized to its content and anchored at the safe area's bottom:
    `sheetTop = safe.bottom − (ruleWidth + titleHeight + gap + tileHeight + gap + rowsPerColumn·rowHeight + gap)`.
  - **Outputs.** It returns the page rect (from the safe area's top to `sheetTop`), the plate, title, ✕, `tile[4]`,
    `column[2]`, `rowsPerColumn = ceil(rowCount / 2)`, and:
    - `fitsOverPage`: the page rect is at least ⅓ of the safe height;
    - `fitsAlone`: `sheetTop >= safe.y`.
  - **Cleared mode** uses the same geometry, so the cleared screen shows a blank band where the page would be, and a tap
    there still closes. This is d1's "same layout".
  - **X4 Pro worst case.** Title 44 + gap 8 + tile about 81 + gap 8 + 6 rows × 50 + gap 8 + rule 2 ≈ 451. That puts the
    sheet top near y = 349, so `fitsOverPage` holds.
- **A-17: rendering.**
  1. **OverPage:** `writeFramebufferRegion(pageRect, snapshot)`. **Cleared:** `renderer.clearScreen()`.
  2. The plate: `fillRect` white over the plate rect, and a `ruleWidth` black top edge
     (`LauncherActivity.cpp:396-398`). Text never sits over page pixels.
  3. `renderUi()` builds, in this order:
     1. `frame().hit(pageRect, ACTION_CLOSE)`
     2. `frame().hit(plateRect, ACTION_CHROME)`
     3. the title, with `target().text`
     4. the ✕: `frame().hit` plus an icon via `target().bitmap`
     5. each tile:
        - `frame().hit(tileRect, ACTION_ROW, index)`
        - its border, with `renderer.drawRoundedRect`: 3 px when it is the selected index, 2 px otherwise (the launcher
          does the same, `LauncherActivity.cpp:399`)
        - the icon, centred in the upper part, with `target().bitmap(..., BitmapMode::Center)`
        - the label, centred below it, with `target().text`

        This follows `FrontlightPanelActivity.cpp:212-223`.
     6. the two columns: for each, `screen.setContentMargin(columnInsets)` then `screen.list(props, h)`. This keeps the
        theme's substitution, as `FreeInkApp.h:245-301` does. The review confirmed the mechanics (`FreeInkApp.h:65-67,301`).

     Routing scans newest-first (`OptionPopup.h:216-219`), so tiles and rows win inside the plate, the guard absorbs
     the plate's gaps, and only the page rect closes.
  4. `displayBuffer(firstPaint && mode == Cleared ? HALF_REFRESH : FAST_REFRESH)`.
- **A-18: interaction budget.** The worst case is 2 + 1 + 4 + 14 = 21 hits, under `MAX_INTERACTIONS = 64`
  (`UiAppHost.h:35`).
- **A-19: actions.**
  - `ACTION_ROW` carries each item's flat index, for tiles and rows alike, as rows already do
    (`EpubReaderMenuActivity.cpp:36`).
  - `ACTION_CLOSE = ACTION_USER` and `ACTION_CHROME = ACTION_USER + 1` (`UiListActivity.h:25-26`).
  - A new `onEnter()` override calls `UiListActivity::onEnter()` and then `app.on(ACTION_CLOSE, …)`.
  - `handleCustomInput` (after the popup):
    - routes the snapshot through `UiAppHost::routeTouch`;
    - on `ACTION_CHROME`, calls `app.clearTapFlash()` and returns `true` without requesting a render (the review found
      `route` invalidates and arms a flash for any event, `FreeInkApp.h:729-741`);
    - on `ACTION_CLOSE`, calls `closeCancelled()`;
    - on `ACTION_ROW`, falls to the existing dispatch.
- **A-20: physical buttons.**
  - Nav Next and Previous step through the flat order (tiles, then rows row-major), and Confirm activates.
  - In both modes, `navigateButtons` is overridden to register only the release steps, because nothing pages.
  - The selected tile gets the 3 px border. The selected row uses the column's list selection.
- **A-21: value slots.** Night mode, Frontlight and Auto turn show their values as today
  (`EpubReaderMenuActivity.cpp:191-199`), capped by `utf8SafeSummary` at 12 bytes (Spanish "Desactivado" is 11). Fit in
  a half column is checked on the device (V-5).
- **A-22: no scrolling list anywhere.** Today's `renderer.clearScreen()` + header + list render
  (`EpubReaderMenuActivity.cpp:222-232`) is removed. If `fitsAlone` were ever false (T-2 proves it is not on the X4
  Pro), the menu logs `LOG_ERR` and still renders Cleared. The rows that do not fit are clipped, not scrolled, which is
  unreachable on this device.

### Closing and lifetime

- **A-23: closing.**
  - A tap on the page rect closes through `ACTION_CLOSE` → `closeCancelled()` (`EpubReaderMenuActivity.cpp:84-90`).
    Swipe releases carry −1,−1 and do not route as taps (`OptionPopup.h:91-93`).
  - The ✕ also routes to `ACTION_CLOSE`.
  - The left-edge swipe (`wasReleased(Back)`, `MappedInputManager.cpp:265`; `EpubReaderMenuActivity.cpp:155-158`) and
    Home (`:92-95`) are unchanged.
- **A-24: release.** `onExit()` resets the snapshot buffer before `UiListActivity`'s teardown. It runs under the
  manager's `RenderLock` (`ActivityManager.cpp:176-182`). The reader then repaints through its normal cadence
  (`ActivityManager.cpp:130-133` → `ReaderUtils::displayWithRefreshCycle`, `ReaderUtils.h:165-176`).
- **A-25: logs.**
  - `LOG_INF("MENU", …)` prints `ESP.getFreeHeap()` (internal only, per the review) and
    `heap_caps_get_free_size(MALLOC_CAP_SPIRAM)` (the pattern at `BibleSearchIndexer.cpp:325`) at three points:
    - `before`: first render, before the allocation;
    - `open`: after the capture;
    - `closed`: in `onExit`, after release.
  - `LOG_DBG("MENU", "sheet mode: over-page|cleared (<reason>)")` records the path. The reason is one of `not-on-page`,
    `night`, `no-fb`, `no-fit`, `oom` or `rotated`.
  - `x4pro-gh_release` compiles these out (`LOG_LEVEL=0`).
- **A-26: icons.**
  - Add `layout-grid`, `search`, `tag` and `x` to `listIcons.manifest` (`bookmark` is already there). Regenerate at 24
    and 32 px with `gen_icons.py`. It needs `rsvg-convert` and Pillow (R §6), installed locally and not added to the
    repo.
  - Delete the orphaned `search24.h` and `search32.h`.
  - The 13 existing icon arrays must diff byte-identical. If they do not, keep the old arrays and splice in only the new
    ones.
  - Format with `./bin/clang-format-fix`.

## Data and control flow

```
Reader render task: renderContents → painted loop → chapterPassageCount = count      [render lock held]
Reader loop: Confirm / centre tap / Home-hold → openReaderMenu(pageOnScreen = true)
Sub-screen cancel handlers                     → openReaderMenu(pageOnScreen = false)
openReaderMenu: n = isBible ? chapterPassageCount : 0   [RenderLock, int read]
  → startActivityForResult(EpubReaderMenuActivity(title, orientation, footnotes, bookmarks,
                                                  highlights, isBible, n, pageOnScreen))
ctor: ReaderMenuModel::build → items/quickCount/rowCount; labels + "Tags here (n)" set once
onEnter: UiListActivity::onEnter → app.on(ACTION_CLOSE) → requestUpdate
first render (render task):
  layout = ReaderMenuSheetLayout::compute(...)                    // before any allocation
  LOG before
  OverPage iff pageOnScreen && !inverted && hasFrameBuffer && fitsOverPage
               && alloc(cap) && readFramebufferRegion(pageRect) > 0
  else Cleared (reason logged); LOG open
every render: popup? processRender : restore-or-clear → plate → renderUi → display(HALF on first Cleared, else FAST)
loop: popup → Back/Confirm → handleCustomInput routing (CLOSE / CHROME / ROW) → release-only nav
onExit: free snapshot → LOG closed
Reader result: unchanged cases + TAGS_HERE → HighlightsActivity(spineFilter = currentSpineIndex, title)
```

## Error handling

| Failure | Behaviour | Log |
|---|---|---|
| Snapshot allocation fails, or the read returns 0 | Cleared | `LOG_ERR("MENU", "page snapshot unavailable (%u bytes); cleared sheet")` |
| Night mode, no framebuffer, not page-on-screen, `!fitsOverPage` | Cleared, with no allocation | `LOG_DBG` with the reason |
| Rotation (capability builds only) | Cleared, snapshot freed under lock | `LOG_DBG` |
| `!fitsAlone` (unreachable on X4 Pro, T-2) | Cleared, clipped | `LOG_ERR` |
| Model over `MAX_QUICK`/`MAX_ROWS` | Clamp and log | `LOG_ERR` |

Nothing asserts or aborts. The one allocation is `makeUniqueNoThrow` and null-checked.

  - the model array inside the heap-allocated activity (about 18 bytes of enums plus counts);

## Risks

- **A-6 depends on the framebuffer matching the controller baseline on every reader path.** If it does not, the first
  OverPage paint re-drives more than the sheet. V-3 would catch it, and the fix is a HALF first paint for OverPage too.
- **The per-column `setContentMargin` (A-17) has no precedent.** The fallback is `fui::list(frame, rect, props)` with
  the theme fields copied as `FreeInkApp.h:245-301` does.

## Follow-ups (not built here)

- **Page visible on reopen (d1's rejected option a).** The reader would own the page-region snapshot and keep it while
  a sub-screen is open, so Go to, Search, Footnotes or Go to % cancels could redraw the sheet over the unchanged page
  with one HALF refresh. It needs cross-activity ownership and invalidation when the page changes.
