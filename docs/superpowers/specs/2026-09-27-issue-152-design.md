## Problem

Batch 2 (#144, #145, #146) left nine independent minor defects: one real per-byte locking cost in
the shared JSON reader, redundant or dead code in four places, one dead field in a persisted store,
and user and contributor docs that describe code that no longer exists. None is a bug a user sees
today; together they make the code read as if deleted things still matter, and item 1 is a
performance trap for every store that adopts the streaming reader.

## Goal

Land items 1–9 of #152 as one PR, each independently revertible, with:

- the streaming reader buffered and proven buffered by a host test;
- every piece of code the issue names as dead or redundant removed, with no new dead code left
  behind by the removal;
- `recent.json` still loadable from every file an earlier build wrote, and every file this build
  writes still loadable by an earlier build;
- docs that describe the launcher and the current code.

## Architecture and flow, per item

### Item 1 — buffer `readDocFromFileStreamed`

**Today.** `readDocFromFileStreamed` (`lib/Serialization/PersistableStore.cpp:140-160`) hands
`deserializeJson` a `HalFileReader` (`:19-32`) whose `read()` is `file_.read()` (`:23`).
ArduinoJson's JSON parser calls only `read()`, one character per call
(`Json/Latch.hpp:38` in the fetched v7.4.2), and each `HalFile::read()` takes `storageMutex`
(`lib/hal/HalStorage.cpp:138-141,159`). A 60 KB passage file is ~60,000 mutex takes and SdFat calls.

**Change.** Replace `HalFileReader` with `JsonFileReader`, an ArduinoJson reader over a
`serialization::BufferedFileReader` (`lib/Serialization/BufferedFile.h:74-133`), mirroring
`JsonFileWriter` over `BufferedFileWriter` in the same file (`PersistableStore.cpp:34-54`) — the
model file:

```cpp
constexpr size_t READ_BUFFER_BYTES = 512;   // beside WRITE_BUFFER_BYTES (:15)

class JsonFileReader {
 public:
  explicit JsonFileReader(serialization::BufferedFileReader& in) : in_(in) {}
  int read() { uint8_t c; return in_.read(&c, 1) == 1 ? c : -1; }
 private:
  serialization::BufferedFileReader& in_;
};
```

and in `readDocFromFileStreamed`, after the size-0 check (`:148-151`):

```cpp
serialization::BufferedFileReader buffered(file, READ_BUFFER_BYTES);
JsonFileReader reader(buffered);
const auto error = deserializeJson(doc, reader);
```

The flow is otherwise unchanged: `exists` → open → size check → parse → classify. `readAdopting`
calls the same reader for `<path>.tmp` (`:178`), so the `.tmp` path is buffered too.

- **A1.** Buffer size 512 bytes, equal to `WRITE_BUFFER_BYTES` (`:15`): one SdFat sector, under the
  4,096-byte PSRAM auto-routing threshold the comment at `:14` cites, so it lands in internal SRAM.
  One heap allocation per streamed read, freed at scope exit. A stack buffer was rejected: 512 bytes
  breaks the 256-byte local-variable rule (`AGENTS.md`, "Stack safety"), and `BufferedFileReader`
  owns its buffer by design (`BufferedFile.h:19-21`). The existing 4,096-byte
  `BUILD_IO_BUFFER_SIZE` (`BookMetadataCache.cpp:20`) was rejected: it would route to PSRAM and is
  sized for a multi-file build, not one sequential parse.
- **A2.** OOM needs no new path: `BufferedFileReader` degrades to unbuffered passthrough when its
  allocation fails (`BufferedFile.h:19-21,83-88`), which is exactly today's behaviour.
- **A3.** `JsonFileReader` has `read()` only, no `readBytes`. The JSON parser never calls
  `readBytes` (`Json/Latch.hpp:38` is its only pull), and ArduinoJson's `Reader<T>::readBytes` is a
  member of a class template, instantiated only if used (`Deserialization/Reader.hpp:26-28`), so
  nothing requires it. `HalFileReader::readBytes` (`PersistableStore.cpp:25-28`) goes with the class.
  *Changed in spec review pass 0 (MINOR-5): the earlier draft kept it for symmetry, which is new dead
  code in a cleanup PR.*
- **A4.** `readDocFromFileChecked` (`:123-138`) stays on `Storage.readFile`. The issue scopes item 1
  to the streamed reader.

## Error handling

No new error paths. Item 1 degrades to today's unbuffered read on OOM (A2); a short or failed read
still surfaces as an ArduinoJson parse error, classified `ParseError` as today (`:155-158`) —
`BufferedFileReader::read` returns 0 at EOF or error (`BufferedFile.h:94-96`), which `JsonFileReader`
maps to `-1`, the same end-of-input signal `HalFile::read()` gives. Item 2's saves still fail
through the open when the directory cannot be created (`PersistableStore.cpp:59-60,75-77`). Item 4
leaves every refusal path in `fromJson` (`RecentBooksDoc.cpp:57-58`) and the budget check as-is.
