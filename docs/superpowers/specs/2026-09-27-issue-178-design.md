## Problem

Five independent defects left by batch 3:

1. A book that is not in the download folder or at `/` cannot be opened. The
   Publications list reads one directory level of two folders
   (`src/util/CardBooks.cpp:19-45`), and the file browser is unreachable on the
   X4 Pro: its reader entry needs a physical Back button
   (`src/activities/reader/ReaderUtils.h:256-263`), and its other entries sit
   behind an image viewer or a no-Bible screen (note, item 1 table).
2. Weekday names live in three translated sources, in two orders, with two
   Spanish capitalisations (`english.yaml:425,430-436,481`;
   `spanish.yaml:370,375-381,423`).
3. Five helpers are copied: the civil-date arithmetic
   (`src/network/WolWeekScan.cpp:20-55` vs
   `src/activities/boot_sleep/StudySleepPick.h:147-180`), the UTC-offset day shift
   (`WolWeekScan.cpp:118-127` vs `StudySleepPick.h:201-206`), the cover-thumbnail
   lookup (`PublicationsActivity.cpp:81-92` vs `src/util/CoverThumb.cpp:29-47`), the
   publication-language label (`CatalogSearchActivity.cpp:59-64` vs
   `BibleDownloadActivity.cpp:64-65`), and the download progress throttle, three
   times (`MeetingDownloadActivity.cpp:249-257`, `BibleDownloadActivity.cpp:214-222`,
   `CatalogSearchActivity.cpp:463-469`).
4. (a) "This week" is the UTC ISO week in four places
   (`MeetingsActivity.cpp:105-109`, `LauncherActivity.cpp:177-180`,
   `MeetingDownloadActivity.cpp:127-133`, `src/network/MeetingWeekPrefetch.cpp:26-33`)
   while the sleep screen's date is local (`StudySleepScreen.cpp:186-194`). (b) The
   v1 catalog index is still built and published with no written condition for
   stopping (`.github/workflows/catalog-index.yml:10-14,89-90,109-110,146-162`).
5. The tag-retire confirmation says "Delete this tag from every highlight in this
   book?" (`english.yaml:391`) for an action that retires the tag everywhere and
   deletes no highlight (`src/study/StudyStore.h:98-103`). Spanish has no
   translation of it at all.

## Goal

- A book in any folder can be opened from a screen the X4 Pro reaches by touch.
- One translated source of weekday names, in one documented order, with every
  short form derived from it and the other keys gone from every YAML.
- Each duplicated helper exists once, pure where it can be, host-tested where it is
  pure, with no behaviour change beyond the labelled ones below.
- The meetings week, the launcher's meeting tile, the downloader and the prefetch
  agree with the sleep screen on what day it is, locally.
- The v1 retirement condition and procedure are written where the next person
  changing the workflow will read them.
- The retire confirmation says what retiring does, in English and Spanish.

## Non-goals

- No gesture on the reading surface; `ReaderUtils::handleBackNavigation` is not
  touched (batch brief; issue item 1).
- `CardBooks::list()` stays non-recursive. A recursive scan would open every
  directory on every Publications entry, and the file browser already walks the tree.
- v1 is **not** stopped in this change (batch brief).
- The retire popup's action button stays `STR_DELETE`
  (`TagFilterActivity.cpp:104`, `TagPickerActivity.cpp:250`); the issue asks for
  the prompt only.
- The other copies of the BMP row unpack (`LauncherActivity.cpp:380-384`,
  `SleepActivity.cpp:632-636`) are not folded. Each has a different crop and draws
  straight to the renderer; the issue names only the Publications copy, which
  duplicates `CoverThumb::pathFor`.
- No change to `MappedInputManager`, `HalClock`, any stored format, or any
  persisted setting value.

### 3.4 Download progress throttle → `src/util/ProgressThrottle.h`

Header-only, pure, modelled on `LauncherRefresh.h`:

```cpp
class ProgressThrottle {
 public:
  static constexpr int STEP_PERCENT = 5;
  static constexpr unsigned long MIN_UPDATE_MS = 5000;
  static int percentOf(size_t downloaded, size_t total);   // 0 when total == 0
  void reset();                                           // last = -1, lastMs = 0
  // True, and records percent and now, when a repaint is due.
  bool shouldRepaint(size_t downloaded, size_t total, unsigned long nowMs);
 private:
  int lastPercent_ = -1;
  unsigned long lastMs_ = 0;
};
```

`shouldRepaint` is the existing predicate, character for character:
`percent >= 100 || lastPercent_ < 0 || percent >= lastPercent_ + STEP_PERCENT ||
nowMs - lastMs_ >= MIN_UPDATE_MS`, with `percentOf` as
`static_cast<int>(static_cast<uint64_t>(downloaded) * 100 / total)`.

The three activities replace `lastRenderedPercent`/`lastProgressUpdateMs`
(`MeetingDownloadActivity.h:79-80`, `BibleDownloadActivity.h:74-75`,
`CatalogSearchActivity.h:127-128`) with one `ProgressThrottle progressThrottle;`,
their resets (`MeetingDownloadActivity.cpp:286-287`,
`BibleDownloadActivity.cpp:244-245`, `CatalogSearchActivity.cpp:137-138,388-389`)
with `progressThrottle.reset()`, and their predicate with
`if (progressThrottle.shouldRepaint(downloaded, total, millis())) requestUpdate(true);`.
Their per-file `DOWNLOAD_PROGRESS_*` constants go. The input pumping above each
predicate is **not** folded: it differs per activity
(`CatalogSearchActivity.cpp:452-456` has no home gesture).
`MeetingDownloadActivity.cpp:190`'s `lastRepaintMs` is a different timer and stays.

**A3.7 — unsigned wrap.** `nowMs - lastMs_` stays `unsigned long` arithmetic, so
`millis()` wrap behaves as today.

## Item 2 — one source of weekday names

**A2.1 — the source is the seven day keys, Monday first.** `STR_MONDAY` …
`STR_SUNDAY` stay; `STR_WEEKDAYS` and `STR_WEEKDAYS_NARROW` are removed from
`english.yaml` and `spanish.yaml` (no other YAML has them). The order is ISO:
index 0 = Monday, matching `isoWeekday() - 1`, the Monday-first strip
(`MeetingWeekView.h:20`) and the settings ordinals `MEETING_DAY_MONDAY = 1` …
`MEETING_DAY_SUNDAY = 7` (`CrossPointSettings.h:74-82`). The reverse — one list key
with the day keys derived — is rejected: the meeting-day settings need a `StrId`
per value (`SettingsActivity.h:33`), the settings list is built once in a
function-local static (`SettingsList.h:229-230`) so runtime strings would freeze
at the boot language, and the >2-option popup reads `enumValues` only
(`SettingsActivity.cpp:256-258`).

The one documented order lives in a new header, `src/util/WeekdayNames.h`:

```cpp
// Monday first: index = isoWeekday() - 1 = meeting-day setting - 1.
inline constexpr StrId WEEKDAY_NAME_IDS[7] = {StrId::STR_MONDAY, …, StrId::STR_SUNDAY};
```

Consumers:

- `SettingsList.h:250-258` fills `meetingDayValues[i + 1] = WEEKDAY_NAME_IDS[i]`.
- The sleep screen: `formatDateLine` takes the seven names instead of a list,
  `const char* const (&weekdayNames)[7]`, Monday first, and picks
  `weekdayNames[isoWeekday(local) - 1]`. `StudySleepScreen.cpp:193` builds the array
  from `tr()` of each id. `catalog::wordAt` is still used for `STR_MONTHS_SHORT`.
- The meetings strip: `MeetingsActivity.cpp:198-200` replaces
  `copyWordAt(tr(STR_WEEKDAYS_NARROW), i, …)` with
  `copyInitial(I18N.get(WEEKDAY_NAME_IDS[i]), out.letters[i], sizeof(out.letters[i]))`.
- `copyInitial(const char* word, char* out, size_t outSize)` is new in
  `MeetingWeekView.{h,cpp}`, beside `copyWordAt`, which it mirrors: it copies the
  first UTF-8 code point (1-4 bytes by lead byte) and terminates; false, `out`
  empty, when the word is empty or null or the code point does not fit.
  `letters` is `char[7][8]` (`MeetingsActivity.h:98`), so any code point fits.

**A2.2 — Spanish narrow Wednesday becomes "M".** Derived initials give
"L M M J V S D" for Spanish where the YAML has "L M X J V S D"
(`spanish.yaml:370`). The strip shows the day number under every letter and is
always Monday first, so the repeated "M" stays unambiguous in position. English is
unchanged ("M T W T F S S"). A per-language override key would restore "X" but
would be a second source, which is what the issue removes.

**A2.3 — Spanish sleep-screen weekday gains a capital.** The day keys are
capitalised ("Domingo", `spanish.yaml:381`), `STR_WEEKDAYS` was lowercase
(`:423`). The sleep line becomes "Domingo 27 sep"; it starts the line, where a
capital is correct Spanish, and it matches the settings. English is unchanged.
Languages other than English and Spanish fall back to English in both old and
new keys, so they do not change.

**A2.4 — the unused-key count.** Only used keys are removed, and every day key
stays used through `WEEKDAY_NAME_IDS`, so `gen_i18n.py`'s "Unused keys" stays at 1
(`STR_HIGHLIGHTS_TOO_LARGE`, note). Because `gen_i18n.py` scans comments for
`STR_` names, no comment or test may still spell `STR_WEEKDAYS` or
`STR_WEEKDAYS_NARROW` after the change; the implementer greps the tree for both.

**A2.5 — this task edits the YAMLs.** `.claude/agents/ui-dev.md` reserves
`lib/I18n/translations/*.yaml` for the orchestrator, but the batch brief assigns
items 2 and 5 (and item 1's row label) to this task, which runs alone in its
worktree. The edits are confined to `english.yaml` and `spanish.yaml`.

## Item 4a — "this week" is local

### Flow

A pure helper in `CivilDate.h`:

```cpp
// The viewer's date: the UTC date shifted by the local time of day, or the UTC
// date unchanged when the time could not be read.
inline bool localDateOrUtc(const CivilDate& utc, bool haveTime, uint8_t hour, uint8_t minute,
                           uint8_t offsetQuarterHoursBiased, CivilDate& out);
```

and one firmware wrapper that reads the clock, `src/util/LocalDate.{h,cpp}`:

```cpp
// halClock.getDate + getTime + SETTINGS.clockUtcOffsetQ -> localDateOrUtc.
// False when the RTC has no date.
bool readLocalDate(CivilDate& out);
```

Modelled on the clock read in `StudySleepScreen.cpp:186-194`.

The four sites become `readLocalDate(today) && isoWeekFromUtcDate(today.year,
today.month, today.day, week)`:

| Site | Change |
|---|---|
| `MeetingsActivity::refresh` (`:105-109`) | week from the local date; the same local date is passed to `buildWeekHeader` as today. The separate `getTime` + `localDateFromUtc` in `buildWeekHeader` (`:185-193`) goes, and its comment "Only today is local…" is replaced: the week and today are now the same local date. |
| `LauncherActivity::thisWeeksMeetingPublication` (`:177-180`) | local week |
| `MeetingDownloadActivity::runSequence` (`:127-133`) | local week; the log line says "Local date". `STR_CLOCK_NOT_SET` path unchanged. |
| `MeetingWeekPrefetch::due` (`src/network/MeetingWeekPrefetch.cpp:26-33`) | local week |

`isoWeekFromUtcDate` is date-only arithmetic (`WolWeekScan.cpp:67-86` builds a
`time_t` at 00:00 of the given date); feeding it a local date is correct despite
the name. It is not renamed: five test targets and `MeetingPrefetchPlan.cpp:8` call it.

**A4.1 — all four move together.** The cards, the launcher tile and the fetch
must name the same week (the comment at `MeetingsActivity.cpp:185-187` states why
they were kept UTC together), so they change in one commit.

**A4.2 — time unreadable → UTC date.** If `getDate` succeeds and `getTime` fails,
the week falls back to today's behaviour (UTC date) rather than to "clock not
set". `getTime` only fails when the RTC read fails with nothing cached
(`lib/hal/HalClock.cpp:15-40`), so this is a corner, and failing the week there
would make the downloader refuse to run where it runs today.

**A4.3 — known ≤ 10 s skew at UTC midnight.** `getTime` serves a cached value for
up to `CLOCK_POLL_MS = 10000` (`HalClock.h:17`, `HalClock.cpp:18-23`) while
`getDate` reads the RTC. Across UTC midnight the two can disagree for up to 10 s.
The sleep screen already has this; this change inherits it and does not touch
`HalClock`.

**A4.4 — the cache key is unchanged.** `meetingWeekKey(week)` keys the same ISO
week type; only which week counts as "now" moves, by at most one day's worth at
the week boundary. No stored format changes.

`MeetingWeekPrefetch.cpp` is on the net surface; the edit is the one call site.

## Item 4b — the v1 retirement condition

Written into the header comment of `.github/workflows/catalog-index.yml` (beside
the v1 line at `:11`) and into `docs/file-formats.md` under "Version 1"
(`:542-548`), replacing "still published unchanged for firmware that predates
version 2" with the condition and the steps.

**Condition (A4.5).** v1 may stop being published once **both** hold:
1. It is on or after **2026-12-28**, the first scheduled Monday run at least 13
   weeks after v1.17.4, the first release that reads v2
   (`gh release view v1.17.4` → published 2026-09-27; the note, item 4b). OTA is
   user-initiated, so a date is the only bound available.
2. No device the owner supports is still on ≤ v1.17.3 (Settings → About shows
   the version).

Download counts cannot stand in for (2): the workflow re-uploads every asset with
`--clobber` each week, which resets the count (`gh release view catalog --json
assets` on 2026-09-27 shows 0–2 per asset, all updated that week).

The cost of retiring early is bounded: firmware ≤ v1.17.3 keeps its cached index
and Buscar reports the failed fetch, and an OTA update fixes it.

**Steps**, written as a checklist in both places:
1. In `catalog-index.yml`, drop `--out-v1 …` and `--previous-v1 …` from both
   builder calls (`:90`, `:110`), the `previous-$lang.txt` fetch (`:62`), and
   `"catalog-$lang.txt"` from `indexes` in `publish()` (`:149`), leaving v2 there
   unconditionally outside `hold`.
2. Delete the assets once: `gh release delete-asset catalog catalog-S.txt
   catalog-S.txt.gz catalog-E.txt catalog-E.txt.gz`.
3. In `scripts/build_catalog_index.py`, remove `--out-v1`/`--previous-v1`
   (`:354-355`) and the v1 write (`:399-403`), with their tests in
   `scripts/tests/test_build_catalog_index.py`.
4. Update `docs/file-formats.md` and the comment at
   `src/network/CatalogIndexStore.cpp:57-59`. The device keeps accepting a v1
   file (`catalog::indexAcceptable`), so no firmware change is needed.

No code or workflow behaviour changes in this commit; it is comments and docs.

## Error handling

- `readLocalDate` returns false exactly where `getDate` failed before; each site
  keeps its existing failure path (`STR_CLOCK_NOT_SET`, "newest week held",
  `std::nullopt`, no prefetch).
- `formatDateLine` returns false, as today, for an invalid reading or a missing
  name; the sleep screen already handles false.
- `copyInitial` fails closed (empty `out`), as `copyWordAt` does; an empty letter
  draws nothing.
- `ProgressThrottle` has no failure mode.
- The Browse row adds no allocation beyond one `ListItem` in the existing
  `rowItems_` vector, sized by `listCount()` (`PublicationsActivity.cpp:142`).

No new heap allocation anywhere; every new helper is header-only or stack-only.
