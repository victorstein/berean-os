# Issue #237 — Home breathing room and week-strip spacing: design

Research: `docs/superpowers/research/2026-09-30-issue-237-research.md`.
Surface: `ui`. Tier: standard.

Modelled on:
- `src/activities/launcher/HomeLayout.h` itself (#203/#223), which already turns measured font data (`LineHeights`, `:36-41`) into boxes, and its host test `test/home_layout/HomeLayoutTest.cpp`.
- `1fd966f5 feat: add toast padding and line cap (#116)` — a spacing term added to a renderer-free layout header (`src/components/ToastLayout.h`) and pinned in its host test.

## Problem

On device (v1.29.2, owner's photo of 2026-09-30), Home is cramped in three places:

1. **Top edge.** The hero's outline starts `metrics.topPadding` (5 px) under the viewable top: `MastheadLayout::band` puts it at `marginTop + topPadding` (`src/components/MastheadLayout.h:26`), called from `HomeLayout.h:109`. At 480×800 Lyra, `hero.y = 14` (`HomeLayoutTest.cpp:38`).
2. **Header → buttons.** `buttonRow.y = bottomOf(plateHeader)` (`HomeLayout.h:117`), and `plateHeight` has no term between the header and the buttons (`:93-95`). The Continue / Go to row sits on the header's last row.
3. **Week strip.** Seven fixed `STRIP_CELL = 26` px cells (`HomeLayout.h:32`, drawn at `LauncherActivity.cpp:359-360`). A two-digit day at UI_10 is 23 px of ink (below), so adjacent numbers are ~3 px apart and "28 29 30" reads "282930".

## Goal

- Visible space above the hero and between the plate header and the button row.
- On the strip, the ink of adjacent day numbers is at least one digit's ink width apart, with the width **measured** from the UI font at runtime, not hardcoded. Each number stays centred under its weekday letter. The selected day's inverted box does not reach a neighbour's number.
- Every value comes from theme metrics, measured font data or existing Home tokens (`PAD`); no 480/800 in code.
- The whole screen still fits at 480×800 portrait in both themes, pinned by `test/home_layout`.

## Non-goals

- The Meetings screen's own strip (`MeetingsActivity.cpp:324-325`), which is full-width and not cramped.
- `buildWeekStrip` / `MeetingWeekView` (data only, `MeetingWeekView.h:25`): unchanged.
- Recent, verse card, meetings card or icon-row *heights*; the icon row is explicitly protected by the issue.
- Any new theme metric, i18n string, store or on-disk format.

## Assumptions (each is a decision the review should attack)

- **A1 — Who pays for the new vertical space: the hero. DECIDED (hpipe decision d1, orchestrator, 2026-09-30).** The cover gives up the 16 px. "From the empty area under Recent" was the issue author's suggestion, not a requirement; the binding criteria are visible room at the top and above Continue / Go to with the icon row untouched. Recent's rows must not shrink below `listRowHeight`. The PR description records the issue's wording as "the cover gives up 16 px". Reasoning as submitted: the issue says "take the space from the empty area under Recent". Mechanically every new vertical term in `compute` is taken from the hero, which absorbs the remainder (`HomeLayout.h:104`). Recent's height is `lines.small + RECENT_SLOTS * metrics.listRowHeight` (`:89-91`) regardless of how many slots are filled, and the filled count is not known at layout time: `computeLayout()` runs before `resolveTargets()` sets `recentCount` (`LauncherActivity.cpp:78-79`, `:147`). The "empty area" the owner sees is almost certainly unfilled Recent slots, which a fixed layout cannot reclaim. Making Recent yield would mean shrinking its rows below the theme's `listRowHeight` touch token (Lyra 40, Base 30 — Base's 30 is already barely above the 24 px UI_10 line), which is a touch-target regression. The hero has room: its art above the plate falls from 165 to 149 px (Lyra) against a `MIN_HERO_ART` floor of 96 (`:28`).
- **A2 — Top gap = `PAD` (8 px), added to the hero's top.** Implemented by adding `PAD` to `top` and passing `insets.top + PAD` as `band()`'s `marginTop`, so the hero keeps `band()`'s x and width. Lyra `hero.y`: 14 → 22.
- **A3 — Header → button gap = `PAD`.** `plateHeight` gains one `PAD` term and `buttonRow.y = bottomOf(plateHeader) + PAD`. The plate stays pinned to the hero's foot and keeps its existing bottom `PAD`. Lyra plate: 93 → 101.
- **A4 — The hero's cover thumbnail is not regenerated.** The cached thumbnail is `thumb_<h>.bmp` with `h = thumbHeightFor(width, height) = max(height, width / 0.6)` (`src/components/CoverBandGeometry.h:46-48`, `CoverBand.cpp:91-92`). Width is unchanged (464) and the height stays under 773, so the key stays 773 — the same file the masthead and sleep screen share. The test pins this (it already does at `HomeLayoutTest.cpp:40`).
- **A5 — The no-cover fallback header moves down by the same gap.** Today it is drawn at `Rect{0, metrics.topPadding, screenWidth, headerHeight}` (`LauncherActivity.cpp:285-286`), independent of `layout`. `HomeLayout` exposes `fallbackHeader = {0, metrics.topPadding + PAD, screenWidth, headerHeight}` and the draw uses it, keeping today's full-width, inset-free placement and adding only the gap. Home's no-cover header deliberately sits `PAD` below the `topPadding` row that other screens' headers use (e.g. `Masthead.cpp:89`). The screen then breathes at the top with or without a cover.
- **A6 — "Digit width" is the ink width `getTextWidth` returns for `"0"`, and the widest day number is the ink width of `"00"`.** `GfxRenderer::getTextWidth` (`lib/GfxRenderer/GfxRenderer.cpp:600-628`) returns `maxX - minX` of glyph bitmaps from `EpdFont::getTextBounds` (`lib/EpdFont/EpdFont.cpp:7-70`), with advances rounded by `fp4::toPixel` (`lib/EpdFont/EpdFontData.h:27`). Ubuntu's digits share one advance (`188/16 = 11.75`) and one ink box (width 10, left 1) (`ubuntu_10_regular.h`, glyph table from `:1485`), so `"0"` measures `0 → 1+10 = 11` and `"00"` measures `12+1+10 = 23`. Digits are tabular, so `"00"` is the widest one- or two-digit day. Criterion: pitch − widest number ≥ digit, i.e. `cell = twoDigits + digit`. Device: 23 + 11 = **34** (was 26); strip 7 × 34 = 238 (was 182).
- **A7 — Floor at today's cell.** `cell = max(STRIP_CELL_MIN, twoDigits + digit)` with the old `26` renamed `STRIP_CELL_MIN`. `getTextWidth` returns 0 and logs when a font is missing (`GfxRenderer.cpp:610-612`); the floor keeps the strip drawable in that case instead of collapsing to zero width.
- **A8 — The title column shrinks and still fits.** With a 238 px strip the column left of it is `strip.x − PAD − textX = (8+464−8−238) − 8 − 56 = 162` px (arithmetic of `HomeLayout.h:137-140`), down from 218. The widest `STR_MEETINGS` is Spanish "Reuniones", ~104 px in UI_10 bold (only English and Spanish define it; research note). `drawTextIn` truncates the percent line to its box (`LauncherActivity.cpp:61`). The test asserts ≥ 104.
- **A9 — Letter and number share one centre.** Both are already centred on the same cell (`LauncherActivity.cpp:365-369`); widening the cell keeps that. No change beyond the width.
- **A10 — The "today" box keeps its 1 px inset inside its own cell** (`LauncherActivity.cpp:363-364`), now expressed in `HomeLayout`. With a 34 px pitch, a neighbour's 23 px number starts `(34 − 23) / 2 = 5` px into its cell, so the box edge is 6 px clear of it. The test asserts the box stays clear of the neighbours' number ink, using the measured widths.

## Architecture

All geometry stays in the renderer-free `HomeLayout` namespace; the launcher only measures and draws.

### `HomeLayout.h`

- New measured-input struct, mirroring `LineHeights` (`:36-41`):

  ```cpp
  struct TextWidths {
    int digit = 0;      // ink width of "0" at UI_10
    int twoDigits = 0;  // ink width of "00" at UI_10, the widest day number
  };
  ```

- `STRIP_CELL` → `STRIP_CELL_MIN = 26`; new `constexpr int stripCellWidth(const TextWidths&)` returning `std::max(STRIP_CELL_MIN, twoDigits + digit)`.
- `plateHeight` gains `+ PAD` (A3).
- `compute(screenW, screenH, insets, metrics, lines, widths)` — one new parameter.
  - `top = insets.top + metrics.topPadding + PAD`; `band(screenWidth, insets.top + PAD, …)` (A2).
  - `buttonRow.y`, `continueButton.y`, `goToButton.y` = `bottomOf(plateHeader) + PAD` (A3).
  - `stripWidth = STRIP_CELLS * stripCellWidth(widths)`; the strip stays right-aligned in the card (`:138`).
  - `Layout` gains `int stripCell` (the pitch) and `Box fallbackHeader` (A5).
- New `constexpr Box stripDay(const Layout&, int index, int height)` — cell `index`'s box — and `constexpr Box stripHighlight(const Box& cell)` — the 1 px inset box (A10) — so the drawing's geometry is host-tested rather than recomputed in the `.cpp`.

### `LauncherActivity.cpp`

- `computeLayout()` (`:86-98`) measures `renderer.getTextWidth(UI_10_FONT_ID, "0")` and `"00"` and passes `TextWidths`, and logs the resulting cell at `LOG_DBG` for the device check.
- `drawHero()` draws the fallback header at `layout.fallbackHeader` (A5).
- `drawMeetings()` (`:357-377`) takes cell boxes from `HomeLayout::stripDay` and the today box from `stripHighlight`; the dot and text placement are otherwise unchanged.

No change to `LauncherActivity.h`, `MeetingWeekView`, themes, i18n or `test/CMakeLists.txt`.

## Data and control flow

Unchanged in shape: `onEnter` → `computeLayout()` (now also two `getTextWidth` calls, each a walk over one or two glyphs of a built-in flash font — no SD access, no allocation beyond `getTextWidth`'s existing local `std::string` for bidi) → `HomeLayout::compute` → cached `layout` → `resolveTargets()` sizes the thumbnail from `layout.hero` (key unchanged, A4) → `render()` draws from `layout`. Touch routing uses the same boxes through `boxFor` (`LauncherActivity.cpp:224-253`); the button boxes move down 8 px with the drawing, so hit-testing follows automatically.

## Error handling

- Missing UI font: `getTextWidth` returns 0 and logs (`GfxRenderer.cpp:610-612`); A7's floor keeps the old 26 px cell.
- The layout is pure arithmetic on already-validated inputs; no new failure path, allocation or I/O. `MIN_HERO_ART` remains asserted by the host test.
