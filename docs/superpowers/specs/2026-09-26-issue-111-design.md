# Issue #111 design — one header for the SD card's path constants

Research: `docs/superpowers/research/2026-09-26-issue-111-research.md` (baseline
`2f303f6f`). Every `file:line` here was re-read at that commit.

Modelled on **`lib/Serialization/SaveBudget.h`**: a header-only file in
`lib/Serialization/`, `#pragma once`, one namespace, `inline constexpr` values, a
`constexpr` predicate beside them, and a host test in `test/save_budget/`.

## Problem

Neither SD root has a single definition. `"/.crosspoint"` is spelled as a bare root
13 times in 10 files and inside 8 more full paths; `"/.berean"` is defined as a
root constant in 5 files under two names (`BEREAN_DIR`, `STUDY_DIR` at
`src/network/CatalogIndexStore.cpp:27`) and repeated as the prefix of 11 more path
constants. The research note's §1 tables list every site.

The cost is drift, not a present bug: a new store that mistypes the root writes its
data somewhere nothing else looks, and `/.crosspoint/highlights` is already spelled
two ways — `src/util/HighlightFile.cpp:14` with a trailing slash,
`src/study/MigrationRunner.cpp:31` without.

## Goal

One header, `lib/Serialization/SdPaths.h`, owns the spelling of both roots and of
every fixed, well-known path beneath them. Every code use listed in the research
note reads from it. Every string the firmware passes to `Storage` after the change
is **byte-identical** to the one it passes today.

## Non-goals

- **No on-card rename**, no format-version bump, no cache invalidation.
- **No change to how paths are composed at runtime** — the per-book stems
  (`pathflatten::toCacheName`, `Epub`'s `/epub_<hash>`, `catalog-<lang>.idx`,
  `<pubkey>.json`) keep being built where they are built today.
- **Comments are not rewritten.** Comments that name a path (e.g.
  `src/study/MigrationRunner.h:5`, `lib/Serialization/PersistableStore.h:53`)
  describe the card and stay as prose.
- **`src/util/RecentBooksDoc.h:41-43`**'s hand-derived 57-byte bound stays a
  comment; turning it into a `static_assert` is a separate change.
- **Host-test literals stay literal**
  (`test/protected_path/ProtectedPathTest.cpp`, `test/recent_books_doc/RecentBooksDocTest.cpp`).
  They assert the on-card contract; a test that reads the constant cannot catch a
  change to it.
- **`lib/ProtectedPath`** matches any dot-prefixed component
  (`lib/ProtectedPath/ProtectedPath.h:5-8`) and needs no root constant.
- **No memory or flash gain is claimed.** Named string literals are already
  candidates for the linker's constant merging; this change is about one spelling,
  not bytes.

## Architecture

### The header

`lib/Serialization/SdPaths.h`, namespace `sdpaths`:

```cpp
#pragma once

#include <string_view>

// Every fixed path this firmware reads or writes on the SD card. Full paths are
// written out whole because C++20 cannot join named constants at compile time;
// the static_asserts below keep each one under its root.
namespace sdpaths {

inline constexpr char CROSSPOINT_DIR[] = "/.crosspoint";
inline constexpr char BEREAN_DIR[] = "/.berean";

inline constexpr char SETTINGS_FILE[] = "/.crosspoint/settings.json";
inline constexpr char STATE_FILE[] = "/.crosspoint/state.json";
inline constexpr char RECENT_BOOKS_FILE[] = "/.crosspoint/recent.json";
inline constexpr char WIFI_FILE[] = "/.crosspoint/wifi.json";
inline constexpr char SLEEP_FRAME_FILE[] = "/.crosspoint/sleep_frame.bin";
inline constexpr char HIGHLIGHTS_DIR[] = "/.crosspoint/highlights";
inline constexpr char BOOKMARKS_DIR[] = "/.crosspoint/bookmarks";

inline constexpr char PUBKEYS_FILE[] = "/.berean/pubkeys.json";
inline constexpr char TAGS_FILE[] = "/.berean/tags.json";
inline constexpr char MEETING_WEEKS_FILE[] = "/.berean/meeting-weeks.json";
inline constexpr char MIGRATION_REPORT_FILE[] = "/.berean/migration-report.json";
inline constexpr char MIGRATION_LEDGER_FILE[] = "/.berean/migration-ledger.json";
inline constexpr char SEARCH_DIR[] = "/.berean/search";
inline constexpr char SEARCH_INDEX_FILE[] = "/.berean/search/bible.idx";
inline constexpr char SEARCH_CHECKPOINT_FILE[] = "/.berean/search/bible.partial";
inline constexpr char PASSAGES_DIR[] = "/.berean/passages";
inline constexpr char UNITS_DIR[] = "/.berean/units";
inline constexpr char COMPLETION_DIR[] = "/.berean/completion";

constexpr bool isUnder(std::string_view path, std::string_view dir) {
  return path.size() > dir.size() + 1 && path.starts_with(dir) && path[dir.size()] == '/';
}

static_assert(isUnder(SETTINGS_FILE, CROSSPOINT_DIR));
// ... one static_assert per constant, against its root (and the three search
// paths also against SEARCH_DIR).

}  // namespace sdpaths
```

- **A1 — Home is `lib/Serialization/`.** The issue names it; `SaveBudget.h`
  lives there; `<SaveBudget.h>` already resolves from `src/study/`,
  `src/network/` and `src/util/` (research §4), and `PersistableStore.cpp` — one
  of the users — is in that library.
- **A2 — `inline constexpr char NAME[]`, not `const char*`.** The array form is
  what `src/main.cpp:227` and `src/activities/boot_sleep/SleepActivity.cpp:34-36`
  already use for SD paths; it decays to `const char*` at every call site, carries
  its length for `std::string_view` in `static_assert`, and `inline` gives one
  definition across translation units (C++17 inline variables; the build is
  `-std=c++2a`).
- **A3 — Full paths are written out whole, guarded by `static_assert`.** Research
  §2 lists the options. A preprocessor root (`#define`) is rejected: the repo
  keeps constants `constexpr` (`CLAUDE.md`, resource protocol §6). A
  `consteval` array-join helper is rejected: the repo has none (research §2 grep)
  and `data-dev.md` forbids inventing a cross-cutting mechanism. Written-out
  literals plus a `constexpr` predicate uses only what the repo already does —
  `constexpr bool persist::fitsBudget` (`lib/Serialization/SaveBudget.h:26`) and
  `static_assert` on store constants (`src/RecentBooksStore.cpp:125-128`). A
  mistyped root then fails the build in every includer.
- **A4 — Directory constants carry no trailing slash.** `HighlightFile.cpp:14` and
  `BookmarkUtil.cpp:10` return a slash-terminated `std::string`; they will return
  `std::string(sdpaths::HIGHLIGHTS_DIR) + "/"` (resp. `BOOKMARKS_DIR`), which is
  byte-identical to today and still one `std::string` construction per call, as
  today. `MigrationRunner.cpp:31` already uses the unslashed form.
- **A5 — Store-owned constant names stay, as aliases.** Callers name paths through
  their owner: `MigrationRunner::REPORT_PATH` (`src/network/CrossPointWebServer.cpp:1847,1853`),
  `BibleSearchStore::INDEX_PATH` (`src/study/BibleSearchIndexer.cpp:229`), etc.
  Those declarations keep their names and types and change only their initialiser:
  `inline constexpr const char* REPORT_PATH = sdpaths::MIGRATION_REPORT_FILE;`.
  The spelling has one definition; the owner still names what it owns; no caller
  changes. The alternative — delete the aliases and rewrite every caller — widens
  the diff into `CrossPointWebServer.cpp` and `BibleSearchIndexer.cpp` for no
  change in behaviour.
- **A6 — File-local root duplicates are deleted, not aliased.** The five
  `BEREAN_DIR`/`STUDY_DIR` definitions and `LEGACY_DIR`, `PASSAGES_DIR`,
  `UNITS_DIR`, `COMPLETION_DIR` are TU-private (`constexpr` in a `.cpp`,
  anonymous namespace or file scope); their uses switch to the `sdpaths::` name.
  They are exactly the repetition the issue asks to remove.
- **A7 — `catalog-<lang>.idx` is composed from `BEREAN_DIR` at runtime,** as today
  (`src/network/CatalogIndexStore.cpp:51`); it is not a fixed path.
- **A8 — `src/main.cpp` is a shared append point** (`.claude/agents/data-dev.md`,
  "Shared files — report, do not edit"). Its one change — `#include <SdPaths.h>`
  and line 227 becoming
  `constexpr const char* SLEEP_FRAME_FILE = sdpaths::SLEEP_FRAME_FILE;` — goes into
  the PR description as exact lines for the orchestrator to apply, not into this
  branch. Likewise `test/CMakeLists.txt`'s `add_subdirectory(sd_paths)`.

## Error handling

Unchanged. No call site gains or loses an error path: every `mkdir`, `exists`,
`open` and `rename` receives the same string and handles failure the way it does
today. The only new failure mode is at compile time — a constant outside its root
fails its `static_assert` — which is the point.

## Testing strategy

TDD, mirroring `test/save_budget/SaveBudgetTest.cpp` and its `CMakeLists.txt`.

1. **Red:** `test/sd_paths/SdPathsTest.cpp` with `EXPECT_STREQ` pinning every
   `sdpaths::` constant to its **literal** on-card value
   (`EXPECT_STREQ(sdpaths::SETTINGS_FILE, "/.crosspoint/settings.json")`), plus
   `isUnder` cases: accepts a child, rejects the root itself, rejects a sibling
   that shares a prefix (`"/.bereanx/a"` vs `"/.berean"`), rejects `"/.berean/"`
   with an empty tail. Fails to build until the header exists.
2. **Green:** add `SdPaths.h`; the test passes. The literals in the test are the
   byte-identical contract (Goal) — the test, not the header, is the source of
   truth for what is on the card.
3. **Sweep:** switch every site in the table. Verification that none was missed:

   ```bash
   grep -rn '"/\.crosspoint\|"/\.berean' src lib --include='*.cpp' --include='*.h'
   ```

   must print only `lib/Serialization/SdPaths.h` lines (plus `src/main.cpp:227`
   until the orchestrator applies A8).
4. **Build:** `pio run` (x4pro) once after the last code edit — this is what
   proves every `static_assert` and every `#include <SdPaths.h>` resolves on the
   target toolchain (GCC 14.2.0, research §3).
5. **Existing suites** that link touched code — `recent_books_doc`,
   `protected_path`, `bookmark_*`, `save_budget` — must still pass unchanged; their
   literals are deliberately untouched.
6. **Format:** `git add` the new files, then `./bin/clang-format-fix` over the
   whole tree.

Not host-testable: that the firmware still finds existing data on a real card. The
`EXPECT_STREQ` pins make it follow by construction; for the human tester, boot on
a card with existing `/.crosspoint/settings.json`, highlights and `/.berean/tags.json`
and confirm settings, highlights and tags are all still present.
