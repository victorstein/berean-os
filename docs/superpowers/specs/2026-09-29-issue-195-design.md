# Issue #195 — retire Bible chapter-completion recording

**Date:** 2026-09-29
**Branch:** `refactor/195-retire-chapter-completion` (base `3591e3fe`)
**Research:** `docs/superpowers/research/2026-09-29-issue-195-research.md` (cited as **R**)
**Modelled on:** the retirement in #197 (`3591e3fe`), and the change this undoes, #78
(`1269fced`). `src/activities/reader/BibleReference.h` is the model for the one new header.

## Problem

The firmware still records which Bible chapters were paged through, but nothing reads that record
any more. #197 removed its last two readers, the Home subtitle and the sleep-screen strip (R §1).

The record still costs:

- **An SD read on every Bible open.** `StudyStore::openPublication` loads
  `/.berean/completion/bible.json` (`src/study/StudyStore.cpp:71-76`).
- **An atomic SD write per newly read chapter**, under `storageMutex`. `pageTurn` calls
  `recordDocumentRead()` (`src/activities/reader/EpubReaderActivity.cpp:909, 917`), which calls
  `StudyStore::markDocumentRead` (`StudyStore.cpp:110-121`), which calls
  `ChapterCompletionFile::save` (`src/study/ChapterCompletionFile.cpp:28-37`), which calls
  `writeDocToFileAtomic`.
- **149 bytes of singleton storage and two latches** (`src/study/StudyStore.h:193-200`).
- **Two popups a user can still see:** a load-failure notice on Bible open
  (`EpubReaderActivity.cpp:219-221`) and a save-failure notice on a chapter turn (`:942-944`).
  Both report failures of a record that nothing uses.
- **About 700 lines of code and 32 host tests:** the 30 `ChapterCompletion*` tests counted in R §5,
  plus 2 `CanonicalChapters` tests (`test/chapter_completion/ChapterCompletionTest.cpp:30, 37`) that R
  §5's grep missed.

## Goal

Delete the write path, the load path, the record type and its storage shell, so that the firmware
neither reads nor writes `/.berean/completion/`. Existing files are left exactly as they are.

## Non-goals

- **Deleting `/.berean/completion/*.json` from cards.** The issue says so explicitly. Nothing in the
  firmware removes anything under `/.berean/`: Clear Cache walks only `CROSSPOINT_DIR`
  (`src/activities/settings/ClearCacheActivity.cpp:101, 120-121`).
- **Shrinking the two-slot `PostedMessage` queue.** It is general-purpose, and every reader refusal
  goes through `ReaderUtils::showMessage` (R §3.6).
- **Editing the historical design docs** (`2026-09-13-…`, `2026-09-23-…`). They record past
  decisions.
- **Any change to page-turn behaviour.** The page-turn branch condition is kept byte-for-byte in
  meaning (A-3).
- **Any change to Meetings progress.** It never read this record (R §1).

## Decisions

### D1 — the page-turn predicate moves out before its header is deleted

`study::forwardTurnLeavesDocument` (`lib/StudyStore/StudyStore/ChapterCompletion.h:63-68`) is
`pageTurn`'s own branch condition (`EpubReaderActivity.cpp:903`). It is not completion logic, and
its only tests live in the suite being deleted (`test/chapter_completion/ChapterCompletionTest.cpp:102-113`).
It moves to a new pure header `src/activities/reader/PageTurn.h`, and its two tests move to the
existing `test/auto_page_turn/` suite.

**Model:** `src/activities/reader/BibleReference.h`, a pure inline helper free of Arduino and Epub,
tested from a host suite with `${REPO_ROOT}/src` on the include path (`test/ui_layout/CMakeLists.txt`,
`BibleReferenceTest.cpp`). `test/auto_page_turn/CMakeLists.txt` has the same shape and already tests
`activities/reader/AutoPageTurn.h`, so no new test directory and no `test/CMakeLists.txt` append is
needed.

**Rejected: inline the pre-#78 condition** (`section->currentPage < section->pageCount - 1 ||
section->isBuilding()`, from `git show 1269fced`). It is smaller, but it drops the only tests of
the forward-turn boundary. #78 introduced the named predicate precisely so that this branch was
tested.

### D2 — delete outright, and prove it with a grep

This mirrors #197. The code and its tests are removed, not stubbed or put behind a flag. The PR
quotes a word-anchored grep over `src lib test` showing that no reference is left (see Testing).

`EpubReaderActivity.cpp` gets `ChapterCompletion.h` today only transitively, through
`study/StudyStore.h:10` (included at `EpubReaderActivity.cpp:50`). It must include `"PageTurn.h"` directly. It keeps its other `study::` uses

header. The firmware build confirms this.

`lib/StudyStore/StudyStore/UnitAnchors.h` (which `ChapterCompletion.h:9` includes) stays. It is
reached directly from `StudyStore.cpp:12`.

## Data and control flow after the change

- **Bible open:** `openPublication` loads the tag palette and the passages, then the unit index
  (`StudyStore.cpp:59-81`, minus `:71-76`). There is no completion read and no completion latch.
- **Forward turn off the last page:** `forwardTurnLeavesDocument` is true, the code takes
  `RenderLock`, advances `currentSpineIndex` (or sets it to the end), resets the section and stamps
  the time. There is no StudyStore call and no SD access on this path.
- **On the card:** `/.berean/completion/bible.json`, if present, is never opened. No code path
  builds that path string any more (only the unused `COMPLETION_DIR` constant names it).

## Error handling

- The two completion failure modes (load refused, save failed) disappear together with their
  popups and strings. There is nothing left to fail.
- **A corrupt or future-version completion file** used to latch `completionSaveDisabled_` and show a
  notice. Now it is simply ignored, which is the intended behaviour for a retired file.
- The passage store's `saveDisabled_` latch and `STR_HIGHLIGHTS_LOAD_FAILED` (`EpubReaderActivity.cpp:216-218`)
  are unaffected.

### 1. TDD for the one piece of new code

1. **Red.** Add `test/auto_page_turn/ForwardTurnTest.cpp`, including `"activities/reader/PageTurn.h"`,
   with the two tests moved from `ChapterCompletionTest.cpp:102-113` (four + one expectations,

### 2. Removal proof, quoted in the PR

After `pio run` has regenerated the I18n headers:

    grep -rnw -e ChapterCompletion -e ChapterCompletionFile -e markDocumentRead \
      -e recordDocumentRead -e takeCompletionLoadFailureNotice -e CompletionMarkResult \
      -e completionSaveDisabled_ -e STR_CHAPTERS_READ_LOAD_FAILED -e STR_CHAPTERS_READ_SAVE_FAILED \
      -e canonicalChapterCount -e CANONICAL_CHAPTER_TOTAL -e completionLoadFailureAnnounced_ \
      -e saveBibleCompletion -e CompletionSaveFn -e markDocumentChapters -e BIBLE_BOOK_COUNT \
      -e completion_ src lib test

This must return nothing, apart from generated I18n headers that the build regenerates.
`grep -rn COMPLETION_DIR src lib test` must return only `SdPaths.h:32, 56` and
`SdPathsTest.cpp:35`.

### 3. Suites

- `cmake -S test -B build/test && cmake --build build/test && ctest --test-dir build/test` passes
  **1272** tests: the 1302 baseline (R §5), minus 32 (the 30 `ChapterCompletion*` tests and the 2
  `CanonicalChapters` tests), plus the 2 moved tests. Check with
  `ctest -N | grep -c -E "ChapterCompletion|CanonicalChapters"`, which returns 32 today and must return 0 after the change.
- `pio run -e x4pro` builds with no new warnings from `src/` or `lib/`.
- `pio check` passes.
- `./bin/clang-format-fix`, over the whole tree after `git add`, is clean.

### 4. Device checks for the owner

1. **The file is untouched.** On a card that has `/.berean/completion/bible.json`, record its size
   and SHA-256 from a computer. Flash, open the Bible, page forward across at least two chapters
   never read before, then exit. Re-check the card: the bytes are identical and no `.tmp` sits
   beside the file.
2. **A normal boot and read.** A card with a completion file boots, opens the Bible, and shows no
   "Chapters read …" popup.
3. **Page turns still work.** Paging forward off a chapter's last page loads the next chapter.
   Paging off the last page of a book reaches the end-of-book screen. Paging forward while a
   section is still building stays in the section.
