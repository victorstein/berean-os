# Issue #172 — design: web-server route groups and `setup()` init stages

Task `t10`, tier `heavy`. Research: `docs/superpowers/research/2026-09-27-issue-172-research.md`
(cited as "R§n"). Line numbers are against `7c080671`.

## Problem

`src/network/CrossPointWebServer.cpp` is 1,883 lines holding every route handler of the device's
web server in one class (R§2, R§3b). The files, settings and fonts groups share nothing with each
other except the `WebServer` pointer and three small helpers (R§3c), yet a reviewer changing one has
to page through all of them, and the class header carries both groups' upload state
(`CrossPointWebServer.h:35-51, 121-133`).

`src/main.cpp` `setup()` (`:340-606`) is a 267-line function whose thirteen phases (R§5) hand eight
local values to each other by scope. Which phase reads which flag is only visible by reading all of
it; the boot-routing decision — the rule that picks crash report, reader or home —
cannot be tested because it is buried in the function (`:559-586`).

## Goal

Two behaviour-preserving extractions on one branch, **two commits** in this order (batch brief):

1. **Route groups.** `FileRoutes`, `SettingsRoutes`, `FontRoutes` each own their handlers (and, for
   files and fonts, their upload state) in their own translation unit under `src/network/`.
   `CrossPointWebServer` keeps lifecycle, core routes (`/`, `/api/status`, not-found), `/migration`,
   Wi-Fi credentials, WebSocket upload, UDP discovery and WebDAV registration.
2. **Boot stages.** `setup()` becomes a short sequence of named `static` functions in `main.cpp`
   passing one `BootContext` struct. The three pure decisions — silent-reboot decode, boot-resume
   resolution, first-activity route — move to a header-only `src/boot/BootDecisions.h` with a host
   test.

Success: every route answers byte-identically (same path, method, status, body, headers, protection);
boot takes the same steps in the same order; `pio run -e x4pro` builds with no new warnings; all host
tests pass, including the new suite.

## Non-goals

- No functional, settings, string, on-disk format or HTTP contract change.
- Not splitting core, `/migration`, Wi-Fi, WebSocket or UDP out of `CrossPointWebServer` — the issue
  names files, settings and fonts only.
- Not fixing pre-existing oddities met on the way: `handleFontList`'s `const_cast`
  (`CrossPointWebServer.cpp:1656`), the unchecked throwing `vector::resize` in the upload-state
  constructors (`.h:50, :132`), `startDeepSleep` lacking `[[noreturn]]` (`HalPowerManager.h:43`).
- No new test infrastructure: no growth of `test/stubs/Arduino.h`'s `String` (R§6), no stub
  `WebServer`.
- Not moving `t1`, `wakePowerReleasePending`, `allowSleepAt` out of globals — they are read by
  `loop()` (`main.cpp:657, 717, 734`) and pre-exist; the issue forbids only *new* globals.

## Assumptions (each is a decision the review should attack)

### Web server

- **W1 — A route group is a plain class that registers its own `server.on(...)` routes, not a
  `RequestHandler` subclass.** The issue names `WebDAVHandler` as the precedent for "a route group
  outside the class". What WebDAV establishes is the *outside the class, own translation unit, own
  state, handlers take `WebServer&`* part (`WebDAVHandler.h:6-43`). Its *subclass* part would force
  each group to re-implement exact-URI + method matching (`Uri.h:24-26`,
  `RequestHandlersImpl.h:83-89`) and the multipart upload hooks (`canUpload`/`upload`,
  `RequestHandlersImpl.h:91-97`; `Parsing.cpp:355-356`) that today's `server->on(path, method, fn,
  ufn)` gets from the core. Re-implementing dispatch is the one way this refactor could change which
  handler answers a request. A group that calls `server.on(...)` keeps the core's
  `FunctionRequestHandler` for every route, so dispatch is untouched. Modelled on: `WebDAVHandler`
  (file layout, `WebServer& s` handler parameter, owned streaming state) and `ReaderBookmarks`
  (`src/activities/reader/ReaderBookmarks.h`, PR #171 — a sub-object owned by value by the class it
  was carved out of).
- **W2 — Groups are by-value members of `CrossPointWebServer`.** `FileRoutes fileRoutes;`,
  `SettingsRoutes settingsRoutes;`, `FontRoutes fontRoutes;` (not `settings`: `handleGetSettings` already has a local of that name, `CrossPointWebServer.cpp:1139`). `UploadState` (4 KB vector) moves into
  `FileRoutes`, `FontUploadState` (4 KB vector) into `FontRoutes`. Both are still constructed inside
  the `CrossPointWebServer` object allocated by `makeUniqueNoThrow<CrossPointWebServer>()`
  (`CrossPointWebServerActivity.cpp:263`), so the same two 4 KB blocks are allocated at the same
  moment; no heap allocation is added or moved. A `unique_ptr` per group was rejected: it adds three
  allocations and three OOM paths for no gain.
- **W3 — Handlers reach the server through a `WebServer&` captured at registration.** Each group has
  `void registerRoutes(WebServer& server)`; lambdas capture `[this, &server]` and call
  `handleX(server)`, mirroring WebDAV's `handleGet(WebServer& s)` (`WebDAVHandler.h:24`). Lifetime:
  the `FunctionRequestHandler`s holding those lambdas are owned and deleted by the `WebServer`
  (`WebServer.cpp:52-65`); the `WebServer` is destroyed by `server.reset()` in `stop()`
  (`CrossPointWebServer.cpp:284`), which the destructor calls (`:88`) *before* any member (including
  the groups) is destroyed. Every early-return failure path in `begin()` also resets `server`
  (`:127-130, :186-189, :197-203`), so no registered lambda can outlive its group or its server.
- **W4 — `FileRoutes` keeps `handleUpload`'s `!running || !server` guard** (`:644`) by holding a
  `const bool&` to the owner's `running`, passed at construction. The guard is unreachable in
  practice (handlers only run inside `handleClient()`, which returns early when `!running`, `:297`),
  but deleting it is a behaviour change in principle and the refactor is move-only. The `!server`
  half becomes a no-op check against a reference and is dropped: the handler is holding the server
  reference it was called through.
  *Attack surface:* this is the only place a group reads owner state.
- **W5 — Registration order.** `WebDAVHandler::canHandle` claims every URI for GET, PUT, DELETE and
  eight other methods (`WebDAVHandler.cpp:19-38`) and dispatch is first-match in registration order
  (`Parsing.cpp:131-137`, `WebServer.cpp:368-376`). **All group registrations run before
  `addHandler(webDavHandler)` (`:191`) and before `onNotFound` (`:178`).** The order among `on()`
  routes changes — core routes first, then `fileRoutes.registerRoutes`, `settingsRoutes.registerRoutes`,
  `fontRoutes.registerRoutes`, then Wi-Fi — which cannot change dispatch: every `Uri` match is exact
  string equality (`Uri.h:25`) and no two registrations share both path and method (R§3b). The
  resulting route set is checked mechanically (see Testing).
- **W6 — Shared helpers move to `src/network/WebRouteUtils.{h,cpp}`**, namespace `webroutes`:
  `normalizeWebPath` (`:55-71`), `isProtectedWebPath` (`:73-75`), `isProtectedWebName` (`:77-79`),
  `sendHtmlContent` (`:355-358`). They are used by core, files, settings, fonts and the WebSocket
  handler (`:361, 480, 1131, 1531, 1650`; R§3c), so one home both sides include is required. Bodies
  move verbatim. Modelled on `lib/ProtectedPath` (a small namespace of free functions the server
  already calls). Not host-tested: they take Arduino `String`, which the host stub does not model
  (R§6); the logic they wrap, `protectedpath::` and `FsHelpers::normalisePath`, is already tested
  (`test/protected_path/`).
- **W7 — Move-only bodies.** Handler bodies change only `server->` → `server.` and the helper
  namespace prefix. Logs keep their `"WEB"` tag and text. The file-scope upload diagnostics
  (`uploadStartTime`, `totalWriteTime`, `writeCount`, `flushUploadBuffer`, `:614-635`) and
  `handleUpload`'s function-static `lastLoggedSize` (`:638`) move to `FileRoutes.cpp` file scope
  unchanged. `FileInfo` (`.h:15-20`, used nowhere else, R§2) moves to `FileRoutes.h`.
- **W8 — The dead `formatFileSize` declaration (`.h:90`) is deleted.** It has no definition
  (R§3e); nothing can call it, so removal is behaviour-free.
- **W9 — Public API change is confined to `upload`.** `CrossPointWebServer::upload` is public
  (`.h:35-51`) but has no user outside the class (`grep -rn "\.upload\b\|->upload\b" src` finds only
  `server->upload()`, the core's `HTTPUpload` accessor). It becomes `FileRoutes`' private state.
  `begin`, `stop`, `handleClient`, `isRunning`, `getWsUploadStatus`, `getPort` are unchanged.

### `setup()`

- **S1 — Stages are `static` free functions in `main.cpp`, taking `BootContext&`.** The issue allows
  either `main.cpp` or `src/boot/`; stages call a dozen file-local globals (`renderer`,
  `activityManager`, `mappedInputManager`, `fontDecompressor`, `silentRebootMagic`,
  `loadSleepFrameBuffer`, `setupDisplayAndFonts`, …, `main.cpp:46-51, 136-137, 239, 294`), so moving
  them out would need those exported. Modelled on `setupDisplayAndFonts` (`:294-338`), the file's
  existing named init helper.
- **S2 — `BootContext` holds exactly the issue's eight values** — `rebootedFromPanic`,
  `isSilentReboot`, `snapshotTarget`, `wakeupReason`, `recoveryFirmwareMode`, `resume`,
  `allowFastInitialReaderRefresh`, `needsWakeRefresh` — with the defaults the locals have today
  (`false`, `0`, `Splash`). It is a local in `setup()` (stack, 12-ish bytes), not a global.
  `restoreLightOn` (`:428`) and `isSleepWake` (`:467`) stay single-use locals of their stage.
- **S3 — Stage list and order** (each maps 1:1 to research §5, same statements in the same order):

  | Stage | Lines today | Reads | Writes |
  |---|---|---|---|
  | `holdPowerRails`, `t1`, `beginSerialLog()` | `:341-356` | — | — |
  | `readRebootMarkers(ctx)` | `:358-369` | RTC words | `rebootedFromPanic`, `isSilentReboot`, `snapshotTarget` |
  | `beginInputAndPower(ctx)` | `:371-401` | — | `wakeupReason`, `recoveryFirmwareMode` |
  | `mountStorage(ctx)` → `bool` | `:403-410` | `isSilentReboot` | — |
  | `loadPersistedState(ctx)` | `:412-429` | `isSilentReboot` | — |
  | `confirmWakeReason(ctx)` | `:431-456` | `wakeupReason` | global `wakePowerReleasePending` |
  | version log (stays in `setup()`) | `:458-459` | — | — |
  | `beginDisplay(ctx)` | `:461-474` | `isSilentReboot`, `wakeupReason` | `resume` |
  | `runPendingMigration()` | `:476-516` | — | — |
  | `presentBoot(ctx)` | `:518-554` | `resume` | the two refresh flags |
  | `routeFirstActivity(ctx)` | `:556-586` | all | — |
  | `settleSilentResume(ctx)` | `:588-603` | `resume` | — |
  | `allowSleepAt = …` | `:605` | — | global |

  `setup()` becomes the column on the left, with `if (!mountStorage(ctx)) return;` in place of the
  early return.
- **S4 — SD failure keeps its early return and its skipped tail.** `mountStorage` does exactly
  `:405-408` and returns `false`; `setup()` returns immediately, so, as today, `checkPanic`, the
  stores, migration and `allowSleepAt` are skipped (`allowSleepAt` stays `0`, `:52`).
- **S5 — The migration painter's function-local statics stay function-local statics**, now of
  `runPendingMigration` (`:487-488`). They exist because `MigrationProgress::onStep` is a plain
  function pointer and the lambda must be captureless; that does not change.
- **S6 — Three pure decisions go to `src/boot/BootDecisions.h`** (header-only, no firmware
  includes), modelled on `src/activities/reader/AutoPageTurn.h` (PR #171's header-only pure unit)
  and tested like `test/auto_page_turn/`:
  - `SilentReboot decodeSilentReboot(uint32_t magic, uint32_t target)` → `{bool silent; uint32_t
    target;}` — the `:365-367` expression. The RTC read-and-clear (`:368-369`) stays in the stage.
  - `BootResume resolveBootResume(bool isSilentReboot, bool isSleepWake, bool showBootScreen)` —
    `:467-470`.
  - `BootRoute chooseBootRoute(const BootRouteInputs&)` → `RecoveryFirmware | CrashReport |
    SilentReader | SilentHome | Home | ResumeReader` — the `if` chain `:559-586`. The stage performs
    the matching action with the same arguments; the `ResumeReader` branch's `APP_STATE` mutation
    and save (`:581-585`) stays in the stage.
  `BootResume`, `SILENT_REBOOT_MAGIC` and the two target constants (`main.cpp:138-140, 145-149`) move into this
  header so both sides share one definition; the `RTC_NOINIT_ATTR` variables stay in `main.cpp`.
- **S7 — `chooseBootRoute` needs `backHeld` evaluated eagerly.** Today
  `mappedInputManager.isPressed(Back)` (`:575`) runs only if the preceding conditions are false. The
  pure function needs it as an input, so the stage computes it before the call. This is safe only
  because the read has no side effect: `MappedInputManager::isPressed` is `const`
  (`MappedInputManager.cpp:272`) → `mapButton` (`:57-63`) → `HalGPIO::isPressed` `const`
  (`HalGPIO.cpp:178-183`) → `NavKeyGestures::suppressState` `const` (`NavKeyGestures.cpp:52`).
  *Attack surface:* if the review finds a mutable read anywhere down that chain, the fallback is to
  pass `backHeld` only for the final two branches by splitting the function; say so.
- **S8 — Sequencing around `startDeepSleep`.** `confirmWakeReason` ends where the switch ends (`:456`);
  no statement is added after a `startDeepSleep` call inside the stage, and the stage's return is
  followed directly by the version log `:459` (`startDeepSleep` calls: `:436, :448`), as today.

## Architecture

```
src/network/
  CrossPointWebServer.{h,cpp}   lifecycle, core routes, /migration, Wi-Fi, WebSocket, UDP, WebDAV reg.
  FileRoutes.{h,cpp}            /files /api/files /download /upload /mkdir /rename /move /delete
  SettingsRoutes.{h,cpp}        /settings  GET|POST /api/settings
  FontRoutes.{h,cpp}            /fonts /api/fonts /api/fonts/upload /api/fonts/delete
  WebRouteUtils.{h,cpp}         normalizeWebPath, isProtectedWeb{Path,Name}, sendHtmlContent
src/boot/BootDecisions.h        decodeSilentReboot, resolveBootResume, chooseBootRoute
test/boot_decisions/            BootDecisionsTest.cpp + CMakeLists.txt
```

`platformio.ini` has no `build_src_filter`, so new `.cpp` files under `src/` are compiled without
config change (R§7 of the #110 research; re-checked: `grep -n build_src_filter platformio.ini` is
empty). `test/CMakeLists.txt` gains `add_subdirectory(boot_decisions)` (batch brief allows it).

  struct UploadState { /* moved verbatim from CrossPointWebServer.h:35-51 */ } upload;

class SettingsRoutes { public: void registerRoutes(WebServer&); private: /* 3 handlers */ };

`CrossPointWebServer` declares `FileRoutes fileRoutes{running};` after `running`, so the reference binds
to an initialised member.

## Data and control flow

**Request path (unchanged).** `handleClient()` → `WebServer::handleClient` → first matching
`FunctionRequestHandler` → the lambda registered by the group → group handler with the `WebServer&`.
For `/upload` and `/api/fonts/upload` the core calls the upload lambda per chunk then the completion
lambda, as today.

**Boot path.** `setup()` → stages in S3 order; `BootContext` carries values forward; the three
decisions are computed by `BootDecisions.h` from values the stages read, and the stages perform the
side effects.

## Error handling

- Web server: every OOM path in `begin()` (`:127-130, :186-189, :197-203`) is untouched. Groups add
  no allocation (W2) and `registerRoutes` has no failure mode beyond the core's own `on()`, which is
  already unchecked today.
- Upload failures, protected-path refusals and their status codes move with the handler bodies (W7).
- Boot: the only early exit is SD failure (S4). `startDeepSleep` paths unchanged (S8). Migration's
  failure log (`:510`) moves with the stage.

## Testing strategy

TDD applies where there is a pure unit:

1. **`test/boot_decisions/`** — written first, failing to compile until `BootDecisions.h` exists.
   Cases: decode (magic mismatch → not silent, target 0; magic + target 0/1 → kept; magic + target 2
   or `0xFFFFFFFF` → 0), resume (silent wins over sleep wake; sleep wake + `!showBootScreen` →
   SplashlessWake; sleep wake + `showBootScreen` → Splash; cold boot → Splash), route (recovery beats
   panic beats everything; silent + reader target + open path → SilentReader; silent + reader target
   + empty path → SilentHome; silent + home target → SilentHome even with a stale reader path; each of
   the four go-home conditions alone → Home; all clear → ResumeReader). One test per branch of
   `:559-586`.
2. **Route table equality (mechanical, pre/post).** Before commit 1, extract `(method, path)` from
   every `server->on(` in `CrossPointWebServer.cpp`; after, from `server.on(`/`server->on(` across
   the five files; the sorted sets must be equal (20 routes) and match `docs/webserver-endpoints.md`.
   The command and both outputs go in the PR. A `grep -n` on the new `begin()` shows every
   `registerRoutes` line above `addHandler`.
3. **Move-only review aid.** `git diff --color-moved=dimmed-zebra` per commit; the PR states that
   the only non-moved lines are declarations, registration, `server->`/`server.` and helper prefixes.
4. **Build.** `pio run -e x4pro` through the batch lock; no `warning:` line may name a file this
   task creates or edits (baseline: zero such lines of 249, research §8). If `#106` has landed, rebuild with its `-Wall` too.
5. **Host tests.** Full `ctest` run.
6. **Device (human).** Boot normally; sleep and wake (splashless path); stage a panic reboot if
   possible; File Transfer lists, uploads, renames, moves and deletes; a dot-dir path is refused; web
   settings page loads and saves; fonts page lists; a font upload and delete round-trip.

## If commit 2 balloons

The batch brief allows stopping after commit 1. The trigger is concrete: if `chooseBootRoute`'s
extraction cannot keep S7's evaluation order without restructuring more than `:559-586`, ship commit
1 plus the `BootContext` stage split without `BootDecisions.h`, and say so in the PR.
