# Issue #108: make fallible allocations nothrow. Design

Research: `docs/superpowers/research/2026-09-26-issue-108-research.md` (cited below as **R§n**).
Branch `fix/108-nothrow-fallible-allocations`. Surface `epub`. The batch context routes the
GfxRenderer, reader and network sites here as well.

## Problem

This firmware builds with `-fno-exceptions` (`platformio.ini:72`), but it links against
libraries built with exceptions on (`CONFIG_COMPILER_CXX_EXCEPTIONS=y`, R§1). When a bare
`new` fails, it throws `std::bad_alloc`. No firmware frame can catch that, so it reaches
`std::terminate()` and then `abort()`. The device reboots, and whatever the user was doing is
gone.

R§3's tables list 37 bare new-expressions (32 if each ditherer constructor counts once). Several are sized from content (image width) or run on the
chapter layout path while the heap is at its most loaded. The worst case is structural:
the three `*Ditherer` constructors (`lib/GfxRenderer/BitmapHelpers.h:27-29,108-110,209-210`)
allocate their error rows with a throwing `new`. So even
`makeUniqueNoThrow<AtkinsonDitherer>(outWidth)` in the gold-standard file
(`lib/JpegToBmpConverter/JpegToBmpConverter.cpp:683`) still aborts on OOM. Two existing
null checks after a bare `new` are dead code (`ChapterHtmlSlimParser.cpp:775-778,783-786`).

## Goal

Every allocation R§3 lists either returns null on failure or is `makeUniqueNoThrow`. Each one
is followed by a `LOG_ERR` and a failure path that the caller already understands. No new
failure is ever cached to SD as though it were a success.

## Non-goals

- **NG1.** The 69 fixed-size `std::make_unique` calls: 61 activities, 4 themes and 4
  `HalFile::Impl` (R§4). None is sized from input. The `HalFile` sites are on the `hal`
  surface. Whether `startActivityForResult` tolerates a null activity was not verified, and
  converting those calls would require that. This work converts only `QrUtils.cpp:36` from
  the `std::make_unique` group.
- **NG2.** `std::make_shared` at `ChapterHtmlSlimParser.cpp:1693` and
  `ParsedText.cpp:1560,1589` (R§3, adjacent). They are per-line allocations of fixed-size
  objects, and fixing them properly means changing `ParsedText`'s line callback contract.
  The existing line drop on a `TextBlock` arena failure (`ParsedText.cpp:1562-1565`) needs
  the same contract change and stays as it is. The `shared_ptr` control blocks of the nothrow
  element sites (`ChapterHtmlSlimParser.cpp:380,810,817`) are also still allocated with the
  throwing `operator new`, and so are the `vector<shared_ptr>` growth in
  `Page::deserialize` (`Page.h:77`, `Page.cpp:188,194,200`). All of these are small, fixed-size
  allocations. This spec records them all for a follow-up issue.
- **NG3.** Existing `malloc`/`new (std::nothrow)` sites that already null-check, such as the
  `rowBuffer`/`grayRow` mallocs in `PngToBmpConverter.cpp:618,655` and the element-level drops
  at `ChapterHtmlSlimParser.cpp:380,810,817`. Their object allocation is nothrow. Their
  `shared_ptr` control block is not (NG2). This work does not change their behaviour.
- **NG4.** No new on-disk format, no new I18n string, and no change to the section cache
  version. Nothing written to SD changes shape.

## Data and control flow

### Image conversion (rows 1-4)

The flow is `Epub::generateCoverBmp`/`generateThumbBmp` (`Epub.cpp:601,635,694,730`), then
`{Jpeg,Png}ToBmpConverter`, then the ditherer. When the ditherer fails:

1. `makeUniqueNoThrow<XDitherer>(w)` succeeds, but a row allocation inside the constructor
   returns null. `valid()` is then false.
2. The converter logs `OOM: XDitherer` and returns `false`. In JPEG every buffer is a `ctx`
   `unique_ptr`, so RAII frees them all. In PNG the ditherers and scaling buffers are
   `unique_ptr`, and the three remaining mallocs are freed by the `ScopedCleanup` in row 3.
3. `Epub` already treats a `false` converter result as "no cover" (the `success` locals at
   `Epub.cpp:601`, `:635`). Nothing new reaches SD beyond what an ordinary failed conversion
   already leaves.

`Bitmap::parseHeaders` works differently. It sets the dithering strategy for a BMP that is
already on disk (`Bitmap.cpp:167-175`). On OOM it leaves both ditherers null. `readNextRow`
already takes the quantize branch when both are null (`Bitmap.cpp:195-200`), so the image
renders undithered (A3).

The swap in `nextRow()` (`BitmapHelpers.h:79-82`, `:178-181`, `:299-301`) becomes
`std::swap` of the `unique_ptr`s. `processPixel` indexes through `unique_ptr<T[]>::operator[]`.
That inlines to the same load as the raw pointer, so the pixel loop gets no slower.

### Chapter layout (rows 7-8)

`ChapterHtmlSlimParser` gets one private member and one helper:

```cpp
bool allocationFailed_ = false;
void markAllocationFailed(const char* what);  // LOG_ERR("EHP", "OOM: %s", what); allocationFailed_ = true;
```

- **Allocation sites.** At `:234`, `:325`, `:774`, `:782`, `:1667`, `:1676`, `:1704`, `:341`
  and `:368`, a failed allocation calls `markAllocationFailed()` and returns from the current
  function. Nothing is dereferenced after that return.
- **`startNewTextBlock` (`:325`).** It allocates into a local and moves it into
  `currentTextBlock` only on success. On failure the previous block stays in place, so the
  35 `currentTextBlock->` dereferences in the file never see null during the rest of the
  current expat callback. Anything laid out after that point is discarded with the build
  (A1).
- **Sticky guard.** `addLineToPage` and `makePages` return immediately while
  `allocationFailed_` is set, so no text page is assembled after a failure. The
  horizontal-rule and image page breaks (`:364-366`, `:768-771`) may still emit a non-null
  page into the `.tmp` before the parse stops. `abandonBuild` discards it. The guard matters because `Section::onPageComplete` dereferences `page`
  without a null check (`Section.cpp:92`), and a page assembled after a dropped line would
  otherwise be written to the `.bin`.
- **`parseStep()`** returns `ParseStatus::Error` when `allocationFailed_` is set after
  `XML_ParseBuffer` (`:1600`). The chunk is at most `PARSE_BUFFER_SIZE = 1024` bytes
  (`:26`), so the flag surfaces within one chunk. `Section::buildSomeMore` already calls
  `abandonBuild()` on `Error` (`Section.cpp:459-462`). That removes the `.tmp` and any partial
  (`Section.cpp:700-716`).
- **`beginParse()`** returns `false` when the root `startNewTextBlock` (`:1553`) fails.
  `Section` already abandons the build in that case (`Section.cpp:443-446`).
- **`finishParse()`** checks `allocationFailed_` immediately after the trailing
  `makePages()` (`:1631`). It returns `false` **before** touching `currentPage` or calling
  `completePageFn` (`:1636`). Otherwise a null `currentPage` would reach
  `Section::onPageComplete` and be dereferenced (`Section.cpp:92`).
  `Section::finalizeBuild` ignores that return today (`Section.cpp:632`). Row 8 makes it
  abandon instead of committing.

The reader already has a failure path for every one of these: `showBuildError()` shows
`STR_INDEX_FAILED` (`EpubReaderActivity.cpp:1013-1017`, reached at `:1084-1089` and `:1124-1128`).

### Page load (row 6)

When `Page::deserialize` returns `nullptr`, `Section::loadPage` passes it through
(`Section.cpp:737-741`, `:775-778`), and the reader's existing null-page handling takes over.
The resulting behaviour matches what a corrupt page cache already produces.

### Epub load (row 5)

`Epub::load` returning `false` is the existing "book unusable" signal (R§3). The site at
`:383` runs after `bookMetadataCache.reset()`, so a failure there leaves the cache null. The
accessors already guard against that (`Epub.cpp:534,543,552,570,662`). `getCssParser()` may
return null, and its only consumer checks for that (`Section.cpp:392-393`).

## Error handling: labelled assumptions

- **A1: an allocation the parser itself makes fails the whole chapter build, not just the element.**
  Scope: `Page` and `ParsedText` allocations in `ChapterHtmlSlimParser`. `ParsedText`'s own
  line drop stays (NG2).
  Rejected alternative: drop the line or block and keep going. That is what `ParsedText.cpp:1562-1565`
  and `ChapterHtmlSlimParser.cpp:340-345` do today. It is unsafe for `ParsedText`: 9 callers
  of `startNewTextBlock` go on to dereference `currentTextBlock`. For pages, a later allocation
  that succeeds would emit a page with lines missing, and that page would be committed to
  the section cache and served until the cache is invalidated. OOM is transient, so
  rebuilding on the next open is the right way to recover.
- **A2: the two existing nothrow `Page` sites (`:341`, `:368`) join A1.** Today they drop the
  rule and continue with `currentPage == nullptr`. If only the new sites followed A1, the
  parser would treat the same failure two ways. The element-level drops (`:380` rule, `:810`
  image block, `:817` page image) stay as they are (NG3), because losing one decorative
  element does not corrupt the text.
- **A3: a failed `Bitmap` ditherer degrades to undithered output.** It does not fail the
  image. Rejected alternative: a new `BmpReaderError::OomDitherer`. Every BMP render would then
  fail on a tight heap for a quality feature, and the undithered path already exists.
- **A4: any allocation failure in `CrossPointWebServer::begin()` fails the start.** On a
  `WebSocketsServer` or `WebDAVHandler` failure, `begin()` calls `server->stop()` and
  `server.reset()` (the teardown order of `stop()`, `CrossPointWebServer.cpp:264-270`), then
  returns before `running = true`. Rejected alternative: serve HTTP without WebSocket or
  WebDAV. That would be a partially working server with no UI to tell the user.
- **A5: a failed `DNSServer` allocation runs the AP without the captive portal.** The web UI
  can still be reached by IP, and the loop already tolerates a null `dnsServer` (`:285`).
- **A6: a failed QR buffer draws no QR code.** `drawQrCode` returns `void`
  (`QrUtils.cpp:11`). Each caller draws text beside the code: the SSID for the Wi-Fi QR (`:430`,
  `:433`), which is enough to join the open AP, and the URL for the two URL codes
  (`CrossPointWebServerActivity.cpp:451-453,472`). The user keeps a way in.
- **A7: the dead `Bitmap::errorCurRow`/`errorNextRow` members are removed.** Nothing allocates
  them (R§3). They exist only in the destructor this work rewrites.
- **A8: log tags are the files' existing ones.** They are `JPG`, `PNG`, `EBP`, `PGE`, `EHP`,
  `SCT`, `DEC`, `ERS`, `WEB`, `WEBACT`, `GFX` (for `Bitmap.cpp`) and `QR` (`QrUtils.cpp:64`), with the
  message format `OOM: <what>`. That matches `JpegToBmpConverter.cpp:678`.
- **A9: no heap-headroom pre-checks are added.** This work makes failure survivable. It does
  not try to predict failure.
- **A10: a transient OOM may throw away valid SD caches, and that is accepted.** There are
  two ways it happens:
  - A parser OOM leads to `abandonBuild()`, which also deletes a committed partial `.bin`
    (`Section.cpp:709-713`).
  - A `Page::deserialize` OOM makes the reader run `abandonBuild(); clearCache();` on a
    correct section and rebuild it (`EpubReaderActivity.cpp:1252-1259`). After
    `MAX_PAGE_LOAD_RETRIES` (`EpubReaderActivity.h:38`) it shows `STR_PAGE_LOAD_ERROR`.

  Both cost a rebuild. Neither writes anything to SD that could be mistaken for success, so
  the Goal holds. Rejected for now: a separate OOM result from `loadPage` that leaves the
  cache alone. It changes the reader's contract and is out of scope.

## Resource justification

No new allocation is introduced. Every change swaps a throwing `new` for a nothrow one of
the same size in the same memory (ditherer rows over 4096 B still go to PSRAM, per the
auto-routing threshold). The only size change is `Bitmap` losing two unused pointers
(8 bytes per instance). The parser gains one `bool`.

## Testing strategy

- **Host, new suite `test/ditherers/`.** Modelled on `test/bit_blit/CMakeLists.txt`. It
  compiles `BitmapHelpers.cpp` against `test/stubs` (`Bitmap.h` pulls in `<HalStorage.h>`,
  which resolves to the stub). Unlike `bit_blit`, its include path adds `${REPO_ROOT}/lib/Memory`
  (as `test/pagination/CMakeLists.txt:31` does) and `${REPO_ROOT}/test/stubs`. The `add_subdirectory` line goes in the PR description for the
  orchestrator, because `test/CMakeLists.txt` is a shared file (see `epub-dev.md`).
  1. `valid()` is true at widths 1, 480 and 2048, for all three ditherers.
  2. **Golden equivalence.** Output of `processPixel`/`nextRow` over a fixed gradient
     matches a checked-in expected sequence, captured from the current code before the
     refactor. This is the test that shows the refactor to `unique_ptr` changed nothing.
  3. **OOM path.** A row allocation failure gives `valid() == false`, and destruction does
     not crash. **This needs a failure-injection seam, and the repo has none**
     (`grep -rn "operator new" test` finds nothing, R§6). The seam is set by decision D1,
     below.
- **Not host-testable.** The parser, `Section`, `Epub`, the reader and the web server are not
  in any host build (R§6). They are verified by the firmware build (`pio run`,
  `pio run -e x4pro-gh_release`) and by review against the flow above.
- **Device checks, for the human tester:**
  1. Open a chapter with images and a cover. Output should be unchanged, with no
     `OOM:` lines in the serial log.
  2. Start the web server in both AP and STA mode. Upload over WebSocket and WebDAV.
  3. Heap: `ESP.getFreeHeap()` before and after one reader enter/exit cycle should match
     today's figure (no leak from the ownership changes).

### D1: decided (host OOM injection)

The orchestrator decided D1 and approved the recommendation with three conditions. The
test is built exactly this way:

1. **Both nothrow forms are replaced.** Replacing only one form would miss half the call
   sites, because `makeUniqueNoThrow` uses the array form for `T[]` (`lib/Memory/Memory.h:33`)
   and the scalar form otherwise (`:26`). The file `test/ditherers/FailingNothrowNew.cpp`
   replaces:
   - `operator new(std::size_t, const std::nothrow_t&) noexcept` and `operator new[](…)`.
     Both forward to `std::malloc`, and both return `nullptr` while the injector is armed and
     its countdown hits zero.
   - To keep allocation and deallocation consistent, every `operator delete`/`delete[]`
     form (plain, sized and nothrow). All of them forward to `std::free`.
   - The throwing `operator new`/`new[]`, forwarding to `std::malloc`. They are never
     injected, and they throw `std::bad_alloc` on a real null, since the host build has
     exceptions. Every allocation in the binary therefore comes from `malloc` and every
     deallocation goes to `free`, so no pair is mismatched.
2. **The injector is disarmed by default.** An RAII guard in the test arms it with
   "fail the Nth nothrow allocation from now" and disarms it on scope exit. Only the
   constructor under test runs inside the guard, so gtest's own allocations never fail.
   The ditherer is constructed on the stack inside the guard, so N counts row allocations
   only. N ∈ {1,2,3} for the two Atkinson classes and N ∈ {1,2} for `FloydSteinbergDitherer`
   (two rows, `BitmapHelpers.h:209-210`). That exercises partial
   construction: rows that already allocated are freed by their `unique_ptr`s, and the
   test runs under the default toolchain without leak checking, so this is shown by the
   object destructing without a crash.
3. **The seam stays in `test/ditherers/` only.** It lives in that suite's own source list
   and is never added to `test/stubs/`, which issue #99 owns in this batch and every suite
   links.
4. **The suite compiles with `-fno-builtin`**
   (`target_compile_options(DitherersTest PRIVATE -fno-builtin)`), with a comment saying why.
   Under optimisation, clang may omit replaceable allocation calls made from new-expressions
   when the result is only null-checked, zeroed and deleted. The injected failure then never
   fires, and `valid()` folds to `true`. The reviewer reproduced this with Apple clang 21 at
   `-O2`, and `-fno-builtin` restored the injection. GCC 13 does not omit these calls. This
   stays inside condition 3's confinement.

Rejected: shipping without an OOM host test. The OOM path is the whole point of #108.

## Changes after review pass 0

`docs/superpowers/reviews/issue-108-spec-review-0.md` returned CLEAR. Every finding was accepted
and fixed inline:

- **MAJOR 1.** D1 gains condition 4, `-fno-builtin` on the test target, so clang cannot omit
  the injected allocation.
- **MAJOR 2.** `finishParse` returns before the trailing `completePageFn`. The sticky-guard
  bullet now says exactly what it guards.
- **MAJOR 3.** The PNG OOM paths free the three remaining mallocs through one `ScopedCleanup`.
  Data flow step 2 is corrected.
- **MINOR 4.** The countdown range is set per ditherer, and N counts rows only.
- **MINOR 5.** A1 is scoped to the parser's own allocations. `ParsedText`'s line drop moves to NG2.
- **MINOR 6.** NG3 is reworded. The `shared_ptr` control blocks and the vector growth move to NG2.
- **MINOR 7.** New A10 accepts that a transient OOM may throw away a cache.
- **MINOR 8.** The test include directories are named. `Bitmap.cpp` gets the `GFX` tag and `<Logging.h>`.
- **MINOR 9.** The counts and the A6 wording are corrected.
