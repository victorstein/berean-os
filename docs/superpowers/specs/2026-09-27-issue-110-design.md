# Issue #110 — design: take bookmarks and auto page turn out of EpubReaderActivity

Task `t8`, tier `heavy`. Research: `docs/superpowers/research/2026-09-27-issue-110-research.md`
(cited below as "R§n"). All line numbers are against `9a307341`.

## Problem

`src/activities/reader/EpubReaderActivity.cpp` is 1,952 lines with 52 includes (R§1). Its bookmark
logic — a resident list, a read-failure latch, a five-way toast, and a save-with-rollback rule — is
spread across nine members of the class (`EpubReaderActivity.h:41-58, 131-134`), four method bodies
(`EpubReaderActivity.cpp:1765-1905`), three anonymous-namespace helpers (`:86-114`) and eight call
sites (R§3a). Auto page turn is three members (`.h:31-32, 40`) read and written from nine places
(R§3c). A reviewer touching `loop()` or `renderBook()` has to hold all of it at once, which is the
interaction-missing cost the issue names.

## Goal

Two behaviour-preserving extractions, in the issue's order, shipped as **one PR of two commits**
(one pipeline task owns one branch). PRs are squash-merged, so they land on `main` as one commit;
the per-commit split exists so review can read each move with `git diff --color-moved`:

1. **Bookmarks** → a `ReaderBookmarks` object the activity owns, plus the pure page-match rule in a
   host-tested header.
2. **Auto page turn** → a small header-only `AutoPageTurn` type with a host test.

Success: identical on-device behaviour; `EpubReaderActivity.cpp` loses the bookmark bodies and
helpers; the two pure pieces have host tests; `pio run` builds clean under `-Wformat`.

## Non-goals

- **No functional change** — no settings, strings, on-disk format, toast timing or refresh count.
- Not fixing the pre-existing unsynchronised cross-task reads of these flags (A6).
- Web-server route groups and `setup()` stages (A1). Named as follow-ups in the PR.
- `WifiSelectionActivity` — its prefetch is already delegated to `MeetingWeekPrefetch`
  (`WifiSelectionActivity.cpp:20, 639-658`; R§2).
- No new test infrastructure: new suites follow the existing `test/<suite>/CMakeLists.txt` shape.

## Assumptions (each is a decision the review should attack)

- **A1 — Scope stops at the reader.** The web server is `src/network`, owned by the `net` surface,
  and `setup()` lives in `src/main.cpp`, which `.claude/agents/ui-dev.md` ("Shared files — report,
  do not edit") forbids this worker to edit. The pipeline brief says "Work only on this surface" and
  allows stopping at a clean point with the rest named in the PR. So this branch does items 1–2 of
  the issue's reader list. The PR uses `Closes #110` as the pipeline requires, so **a follow-up issue
  for the remainder is a precondition of merge, not an option**: the PR body carries its full text,
  ready to file — the web-server route groups (files, settings, fonts; `src/network`, `net` surface),
  the `setup()` named init stages (`src/main.cpp`, orchestrator-owned), and a one-line record that a
  passage controller was considered and rejected (A2). Filing an issue is outward-facing, so the
  worker hands the text to the orchestrator, which files it and links it from the PR before merge.
- **A2 — No separate "passage controller".** The passage entry points (`openHighlightPassageAt`
  `:344-350`, `openHighlightPassage` `:352-378`, `openHighlights` `:380-400`) are
  `startActivityForResult` calls whose result handlers call protected `Activity` members
  (`requestUpdate`, `navigateTo`). Their only state is `highlightsLoaded` and a transient anchor
  (`.h:68, 73-74`); persisted passage data already lives in `STUDY` and rendering in
  `HighlightOverlay` (R§3b). Moving them would produce an object that calls back into the activity
  for every operation. They stay. The "bookmark and passage controller" of the issue is delivered as
  the bookmark controller only; the PR says so.
- **A3 — Bookmark controller is an owned member by value, modelled on `EndOfBookOptions`.**
  `EndOfBookOptions` (`EndOfBookOptions.h`) is the reader's existing owned sub-object: a narrow
  public API, the activity acts on what it returns. It is held through
  `unique_ptr` (`ReaderActivity.h:17`) only because it is created lazily at end of book;
  `ReaderBookmarks` exists for the whole session, so it is a plain member. **No new heap
  allocation**: its fields are the ones removed from the activity, which is itself heap-allocated.
- **A4 — The activity keeps the locking, the position and the redraw requests.** `ReaderBookmarks`
  never calls `requestUpdate()` (it has no `Activity` access) and never takes `RenderLock`. The
  activity calls `requestUpdate()` on every path, as today: every path of `addBookmark` past its
  opening guard ends in `requestUpdate()` (`:1810, :1875, :1892`), and the guard
  `if (!section || !epub) return;` (`:1802`) stays in the activity.
- **A5 — Toggle is two calls, so the order of effects does not move.** Today `addBookmark` (`:1801-1893`)
  does, in order: arm the toast (`:1805-1806`); if saving is disabled, set `LoadDisabled` and stop
  (`:1808-1812`); log; read `pageCount`/`currentPage` under `RenderLock` (`:1817-1821`); compute
  `SavedProgressPosition` from `getCurrentPosition()` (`:1823`); match, mutate, save, roll back. A
  single `toggle(...)` taking a pre-built position would run `getCurrentPosition()` — which reads
  `section->getVisibleTextOffsetForPage` and `getParagraphIndexForPage` (`:1928-1951`) — even on the
  save-disabled path, and before the locked read. So:
  1. `bool beginToggle(unsigned long nowMs)` — arms the toast; returns false (toast `LoadDisabled`)
     when saving is disabled. The activity then `requestUpdate()`s and returns.
  2. The activity logs, does the locked read and computes the progress exactly as `:1814-1823`.
  3. `void toggle(const std::shared_ptr<Epub>&, Section&, int spineIndex, int currentPage, int pageCount,
     std::optional<uint32_t> visibleOffset, const SavedProgressPosition&)` — the body from `:1824`
     to `:1891` verbatim. It keeps `Section&` because the add path reads the page text from SD
     (`section->getTextFromSectionFile()`, `:1850`) only when adding; a snapshot built up front would
     put that SD read on the remove path.
  `getCurrentPosition` stays an activity member (`:1928`) and is not duplicated.
- **A6 — Threading is unchanged, not improved.** `showBookmarkMessage`/`currentPageBookmarked` are
  plain `bool`s written on the main task (`addBookmark`, `loop :521-523`) and on the render task
  (`updateBookmarkFlag` from `renderBook :1271`), read by `renderBook :1318` and
  `renderStatusBar :1683`. Same for `automaticPageTurnActive` (`loop :495-518`; `renderBook :1033,
  :1258-1277`; `renderStatusBar :1659`). The moved fields keep the same types and are touched from
  the same call sites; no accessor adds a new cross-task access.
- **A7 — `lastPageTurnTime` stays on the activity.** It is also the manual-turn debounce
  (`:615`, `kMinManualTurnGapMs`) and is written on every successful `pageTurn` (`:947-975`).
  `AutoPageTurn` takes it as an argument to `due()`; it does not own it.
- **A8 — The page-match rule moves to `src/util/BookmarkMatch.h`**, modelled on
  `src/util/BookmarkSaveAction.h` (pure, header-only, Arduino-free, host-tested in
  `test/bookmark_save_action/`). `ProgressRange` and `bookmarkMatchesProgress` move verbatim
  (`:86-89, :104-114`), with `bookmarkProgressEpsilon` (`:60`). `getPageProgressRange` (`:91-102`)
  needs `Epub::calculateProgress`, so it moves into `ReaderBookmarks.cpp`, not the pure header.
- **A9 — `AutoPageTurn` is header-only, modelled on `ReturnStack.h`** (header-only, firmware-free,
  tested in `test/return_stack/`). It takes `now` as a parameter so it needs no `millis()`.
- **A10 — New host-test directories need `add_subdirectory` lines in `test/CMakeLists.txt`**,
  a shared file (`ui-dev.md`). The worker writes the lines in the PR body for the orchestrator to
  apply, next to `:127-128` (bookmark suites) and `:78` (`return_stack`). The worker still builds
  and runs them locally with the line applied in a scratch edit that is not committed.
- **A11 — Log tags and messages move unchanged** (`"ERS"`), so serial logs read the same.

## Error handling

Unchanged by construction; the bodies move verbatim:

- Read failure latches `saveDisabled` once and shows the message on the transition only (`:1792-1797`).
- Save-disabled toggle shows `LoadDisabled` without touching the list (`:1808-1812`).
- Save refusal rolls the list back by the collected indices and re-derives the flag
  (`:1880-1891`), toast `TooLarge` or `SaveFailed`.
- `toastText` keeps the switch that maps `SaveFailed` and `LoadDisabled` to
  `STR_ERROR_GENERAL_FAILURE` (`:1765-1778`).
- `AutoPageTurn::start` rejects option 0 and out-of-range, as `:916`. `pagesPerMinute()` is only
  called while active, when `durationMs_ > 0` (the status bar reads it only under
  `automaticPageTurnActive`, `:1659`), matching today's division.

## Testing strategy

TDD per pure piece; each failing test is written and run first (it fails to compile until the
header exists), then the header is added.

- `test/bookmark_match/BookmarkMatchTest.cpp` (model: `test/bookmark_save_action/`): exact
  computed-position match; percentage inside the range; the epsilon edges on both sides; percentage
  clamped outside [0,1]; computed fields matching spine but not page count falls back to the range.
- `test/auto_page_turn/AutoPageTurnTest.cpp` (model: `test/return_stack/`): option 0 and
  `size(RATES)` rejected and inactive; each option's duration and `pagesPerMinute`
  (1,1,3,6,12); `due` at `duration-1` false and `duration` true; `due` across the wrap of
  `millis()`, built from `std::numeric_limits<unsigned long>::max()` (e.g. `last = max - 99`,
  `now = duration - 100`) because host `unsigned long` is 64-bit while the device's is 32-bit, so a
  hard-coded `0xFFFFFFFFUL` would not wrap on the host; `stop` deactivates.
- `ReaderBookmarks` itself is not host-built: it needs `Epub` and `Section`, which no suite
  compiles (`grep -rn 'Epub.cpp\|Epub/Section.cpp' test/*/CMakeLists.txt` finds none).
  `BookmarkFile` alone would not block it — `test/stubs` has an in-memory Storage fake for it
  (`src/util/BookmarkSaveAction.h:9-11`). Its correctness rests on the verbatim move,
  checked by diff review (`git diff --color-moved`).
- Build: `pio run` (x4pro) through the batch lock script, once after the last edit; `./bin/clang-format-fix`
  over the whole tree.
- **Device check for the human tester:** toggle a bookmark on and off (toast Added/Removed, status-bar
  flag); open the bookmarks list and return; enable auto turn at each rate and confirm the status
  bar shows the rate and pages advance; cancel with a centre tap; a manual swipe right after an auto
  turn is still debounced.
