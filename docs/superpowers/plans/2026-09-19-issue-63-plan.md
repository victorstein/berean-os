## Step 2 — the predicate (green), and commit the pair

**File:** `lib/Serialization/DocReadStatus.h`

The file is 22 lines and ends with `classifyDocRead`'s closing `}`. **Append**
after it:

```cpp

// Whether a read-modify-write caller may go on to write, given the status its
// read returned. Ok and Missing are both safe -- Missing legitimately means
// "start a new document". Unreadable and ParseError are not: the bytes are
// still on the card, and an atomic write replaces them cleanly, leaving
// nothing torn to notice.
//
// A comparison rather than a switch on purpose: a status added later is false
// -- refuse -- which is the safe direction, and the asserts below force that
// choice to be made deliberately rather than inherited.
constexpr bool mayOverwriteAfterRead(const DocReadStatus status) {
  return status == DocReadStatus::Ok || status == DocReadStatus::Missing;
}

static_assert(mayOverwriteAfterRead(DocReadStatus::Ok));
static_assert(mayOverwriteAfterRead(DocReadStatus::Missing));
static_assert(!mayOverwriteAfterRead(DocReadStatus::Unreadable));
static_assert(!mayOverwriteAfterRead(DocReadStatus::ParseError));
```

`constexpr` and `static_assert` are compile-time only, so this adds nothing to
flash or DRAM in any translation unit that includes the header — and
`PersistableStore.h:10` includes it everywhere.

**4c — `readLedger`.** Replace the whole function (currently `:52-63`):

```cpp
  std::vector<std::string> done;
  JsonDocument doc;

    return done;
```

with:

```cpp
// nullopt means the ledger's bytes are on the card but unusable -- unreadable,
// unparseable, or a format this build refuses. An empty vector means genuinely
// absent, or present and recording nothing; both are safe to append to.
//
// The two must not be collapsed. A ledger read as "nothing migrated" re-runs
// the migration, and PassageDoc::add appends without deduplicating, so every
// passage in every already-migrated file would be added a second time.
std::optional<std::vector<std::string>> readLedger() {
  JsonDocument doc;
  const DocReadStatus status = PersistableStoreBase::readDocFromFileAdopting(MigrationRunner::LEDGER_PATH, doc);
  if (status == DocReadStatus::Missing) return std::vector<std::string>{};
  if (status != DocReadStatus::Ok) return std::nullopt;
  if ((doc["v"] | 0) > LEDGER_FORMAT_VERSION) {
    LOG_ERR(MODULE, "Refusing to read a newer ledger format");
    return std::nullopt;
  }

  std::vector<std::string> done;
  for (const JsonVariantConst v : doc["done"].as<JsonArrayConst>()) {
    const char* name = v["f"] | "";
    if (name[0] != '\0') done.emplace_back(name);
  }
  return done;
}
```

A ledger written before this change carries no `"v"`, so `doc["v"] | 0` is `0`
and `0 > 1` is false — it loads unchanged. Older builds never read the key, so
a ledger stamped `"v": 1` loads there too.

**The `LOG_ERR` on the version arm is a deliberate departure from the spec's
error table**, which has `readLedger` silent and leaves the logging to
`readDocFromFileAdopting` and `runIfPending`. It is added because this is the one
`nullopt` cause nothing else reports: a well-formed future-format file reads
`Ok`, so `readDocFromFileAdopting` logs nothing. The cost is that `readLedger`
runs from both `pending()` and `runIfPending`, so a future-format ledger emits
this line **twice** before `runIfPending`'s own refusal — three ERR lines for one
condition. That is accepted as cheaper than threading a reason code out of
`readLedger` for a condition this rare. Do not "fix" the duplicate by deleting
the log; it is the only report of a refused format.

## Step 5 — `appendLedger` honours the status, the version and the budget


with:

```cpp
bool appendLedger(const std::string& name, const uint16_t passages) {
  JsonDocument doc;
  // Refuse BEFORE reading doc: a ParseError leaves the partially parsed
  // document behind, so appending to it would write back half a ledger.
  const DocReadStatus status = PersistableStoreBase::readDocFromFileAdopting(MigrationRunner::LEDGER_PATH, doc);
  if (!mayOverwriteAfterRead(status)) {
    LOG_ERR(MODULE, "Migration ledger unreadable; refusing to overwrite it");
    return false;
  }
  if ((doc["v"] | 0) > LEDGER_FORMAT_VERSION) {
    LOG_ERR(MODULE, "Refusing to rewrite a newer ledger format");
    return false;
  }
  doc["v"] = LEDGER_FORMAT_VERSION;
  if (!doc["done"].is<JsonArray>()) doc["done"].to<JsonArray>();

  const auto row = doc["done"].as<JsonArray>().add<JsonObject>();
  row["f"] = name;
  row["p"] = passages;

  // Bounded well clear of the ceiling: at most 200 sources (legacySources
  // caps the listing) at at most 146 bytes a row -- the SD layer reads a
  // filename into a char[128] -- is about 29 KB. The gate is the rule, not a
  // reachable limit.
  if (measureJson(doc) > persist::DEFAULT_SAVE_BUDGET) {
    LOG_ERR(MODULE, "Migration ledger exceeds the save budget; not written");
    return false;
  }

  Storage.mkdir(BEREAN_DIR);
  return PersistableStoreBase::writeDocToFileAtomic(MigrationRunner::LEDGER_PATH, doc);
}
```

`<SaveBudget.h>` is already included at `:10`, so `persist::DEFAULT_SAVE_BUDGET`
and `measureJson` need no new include. This is the same shape as the gate in
`src/study/PubKeyRegistry.cpp:36-39`.

No shrink exception here, unlike `src/util/BookmarkSaveAction.h`: the ledger only
ever appends rows, so a document that is over budget and shrinking does not
exist.

**Verify by reading:** every refusal returns **before** `Storage.mkdir`, so a

```bash
gh pr create --repo victorstein/berean-os --base main \
  --title "fix: refuse to overwrite study files that could not be read" \
  --body "$(cat <<'EOF'
`readDocFromFileAdopting` returns a `DocReadStatus` so a caller can tell `Missing` (safe to
overwrite) from `Unreadable` / `ParseError` (never overwrite) — `DocReadStatus.h:5-7` states that as
a requirement. Twelve call sites exist outside `PersistableStore`; ten obeyed it. The two that did
not were the two that then wrote the file back.

`PubKeyRegistry::record` (`PubKeyRegistry.cpp:23`) discarded the status, so a corrupt
`/.berean/pubkeys.json` became a **one-entry** registry — written atomically, with no torn file to
notice. Every other publication lost the symbol its tags are keyed on.
`MigrationRunner::appendLedger` (`MigrationRunner.cpp:74`) was the same shape.

### The fix

`mayOverwriteAfterRead` in `lib/Serialization/DocReadStatus.h` — the caller-side half of the
contract that header already states in prose, beside `classifyDocRead` and in the suite that already
described the rule (`test/doc_read_status/DocReadStatusTest.cpp:21-27`). Both sites refuse **before
reading `doc`**, because `deserializeJson` leaves a partially parsed document behind on
`ParseError` and `readDocFromFileAdopting` deliberately does not clear it on that arm
(`PersistableStore.cpp:89-101`).

### Beyond the two lines the issue names

Research established what the issue left open: `PassageDoc::add`
(`lib/StudyStore/StudyStore/PassageDoc.cpp`) is a plain `push_back` with no identity check, so a
lost ledger does not cause redundant work — it **duplicates every passage in the file**, and the
user cannot tell an original from its copy.

Fixing `appendLedger` alone would not have closed that, because `readLedger` already collapsed
`Unreadable` and `ParseError` into an empty `done` list. So:

- `readLedger` returns `std::optional`; `nullopt` means "bytes on the card, unusable".
- `runIfPending` refuses the whole run on `nullopt`, the same posture as the tag-palette refusal two
  lines below it (`MigrationRunner.cpp:166-169`).
- The ledger gains `"v": 1` and refuses a newer format. Not decoration: a future-format ledger read
  as empty re-migrates and duplicates, the same failure through a different door. Compatible both
  ways — an older ledger has no `"v"` and loads; older builds never read the key.
- `appendLedger` gains the `measureJson` gate every other store here has
  (`PubKeyRegistry.cpp:36-39`). This half is rule compliance, **not** a reachable overflow: at most
  200 sources at at most 146 bytes a row is ~29 KB against a 45,000-byte budget.
- Both `appendLedger` call sites now check the result and stop the run. A ledger write failure is
  global, not per-file.

It also closes this issue's compound scenario: #51 fixed the half where an interrupted write left
the registry only in `pubkeys.json.tmp`; this fixes the half where the next `record()` destroyed the
survivor.

### Deliberately not here

The user-visible surface for a refusal is **#39** — this change logs and returns `false`, and
nothing reaches the screen. `PublicationDownloader` is unchanged: a download that is complete and
MD5-verified is not discarded because an index file is corrupt, and `src/network/` is a different
surface. `writeReport`'s truncation is a documented choice for a diagnostic file nothing reads back,
left alone as the issue asks.

**Known residue, disclosed:** `PassageDoc::add` still does not deduplicate, so re-migration by any
other route still duplicates. This removes the trigger #63 owns, not the underlying hazard — worth a
follow-up against `lib/StudyStore/`. And a card with legacy highlights and a corrupt ledger now
paints the migration screen and refuses on every boot until the file is removed. That is deliberate:
blocking is recoverable, silently duplicating is not.

- `pio run` SUCCESS. `pio check -e x4pro --fail-on-defect low --fail-on-defect medium
  --fail-on-defect high`: no defects. `./bin/clang-format-fix` over the whole tree, then

**Not verified on hardware — needs the human tester.** Four cases, on a debug `x4pro` build with

1. **Corrupt registry.** Write `{"v":1,"p":{` over `/.berean/pubkeys.json`, note its bytes, download
   a publication. **Expected:** the download succeeds, serial shows
   `ERR PUBKEYS Registry unreadable; refusing to overwrite it`, and the file is **byte-identical**

2. **Empty registry.** Truncate `pubkeys.json` to zero bytes and repeat. **Expected:** the same

3. **Absent registry — the regression guard.** Delete both `pubkeys.json` and `pubkeys.json.tmp`,
```
