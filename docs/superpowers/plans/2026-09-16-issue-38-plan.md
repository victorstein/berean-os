## What this change is

A **deletion**. The reader menu has a row, *Show page as QR*, that encodes the
current page's text as a QR code. It does not work — the spec's Problem section
has the mechanism — and it is being removed. Nothing is added. No behaviour is
replaced. There is no fallback and no "feature removed" message.

Seven edits across five files, in an order where **every intermediate commit
compiles**, plus one build at the end.

## Two corrections to the spec, found while writing this plan

The spec cleared review, but two of its commands do not work as written. This
plan uses the corrected forms; the spec has been amended to match.

1. **The completeness grep can never return zero as the spec writes it.** The
   spec says `grep -rn "DISPLAY_QR\|QrDisplayActivity" src lib` should "expect no
   hits". It cannot: `STR_DISPLAY_QR` is defined in **31 translation YAMLs under
   `lib/I18n/translations/`**, which the spec's own non-goals forbid touching,
   and in the build-generated `lib/I18n/I18nKeys.h` and `I18nStrings.*`. The gate
   must exclude both. Corrected form, used throughout this plan:

   ```sh
   grep -rn "DISPLAY_QR\|QrDisplayActivity" src lib \
     --include='*.cpp' --include='*.h' | grep -v "I18nKeys.h\|I18nStrings"
   ```

   That returns **13 lines today** and must return **0** when you are done.

2. **`-G Ninja` fails on this machine.** Ninja is not installed
   (`command -v ninja` → nothing); CI installs it, you do not have it. Configure
   the host suite with the default generator instead:

   ```sh
   cmake -S test -B build/test -DCMAKE_BUILD_TYPE=Release
   ```

   Verified working. `cmake -S test -B build/test -G Ninja …` fails with
   `CMake was unable to find a build program corresponding to "Ninja"`.

## About TDD here

**There is no failing test to write, and you should not invent one.** The host
suite in `test/` compiles nothing from `src/activities/` — it has no Arduino, no
display, no `HalStorage` — so the reader menu has no host-testable surface, and
the spec (cleared by an adversarial review) declined to build one for a deletion.
Standing up a shim for the entire UI stack to assert that a row is absent would
be far more code than the change, and it would test the shim.

What replaces the red/green loop, step by step, is an **executable assertion that
fails before the edit and passes after**. Every step below has one. Run the
"before" command and see it fail; make the edit; run the "after" command and see
it pass; commit. That is the same loop with `grep` in place of `ctest`.

**One thing the compiler will not catch, so the grep is load-bearing:** the
review established that the `MenuAction` switch is *not* exhaustive (14 cases, 16
enumerators) and the build sets no `-Wall` or `-Werror`. Deleting a `case` while
leaving its enumerator behind **compiles and ships silently**. Step 4 is what
catches that. Do not skip it.
