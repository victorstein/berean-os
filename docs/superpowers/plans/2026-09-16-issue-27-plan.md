# Implementation plan — atomic, budgeted saves (#27)

**Spec**: `docs/superpowers/specs/2026-09-16-issue-27-design.md` (read it first; it
is the only other document you need)
**Review**: `docs/superpowers/reviews/issue-27-spec-review-0.md` — CLEAR, all
findings already folded into the spec
**Branch**: `fix/27-atomic-store-saves`
**Date**: 2026-09-16

## What you are doing, in one paragraph

Four singleton stores persist JSON to the SD card through `saveToFile()`, which is
non-atomic and unmeasured. `saveToFileAtomic()` sits beside it, does both things
correctly, and has zero callers. You are switching every caller over, giving each
store a byte budget, and adding four `static_assert`s so a budget that fails to
take effect is a build error instead of silence.

## How TDD works here — read this before step 1

**No host test can reach this code.** `lib/Serialization/PersistableStore.h:3`
includes `<Arduino.h>` unconditionally, so nothing that instantiates a
`PersistableStore` subclass is host-buildable; `test/highlight_file/CMakeLists.txt:1-4`
already records this. There is no gtest to write. Every step below still has a
real executable red/green, in one of two forms:

- **`static_assert` + `pio run`** — a compile-time test. Steps 2 is red (build
  fails) before the implementation and green after. This is a genuine failing
  test, not a stand-in.
- **`grep`** — for the mechanical conversion steps, the failing check is "this
  file still contains N calls to the wrong function" and the passing check is
  "zero". Instant, and it is the same check the spec's verification ladder uses.

**Build discipline.** `CLAUDE.md` says build once, after the last edit. Firmware
builds are slow and touching a store header rebuilds most of the tree, so this
plan uses `grep` as the per-step check and spends **four** builds: a baseline in
step 1, the red/green pair in step 2, and the final one in step 11.
Do not add builds between them.

**Commands.** Spell both out in full every time; the prefixes are load-bearing,
and without them you get a failure rather than a false pass.
`~/.platformio/penv/bin/pio run` to build (the bare `pio` is not on `PATH`) and
`PATH="$PWD/.venv/bin:$PATH" ./bin/clang-format-fix` to format.

Run everything from `/Volumes/stein/.herdr/worktrees/berean-os/fix-27-atomic-store-saves`.

### 2b. Green — declare the budgets

Put each in the **public** section, immediately above the existing
`getFilePath()`. Public placement is deliberate, though not for the reason it may
look: `requires { T::SAVE_BUDGET; }` (`PersistableStore.h:112`) is a soft test,
and a private constant works here **only** because each store friends
`PersistableStore<T>` (`CrossPointState.h:11`, `CrossPointSettings.h:13`,
`WifiCredentialStore.h:41`, `RecentBooksStore.h:26`) — a link nothing connects to
the budget and a future cleanup would sever without a diagnostic. Public placement
removes the dependency; the `static_assert`s catch it either way.

`src/CrossPointState.h`, above line 32 (`static const char* getFilePath()`):
```cpp
  // Fixed key set: 11 keys, two 16-element uint16_t arrays, seven scalars, and
  // two SD path strings assumed <= 255 B each. ~1,180 B worst case.
  static constexpr size_t SAVE_BUDGET = 2048;

```

`src/CrossPointSettings.h`, above line 386 (`static const char* getFilePath()`):
```cpp
  // One key per SettingsList.h row plus nine written by hand in toJson();
  // values are almost all single bytes. ~1,600 B worst case.
  static constexpr size_t SAVE_BUDGET = 4096;

```

`src/WifiCredentialStore.h`, above line 44 (`static const char* getFilePath()`):
```cpp
  // 8 networks x (ssid <= 32 B, base64 of a <= 64 B password, two integers).
  // ~1,700 B worst case. The headroom absorbs a password written through the web
  // server, which does not bound it (CrossPointWebServer.cpp:1385); the load path
  // discards anything over MAX_PASSWORD_LENGTH on the next boot (:52-56).
  static constexpr size_t SAVE_BUDGET = 8192;

```

`src/RecentBooksStore.h`, above line 29 (`static const char* getFilePath()`):
```cpp
  // Deliberately the shared default rather than a tighter figure. The entry
  // count is capped at MAX_RECENT_BOOKS, but each entry holds four unbounded
  // std::strings -- title and author come straight from EPUB metadata with no
  // truncation on the way in -- so the accepted worst case is 10 x 4 unbounded
  // strings. A tight ceiling here would refuse a legitimate save on a real
  // book, and the only symptom would be recents quietly not updating.
  static constexpr size_t SAVE_BUDGET = persist::DEFAULT_SAVE_BUDGET;

```

`persist::DEFAULT_SAVE_BUDGET` is already visible: `RecentBooksStore.h:3` includes
`<PersistableStore.h>`, which includes `SaveBudget.h` at its line 11.
