### Deviations from the spec

1. **Where the A9 abbreviation test lives.** `BibleBookNameTable.h` includes `<Epub.h>` and
   `SpineHtmlStream.h` (`BibleBookNameTable.h:3,11`). `Epub.h` needs `<Print.h>`
   (`lib/Epub/Epub.h:3`), and there is no host stub for it (`ls test/stubs`), so the table cannot
   be built on the host. Following the spec's own fallback (Testing 4), the label copy and
   `copyUtf8Truncated` move into a pure `BookLabels.h`, and the test targets that header.
   `setAbbreviations` is a one-line call into it.
2. **The book index is filled in place.** The spec sketched
   `storeBooks(const BibleBookIndex&)`. A `BibleBookIndex` is ~5.7 KB, which is far past the
   256-byte stack rule, and the navigator has no such object to hand over. So the cache instead
   exposes `booksToFill()` and `commitBooks()`: the navigator writes straight into the cache's
   storage, and a commit with `bookCount == 0` stores nothing (A8). The navigator keeps its own
   members (`bookNames`, `bookTargetSpine`, ...) and copies to and from the index with two
   helpers. That avoids renaming every use of them in `BibleNavigationActivity.cpp`, which A6's
   "one member" wording had implied.
3. **A10's band cache is an ink bitset, not a framebuffer snapshot.** This is a mechanism change,
   not packaging (Task 9). `readFramebufferRegion` snaps its rectangle outward to 8-pixel
   boundaries in panel memory (`GfxRenderer.cpp:348-352`). In portrait that spills into the rows
   above and below the band, and the snapshot would be taken in `drawFooter`, after the grid is
   drawn, so a restore could paint stale grid pixels back. Task 9 records the band's inked pixels
   during the blit into a band-exact bitset of the same 7,050 B, held in the same reader-life
   cache in explicit PSRAM. The gate, the ownership and the validity argument stay as in the spec.

```cpp
#pragma once

#include <Utf8.h>

#include <cstddef>
#include <cstring>
#include <string>
#include <string_view>

// Free of Epub and Arduino so the host suite can exercise it (test/number_grid).

// Copies `source` into `dest`, cut on a UTF-8 boundary so drawText never sees
// an incomplete sequence (which renders as a replacement character).
inline void copyUtf8Truncated(char* dest, const size_t destBytes, const std::string_view source) {
  const size_t fit = source.size() < destBytes - 1 ? source.size() : destBytes - 1;
  const int safe = utf8SafeTruncateBuffer(source.data(), static_cast<int>(fit));
  memcpy(dest, source.data(), static_cast<size_t>(safe));
  dest[safe] = '\0';
}

// Fills `rowCount` fixed-stride rows from `labels` in order. Rows past the last label are emptied,
// so a refill never leaves an earlier label behind.
inline void copyLabelRows(char* rows, const size_t rowBytes, const int rowCount, const std::string* labels,
                          const size_t labelCount) {
  for (int i = 0; i < rowCount; i++) {
    char* row = rows + static_cast<size_t>(i) * rowBytes;
    if (static_cast<size_t>(i) < labelCount) {
      copyUtf8Truncated(row, rowBytes, labels[i]);
    } else {
      row[0] = '\0';
    }
  }
}
```

```cpp
#pragma once

#include <Epub/BibleNavScanner.h>

#include <string>
#include <string_view>

// Resolves Bible nav link targets to spine indices without walking the spine from item 0. Free of
// Arduino and Epub so the host suite can exercise it (test/number_grid).
//
// A slot counts as unset while it is negative. Both functions fill every unset slot whose target
// matches, so duplicate targets all resolve, as Epub::resolveFilenamesToSpineIndices does.
namespace SpineSearch {

// The href of spine item `spineIndex`. `scratch` may own the returned bytes.
using HrefAt = std::string_view (*)(const void* ctx, int spineIndex, std::string& scratch);

// Walks [first, spineCount) then [0, first), stopping once no slot is unset. A `first` outside
// the spine starts at 0.
inline void resolveFrom(const std::string* targets, int* out, const int count, int first, const int spineCount,
                        const HrefAt hrefAt, const void* ctx) {
  int unset = 0;
  for (int i = 0; i < count; i++) {
    if (out[i] < 0) unset++;
  }
  if (unset == 0 || spineCount <= 0) return;
  if (first < 0 || first >= spineCount) first = 0;

  std::string scratch;
  for (int step = 0; step < spineCount && unset > 0; step++) {
    const int spineIndex = (first + step) % spineCount;
    const std::string_view tail = BibleNav::filenameTail(hrefAt(ctx, spineIndex, scratch));
    for (int j = 0; j < count; j++) {
      if (out[j] >= 0 || std::string_view(targets[j]) != tail) continue;
      out[j] = spineIndex;
      unset--;
    }
  }
}

// Takes one TOC entry's build-time spine index for every unset target naming the same file.
// book.bin resolves a TOC entry's spine when it is built, so this costs no spine reads.
inline void takeTocSpine(const std::string* targets, int* out, const int count, const std::string_view tocHref,
                         const int tocSpine, const int spineCount) {
  if (tocSpine < 0 || tocSpine >= spineCount) return;
  const std::string_view tail = BibleNav::filenameTail(tocHref);
  for (int j = 0; j < count; j++) {
    if (out[j] < 0 && std::string_view(targets[j]) == tail) out[j] = tocSpine;
  }
}

}  // namespace SpineSearch
```

```cpp
#pragma once

#include <cstdint>
#include <cstring>

// The Bible navigator's limits, shared with the reader's cache of what it resolved.
namespace BibleNavLimits {
constexpr int MAX_BOOKS = 66;
constexpr int MAX_CHAPTERS = 150;  // Psalms
// Sized in UTF-8 bytes; see BibleBookNameTable::NAME_BYTES.
constexpr int BOOK_NAME_BYTES = 48;
constexpr int BOOK_ABBREV_BYTES = 16;
}  // namespace BibleNavLimits

// What the Bible navigator read from SD, kept by the reader so a second Go to reads none of it.
// Only a successful load is kept. Nothing invalidates it during a reader's life: the book never
// changes under a live reader. The navigator reads and writes it on the loop task only.
//
// A template over the book table so the host suite can exercise the logic without Epub
// (test/number_grid); the firmware instantiates it once, in BibleBookIndex.h.
template <typename Books>
class BibleNavCacheOf {
 public:
  bool hasBooks() const { return booksStored; }
  const Books* books() const { return booksStored ? &storedBooks : nullptr; }

  // Filled in place because a book table is far too large for a task stack. Withdraws any stored
  // copy until commitBooks().
  Books& booksToFill() {
    booksStored = false;
    return storedBooks;
  }
  void commitBooks() { booksStored = storedBooks.bookCount > 0; }

  // The stored chapter spines when `book` is the book they were stored for, else nullptr.
  const int16_t* chaptersFor(const int book, int& count) const {
    if (chapterBook < 0 || book != chapterBook) {
      count = 0;
      return nullptr;
    }
    count = chapterCount;
    return chapterSpine;
  }

  // Replaces the stored chapters. Only the book last opened is kept: that is the one the next
  // Go to most likely enters at.
  void storeChapters(const int book, const int16_t* spines, const int count) {
    if (book < 0 || spines == nullptr || count <= 0 || count > BibleNavLimits::MAX_CHAPTERS) return;
    memcpy(chapterSpine, spines, static_cast<size_t>(count) * sizeof(int16_t));
    chapterCount = count;
    chapterBook = book;
  }

 private:
  Books storedBooks{};
  bool booksStored = false;
  int chapterBook = -1;
  int chapterCount = 0;
  int16_t chapterSpine[BibleNavLimits::MAX_CHAPTERS] = {};
};
```

This replaces the spec's `readFramebufferRegion` snapshot with an ink bitset recorded during the
blit. `readFramebufferRegion` snaps its rectangle outward to 8-pixel boundaries in panel memory
(`GfxRenderer.cpp:335-359`). In portrait that spills rows above and below the band, and the
snapshot is taken in `drawFooter`, after the grid has been drawn, so a restore could paint stale
grid pixels back. A band-exact bitset has no such spill. The buffer is the same size as the
issue's figure: `470 × 120 / 8 = 7,050 B`. It is held in PSRAM explicitly, with the same idiom as
`CatalogIndexStore` (`CatalogIndexStore.h:83-90`, `.cpp:40-47`). A restore replays the pixels
with `drawPixel`, so it removes the 783-row SD stream but not the plotting. The "after" log line
`"Band restored in N ms"` shows what is left.

### 9.2 Create `src/components/BandInk.h`

```cpp
#pragma once

#include <cstddef>
#include <cstdint>

// A band's ink as a packed bitset, row-major and MSB first: every pixel CoverBand inked, so a
// repaint can plot it again without streaming the cover from SD. Pure, for test/cover_band.
namespace BandInk {

constexpr size_t bytesFor(const int width, const int height) {
  return width > 0 && height > 0 ? (static_cast<size_t>(width) * static_cast<size_t>(height) + 7) / 8 : 0;
}

inline size_t bitIndex(const int width, const int x, const int y) {
  return static_cast<size_t>(y) * static_cast<size_t>(width) + static_cast<size_t>(x);
}

inline void set(uint8_t* bits, const int width, const int x, const int y) {
  const size_t i = bitIndex(width, x, y);
  bits[i >> 3] = static_cast<uint8_t>(bits[i >> 3] | (0x80u >> (i & 7)));
}

inline bool test(const uint8_t* bits, const int width, const int x, const int y) {
  const size_t i = bitIndex(width, x, y);
  return (bits[i >> 3] & (0x80u >> (i & 7))) != 0;
}

}  // namespace BandInk
```

```cpp
// heap_caps_malloc is the only way to demand PSRAM; makeUniqueNoThrow's operator new takes no
// capability. Zeroed on every fill, because draw only ever sets bits.
uint8_t* reserveInk(Masthead::BandInkCache& cache, const size_t bytes) {
  if (bytes == 0) return nullptr;
  if (!cache.bits || cache.bytes != bytes) {
    cache.valid = false;
    cache.bits.reset(static_cast<uint8_t*>(heap_caps_malloc(bytes, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)));
    cache.bytes = cache.bits ? bytes : 0;
    if (!cache.bits) {
      LOG_ERR(MODULE, "OOM: %u B band ink", static_cast<unsigned>(bytes));
      return nullptr;
    }
  }
  memset(cache.bits.get(), 0, bytes);
  return cache.bits.get();
}
```
