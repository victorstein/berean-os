## How TDD works here

No host test can reach this code (spec A6). The red/green test is the i18n generator:

```bash
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/
```

- It exits 1 with `CRITICAL: N string(s) used in source but missing from english.yaml:` when source uses a key that has no English value. That is the red run.
- It exits 0 once the key exists. That is the green run.

Each task below rewrites the call sites first, runs the generator and sees red, adds the keys, runs it again and sees green, and then commits. The red state is never committed, so every commit builds.

Each task makes a single-group change, which is why the steps are grouped as they are. The expected `String keys:` count after each task is:
- Task 1: 476
- Task 2: 480
- Task 3: 482
- Task 4: 486

The baseline is 475 (research §6).

**4a. Rewrite the call sites.** In `FontDownloadActivity.cpp`, make four replacements. Each one matches the full line, including its 6-space indent.

Replace

```cpp

```

with

```cpp

      snprintf(message, sizeof(message), tr(STR_FONT_FILE_DOWNLOAD_FAILED), file.name.c_str());
```
