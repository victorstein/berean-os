# Issue #37 — implementation plan: gate screen rotation

Implements `docs/superpowers/specs/2026-09-16-issue-37-design.md` (reviewed
CLEAR). Read the spec's assumption index (§8) before starting; this plan does
not re-argue the decisions.

Six steps. Steps 1–4 are the change; step 5 is the guard rails; step 6 is the
hand-off. Every step leaves the tree building and committable.

**Every number and every line of code below was executed in this worktree before
being written down.** The full change was applied, built, formatted and reverted;
the expected outputs are measurements, not predictions.

---

## About TDD here, read this first

The usual loop is write a failing test, watch it fail, implement, watch it pass.
**There is no host test that can cover this change**, and that is a finding, not
an omission — spec §7.2 and **A11**: no suite under `test/` compiles
`src/SettingsList.h`, and both repo gates (`scripts/settings_snapshot.py`,
`scripts/i18n_orphans.sh`) are textual scans that this design deliberately leaves
unchanged. A test asserting `BEREAN_CAP_ROTATION == 0` would assert the build
flag, not the behaviour.

So steps 2, 3 and 4 each use a **preprocessor assertion** as the red→green test.
It compiles the real translation unit with the real build flags, stops after
preprocessing, and counts the gated construct in the output. That is a genuine
behavioural check of a compile-time gate: it reports what the compiler will
actually see, not what the source text says. Each one was confirmed to return
`1` before the change and `0` after.

Step 1's test is the `#error` of **A2** firing — real behaviour, not a flag
read. Step 5's checks are regression guards that must *not* move.

This is the strongest verification available without the larger change **A11**
puts out of scope. A green build still proves only that it compiles; the device
walk in step 6 is the real verification, and it is the human's.

## Step 1 — add the capability (4 min)

### The test, first

The behaviour to verify is **A2**: a build for a device that is not the X4 Pro
must fail loudly rather than silently inherit a rotation policy. Run this now,
before the edit:

```bash
python3 - <<'PY'
import json, shlex, subprocess
db = json.load(open("compile_commands.json"))
e = next(x for x in db if x["file"].endswith("src/activities/settings/SettingsActivity.cpp"))
args = shlex.split(e.get("command") or " ".join(e["arguments"]))
out, skip = [], False
for a in args:
    if skip:
        skip = False
        continue
    if a == "-o":
        skip = True
        continue
    if a in ("-c", "-MMD"):
        continue
    out.append(a)
out = [a for a in out if not a.startswith("-DFREEINK_DEVICE_X4PRO")]
r = subprocess.run(out + ["-E", "-UFREEINK_DEVICE_X4PRO", "-DFREEINK_DEVICE_X4=1"],
                   capture_output=True, text=True)
print("returncode:", r.returncode)
for line in r.stderr.splitlines():
    if "BEREAN_CAP_ROTATION" in line:
        print(line[:160])
PY
```

RED: `returncode: 0`, no output lines at all. Measured on the pristine tree:
rc 0, zero errors.

That clean pass is the bug **A2** closes: `-DFREEINK_DEVICE_X4=1` names a *different*
device, `BoardConfig.h:33-67` defaults every other `FREEINK_DEVICE_*` to 0 and
`:71-75` errors only when none is set, so BoardConfig accepts the build happily
and today nothing objects. Note the flag deliberately names another device
rather than stripping the device entirely: with no device at all BoardConfig
errors first and you would be watching *its* diagnostic, not ours.

### Implement

In `src/CrossPointSettings.h`, replace line 6:

```cpp
#include <cstdint>
```

with:

```cpp
#include <cstdint>

// Whether screen rotation is OFFERED to the user. The renderer's rotation
// support is untouched; this gates only the three places that exposed it.
//
// The X4 Pro's Left/Right nav buttons are a fixed physical pair and the panel
// cannot report which way is up, so a rotated frame and a fixed mapping cannot
// both be right. A future board must answer this question for itself rather
// than inherit the answer -- hence the #error rather than a default. (A build
// with no device at all is already caught earlier, by BoardConfig.h; this
// catches a build for a DIFFERENT device, which BoardConfig accepts.)
#ifndef BEREAN_CAP_ROTATION
#if FREEINK_DEVICE_X4PRO
#define BEREAN_CAP_ROTATION 0
#else
#error "BEREAN_CAP_ROTATION: unhandled device set; decide whether this board offers rotation"
#endif
#endif
```

File scope, above `class CrossPointSettings` on line 8 — **not** inside the
class beside the `ORIENTATION` enum. The spec (**A3**) says "beside the enum it
constrains" and that enum is a class member at `:67`; a preprocessor block there
is legal but reads badly. Same header, same purpose, file scope.

`FREEINK_DEVICE_X4PRO` arrives as a `-D` on the command line
(`platformio.ini:166, 184`), so it needs no include here.

### Run the test again

Re-run the step-1 test block above.

GREEN:

```
returncode: 1
src/CrossPointSettings.h:21:2: error: #error "BEREAN_CAP_ROTATION: unhandled device set; decide whether this board offers rotation"
```

Our `#error` now fires. Line 21 is where it lands if you paste the block exactly
as given; if yours differs the line will too, and the message is what matters.

Then confirm nothing else moved:

```bash
python3 /tmp/ppcount.py src/activities/settings/SettingsActivity.cpp \
  'STR_ORIENTATION, &CrossPointSettings::orientation'          # expect: still 1
```

Still `1` — the capability exists but gates nothing yet. That is correct for
this step.

## Step 6 — hand off the device test (2 min)

Everything above proves the change compiles and that the compiler no longer sees
the three constructs. **It does not prove the feature works.** Per spec §7.2 the
device walk is the only real verification and it is the human's. Hand over
exactly this:

1. **Settings → Reader** reads **Text Settings, Manage fonts, Images, Night
   mode, Customise status bar** — five rows, with no Orientation row between
   Manage fonts and Images. Do *not* expect Hyphenation or Extra spacing on this
   screen; they carry `.withTextSettings()` and live in the Text Settings
   sub-screen. Open Text Settings and confirm they are still there.
2. **Settings → Controls → Long-press behaviour** offers **Off / Chapter skip**
   only, and now cycles on tap instead of opening a popup — the popup is gated
   on more than two values (`SettingsActivity.cpp:260`).
3. **Reader → centre-tap menu** has no Orientation row; Night mode, Frontlight
   and Auto page turn are still present and still activate.
4. **A unit previously saved in landscape** comes up portrait and stays portrait
   across a reboot (**A5**).
5. **Sleep screen** renders right way up after a power-pull and after a normal
   sleep (`SleepActivity.cpp:513, 525`).
6. **A long touch page-turn** no longer rotates the screen (**A7**).
7. **Heap** stays above ~50 KB across a reader → settings → reader cycle.

Also state plainly in the hand-back what was *not* verified: anything needing
hardware — heap figures, e-ink appearance, the power-pull test — plus the
landscape-unit migration in item 4, which needs a device that actually has a
non-portrait value persisted.

## If a step fails

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ppcount.py` exits 2 with a compiler error | `compile_commands.json` is stale after an edit | It records flags, not content, so it does not need regenerating — a real compile error in your edit is the actual cause; read the stderr it printed |
| `ppcount.py` raises `StopIteration` | no database, a database holding no project sources, or wrong path spelling | `rm -f compile_commands.json && ~/.platformio/penv/bin/pio run -t compiledb` — delete first, a plain re-run does not repair it; then check the path spelling |
| a stray `.d` file appears at the repo root | `-MMD` was not stripped | delete it; use the step-0 script verbatim |
| `clang-format-fix` exits 1 saying not found | missing `PATH` prefix | `PATH="$PWD/.venv/bin:$PATH" ./bin/clang-format-fix` |
| `#error "BEREAN_CAP_ROTATION..."` in a normal build | `FREEINK_DEVICE_X4PRO` not reaching the TU | you are building a non-`x4pro` env; both envs in `platformio.ini` define it at `:166` and `:184` |
| snapshot or orphan diff is non-empty | a row was deleted, not gated | restore the row text and wrap it in `#if` instead |
