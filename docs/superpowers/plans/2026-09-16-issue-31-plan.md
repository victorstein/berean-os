## What this change is

Delete 22 `STR_*` keys from the 32 YAML files in `lib/I18n/translations/`. That
is the whole change: **no `.cpp`, `.h`, `.c`, `.py`, `.ini` or `.md` file outside
`docs/superpowers/` is edited.**

The 22 are strings nothing references — OPDS, Calibre and general-reader
leftovers, plus `STR_DISPLAY_QR`, orphaned when the QR feature was removed in
`4a107d5c`. They sit in front of translators, who are told by `docs/i18n.md:254-260`
to keep their language file current.

**This change cannot save flash, and a flash figure that moves is a bug, not a
win.** `platformio.ini:131` runs `scripts/gen_i18n.py` as a build pre-step, and
imported by SCons it calls `main(strip_unused=True)` (`gen_i18n.py:1001`), so
every build already drops these keys before generating C++. The generated
`lib/I18n/I18nKeys.h`, `I18nStrings.h` and `I18nStrings.cpp` must come out
**byte-identical** to what they are today. That is the primary gate, and Step 1
proves it can fail before you rely on it.

One key that *looks* unused stays: **`STR_HIGHLIGHTS_TOO_LARGE`**. Issue #39 asks
this task by name not to strip it. After this change the generator reports
`Never used: 1`, and that is correct and expected — see "What you must NOT do".

## About TDD here

**There is no failing unit test to write, and you must not invent one.** The host
suite in `test/` is entirely i18n-free — `grep -rnE "\bI18n\b|\bStrId\b|\bSTR_[A-Z]|\btr\("`
over `test/` returns zero hits, and no suite's `CMakeLists.txt` mentions `I18n`.
The subject here is data, not behaviour; a test would be a test of
`scripts/gen_i18n.py`, which is a different issue.

What replaces the red/green loop is an **executable assertion that genuinely
fails before the edit and passes after** — the same assertion both times, not a
before-measurement and a different after-measurement. Steps 2 and 3 each open
with the *final* assertion run against the unedited tree, where it returns the
wrong answer; you make the edit; you run the same command again and it returns
the right one. Same loop, `grep` and `diff` in place of `ctest`.

**The one failure mode nothing else catches.** Deleting a *live* key from
`english.yaml` fails the build loudly (`gen_i18n.py:874-881` prints
`CRITICAL: … used in source but missing from english.yaml` and calls
`sys.exit(1)`). Deleting a *live* key from any of the other 31 files does **not**:
the generator exits 0, reports the same key count, and English silently
substitutes for that language on screen. The byte-identical `diff` in Step 4 is
the only thing that catches it. Step 1 exists so you have watched it catch one
before you trust it.

## Step 1 — prove the diff gate can fail (no commit, nothing in the repo is touched)

Three minutes, and do not skip it. Step 4's gate is the only guard on a silent
mistake. A gate you have never seen fail is a gate you cannot read a pass from.

This works entirely in `/tmp`. The repo is not modified.

```sh
rm -rf /tmp/i18n-vacuity && mkdir -p /tmp/i18n-vacuity/out
cp -R lib/I18n/translations /tmp/i18n-vacuity/translations
```

You need one **live** key whose Spanish text differs from its English text.
**Derive it — do not hardcode one.** The previous version of this plan named
`STR_TAGS_AND_SETTINGS`, and `main` deleted exactly that key out from under it,
which turned this demonstration into a false alarm that sent the implementer
back to redo Step 0 in a loop. This snippet re-derives a valid key every run:

```sh
VKEY=$(python3 - <<'PY'
import re
from pathlib import Path
kr = re.compile(r'^([A-Za-z_][A-Za-z0-9_]*): (.*)$')
def load(path):
    return {m.group(1): m.group(2) for m in
            (kr.match(l) for l in Path(path).read_text(encoding='utf-8').splitlines()) if m}
en = load('lib/I18n/translations/english.yaml')
es = load('lib/I18n/translations/spanish.yaml')
skip = set(Path('/tmp/i18n-remove.txt').read_text().split()) | {'STR_HIGHLIGHTS_TOO_LARGE'}
for k in sorted(en):
    if k in es and es[k] != en[k] and k not in skip:
        print(k); break
PY
)
echo "vacuity key: $VKEY"
grep -n "^${VKEY}:" lib/I18n/translations/english.yaml lib/I18n/translations/spanish.yaml
```

`$VKEY` must be non-empty and the `grep` must print **two** lines with
**different** values. Excluding `/tmp/i18n-remove.txt` and
`STR_HIGHLIGHTS_TOO_LARGE` leaves only the 419 keys that are live, so any key
this picks is guaranteed to reach the generated tables. At the time of writing it
yields `STR_ADD_HIDDEN_NETWORK` (`"Add hidden network..."` /
`"Añadir red oculta..."`), but do not depend on that — use whatever `$VKEY` is.

```sh
sed -i '' "/^${VKEY}:/d" /tmp/i18n-vacuity/translations/spanish.yaml

python3 scripts/gen_i18n.py /tmp/i18n-vacuity/translations /tmp/i18n-vacuity/out \
  --strip-unused > /tmp/i18n-vacuity/gen.log 2>&1
echo "generator exit=$?"
grep -c CRITICAL /tmp/i18n-vacuity/gen.log || true
```

Expect `generator exit=0` and `0` CRITICALs. (`grep -c` prints `0` and exits 1
when it matches nothing, hence the `|| true`; the printed `0` is the answer.)
**The generator does not notice.** That is the silent failure mode, reproduced.

Now the gate:

```sh
diff -r /tmp/i18n-before /tmp/i18n-vacuity/out > /dev/null \
  && echo "GATE MISSED IT — stop and report" \
  || echo "GATE CAUGHT IT — the gate works"
```

Expect `GATE CAUGHT IT`. If you see `GATE MISSED IT`, work through these in
order rather than assuming the snapshot is at fault:

1. `$VKEY` was empty or the `sed` matched nothing — re-run the derivation and
   check the `grep -n` printed two lines with different values.
2. The key you deleted has the same text in both languages, so the dedup never
   stored it separately and deleting it genuinely changes nothing. The
   derivation excludes this case; a hand-picked key would not.
3. `/tmp/i18n-before` was re-taken after an edit. Redo Step 0.

Do not proceed until you have seen `GATE CAUGHT IT` — Step 4 gate 1 is the only
guard on the silent failure, and an unproven guard is not one.

Clean up so a stale directory cannot confuse Step 4:

```sh
rm -rf /tmp/i18n-vacuity
```

No commit — nothing in the repo changed. Confirm that: `git status --short`
must still be empty.

## Step 4 — the gates

Five minutes, most of it the build. No edits. Run them in this order; two of them
depend on it.

```sh
# 1. THE PRIMARY GATE. The generated C++ must be byte-identical to Step 0's
#    snapshot. This is the only thing that catches a live key deleted from a
#    non-English file -- the generator accepts that silently. You watched this
#    gate catch exactly that case in Step 1.
rm -rf /tmp/i18n-after && mkdir -p /tmp/i18n-after
python3 scripts/gen_i18n.py lib/I18n/translations /tmp/i18n-after --strip-unused > /dev/null
diff -r /tmp/i18n-before /tmp/i18n-after && echo "IDENTICAL"
# expect: no output from diff, then IDENTICAL

# 2. The generator's own report: exactly one unused key, and it is named.
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/ --verbose \
  | sed -n '/Unused keys/,/^$/p'
# expect EXACTLY these four lines (the sed range matches the summary line too):
#   Unused keys (1):
#     - STR_HIGHLIGHTS_TOO_LARGE
#   <blank>
#   Unused keys: 1 (pass --strip-unused to remove them)
# and NO line containing CRITICAL

# 3. Shape of the whole change. Measure THIS change -- the two commits you just
#    made -- not the distance to `main`. `git diff … main` is wrong here: it is
#    a moving target, and when `main` carries a change to these same files that
#    this branch does not yet have, it reports insertions on the success path
#    and reads exactly like the scope creep this plan warns about.
git diff --stat HEAD~2 HEAD -- lib/I18n/translations/ | tail -1
# expect: 32 files changed, 666 deletions(-)   -- and no insertions
# This form is invariant under rebase and under anything `main` does.

# 4. Build. Regenerates lib/I18n/I18nKeys.h, which gate 5 greps.
#    Redirect rather than pipe: `| tee` makes $? the exit status of tee, which
#    is always 0, so a failed build would read as a pass.
~/.platformio/penv/bin/pio run > /tmp/i18n-build.log 2>&1
echo "build exit=$?"                      # expect: 0
grep -E 'Stripping|String keys|RAM:|Flash:|SUCCESS' /tmp/i18n-build.log
# expect these SEVEN lines, in this order. The FIRST is the generator's own
# string accounting, NOT the binary's size -- it is printed before the
# Stripping line, which is why it leads:
#   "  Flash: 241,894 B strings (deduped)  +  28,288 B offset tables  =  270,182 B"
#   "  Stripping 1 unused string(s) from output."     (was 23)
#   "  String keys: 419"                              (unchanged)
#   "RAM:   [==        ]  19.5% (used 64052 bytes from 327680 bytes)"
#   "Flash: [========  ]  81.1% (used 5314686 bytes from 6553600 bytes)"
```
