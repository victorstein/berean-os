## What this change is

Delete 22 `STR_*` keys from the 32 YAML files in `lib/I18n/translations/`. That
is the whole change: **no `.cpp`, `.h`, `.c`, `.py`, `.ini` or `.md` file outside
`docs/superpowers/` is edited.**

The 22 are strings nothing references — OPDS, Calibre and general-reader
leftovers, plus `STR_DISPLAY_QR`, orphaned when the QR feature was removed in
`4a107d5c`. They sit in front of translators, who are told by `docs/i18n.md:254-260`
to keep their language file current.

**This change cannot save flash, and a flash figure that moves is a bug, not a
win.** `platformio.ini:131` runs `scripts/gen_i18n.py` as a build pre-step, and
imported by SCons it calls `main(strip_unused=True)` (`gen_i18n.py:1001`), so
every build already drops these keys before generating C++. The generated
`lib/I18n/I18nKeys.h`, `I18nStrings.h` and `I18nStrings.cpp` must come out
**byte-identical** to what they are today. That is the primary gate, and Step 1
proves it can fail before you rely on it.

One key that *looks* unused stays: **`STR_HIGHLIGHTS_TOO_LARGE`**. Issue #39 asks
this task by name not to strip it. After this change the generator reports
`Never used: 1`, and that is correct and expected — see "What you must NOT do".

## About TDD here

**There is no failing unit test to write, and you must not invent one.** The host
suite in `test/` is entirely i18n-free — `grep -rnE "\bI18n\b|\bStrId\b|\bSTR_[A-Z]|\btr\("`
over `test/` returns zero hits, and no suite's `CMakeLists.txt` mentions `I18n`.
The subject here is data, not behaviour; a test would be a test of
`scripts/gen_i18n.py`, which is a different issue.

What replaces the red/green loop is an **executable assertion that fails before
the edit and passes after**. Every step below has one: run the "before" command
and watch it fail, make the edit, run the "after" command and watch it pass,
commit. Same loop, `diff` and `grep` in place of `ctest`.

**The one failure mode nothing else catches.** Deleting a *live* key from
`english.yaml` fails the build loudly (`gen_i18n.py:874-881` prints
`CRITICAL: … used in source but missing from english.yaml` and calls
`sys.exit(1)`). Deleting a *live* key from any of the other 31 files does **not**:
the generator exits 0, reports the same key count, and English silently
substitutes for that language on screen. The byte-identical `diff` in Step 4 is
the only thing that catches it. Step 1 exists so you have watched it catch one
before you trust it.

## Step 4 — the gates

Five minutes, most of it the build. No edits. Run them in this order; two of them
depend on it.

```sh
# 1. THE PRIMARY GATE. The generated C++ must be byte-identical to Step 0's
#    snapshot. This is the only thing that catches a live key deleted from a
#    non-English file -- the generator accepts that silently. You watched this
#    gate catch exactly that case in Step 1.
rm -rf /tmp/i18n-after && mkdir -p /tmp/i18n-after
python3 scripts/gen_i18n.py lib/I18n/translations /tmp/i18n-after --strip-unused > /dev/null
diff -r /tmp/i18n-before /tmp/i18n-after && echo "IDENTICAL"
# expect: no output from diff, then IDENTICAL

# 2. The generator's own report: exactly one unused key, and it is named.
python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/ --verbose \
  | sed -n '/Unused keys/,/^$/p'
# expect:
#   Unused keys (1):
#     - STR_HIGHLIGHTS_TOO_LARGE
# and NO line containing CRITICAL

# 3. Shape of the whole diff.
git diff --stat main -- lib/I18n/translations/ | tail -1
# expect: 32 files changed, 666 deletions(-)   -- and no insertions

# 4. Build. Regenerates lib/I18n/I18nKeys.h, which gate 5 greps.
#    Redirect rather than pipe: `| tee` makes $? the exit status of tee, which
#    is always 0, so a failed build would read as a pass.
~/.platformio/penv/bin/pio run > /tmp/i18n-build.log 2>&1
echo "build exit=$?"                      # expect: 0
grep -E 'Stripping|String keys|RAM:|Flash:|SUCCESS' /tmp/i18n-build.log
# expect: "Stripping 1 unused string(s) from output."   (was 23)
#         "String keys: 420"                            (unchanged)
#         RAM:   ... 64052 bytes from 327680
#         Flash: ... 5314782 bytes from 6553600
#         [SUCCESS]
# A DIFFERENT FLASH FIGURE IS A FAILURE SIGNAL, not a win. Gate 1 proved the
# generated sources are identical, so the binary has no legitimate way to move.

# 5. Orphan gate. MUST run after the build: scripts/i18n_orphans.sh greps the
#    build-generated lib/I18n/I18nKeys.h, and against a stale copy it reports
#    the exact inverse of the truth. Assert on its STDOUT, never its exit
#    status -- it ends in an echoing `while` loop (i18n_orphans.sh:9-13) and
#    returns 0 whether it finds 0 orphans or 23.
./scripts/i18n_orphans.sh
# expect exactly one line: orphan: STR_HIGHLIGHTS_TOO_LARGE

# 6. Host suite (CI's unit-tests job). Default generator, NOT -G Ninja:
#    ninja is not installed on this host.
cmake -S test -B build/test -DCMAKE_BUILD_TYPE=Release > /dev/null
cmake --build build/test > /dev/null
ctest --test-dir build/test --output-on-failure -j
# expect: 100% tests passed. The suite is i18n-free, so this is a regression
# check on the tree, not on this change.

# 7. Format, whole tree, exactly as CI does. Expect a no-op: no C/C++ was
#    touched. Without the PATH prefix the wrapper exits 1 because it cannot
#    find clang-format.
PATH="$PWD/.venv/bin:$PATH" ./bin/clang-format-fix
git status --short
# expect: empty -- the format run must change nothing
```

`pio check` is deliberately **not** in this list. It analyses C/C++, this change
edits none, and gate 1 proves the generated C++ is identical — so its result
cannot differ from the baseline by construction.

If every gate passes there is nothing to commit here; Steps 2 and 3 are the whole
change.

## What you must NOT do

- **Do not strip `STR_HIGHLIGHTS_TOO_LARGE`.** `Unused keys: 1` is the correct
  end state. Issue #31's acceptance criterion 5 asks for zero; it cannot be met
  while criterion 2 and issue #39 both say to keep this key, and the spec
  escalated that conflict rather than resolving it. Do not "finish the job" by
  deleting it.
- **Do not edit `AGENTS.md`** (or `CLAUDE.md`, a symlink to it), even though
  `:336` and `:709` use `tr(STR_LOADING)` as the worked example and go stale the
  moment this merges. It is recorded as a follow-up in the spec's A4.
- **Do not delete the 17 keys that exist only outside `english.yaml`** (in
  `hebrew`, `polish`, `norwegian`, `kazakh`). They are real dead weight and
  deliberately out of scope — spec A3.
- **Do not edit `scripts/i18n_orphans.sh` or `scripts/gen_i18n.py`.** Both have
  known wrinkles this plan works around; fixing them is someone else's task.
- **Do not stage `lib/I18n/I18nKeys.h`, `lib/I18n/I18nStrings.h` or
  `lib/I18n/I18nStrings.cpp`.** They are gitignored (`.gitignore:8-10`) and are
  rewritten by nearly every command in this plan. `git add lib/I18n/translations/`,
  never `git add lib/I18n/`.
- **Do not re-take `/tmp/i18n-before` after an edit.** It is the only "before"
  there is.
- **Do not sort, re-indent, strip trailing whitespace, or add a trailing newline
  to any YAML.** A pure line delete is what makes `git diff --stat`'s
  "0 insertions(+)" a real assertion.
- **Do not push, do not open a PR, do not commit to `main`.**
