cat > .pio/issue112-pr-body.md <<'EOF'
## Summary

Release builds (`x4pro-gh_release`, what OTA installs) no longer write a log over serial.

- **`platformio.ini`.** The release env drops `-DENABLE_SERIAL_LOG` and sets `-DLOG_LEVEL=0`.
  Every `LOG_*` now compiles to nothing in release. `setup()` no longer calls `Serial.begin()` or
  waits the 250 ms USB-enumeration delay.
- **The `CMD:` serial handler** (`src/main.cpp:618-633`) can no longer run in release. It is still
  compiled in. Without `Serial.begin()` the HWCDC RX queue is never allocated, so
  `logSerial.available()` returns -1 (framework `HWCDC.cpp:562-565`). `readStringUntil` never
  runs, so it cannot stall the loop, and the framebuffer dump is unreachable.
- **Docs.**
  - `AGENTS.md` (`CLAUDE.md`) and `.clangd` now say `-std=gnu++2a`, matching `platformio.ini:40`.
  - The User Guide and the bug-report form now say a serial log needs a development build.

The dev env `x4pro` is unchanged.

## Trade-off to see before merging

Release crash reports (`/crash_report.txt`) lose their **"Last logs"** section. Only `LOG_*` calls
fill that ring buffer. On this Xtensa board the stack section was already empty
(`lib/hal/HalSystem.cpp:47-49`), so a release crash report now holds only the version and the
panic reason. Upstream raised release logging to INFO in c40e92e4 partly for that content.
