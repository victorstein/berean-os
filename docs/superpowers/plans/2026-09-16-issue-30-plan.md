## Step 1 — the decision helper, test first

### Red

Create `test/launcher_refresh/LauncherRefreshTest.cpp`:

```cpp
#include <gtest/gtest.h>

#include "activities/launcher/LauncherRefresh.h"

// The launcher's first paint after a wake has to be non-differential: the panel
// is still showing the sleep screen, and a differential refresh only drives the
// pixels that differ from a baseline that does not contain it. Every later paint
// in the same entry is an ordinary fast refresh.
//
// The second argument is "this entry has already painted", not "this is the
// first paint". That polarity is the one thing a caller can silently invert, and
// the launcher reads it before setting its own latch, so it is pinned here.

TEST(LauncherRefresh, FirstPaintOfAFlaggedEntryNeedsACleanPaint) {
  EXPECT_TRUE(launcherNeedsCleanPaint(true, false));
}

TEST(LauncherRefresh, LaterPaintsOfAFlaggedEntryDoNot) {
  EXPECT_FALSE(launcherNeedsCleanPaint(true, true));
}

TEST(LauncherRefresh, AnUnflaggedEntryNeverDoes) {
  EXPECT_FALSE(launcherNeedsCleanPaint(false, false));
  EXPECT_FALSE(launcherNeedsCleanPaint(false, true));
}

TEST(LauncherRefresh, ResolvesAtCompileTime) {
  static_assert(launcherNeedsCleanPaint(true, false));
  static_assert(!launcherNeedsCleanPaint(false, false));
  SUCCEED();
}
```

### Green

Create `src/activities/launcher/LauncherRefresh.h`:

```cpp
#pragma once

// Whether one launcher paint has to be non-differential.
//
// cleanInitialRefresh is set by the wake path when the panel is still showing a
// frame the launcher did not draw: the sleep screen, after a wake that found no
// Quick Resume frame on the card. A differential refresh cannot clear that, so
// the first paint of such an entry must not be one. Every later paint in the
// entry diffs against a baseline the launcher itself drew.
//
// firstRenderDone is "this entry has already painted", so the first paint passes
// false. Lives here, free of firmware includes, so that polarity can be tested
// on the host -- inverting it costs the wake paint its clean, and nothing the
// device shows afterwards says which way round it went.
constexpr bool launcherNeedsCleanPaint(const bool cleanInitialRefresh, const bool firstRenderDone) {
  return cleanInitialRefresh && !firstRenderDone;
}
```

Add no includes to this file. It compiles with `${REPO_ROOT}/src` alone, which is
what keeps the suite off `<HalDisplay.h>`, `<Arduino.h>` and the freeink-sdk
panel chain.

Run it again:

```bash
cmake --build build/test --target LauncherRefreshTest
./build/test/launcher_refresh/LauncherRefreshTest
```

Expect `[  PASSED  ] 4 tests.` Then the whole suite, to prove nothing else moved:

```bash

```

Then replace the last statement of `LauncherActivity::render`, currently line
473:

```cpp
  renderer.displayBuffer();
}
```

with:

```cpp
  const bool cleanPaint = launcherNeedsCleanPaint(cleanInitialRefresh, firstRenderDone);
  const auto mode = cleanPaint ? HalDisplay::HALF_REFRESH : HalDisplay::FAST_REFRESH;
  LOG_DBG(MODULE, "Paint: clean=%d firstPaint=%d mode=%s", cleanInitialRefresh ? 1 : 0, firstRenderDone ? 0 : 1,
          cleanPaint ? "HALF" : "FAST");
  renderer.displayBuffer(mode);
  firstRenderDone = true;
}
```

Three things to get right, each of which the spec calls out:

- **No `requestUpdate()` after this** (spec A3). `HomeActivity.cpp:308-311` calls
  one behind `!firstRenderDone` because it paints a skeleton and loads recents
  afterwards. The launcher resolves everything in `onEnter`
  (`LauncherActivity.cpp:65-72`) and has no second pass. Adding it would put a
  second full-screen refresh on every launcher entry.
- **`firstPaint` in the log is the negation of `firstRenderDone`** (spec A8,
  spec review MINOR 1). It is read before the latch is set:
  `firstRenderDone ? 0 : 1`, not `firstRenderDone ? 1 : 0`.
- **The latch is set unconditionally** (spec A6), after the paint, not inside a
  branch.

`MODULE` is already defined in this file as `"LAUNCH"` (line 39). `LOG_DBG`
compiles out at `LOG_LEVEL=1`, the release env (`platformio.ini:188`,
`lib/Logging/Logging.h:57-60`), so this ships as nothing. `mode` is still used by
`displayBuffer` when the log vanishes, so there is no unused-variable warning.

No test runs here. Do not build the firmware yet.

1. Sleep screen set to anything but Quick Resume (default is `DARK`). Sleep,
   wake. Expect `[DBG] LAUNCH Paint: clean=1 firstPaint=1 mode=HALF`, and exactly
   one `Paint:` line for that entry. Other `LAUNCH` lines are normal —
   `resolveTargets` logs the meeting publication and any generated thumbnail
   (`LauncherActivity.cpp:124,136,219`).
2. Press a nav button on the launcher. Expect `clean=1 firstPaint=0 mode=FAST`.
3. Sleep screen set to Quick Resume. Sleep, wake. Expect
   `clean=0 firstPaint=1 mode=FAST`.
4. Home gesture back to the launcher from the reader. Expect
   `clean=0 firstPaint=1 mode=FAST`.
5. Exactly one refresh per launcher entry. A second full-screen refresh on entry
   means step 3's "no `requestUpdate()`" was violated.
6. **The ghosting itself**: sleep so the sleep image is on the panel, wake, and
   look at the launcher for a ghost of it. On a default unit this will look the
   same before and after — see 7c.
